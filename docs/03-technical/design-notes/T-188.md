# T-188 design note: chart period selector (C3, written by the implementer)

Requirement: FR-CHT-04 (widened) / D-68. Today `chartsPeriodProvider` is a bool (this / last cycle) and every chart provider is built on `chartsCurrentCycleProvider`. This note fixes the model, the buckets, which charts support which periods, and how it is stored.

## 1. Model (pure Dart, `insights/domain/chart_period_selection.dart`)

`ChartPeriodSelection(preset, offset, customFrom, customTo)`. It holds no dates except the custom range, so a relative preset re-resolves when `todayProvider` changes (midnight, travel, test clock).

| Preset | Kind | Resolves to (offset 0) | Stepping back |
|--------|------|------------------------|---------------|
| thisCycle / lastCycle | cycle | the payday cycle containing today / the one before | one cycle earlier |
| thisMonth / lastMonth | month | full calendar month | one month earlier |
| last3 / last6 / last12Months | rolling | first day of the month (N-1) months ago .. today | previous full block of N months |
| thisYear | year | 1 Jan .. 31 Dec | previous year |
| custom | custom | the picked from..to | shifted back by its own length |

- `offset` counts steps. `lastCycle` and `lastMonth` carry a built-in base of 1, so stepping back from "last cycle" gives two cycles ago and the chip still reads as a range. All kinds resolve to a `ChartPeriod` (from..to inclusive) via `resolve(today, schedule)`. Cycle kind uses `PaydaySchedule.cycleOn / before / after`, so payday eras are honoured; month and year are plain Gregorian arithmetic (day 29..31, leap years covered by `CivilDate`).
- `canStepForward(today)`: the next period's first day must be <= today and, for non-custom presets, the period count back stays >= 0. `canStepBack`: not before 2000-01-01.
- Custom range: from <= to <= today, at most 1827 days (5 years; the picker clamps the start). Longer or malformed stored values decode to the default.
- Payday cycles are one schedule for the whole app (`paydayScheduleProvider`), not per currency, so "per currency's payday cycle" resolves identically for every currency chip. Flagged as a PO question.

## 2. Buckets (`bucketsOf`)

Length <= 31 days: day buckets. <= 190 days: week buckets (7-day chunks from the start; the last one clipped). Longer: calendar-month buckets clipped to the range. Buckets that start after today are dropped. The "cycles" bucket in the task text is not built: weeks cover the same ground without a second code path (flagged as a PO question). `ChartRepository.cashFlow` already takes any list of buckets and runs one daily query for the span, so no repository change is needed and cost is independent of bucket count.

## 3. Which charts follow which period

| Chart | Rule |
|-------|------|
| Cash flow | buckets above; footnote and explanation use the whole period's total |
| Categories, merchants, 50/30/20, cards split, week pattern | the selected period as is (week pattern used 3 cycles before; it now uses the selection, and its own minimum-rows rule gives the "not enough data" note) |
| Net worth | the period, widened to at least 12 months ending at the period end ("may extend") |
| Burn rate, month vs average | cycle kind only (they are about one cycle's pace and the 3 cycles before it). Other kinds show the short note "This chart needs a payday cycle". For a past cycle the burn curve runs to the cycle's end |
| Budget progress | the budget screen's current cycle; a note when another period is selected |
| Installments, subscriptions, inflation | not period charts (fixed horizon); unchanged |

`ChartPeriodSupport` (domain) holds this table so UI and tests share it.

## 4. Providers and storage

- `chartPeriodSelectionProvider` (Notifier) reads/writes the new setting `charts.period` (text codec `<preset>|<offset>|<from>|<to>`; strict decode, anything odd = this cycle). Same encrypted `settings` table, no schema change, no migration. `select` updates state at once, then saves; a failed save keeps the choice for the session only.
- `chartsPeriodProvider` becomes `Provider<ResolvedChartPeriod>`-like (`chartsResolvedPeriodProvider`: selection + today + payday schedule -> period, kind, previous period). `chartsCurrentCycleProvider` is removed; every chart, explainer, currency list and detail screen reads the resolved period. The "previous *" explainer providers use the previous period of the same length (`ChartPeriodSelection.stepped(+1)`), not "the cycle before".
- Card/currency filters are untouched: `ChartFilter` keeps the code and account ids.

## 5. UI

Chip at the top of Charts: resolved range ("25 Oct – 24 Nov", digits per setting) with ‹ › buttons (44 pt targets, chevrons mirror in RTL, next disabled at today). Tap opens a `showZSheet` with the presets (check marks) and "Custom range" which opens the existing Material `showDateRangePicker` (Gregorian, locale digits). Chart detail shows the same range in its context line.

## 6. Explanations

Basic/deep fact lines that said "this cycle / last cycle" get two placeholders, `{now}` ("this cycle", "this month", "the last 6 months", "1 Jan – 31 Mar") and `{prev}` ("the previous cycle", ...). Phrases are built from the selection in `ExplainFormat`. Burn-rate and month-vs-average wording stays (cycle-only charts). Tip and deep-tip lines say "per cycle" and are sized for one cycle, so they appear only when the selection is a cycle; other kinds show facts only.

## 7. Performance (AC5)

Benchmark cases added to `chart_benchmark_test.dart`: cash flow with weekly buckets over "last 6 months" and monthly buckets over "last 12 months" and a 2-year custom range; donut, merchants, cards for the 12-month and 2-year ranges; net worth widened. Gate stays 100 ms per query on 10k rows (spec: < 300 ms per chart).

## 8. Tests

Domain unit tests (resolution at month ends, payday 1/25/28 with era change, leap year, Ramadan-edge dates, stepping, codec, bucketing). Provider test for persistence across a container restart. Widget tests for chip, sheet, stepping, unsupported-note. Goldens: picker sheet and 6-month view, ar/en, light/dark (images regenerated by CI).
