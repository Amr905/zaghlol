## How to read this

- **PASS**: tests that exercise the requirement were executed in this audit and passed, at the level the "Test scenario" and "Actual result" columns state. Most are component level (unit, widget, golden, backend integration on a real PostgreSQL 17). It is not a claim that the behaviour was seen on a phone.
- **BLOCKED**: the acceptance criterion needs something this audit did not have (a phone or emulator, an iPhone, store accounts, real bank samples, a deployed backend, a human reviewer). Component tests that did pass are counted in the row.
- **FAIL**: executed and the result differs from the requirement. **NOT IMPLEMENTED**: no implementation found. **NOT TESTED**: not examined.
- The mapping from a requirement to test suites is by feature folder and test name, made by the auditor. The count is the number of passing tests in those suites, not a count of tests proven to check that exact sentence.
