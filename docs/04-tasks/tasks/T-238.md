## Scope
1. **E2E-09:** Free sees the export preview only; Gold exports CSV. Gold must come from a backend-signed entitlement in production; for the test use the existing dev/test seam (dev flavor fake signer or test override, whichever the code already provides; never add a production bypass). Assert the CSV file's header and row count (not amounts in logs).
2. **E2E-10:** switch language (ar ↔ en) and digits (Arabic-Indic ↔ Western); visit every tab and the main sub-screens; assert direction (RTL/LTR), digits in a known amount and no overflow errors (fail on any FlutterError).
3. **E2E-11:** turn on app lock; background and foreground the app; assert the lock screen shows; take a screenshot of the app switcher state if feasible (`FLAG_SECURE` check via `dumpsys window`), assert secure flag when the setting says so.
4. **E2E-12:** Settings → delete everything → assert first-launch state (welcome screen, DB empty, settings reset, scheduled notifications cleared).
## Rules for all three device tasks (T-236..T-238)
- New file(s) under `app/integration_test/`, real app (`main()`, real providers, real encrypted DB) on the CI emulator, devSms flavor; follow `sms_device_test.dart`, `sms_charts_device_test.dart` and `.github/scripts/device-flows.sh` patterns. Add each as its own job (or a step in an existing job if it fits the 60-minute limit) in `.github/workflows/device-flows.yml`; keep the jobs independent so one failure does not hide others.
- Synthetic data only; logs never print SMS bodies or amounts beyond test ids.
- Screenshots of key states to `device-shots/<sha>/<job>/`.
- When the test finds an app bug, fix it with a unit/widget test (ar + en), and list it in this file. If the fix is large, file an FU with the failing step and skip only that assertion with the reason.
- Emulator runs on `ci/<task-id>` (push, or dispatch `gh api -X POST repos/Amr905/zaghlol/actions/workflows/device-flows.yml/dispatches -f ref=ci/<task-id>`); up to ~3 iterations; report the green run id.
- Another two builders add jobs to `device-flows.yml` in parallel: add your job as a separate block at the end of the jobs list to keep merges simple.
