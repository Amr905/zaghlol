## Description
The pure-Dart pieces that bind restore and sign-in proofs to this install and this body, tested byte-for-byte against the same vectors the backend uses.

## Technical details
- **Strict JSON parser:** rejects duplicate member names at any depth (including inside `purchases[]` items and `attestation`) and lone (unpaired) UTF-16 surrogates; used on the exact restore body the app is about to send, before any hash.
- **JCS (RFC 8785)** canonicalizer over the parsed object (UTF-16 code-unit key ordering, ECMAScript number formatting, string escaping).
- **`restoreBodyHash(installId, body)`** = `SHA-256("zaghlol-restore-v1" ‖ 0x00 ‖ installId ‖ 0x00 ‖ JCS(body without "attestation"))`, `installId` lower-case hyphenated UUID text.
- **`seatKeysDigest(publicKeys)`** = SHA-256 of the concatenated 65-byte points in order (SHA-256 of the empty string when none).
- **`restoreClientDataHash(bodyHash, publicKeys)`** = `SHA-256("zaghlol-restore-attest-v1" ‖ 0x00 ‖ bodyHash ‖ seatKeysDigest)`.
- **`seatMessage(op, installId, challenge)`** = `"zaghlol-seat-v1" ‖ 0x00 ‖ op ‖ 0x00 ‖ installId ‖ 0x00 ‖ challenge`; challenges: `verify` SHA-256(signedTransaction), `restore` bodyHash, `signin` SHA-256(raw nonce).
- Vectors are read from `backend/tests/Zaghlol.Contract.Tests/vectors/` (copied or referenced by path in the test, not re-typed).
- No I/O, no platform channels; never logs inputs or outputs.
