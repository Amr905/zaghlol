## Description
Encrypted Drift database that every repository builds on.

## Technical details
NativeDatabase.createInBackground with sqlite3mc; setup: PRAGMA cipher/legacy/key, verify cipher active else refuse; WAL, foreign_keys; schemaVersion 1; drift_dev schema dump folder; generated migration tests; pre-migration encrypted copy and restore-on-failure; DB file in no-backup dir.

## Design note
Status: written by solution-architect (Opus), 2026-11-10. Inputs: this file; database-schema §0/§4; ADR-002 (+ T-015 Amendment, T-007 findings); security-model §3; T-015 note, code and reviews (m-2, S-2, S-7); FU-050, FU-065, FU-069. No "Plan revision" exists in this file. Library versions (drift_dev matching drift 2.35.x, path_provider 2.1.x) were not re-verified here; the implementer checks pub.dev and cites them in the PR.

**1. Wiring.** `AppDatabase extends _$AppDatabase` (`core/db/app_database.dart`, `@DriftDatabase(tables: [DbMeta])`, `schemaVersion = 1`). It takes a `QueryExecutor` from T-015's `openEncryptedExecutor` (background isolate via `NativeDatabase.createInBackground`, `setup` runs the T-007 sequence; `logStatements:false`); nothing else issues `PRAGMA key`. Skeleton schema v1 has one table, `db_meta(key TEXT PK, value TEXT NOT NULL)`, owned by T-016 (holds `restore_notice_due`; T-019's `settings` stays separate). New dev deps: `drift_dev`, `build_runner` (codegen; generated files committed, CI fails when stale). New runtime dep: `path_provider` (first-party; for the directory only). The executor, key, wiper and clock are injected, so tests use temp dirs and fakes.

**2. Stable DB directory (S-7).** One constant function `dbDirectoryFor(Directory appSupport) = appSupport/'db'`, used by both `dbDirectoryProvider` and the executor path (`mainFile` comes from `DbFileSet(dir)`; AppDatabase never builds a path of its own). `appSupport` = `getApplicationSupportDirectory()` (Android `files/`, iOS `Library/Application Support`). This is excluded from OS backup and device transfer by the T-165 rules (all `<domain>`s excluded; iOS `isExcludedFromBackup` set in AppDelegate), so no new native code. Deviation from the task text "no-backup dir": `noBackupFilesDir` would need a channel method for no gain. Tests: (a) `DbFileSet.directory.path == dirname(executorFile.path)`; (b) the path ends `/db/zaghlol.db` (golden string, so a rename breaks the build); (c) CI test that the Android rules and the iOS exclusion still cover that path. The directory is created before `obtain()`.

**3. Lease validity (S-2, FU-065; the only native change).** Add one method to `SecretStoreHostApi`: `@async bool renewBootstrapLease(int lease)`. Native: if `lease` is current and unexpired, set expiry to now+30 s and return true; else false (it never takes a lease). Kotlin: `BootstrapLeaseManager.renew` next to `isValid`; Swift: same. Dart: `SecretStore.renewBootstrapLease` and `BootstrapLease.ensureValid()` which throws `DbOpenException('DB_LEASE_LAPSED')` on false (code only). Regenerate Pigeon files; update platform-channels §5. Tests: Kotlin JVM (fake clock: valid, expired, stale id, renew extends), XCTest equivalent, Dart fake. Same-lease renewals are unbounded by design, but a dead engine still lapses after 30 s.

**4. Open sequence** (`openAppDatabase`, `core/db/app_database_opener.dart`; pure orchestration over injected deps; returns sealed `DbOpenResult`: `DbOpened(db, {created, wipedOrphan})` or `DbOpenFailed(code)`; never throws to the UI, never logs).
1. File recovery (no key needed): delete `*.migrate.part`; if `zaghlol.db.migrate.tmp` exists a migration was not confirmed, so roll back (see §6).
2. `outcome = bootstrap.obtain()`:
   - `KeyReady(k)`: if the main file is missing (leftovers only), delete the leftovers and call `obtain()` once more (now rotate path); otherwise open with `k`. `DB_KEY_REJECTED` (SQLITE_NOTADB) → `reportRejected(k)`: `KeyInvalidated` → step 3 wipe; `KeyReady(k2)` → retry once with `k2`; any other `DbOpenException` (`DB_OPEN_FAILED`, BUSY, IOERR...) → `DbOpenFailed(DB_UNAVAILABLE)`, never a wipe. `k` is zeroized in `finally`.
   - `KeyCreated(k, reason, lease)`: `lease.ensureValid()`, then create the database (first file) with `AppDatabase(..., restoreNoticeDue: k.restoreNoticeDue)`; `onCreate` runs `createAll` and inserts `db_meta('restore_notice_due','1')` in the same transaction, so the notice cannot be lost between create and mark (D-70). Verify (`verifyEncrypted` already in setup), zeroize, release lease in `finally`. If `ensureValid` fails: no file written, `DB_UNAVAILABLE(leaseLapsed)`; the next launch re-bootstraps.
   - `KeyInvalidated(reason, lease)` (D-50, FR-SEC-05): wipe under the lease (step 3), `recreateAfterWipe(lease)` → `KeyCreated(afterWipe)` → the create path above (with `restoreNoticeDue = true`). Lease released in `finally`.
   - `KeyUnavailable` → `DB_UNAVAILABLE` (foreground gate retries; background keeps spool). `KeyStoreFailed` → `DB_STORE_FAILED`; no file created.
3. **Wipe** = list of `OrphanWipeStep`s from `orphanWipeStepsProvider`. T-016 ships step 1: the DB file set, in order `-wal`, `-shm`, `-journal`, temp/migrate/restore names, **main file last** (a crash mid-wipe still looks like an orphan and resumes; if the main file went first, a leftover WAL plus a still-valid key would silently create an empty database without the notice). Step 2: temp dir contents. T-008 and T-011 append spool and Guard config. Before **each** step: `lease.ensureValid()`; false → stop, `DB_UNAVAILABLE(leaseLapsed)`, nothing else touched (idempotent on retry). After the steps, `anyExists()` must be false, else `DB_WIPE_INCOMPLETE` (never `recreateAfterWipe` over leftovers; it refuses anyway). The only secret slot ever deleted is `dbKey` (inside `recreateAfterWipe`); no wipe step names the iOS seat keys.
4. Provider `appDatabaseProvider` is a `FutureProvider<AppDatabase>` that throws a `DbOpenFailure(code)` (a `SafeException`) on `DbOpenFailed`; `ref.onDispose(db.close)`. The startup gate (not T-016) maps codes to screens. Retry = `ref.invalidate`. `restoreNoticeDue()` / `clearRestoreNotice()` live on `AppDatabase` (reads/deletes the `db_meta` row) for the startup screen.

**5. PRAGMAs.** In `setup` (after T-015's key, `temp_store=2`, WAL, `synchronous=NORMAL`, verify): `busy_timeout = 5000` (two engines), `secure_delete = FAST` (zeroes freed content when free of extra I/O; the file is encrypted, so this is defence in depth for purged raw SMS), `cache_size = -8192` (8 MiB, ADR-002 finding 4; the benchmark may raise it). In `MigrationStrategy.beforeOpen`: `PRAGMA foreign_keys = ON` (a no-op inside a transaction, so never in setup), then in debug/test only `validateDatabaseSchema()`. `onUpgrade` wrapper: `foreign_keys = OFF`, run `stepByStep`, `PRAGMA foreign_key_check` (any row → throw), so a bad migration fails here instead of in production. Statement logging stays off (`driftLogStatements` test already exists; add a grep that no `logStatements: true` exists in `lib/`). A test reads every PRAGMA back from a live encrypted DB.

**6. Migration harness.** `schemaVersion=1` now; `drift_dev make-migrations` produces `app/drift_schemas/drift_schema_v1.json`, `test/generated/schema*.dart` and `schema_versions.dart` (`stepByStep` in `onUpgrade`). CI step: dumped schema equals committed (`dart run drift_dev schema dump` then `git diff --exit-code`), so a table change without a version bump and a dump fails. Layers: (a) generated `SchemaVerifier` tests (every `vN→vN+1`, and `v1→latest` with populated fixtures; for v1 only `startAt(1).validate`) on in-memory databases; (b) **safety net**, tested with a synthetic test-only `schemaVersion=2` database class in the test tree (`FakeV2Database` with one trivial step that can be made to throw), on a real encrypted file:
- Before upgrading (in `setup`, raw db, after verify): `PRAGMA user_version` = v; `0<v<target` and `allowMigration` → `PRAGMA wal_checkpoint(TRUNCATE)`, then **file copy** `zaghlol.db` → `zaghlol.db.migrate.part`, flush, rename to `zaghlol.db.migrate.tmp`. A byte copy is encrypted with the same key and salt by construction. This deviates from database-schema §4.3 (`VACUUM INTO`): VACUUM INTO cannot run inside drift's migration transaction and its output key semantics under sqlite3mc are unproven; update §4.3. Copy failure (disk full) → `DB_MIGRATE_COPY_FAILED`, nothing migrated. `v > target` → `DB_SCHEMA_TOO_NEW`, file untouched (EC-26). `allowMigration:false` (the headless engine, T-008) and `v < target` → `DB_MIGRATION_PENDING`; the spool keeps the entry (ack-after-commit) and the UI engine migrates.
- Success: after `beforeOpen` completes the opener deletes `.migrate.tmp`. Failure (any exception from the first statement, forced by `doWhenOpened`): close the db, delete `-wal/-shm`, rename `.migrate.tmp` over `zaghlol.db`, return `DB_MIGRATION_FAILED(restored: true)` (screen «التحديث ماكملش», error-handling §1; retry allowed). Restore itself failing → `restored:false`, tmp kept, startup rollback (step 1 of §4) retries it on the next launch. Accepted: a crash after success but before tmp deletion rolls back and re-migrates; nothing was written in between except by a headless engine in that millisecond window.
- Tests: success deletes the copy; failing step restores byte-identical bytes (compare every file, as T-015) and the old version reopens; crash simulation (leave `.migrate.tmp`, restart) rolls back; `.part` ignored and deleted; disk-full simulated by an injected copier that throws; too-new refused untouched; headless `allowMigration:false`; the copy opens with the same key (proves "encrypted copy") and its header is not `SQLite format 3`.

**7. Error codes and logging (FU-050).** Extend `DbOpenException.codes` with `DB_LEASE_LAPSED`, `DB_MIGRATION_PENDING`, `DB_SCHEMA_TOO_NEW`, `DB_MIGRATE_COPY_FAILED`; `DbOpenFailed` codes (`DB_UNAVAILABLE`, `DB_STORE_FAILED`, `DB_MIGRATION_FAILED`, `DB_WIPE_INCOMPLETE`, plus the above) are a closed enum with a test that every one maps to a gate state. Diag codes `DB_OPEN_OK`, `DB_OPEN_FAILED`, `DB_ORPHAN_WIPED`, `DB_MIGRATED`, `DB_MIGRATION_FAILED` with fields `{code, fromVersion, toVersion, platform}` only; emitted once T-021 exists, **nothing is logged until then**. No `print`/`debugPrint`/`stdout`/`stderr`/`dump` in `core/db` (extend the app-ci grep per S-5, scoped to `core/db`, `core/crypto`, `core/platform/pigeon_secret_store.dart`). Exceptions rethrown from the isolate keep only the code (`dbOpenExceptionOf` already unwraps `DriftRemoteException`); no file paths, no SQL in messages.

**8. FU-069 and the T-007 short-query item.** (a) `fts_benchmark_test.dart`: the hard gate becomes the real NFR (p95 < 200 ms, FR-TXN-01) on the host; the 50 ms figure stays as a printed soft warning; measurements use the median of 3 runs after one warm-up. (b) Short queries: add a harness variant with a small second FTS5 table, `tokenize='unicode61 remove_diacritics 2' prefix='1 2'`, over merchant and counterparty only (word-prefix match, `MATCH 'ab*'`), and record `short_prefix_ms` vs `like_short_ms` (host + emulator, as ADR-002 table). Result and a one-line DDL proposal are handed to T-017 (database-schema §2.2 gains the second table plus triggers). Search UI uses it for 1–2 char queries. No FTS table lands in T-016 (v1 has `db_meta` only).

**9. Test plan → AC.**
- **AC1 wrong key fails cleanly:** unit (host, real sqlite3mc): create with K1, reopen with K2 → `DB_KEY_REJECTED`, file bytes unchanged; opener turns it into `reportRejected` → `KeyInvalidated`; a BUSY/IOERR-style failure (injected) → `DB_UNAVAILABLE`, **no wipe** (spy wiper). Same on the db-platform legs (Android API 35 + 26, iOS simulator) through `integration_test/app_database_test.dart`, registered in the existing single `db_platform_test.dart` launch (a second launch hung twice).
- **AC2 header not `SQLite format 3`:** the first 16 bytes of `zaghlol.db` after create + inserts, and `.migrate.tmp`; sentinel scan of `-wal`/`-shm` with a positive control (plaintext control file), as T-007.
- **AC3 migration failure restores the copy:** §6 tests, host and device.
- **D-50 / lease:** wipe tests with `FakeSecretStore` + temp dirs: `KeyInvalidated(missing|unusable|rejectedBySqlite)` → all 12+ names gone, main last (recorded order), new key, new DB, `db_meta restore_notice_due=1`; a lease that lapses before step N stops at N-1 with the remaining files intact; before first create no file exists; two openers racing → one wipe. iOS seat key items still present after the wipe (device test, with a planted dummy item under the seat-key service).
- **Negative proofs** (throwaway branches, run IDs in `implementation-status.md`): (a) drop `ensureValid` → lease test red; (b) delete the main file first → order test red; (c) wipe on `DB_OPEN_FAILED` → no-wipe test red; (d) skip the pre-migration copy → AC3 red; (e) `logStatements: true` → existing test red.
- Also: Riverpod `ProviderContainer` test (override `secretStoreProvider`, `dbDirectoryProvider`); `flutter analyze`, format, no `double` (no money in v1); `strings`/RTL n/a (no UI).

**Rejected:** `VACUUM INTO` copy (§6); migrating from the headless engine (two writers racing a schema change); keeping a quarantine copy of an orphan (D-50); passphrase key (T-015 §1); holding the lease for the whole app session (blocks the headless engine).

**Open questions for the PO:** none blocking. FYI: DB directory is `files/db` (not `noBackupFilesDir`) and the pre-migration copy is a file copy; both documented above and are architecture-owned.

## Review follow-ups (added by Lead)
- From the T-165 design note: at startup, detect a DB that exists without its key (OEM transfer or leaked restore). Wipe it and start in first-launch state with the restore offer; never half-open it. Never store app data in `UserDefaults` or SharedPreferences in plaintext.
- From the T-165 security review F6: orphan detection must key on the key being unusable: the alias is missing, unwrap fails, or SQLCipher open fails with a key error. A wrapped-key blob being present does not mean the key is usable. On orphan, wipe the DB, spool, temp files and wrapped blobs. On iOS, never delete the D-62 seat keys.
