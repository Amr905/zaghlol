## Description
Compute `bodyHash = SHA-256(prefix ‖ 0x00 ‖ installId ‖ 0x00 ‖ JCS(body without "attestation"))`. Android: verify a Play Integrity **standard request** token whose `requestHash = b64u(bodyHash)` with the existing verifier (5-min freshness, replay guard, `PLAY_RECOGNIZED`, device/basic integrity per R-19). iOS: verify an App Attest assertion over `SHA-256("zaghlol-ask-attest-v1" ‖ 0x00 ‖ bodyHash)` (cat: its own prefix) with the install's registered key, counter strictly increasing, `attestationObject` on first use. Modes: `Fake` (Development/Testing; `{"type":"dev","proof": HMAC(testKey, bodyHash)}`), `ReportOnly` (Staging; verify, count failures by reason, never refuse), `Enforce` (Production always, regardless of setting).

## Acceptance criteria
1. Binding vectors reproduced byte-exactly for ask and cat.
2. Valid proofs pass; missing, stale (> 5 min), replayed, wrong-body and wrong-install proofs → `DEVICE_ATTESTATION_FAILED` in Enforce; counted-but-passed in ReportOnly.
3. Production with verifiers unconfigured → every LLM request `503 UPSTREAM_UNAVAILABLE`.
4. **Negative proof 1:** startup refuses `Fake` outside Development/Testing and `ReportOnly` outside Staging; in Production the configured mode is ignored and Enforce applies; no remote flag or config key can change the mode (test sets every `remote_config` and flag value).
5. **Negative proof 2:** a proof made for one body is rejected when any byte of the body (outside `attestation`) changes, and a valid proof used twice is rejected the second time.
6. Failure reasons are logged as fixed codes; tokens and assertions never logged.

## Notes for the builder
- The `dev` proof key lives only in test configuration; never in `appsettings.Production*.json`.
