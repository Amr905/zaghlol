## Description
Compute `bodyHash = SHA-256(prefix ‖ 0x00 ‖ installId ‖ 0x00 ‖ JCS(body without "attestation"))`. Android: verify a Play Integrity **standard request** token whose `requestHash = b64u(bodyHash)` with the existing verifier (5-min freshness, replay guard, `PLAY_RECOGNIZED`, device/basic integrity per R-19). iOS: verify an App Attest assertion over `SHA-256("zaghlol-ask-attest-v1" ‖ 0x00 ‖ bodyHash)` (cat: its own prefix) with the install's registered key, counter strictly increasing, `attestationObject` on first use. Modes: `Fake` (Development/Testing; `{"type":"dev","proof": HMAC(testKey, bodyHash)}`), `ReportOnly` (Staging; verify, count failures by reason, never refuse), `Enforce` (Production always, regardless of setting).

## Acceptance criteria
1. Binding vectors reproduced byte-exactly for ask and cat.
2. Valid proofs pass; missing, stale (> 5 min), replayed, wrong-body and wrong-install proofs → `DEVICE_ATTESTATION_FAILED` in Enforce; counted-but-passed in ReportOnly.
3. Production with verifiers unconfigured → every LLM request `503 UPSTREAM_UNAVAILABLE`.
4. **Negative proof 1:** startup refuses `Fake` outside Development/Testing and `ReportOnly` outside Staging; in Production the configured mode is ignored and Enforce applies; no remote flag or config key can change the mode (test sets every `remote_config` and flag value).
5. **Negative proof 2:** a proof made for one body is rejected when any byte of the body (outside `attestation`) changes, and a valid proof used twice is rejected the second time.
6. Failure reasons are logged as fixed codes; tokens and assertions never logged.

## Notes for the builder
- The `dev` proof key lives only in test configuration; never in `appsettings.Production*.json`.

## Design note (builder, Opus, 2026-11-26; written before the code)
**Placement.** Pure parts in `Zaghlol.Application/Llm/Attestation/`: `LlmAttestationMode` + `LlmAttestationSettings.Resolve` (the mode guard),
`LlmBinding` (prefixes, `bodyHash`, `clientDataHash`, JCS), `LlmAttestationProof` (closed parse of the `attestation` member) and
`LlmAttestationVerifier` (`ILlmAttestationVerifier`). Infrastructure `Llm/Attestation/`: `AddZaghlolLlmAttestation` (reads
`Llm:Attestation:*` once), readiness of the two store verifiers, the metric, and the startup check. One additive line in `Program.cs`.
The endpoints (T-349, categorise) call `VerifyAsync` and map the verdict; nothing here reads a header.

**Binding.** `bodyHash = SHA-256(prefix ‖ 0x00 ‖ installId "D" ‖ 0x00 ‖ JCS(root minus top-level "attestation"))`, prefix
`zaghlol-ask-v1` / `zaghlol-cat-v1`; `clientDataHash = SHA-256(clientDataPrefix ‖ 0x00 ‖ bodyHash)` with `zaghlol-ask-attest-v1` /
`zaghlol-cat-attest-v1`. JCS is computed from the same `JsonElement` the endpoint binds (parsed once, duplicates refused by the
caller), so the hashed and the processed body can't differ. Numbers: only integers with |n| ≤ 2^53 (written in plain decimal, `1.0`
→ `1`, `-0` → `0`, as RFC 8785 does); any other number, a lone surrogate or a non-object root gives no hash → `VALIDATION_FAILED`.

**Verification per proof.** `play_integrity` → existing `IPlayIntegrityVerifier.VerifyAsync(token, bodyHash)` (5-min freshness,
`replay_guard` row committed on its own, `PLAY_RECOGNIZED`, device or basic per R-19). `app_attest` → one `ISeatTransaction`
(App login): `RegisterAttestationAsync` when `attestationObject` is present, then `VerifyAssertionAsync` over `clientDataHash`; commit
only when verified (the raised counter is the replay guard; a refusal rolls back). `dev` → `base64url(HMAC-SHA256(devKey, bodyHash))`
compared in fixed time. The proof type must match the caller's platform (Android → Play, iOS → App Attest); a mismatch is `wrong_type`.

**Modes and the guard.** `Llm:Attestation:Mode` ∈ `Fake | ReportOnly | Enforce`, read **once** from `IConfiguration` at startup
(never from `remote_config`, flags or a header; the verifier has no dependency that could carry one). Unset → `Enforce`.
`Fake` only in Development/Testing, `ReportOnly` only in Staging, otherwise startup throws. `Llm:Attestation:DevProofKey`
(base64, ≥ 32 bytes) is refused at startup outside Development/Testing, required by `Fake`, and never used by another mode.
Production: `Resolve` returns `Enforce` without looking at anything else; the startup check also refuses a substituted verifier.
- `Enforce`: platform verifier not configured → `Unavailable` (503 `UPSTREAM_UNAVAILABLE`) before the proof is looked at, so with
  unconfigured verifiers every request is 503; missing/invalid/wrong type → `Refuse` (422 `DEVICE_ATTESTATION_FAILED`); verifier
  outage → `Unavailable`. `dev` proofs are always refused.
- `ReportOnly`: same checks, every non-ok result counted by reason and passed (never 422/503).
- `Fake`: only a valid `dev` proof passes; everything else is refused.
"Configured": Play = a credential source other than `None` and a package name; App Attest = a real Team ID (not the relaxed
placeholder) and a bundle ID.

**Logs and metrics.** One counter `zaghlol.llm.attestation` with fixed tags feature (`ask|cat`), mode, platform, outcome
(`pass|refuse|unavailable`), reason (`ok`, the `AttestationCodes` set, `missing`, `wrong_type`, `not_configured`, `unavailable`).
Logs carry the same codes only. Proof records override `ToString`; tokens are `Sensitive<string>`; no body, question or proof
reaches a logger.

**Accepted residuals.** App Attest has no time freshness (Apple's design; the counter is the replay guard). A request with the
same body re-sent with a fresh proof is allowed (quota idempotency by `requestId` is T-349's). A DB error during App Attest
propagates as an exception (500/503 by the endpoint), also in ReportOnly.

**Negative proofs run locally (guard broken → red, then restored):** (1) ReportOnly guard and the Production force disabled →
`ReportOnlyIsRefusedOutsideStaging` ×4 red (the startup check still refused ReportOnly in Production: defence in depth);
(2) JCS writes every string value as `""` → `AProofForOneBodyIsRefusedWhenAnyByteOfTheBodyChanges` and `…(kind: "wrong_body")` red;
(3) readiness check removed → `WithUnconfiguredVerifiersEveryRequestIsUnavailable` red.

**Self-check:** §1 n/a (no deletes; a refused App Attest rolls its transaction back). §2 replay: Play `replay_guard` row on its own
connection, App Attest counter under the row lock of the existing store; two uses tested. §3 closed proof parser with the OpenAPI
patterns, `UNKNOWN_FIELD` for extra members, lone surrogates and non-integer numbers give no hash; nothing echoed. §4 unknown
mode / forbidden mode / dev key outside Dev-Testing stop startup; Production forced Enforce + real-verifier check. §5 tokens as
`Sensitive<string>`, proof `ToString` names the type, logs and metric tags from fixed sets (sentinel test); dev key copied per call and
zeroed. §6 ask-llm §5 "As built", llm-categorise (cat clientData prefix, FU-400), platform-channels §4a, deployment, error-handling
updated. §7 map above; build, format and non-Docker tests green.

**For T-349 / categorise endpoint:** parse once (`AllowDuplicateProperties = false`), `LlmBinding.BodyHash` (null → 400),
`LlmAttestationProofParser.Parse` on the member if present (invalid → 400), else pass `null` (→ 422 `missing`), then
`ILlmAttestationVerifier.VerifyAsync`; map `Refuse` → 422 `DEVICE_ATTESTATION_FAILED`, `Unavailable` → 503 `UPSTREAM_UNAVAILABLE`
(neither counted). The OpenAPI still lists `attestation` as required; the endpoint task decides whether to relax it.
