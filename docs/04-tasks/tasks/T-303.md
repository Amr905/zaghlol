## Description
Accept up to 50 closed `llmCatFeedback` items only while the install's `llm_categorise` flag is on; re-check each with `ContributionPrivacy` and the category codes (`userCategory` may be `custom`); store `right` as confirmations and `wrong` as corrections with `install_hash` = the existing KMS-peppered contribution HMAC; duplicates per (merchant, install_hash) keep the first; `accepted.llmCatFeedback` = stored rows. ≥ 3 distinct-install corrections whose `ai_category` equals the cache row delete that cache row. Retention: confirmations 365 days or when resolved; corrections 90 days after `resolved_at` or 180 days after creation.

## Acceptance criteria
1. Right on «zawya coffee / dining» → one confirmation row with install hash; Wrong groceries → education → one open correction; `custom` stored as `custom` with no custom name anywhere.
2. Flag off → items ignored, `accepted.llmCatFeedback = 0`; invalid items dropped individually.
3. Three corrections from different installs delete the matching cache row; two do not.
4. **Negative proof 1:** after intake, a dump of both tables contains no install id, account id, IP or app version bytes (data check with marker ids).
5. **Negative proof 2:** a marker merchant in feedback is absent from logs, traces and metrics.
6. Purger tests for each retention rule.
