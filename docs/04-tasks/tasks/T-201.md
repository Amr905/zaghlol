## Description
Move signing, HMAC and envelope keys into a self-hosted OpenBao (free Vault fork) Transit engine so the API never holds private keys: `ecdsa-p256` keys for Sync/Entitlement signing (prehashed digest), `hmac` keys pinned to version 1 for Seat/Audit/InstallHashPepper, and `datakey` + decrypt for envelopes. OpenBao runs as a container on the same server with the built-in static-key auto-unseal; the unseal key is a root-only secret with an offline backup.

## Acceptance criteria
1. `Kms:Provider = OpenBao` implements `ISigningKeyProvider`, `IHmacProvider`, `IDataKeyProvider`; TLS to OpenBao; auth by AppRole or token file with least-privilege policies (API: sign/hmac/datakey on its keys only; worker: envelope only; no export, no key read of private material).
2. Integration tests against a real OpenBao (binary or container) cover sign/verify, JWK export equals the published key, HMAC stability across restarts, envelope round-trip, and timeouts / sealed-server errors (`503 UPSTREAM_UNAVAILABLE`).
3. Setup script creates the keys (non-exportable, no plaintext backup), mounts, policies and audit device; documented backup / restore and unseal-key custody.
4. Migration from T-200: HMAC and envelope keys imported once (BYOK) so existing hashes and envelopes stay valid; new signing kids rotated in with an app release pinning both.
5. Code + security reviews APPROVED.
