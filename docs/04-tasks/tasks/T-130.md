## Description
Server-side verify and acknowledge Android purchases, plus the live Play order-ID lookup used by support.

## Technical details
- **Verify (Android, §4.3):** product table lookup (`422 PURCHASE_WRONG_APP`); subscriptions → `purchases.subscriptionsv2.get`, lifetime → `purchases.productsv2.getproductpurchasev2` (v1 `products.get` not used); product ID returned by Play must match (`422 PURCHASE_TOKEN_INVALID`); `ACTIVE | IN_GRACE_PERIOD` or `PURCHASED` only (pending → `pending`, no Gold); `environment = sandbox` from `testPurchase` / `testPurchaseContext`; `obfuscatedExternalAccountId == HMAC(installId)` (verify only; `PURCHASE_NOT_OWNED`); upsert by token, recording `linked_purchase_token`; acknowledge via `purchases.subscriptions.acknowledge` / `purchases.products.acknowledge` with the Play-returned product ID; 15-min sweeper; alert at 48 h unacked; Polly resilience (`503 STORE_UNAVAILABLE` on open circuit).
- Exposes a `IStoreVerification` result consumed by T-132 (seat at verify, entitlement) and T-185 (restore re-verification without the install-binding check).
- **Ownership lookup for support (D-57, §5.3):** `IPlayOrderLookup.CheckAsync(orderId, purchase)`:
  - **First confirm** that Play Developer API `orders.get` is available to the app's developer account and returns `purchaseToken` (record the evidence in the task file). If yes: the order's `purchaseToken` must be the purchase's token or one in its `linkedPurchaseToken` chain, and its `state` not `CANCELED`, `REFUNDED` or `PENDING_REFUND`.
  - **Fallback (R4-7, R5-8)** if not: compare the order ID with `subscriptionsv2` **`lineItems[].latestSuccessfulOrderId`** of the purchase's token and of each token in the `linkedPurchaseToken` chain (subscriptions), or the `productsv2` order ID (lifetime), together with the purchase state. **The deprecated `latestOrderId` is never read.**
  - Outcomes `pass | fail | unavailable`. The order ID is a `[Sensitive]` value: held in memory for the call only, never stored, logged, traced or put in an exception message.
- **Play Integrity decoding is not here**: it moved to T-181.

## Acceptance criteria
- [ ] Forged or replayed token rejected; a token bound to another install's HMAC → `422 PURCHASE_NOT_OWNED`.
- [ ] Pending purchase grants nothing.
- [ ] Unacked purchase acked by the sweeper; a purchase unacked > 48 h raises the alert metric.
- [ ] Lifetime purchases use `productsv2.getproductpurchasev2` (WireMock asserts the v1 endpoint is never called).
- [ ] `orders.get` availability for the developer account is confirmed (or refuted) and the result recorded in this file before the ownership lookup is implemented.
- [ ] R5-8: the fallback matches on `lineItems[].latestSuccessfulOrderId` across the `linkedPurchaseToken` chain; a WireMock body that only carries `latestOrderId` with the user's order ID gives `fail` (test).
- [ ] Ownership lookup: refunded or cancelled order → `fail`; Play 5xx/timeout → `unavailable` (tests).
- [ ] D-57: a log/trace capture test shows the order ID appears nowhere, including in a Polly retry log and an exception path.
- [ ] FU-011: live response-vs-spec test for verify (Android).
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
