## Description
`LlmEligibility.check(CategorizeInput, merchantNorm, NameLexicon) → Eligible | Ineligible(reason enum)`: source is a business payment merchant field (expense or refund); not a transfer/ATM/cash/salary/income; no `person` counterparty; no identifiers (`hasPersonalDataMarks(minDigitRun: 6)`, phone shapes, IBAN, e-mail, URL, handles) after FR-PAR-04 folding; not person-like (honorifics stripped, 1–4 tokens all given names, no business word); length 2…64; not tried before (lookup injected).

## Acceptance criteria
1. Table test, ar + en: every "Not sent" item of FR-LCAT-05 is ineligible with the expected reason; "Dr Hany Clinic", «صيدلية الشفاء», "Koshary Abou Tarek" are eligible.
2. Arabic-Indic IBANs and phones, digit runs split by spaces/dashes, «حاج سيد», "Dr Mona" → ineligible; «محمود» alone → ineligible (accepted false negative).
3. **Negative proof 1:** property test over generated strings: no `Eligible` output would be rejected by the server's `ContributionPrivacy` rules (same rule cases as the backend; shared cases if they exist, else ported with a source note).
4. **Negative proof 2:** a transfer, ATM, salary or `person` counterparty is never eligible, whatever the merchant text (property test).
5. Reasons are an enum; nothing returns or logs the merchant text.

## Design note (builder)
`LlmEligibility.check(input, merchantNorm, lexicon, kind:, triedBefore:)` is a conjunction of refusals, fail closed: caller-stated `LlmPaymentKind` (only `businessPayment` passes), counterparty and event-category refusals, empty lexicon refuses all; then `looseFold` (masker fold, batch-90 M1-M3 variants) identifier checks (>=4 consecutive or >=6 total digits in any script, `@`, `+digit`, URL/domain, IBAN shape, ref words + digits) which are stricter than the server `ContributionPrivacy`; then person-like (honorific and no business word; or all tokens given names with connectors skipped, no business word). Lists are injected via `NameLexicon` (app loads assets). Residuals: digits spelled as words, look-alike letters as digits, misspelled/unlisted names, a name containing a business word.
