## Description
The only way the app talks to the backend, with the data boundary built in.

## Technical details
- DTOs generated from OpenAPI (no free-form maps; pinned generator version, FU-013); embedded public keys (current + next); verify `Zaghlol-Signature` over the exact body bytes; drop unsigned or invalid bodies of signed operations; error mapping to Failures, unknown problem codes by HTTP status class.
- Tokens in `secure_state`; `rotateInstallToken` honoured.
- **Lazy `POST /v1/installs`** (first sync or first purchase): install ID UUID v4 from a CSPRNG; on `409 INSTALL_EXISTS` regenerate the ID; a retry after a lost response reuses the same `Idempotency-Key` and body bytes (gets a fresh token, R3-6).
- **`Idempotency-Key`** for verify, installs and sign-in: ULID whose 80 random bits come from `Random.secure()`; never reused for a different request; never logged (R3-6).
- **Re-registration (R5-1, §6):** on `401 INSTALL_TOKEN_INVALID`, delete the cached entitlement token and the account token **before** registering a new install ID; emit an `InstallReregistered` event (consumed by T-144 trusted state and the T-179 "own seat key unusable" flag). Local data is kept.
- **Anchoring hook (R4-2):** the six anchoring operations take a `timeNonce` argument supplied by T-144's time-anchor service and send it as `Zaghlol-Time-Nonce`; the client never invents one.
- `seatKeys` members exist only on the iOS request types; the Android build cannot serialize them (compile-time or test).
- Recording client hook for privacy tests (debug only).

## Acceptance criteria
- [ ] Unsigned or tampered response rejected.
- [ ] Only allow-listed fields can be serialized.
- [ ] R3-6: `Idempotency-Key` values come from `Random.secure()` (test with an injected RNG) and never appear in the diag log (test).
- [ ] R5-1: on `INSTALL_TOKEN_INVALID` the entitlement and account tokens are deleted before the new `POST /v1/installs` is sent (ordered fake-server test), and `InstallReregistered` fires.
- [ ] `409 INSTALL_EXISTS` → new install ID; lost 201 → retry with the same key and body (tests).
- [ ] An anchoring call without a `timeNonce` from the time-anchor service fails fast in debug (assert) (test).
- [ ] FU-013: generator version pinned.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
