## Description
Gold works offline for days, can't be faked by editing files or setting the clock back, and can't be borrowed from another install's signed token.

## Technical details
- **Token verification:** ES256 against embedded keys; cache in `secure_state`; feeds `EntitlementState` (T-119), extended with `moved(movedBy)`, `paused`, `tampered` ("connect to check Gold"), `grace`, `pendingVerification`.
- **Install binding (R5-1):** honour an entitlement token only if `sub` == this install's current install ID (exact string), and an account token only if `iid` == it. A token with `acct` set is honoured only while an unexpired account token that itself passes the `iid` check has `sub == acct`. A failing token is **ignored**: not cached, grants nothing, doesn't replace or clear the cached token, and its body never re-anchors trusted time; only the local diag counter `entitlement_sub_mismatch` / `account_iid_mismatch` increments (no message, no log of tokens or IDs).
- **Re-registration (R5-1):** on T-141's `InstallReregistered`, the cached entitlement and account tokens are already gone; this service drops any in-memory copies too.
- **Decision:** Gold only for a verified, install-bound token with `status ∈ {active, grace}`, not `tampered`, and `hw < graceUntil`; `grace` shown from `hw ≥ exp`.
- **Trusted time (R3-1, R4-3; contract backend-api §4.3):** state `{hw, lb, mono, boot, lastServerTime, tampered}` in `secure_state`; clock samples from `TrustedClockHostApi` (T-180); advance at start, resume, every 60 s in foreground, in background tasks and before every Gold check; interval classes (same boot; reboot proven; iOS boot-reference shift with `m ≥ mono` charged `max(m − mono, 6 h)`); tamper test on the **uncharged** `lb` (`w < lb + lower − 10 min`); the 6 h reboot charge goes to `hw` only.
- **Time anchor (R4-2):** one service serializes the six anchoring requests; draws a 128-bit nonce with `Random.secure()`, keeps `pending = {nonce, sentMono, sentBoot}` in memory only (one outstanding; a new request replaces it), passes it to T-141. **Fresh echo** (every token in the body passes the R5-1 binding, `timeNonce == pending.nonce`, same boot, ≤ 60 s by the monotonic clock) → `hw = lb = S`, clear `tampered`, clear `pending`. **Any other signed body** → raise only (`hw = max(hw, S, iat)`, `lb = max(lb, S, iat)`). Unsigned bodies never touch the state. A token whose `iat` is > 10 min ahead of `hw` after anchoring is not trusted. The nonce is never logged or persisted.
- **Refresh (FR-GOLD-04):** `GET /v1/entitlement` whenever online and the cached token is ≥ 12 h old.
- **Sign-out:** delete the cached entitlement token at once, whether or not the call succeeds; store the fresh token the sign-out 200 returns (after the binding check).
- **`supportNotice` (R4-7(2), R5-7):** when a response is stored, write the notice to `secure_state`; delete it only after the user dismisses it; ignore a repeat of a notice already shown or dismissed. The message itself is rendered by T-146.

## Acceptance criteria
- [ ] Airplane mode for 5 days keeps Gold (with one reboot).
- [ ] An edited token falls back to Free.
- [ ] **R5-1 "a validly signed token for another install grants nothing":** a correctly signed `GET /v1/entitlement` body and a sync body with `status: active`, a future `exp` and `sub` = another install ID, delivered **with this app's own fresh nonce echo**: no Gold, the cached token is unchanged, `hw`/`lb` only raised (no re-anchor), `tampered` not cleared, `entitlement_sub_mismatch` incremented.
- [ ] **R5-1 "an account token with a foreign `iid` is not honoured":** a signed sign-in or sync body whose `accountToken` has `iid` ≠ this install, with an entitlement token whose `acct` equals that token's `sub`: the account token isn't stored, the `acct` purchase isn't granted, no re-anchor, `account_iid_mismatch` incremented.
- [ ] **R5-1 re-registration:** after `INSTALL_TOKEN_INVALID`, the old-install token is gone and a replayed old-`sub` body grants nothing.
- [ ] R3-1/R4-3 unit tests on fake clocks and a fake signer, one per bullet of backend-api §4.3 *Required unit tests*: rollback while offline (withheld; recovered by a fresh echo); backward NTP < 10 min (no effect); forward jump then honest correction; reboot on Android (`BOOT_COUNT` change) and iOS (`m < mono`) with the 6 h minimum charge to `hw`; **honest quick offline reboot** (not tampered, `hw` charged 6 h, `lb ≈ w`, still not tampered on every following 60 s advance); **iOS wall correction without reboot** (charge `max(m − mono, 6 h)`, tamper decided against `lb + (m − mono)`); long offline with the clock untouched (Gold until exactly `graceUntil`); old signed response replayed (doesn't lower `hw`); unsigned response ignored; 12 h refresh boundary; 5-day holder guarantee with one reboot.
- [ ] R4-2 unit tests: another install's signed sync/throttle body with a larger `S` below `hw` and a nonce never sent (no lowering, `tampered` kept); a withheld older response (own earlier nonce, delivered after a newer request or after 60 s: raise only); a fresh echo used twice (second time raise only); an `Idempotency-Key` replay echoing an older nonce (raise only).
- [ ] R4-2: the nonce is drawn from `Random.secure()` (injected RNG test), at most one is outstanding, and it never appears in the diag log or `secure_state`.
- [ ] D-61(c): sign-out drops the cached token immediately even when the network call fails; account-linked Gold shows `paused`.
- [ ] `moved` with `movedBy: user | support` and `paused` map to the matching `EntitlementState` values (test).
- [ ] R5-7: `supportNotice` survives an app kill between storing the response and display; a repeated notice after dismissal is ignored (test).
- [ ] Residual 3 of the security review (undetected iOS reboot) is documented in the design note and not "fixed" by extra heuristics.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
