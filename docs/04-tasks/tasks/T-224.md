## Scope
T-220 made the native launch screen follow the system theme. When the user picked a theme in the app that differs from the system, the launch frame still shows the system's colour for a moment. Store the user's theme choice (light/dark/system only, not sensitive) where native code can read it before Flutter starts (Android: a tiny non-backup SharedPreferences file or the app's existing native prefs; iOS: UserDefaults in the app container, excluded from backup per T-165), and apply it before the first frame (Android: set the window background / `AppCompatDelegate` night mode or the splash theme in `MainActivity.onCreate` before `super`; Android 12+: `SplashScreen` theme via `setSplashScreenTheme` where available; iOS: set the window's `overrideUserInterfaceStyle` in `AppDelegate` so the LaunchScreen colorset resolves accordingly, if possible, otherwise the root view background). Flutter writes the value whenever the theme setting changes.
## Acceptance criteria
1. In-app dark on a light phone (and the reverse): no frame in the other theme's colour at cold start, as far as the OS allows (say precisely what remains, e.g. the OS-drawn Android 12 splash icon background).
2. Only the theme choice crosses to native storage; it is excluded from OS backups like other app data (T-165).
3. Kotlin unit test or Robolectric where the repo has them; Dart test for the write; iOS change built on GitHub (push the same commit to `ci/T-224`, report the run).
4. `dart analyze`, `dart format`, touched tests green.

## Evidence (BUILT)
1. Android: `MainActivity.attachBaseContext` wraps the context with the stored choice (`LaunchTheme.wrap`, forces the uiMode night bits), so the theme, launch drawable and `values-night*` resources resolve in the chosen theme before the first frame. iOS: `SceneDelegate` sets `window.overrideUserInterfaceStyle` on scene connect. Remaining: the iOS system-drawn launch screen and the Android 12+ OS-drawn splash (window background and icon background, chosen by the system from its own theme before app code runs, and on a process start where the OS ignores the activity context) can still show the system theme; the first activity frame and everything after follow the choice. Needs a phone.
2. Only `light`/`dark`/`system` is accepted (Kotlin and Swift reject anything else). Android file in `noBackupFilesDir` (all domains excluded by T-165 rules); iOS file in Application Support (directory excluded by T-165; no UserDefaults per the T-165 policy).
3. `LaunchThemeTest.kt` (round trip, rejects other values, garbage reads as system); `app/test/core/platform/launch_theme_test.dart` (write values, no throw); iOS built via `ci/T-224`. Dart: `lib/core/platform/launch_theme.dart`, written from `main.dart` whenever the theme changes. No new settings key. No XCTest added (no test target change; logic kept in `SceneDelegate.swift` to avoid editing the pbxproj).
4. `dart format` and the touched tests green.
