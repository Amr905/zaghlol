## Description
Monitoring per error-handling §4, and the logging rules that keep tokens, proofs, order IDs, seat keys and time nonces out of every log and trace.

## Technical details
- OTel traces/metrics; custom metrics (verify outcomes, unacked count, notification lag, price age, sync size; seat moves and rebinds by channel; `MOVE_COOLDOWN` refusals; support moves, detaches, unfreezes and ownership-check outcomes per purchase and per operator; attestation failures by reason code; Play Integrity quota use).
- **Alert rules as code** (error-handling §4, backend-api §4.3/§5.3), each carrying the purchase UUID only: `MOVE_COOLDOWN` spike; > 2 support moves / purchase / 90 d; > 20 support actions / operator / day; > 5 failed ownership checks / operator / day; any `dispute_frozen` refusal; any `support_unfreeze` call; `seat_rebind` (over-cap rebind); attestation-failure spike; Play Integrity quota > 50 %; unacked > 48 h; notification lag/dead-letter; price age; snapshot 404; sync size.
- **Logging rules (§3.2):** structured fields `ts, level, msg, traceId, route, status, durationMs, installHash, code` (FU-002); never log bodies, tokens, ID tokens, purchase tokens (only `sha256[:8]`), Play Integrity tokens or verdicts, App Attest assertions/objects/key IDs, **`seatKeys`** (D-62), **order IDs** (`[Sensitive]` redaction even from exceptions, D-57), **`Zaghlol-Time-Nonce` / `timeNonce`** (R4-2), **`Idempotency-Key`**, e-mails, full IPs; route templates only; query strings and `Location` headers never logged; framework categories at `Warning` or filtered; outbound URL templates (`…/tokens/{token}`).
- Dashboards: service overview, purchases/entitlements/seats, catalog & prices. Synthetic check definitions.

## Design note
### Design note (solution-architect, 2026-11-06)

**Approach: allow-list everything that leaves the process.** Deny-lists miss new fields. So logs and spans are emitted through allow-listing components, and sentinel tests prove nothing else gets out. Code lives in `Zaghlol.Infrastructure/Observability` and is shared by the API and the workers.

**OTel setup.**
- **Packages:** `OpenTelemetry.Extensions.Hosting`, `OpenTelemetry.Exporter.OpenTelemetryProtocol`, `OpenTelemetry.Instrumentation.AspNetCore`, `OpenTelemetry.Instrumentation.Http` and `OpenTelemetry.Instrumentation.Runtime`. Pin the latest stable 1.x, ≥ 1.13 (net10.0 targets).
- **Test-only:** `OpenTelemetry.Exporter.InMemory`.
- **Not used:** Serilog OTLP sink and `Npgsql.OpenTelemetry`. For DB spans, `AddSource("Npgsql")` is enough because Npgsql 10 has a built-in ActivitySource.
- **Resource:** `service.name` = `zaghlol-api` | `zaghlol-worker`, `service.version`, `deployment.environment.name`. OTLP endpoint from `OTEL_EXPORTER_OTLP_ENDPOINT`.
- **Traces:**
  - `ParentBased(TraceIdRatio(0.1))` in production and 1.0 elsewhere. "100 % on errors" means tail sampling in the collector (`tail_sampling` policy on `status_code = ERROR`), so the app exports at 1.0 to the collector in prod and the collector keeps 10 % plus errors.
  - `RecordException = false` on every instrumentation. `/v1/health` is filtered out.
- **Span redaction** (`RedactingActivityProcessor`, registered **before** the exporter):
  - On `OnEnd` it removes every tag not on `SpanTagAllowList`: `http.request.method`, `http.response.status_code`, `http.route`, `url.scheme`, `url.template`, `server.address`, `server.port`, `network.protocol.version`, `db.system`, `db.operation.name`, `db.query.text` (parameterized SQL only), `error.type`, `otel.status_code`, and `zaghlol.*` keys from a fixed list.
  - It drops `url.full`, `url.path`, `url.query`, `http.url` and `http.target`, sets `url.path` := `http.route` on server spans, and nulls `StatusDescription`.
  - **Outbound spans:** callers tag each request with an explicit template, `request.SetUrlTemplate("/androidpublisher/v3/applications/{packageName}/purchases/subscriptionsv2/tokens/{token}")`. There is no regex guessing; without a template the value is `unknown`. This covers Play `…/tokens/{token}` and `orders/{orderId}`, App Store `transactions/{id}` and `lookup/{orderId}`.
- **Metrics:** ASP.NET Core and HttpClient built-in meters (route and host tags only), runtime, plus the `Zaghlol` meter below. Exported over OTLP.

**FU-002 decision: keep Serilog, with an in-house `ZaghlolJsonFormatter` that writes the doc's names.**
- **Output:** one JSON object per line with `ts` (RFC 3339 UTC, ms, `Z`), `level` (`debug|info|warn|error|fatal`), `msg`, `traceId`, `spanId`, `service`, `category`, then only allow-listed properties: `route`, `method`, `status`, `durationMs`, `installHash`, `code`, `reason`, `operation`, `channel`, `outcome`, `tokenHash8`, `count`, `rule`, `purchaseId` (only on `audit_alert` events), `operatorId`, `errorType`, `stack`.
- **Every allow-listed field also has a value shape:**
  - `code`: `^[A-Z_]{1,40}$`
  - `reason`, `outcome`, `channel`, `operation`: `^[a-z_:]{1,40}$`
  - `installHash`: 16 hex characters
  - `purchaseId`, `operatorId`: UUID
  - `tokenHash8`: 16 hex characters
  - numbers stay numeric
  A value that fails its shape is replaced by `"<invalid>"`. This way a field name can't smuggle out an Apple auth `code` or a token.
- **`msg` is the message template**, not the rendered text. Values appear only in their own allow-listed fields, so a value logged by mistake through a placeholder can never reach the output.
- **Exceptions:**
  - `errorType` (the chain of type names) and `stack` (`StackTrace` frames only) are always written.
  - The **message** is written only for `SafeException` subclasses, whose messages are constants. This keeps order IDs, URIs and Npgsql text out (D-57).
- **Never-logged inputs:**
  - Npgsql `Include Error Detail` is never set: a startup check fails if the connection string contains it.
  - EF `EnableSensitiveDataLogging` is never called.
- **Why not the alternatives:**
  - **(b) Serilog.Expressions templates:** an extra dependency, and still a deny-by-default problem for properties.
  - **(c) MS JSON console logger:** fixed `Timestamp`/`LogLevel` names.
  - **(d) Changing the doc to `@t`/`@m`:** the doc names are what dashboards and queries use.
  - Owning the formatter gives the names **and** the allow-list in about 80 lines.
- **Pipeline:** stdout → platform log agent / OTel collector → log store. `error-handling-and-observability.md` §3.2 is edited in this commit to say so.
- **Request logging:** replace `UseSerilogRequestLogging()`, which logs the raw `RequestPath`, with a small `RequestLogMiddleware`. It writes one `request completed` event with `method`, `route` (the endpoint's `RoutePattern.RawText`, or `unmatched`), `status`, `durationMs`, `code` (from the problem body via `HttpContext.Items`) and `installHash`.
- **`installHash`** = first 8 bytes, hex, of HMAC-SHA256 under a **log key**, set by the install auth handler (T-124) through `LogContext`. The log key is derived once a month in memory as `IKeyedHasher.HmacSha256Async(InstallHashPepper, "zaghlol-log-v1" ‖ 0x00 ‖ yyyy-MM)` (T-123). That avoids a KMS call per log line, can't be joined to `merchant_contributions.install_hash`, and rotates monthly. The doc edit says so.
  - **Wiring order:** T-138 ships `ILogPseudonymizer` with a dev key source. Whichever of T-123 / T-138 merges second wires the KMS-derived source.

**Never-log controls beyond the formatter.**
- **Levels:** `Microsoft.AspNetCore.*`, `Microsoft.EntityFrameworkCore.*`, `System.Net.Http.*`, `Polly` and `Microsoft.Extensions.Http.Resilience` are at `Warning` in every environment, including Development (the tests run in `Production`).
- **No header logging:** no `AddHttpLogging` / `UseHttpLogging` at all; a test asserts the HttpLogging middleware is absent from the pipeline. AspNetCore instrumentation captures no headers (no `EnrichWithHttpRequest` touching headers).
- **Sensitive DTO members:** request DTO members that carry secrets (`orderId`, `seatKeys`, `purchaseToken`, `signedTransaction(s)`, `idToken`, `nonce`, `attestation`, `assertion`, `code`, `refreshToken`) use `Sensitive<T>`, a readonly struct in Domain whose `ToString()` returns `***` and which has a JSON converter. This defeats record `ToString()` and `{@Dto}` destructuring.
  - A reflection test over the API assembly fails if any DTO property with one of those names isn't `Sensitive<…>`. It passes trivially until T-124+ add DTOs; they must comply.
- **Time nonce:** `Zaghlol-Time-Nonce` stays in `ITimeNonceFeature` only (T-123). `Idempotency-Key` is read only by the idempotency filter, which logs `operation` and the outcome, never the key.

**Sentinel test harness (CI).**
- Built on `WebApplicationFactory` in `Production` with real levels:
  - the real formatter writing to an in-memory `TextWriter` sink (the test checks **final bytes**, not `LogEvent`s);
  - an `InMemoryExporter<Activity>` after the redacting processor;
  - a capturing exporter for metrics (check tag values too).
- Test-only endpoints come from an `IStartupFilter`, as in the existing `FaultInjectionStartupFilter`.
- **Placements of a random sentinel per run:**
  - the query string;
  - a path key (`/test/items/{key}`);
  - an outbound call through the `google-play` named client with a fake primary handler to `…/subscriptionsv2/tokens/<s>` and `…/orders/<s>`, with a forced retry so the resilience handler logs;
  - a `303` with `Location: …?code=<s>`;
  - the `Zaghlol-Time-Nonce` and `Idempotency-Key` headers;
  - a body with `seatKeys`/`ownershipCheck.orderId` = `<s>`;
  - an exception whose message contains `<s>` (plain exception type);
  - a Npgsql unique violation whose key value is `<s>` (Testcontainers, once T-122's tables exist; until then, a temp table).
- **Assertion:** `<s>` occurs in no log bytes, no span (name, tags, events, status) and no metric tag.

**Metrics (`Zaghlol` meter; low-cardinality tags only, never IDs).**
- **Purchases:** `zaghlol.purchase.verify` {store, outcome, code}; `zaghlol.purchase.unacked` (gauge; count, oldest age s); `zaghlol.purchase.time_to_ack` (histogram).
- **Store notifications:** `zaghlol.notification.processing_lag` (histogram), `zaghlol.notification.dead_letter`, `zaghlol.notification.ingested` {store}.
- **Prices and sync:** `zaghlol.price.age` (gauge {symbol}); `zaghlol.sync.response.bytes` (histogram {up_to_date}).
- **Seats:** `zaghlol.seat.change` {channel, kind=bind|move|rebind|rebind_over_cap}; `zaghlol.seat.move_cooldown_refused` {channel}.
- **Support and attestation:** `zaghlol.support.action` {action, outcome, ownership_outcome}; `zaghlol.attestation.failure` {platform, reason}.
- **Play Integrity quota:** `zaghlol.play_integrity.calls` and `zaghlol.play_integrity.daily_quota` (config gauge).
- **Signing:** `zaghlol.signing.failure` {reason} (T-123).
- **Alerts:** `zaghlol.audit_alert.fired` {rule}.
- **Ownership:** T-138 ships the instruments as one `ZaghlolMetrics` class; the owning tasks call them.
- **Per-purchase and per-operator alerts can't be metric labels** (cardinality, and 90-day windows). The acting task evaluates them inside its own transaction (T-186: support counts; T-184: over-cap rebind) and calls `IAlertSignal.Raise(rule, purchaseId?, operatorId?)`. That increments `audit_alert.fired{rule}` and writes one `warn` `audit_alert` event carrying `rule` and `purchaseId` (or `operatorId` for per-operator rules). The alert links to that log query.

**Alert rules as code** live in `backend/deploy/observability/alerts/*.yaml`, in Prometheus rule format (accepted by the managed Prometheus offerings of every candidate provider), with dashboards as Grafana JSON in `…/dashboards/`; T-140 adapts both if the provider needs to. Rules:
- **Availability and SLO:** synthetic failures ×3; burn rate 2 %/1 h, 5 %/6 h; p95 sync > 300 ms and verify > 2 s for 15 min.
- **Purchases:** unacked oldest > 48 h; verify failure rate > 5 %.
- **Notifications:** lag > 15 min; any dead-letter.
- **Prices:** age > 6 h warn, > 24 h page.
- **Catalog:** snapshot 404 (synthetic).
- **Sync size:** p95 > 2 KB for up-to-date clients.
- **Seats:** `MOVE_COOLDOWN` spike (rate > 3× the 7-day baseline).
- **Attestation:** failure spike by reason; Play Integrity calls / quota > 0.5.
- **`audit_alert.fired`** for each `rule` ∈ {`support_moves_per_purchase_90d`, `support_actions_per_operator_day`, `ownership_failures_per_operator_day`, `dispute_frozen_refusal`, `support_unfreeze`, `seat_rebind_over_cap`}.
- **Signing failures; security** (401/403 spike, `RATE_LIMITED` spike); **capacity** > 80 %.
- Synthetic checks (`…/synthetics.yaml`): `GET /v1/health` and `POST /v1/sync` with the test install, every minute from 2 regions; the latest catalog snapshot URL.

**Lint test (CI):**
- Parse the rule files and run `promtool check rules` in a pinned `prom/prometheus` image.
- Assert that no label, annotation or expression contains `install|account|token|transaction|order|email|ip|nonce|seat_key`, other than the documented `purchaseId`/`operatorId` mentions in runbook text.
- Assert that every alert in the T-138 list exists (one name per row).

**Doc edit.** `error-handling-and-observability.md` §3.2 and §4 get:
- the formatter, the field allow-list and the stdout pipeline;
- the `installHash` derivation;
- the explicit never-log rows for `seatKeys`, order IDs, `Zaghlol-Time-Nonce`/`timeNonce` and `Idempotency-Key`;
- per-operator alerts carrying the operator UUID (staff, not user data);
- tail sampling for "100 % on errors".

**CI can test:**
- Formatter golden output and FU-002 names.
- All sentinel cases.
- Span tag allow-list.
- Metric emission (`MeterListener`).
- Rule lint and `promtool`.
- A compose smoke: an `otel-collector` (contrib image, pinned) service with the `debug` and `prometheus` exporters; CI curls `:8889/metrics` for `zaghlol_` series. This proves "metrics visible in the local collector".

**CI cannot test (manual or T-140 checklist):**
- Alert delivery and paging.
- Provider-side dashboards rendering.
- Multi-region synthetics.
- Edge/WAF/CDN query and body logging.
- IP truncation in the provider's log store and 30-day retention (T-139/T-140).
- Prod tail-sampling behaviour.

**Rejected alternatives.**
- Deny-list scrubbing enrichers.
- Regex URL templating.
- Per-purchase metric labels.
- A separate alert-evaluator job polling `audit_log`: it would add latency and a second implementation of thresholds that the acting tasks already compute.
