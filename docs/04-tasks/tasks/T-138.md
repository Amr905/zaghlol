## Description
Monitoring per error-handling §4, and the logging rules that keep tokens, proofs, order IDs, seat keys and time nonces out of every log and trace.

## Technical details
- OTel traces/metrics; custom metrics (verify outcomes, unacked count, notification lag, price age, sync size; seat moves and rebinds by channel; `MOVE_COOLDOWN` refusals; support moves, detaches, unfreezes and ownership-check outcomes per purchase and per operator; attestation failures by reason code; Play Integrity quota use).
- **Alert rules as code** (error-handling §4, backend-api §4.3/§5.3), each carrying the purchase UUID only: `MOVE_COOLDOWN` spike; > 2 support moves / purchase / 90 d; > 20 support actions / operator / day; > 5 failed ownership checks / operator / day; any `dispute_frozen` refusal; any `support_unfreeze` call; `seat_rebind` (over-cap rebind); attestation-failure spike; Play Integrity quota > 50 %; unacked > 48 h; notification lag/dead-letter; price age; snapshot 404; sync size.
- **Logging rules (§3.2):** structured fields `ts, level, msg, traceId, route, status, durationMs, installHash, code` (FU-002); never log bodies, tokens, ID tokens, purchase tokens (only `sha256[:8]`), Play Integrity tokens or verdicts, App Attest assertions/objects/key IDs, **`seatKeys`** (D-62), **order IDs** (`[Sensitive]` redaction even from exceptions, D-57), **`Zaghlol-Time-Nonce` / `timeNonce`** (R4-2), **`Idempotency-Key`**, e-mails, full IPs; route templates only; query strings and `Location` headers never logged; framework categories at `Warning` or filtered; outbound URL templates (`…/tokens/{token}`).
- Dashboards: service overview, purchases/entitlements/seats, catalog & prices. Synthetic check definitions.

## Acceptance criteria
- [ ] Metrics visible in the local collector.
- [ ] Alert rules reviewed; every alert listed above exists as code and carries no install ID, account ID, token or transaction ID (rule-file lint test).
- [ ] Sentinel test (§3.2): a sentinel in the query, in a path key, in an outbound Play URL (fake handler) and in the Apple callback's `Location` appears in no log, span or HTTP-logging output at production levels.
- [ ] Sentinel test extension: sentinel values in `seatKeys`, an `ownershipCheck` order ID, the `Zaghlol-Time-Nonce` header and the `Idempotency-Key` header appear in no log, span or exception output.
- [ ] FU-002: log field names match §3.2.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
