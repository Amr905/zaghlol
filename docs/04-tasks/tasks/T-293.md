## Dart API (fixed so the other tasks can call it now)
In `app/lib/core/ui/z_haptics.dart` add:
```dart
enum ZHapticPattern { payday, saved, oops, birdTap }
static Future<void> play(ZHapticPattern pattern) // no-op when disabled
static List<int> timelineMs(ZHapticPattern p)     // hit offsets in ms, for syncing animation beats
```
- **payday** (≈1.6 s, matches the coin rain + bird pop): a rising run of light ticks as coins land (e.g. 0, 140, 260, 360, 450 ms) then one strong "thud" at the bird's pop (~700 ms) and a soft double tap at the end (~1300/1420 ms).
- **saved**: crisp double tap (success), ~0/90 ms.
- **oops**: short low buzz, two pulses.
- **birdTap**: one light tick.
Keep the exact numbers in one table in the task file and `docs/02-design/08-mascot-motion-and-bank-logos.md` (new "Haptics" subsection).

## Native
- **Android** (Kotlin, platform channel `app.zaghlol/haptics`): `VibrationEffect.Composition` primitives (TICK, CLICK, THUD) on API 30+ when `areAllPrimitivesSupported`; else `createWaveform` with amplitudes when `hasAmplitudeControl`; else fall back to Flutter `HapticFeedback` calls on the Dart side. VIBRATE permission if not already declared. Never vibrate when the system "touch feedback"/haptics is off where readable.
- **iOS** (Swift): `CHHapticEngine` pattern (transient events with intensity/sharpness) when `supportsHaptics`; else `UIImpactFeedbackGenerator` steps. Engine started lazily and stopped on background.
- Respect `ZHaptics.enabled` (app setting) and reduce motion (only one light tick then).

## Design note (builder)
- **One table, in Dart.** `ZHaptics` holds the beats (offset ms, strength tick/click/thud, intensity 1-100). `play` sends them as `{hits: [[ms, strength, pct], ...]}` over plain `MethodChannel('app.zaghlol/haptics')`; native only translates and plays. No second copy of the numbers in Kotlin or Swift, so animation and native cannot drift.
- **Reply contract.** `true` = played (or, on Android, the user switched system touch feedback off, so nothing is owed); `false` or a missing plugin or a `PlatformException` = Dart plays the same beats with `HapticFeedback` (tick = light, click = medium, thud = heavy) on a timer. `play` never throws.
- **Reduce motion.** The `reduceMotion:` argument, else the app toggle `ZHaptics.reduceMotion` or the OS `disableAnimations` flag: one light tick through `HapticFeedback`, nothing native. Callers that already hold `reduceMotionProvider` can pass it; a static flag keeps callers free of `ref`.
- **Android.** `HapticsPlan` is pure (parse, primitives, waveform) and unit-tested. API 30+ with TICK, CLICK and THUD all supported: `Composition`; else amplitude control: `createWaveform`; else `false`. `VIBRATE` is a normal permission (no prompt, no data), so the permission list test is updated. Registered in the UI engine only.
- **iOS.** `HapticsHost`: `CHHapticEngine` with transient events (intensity = pct, sharpness by strength) when `supportsHaptics`, else `UIImpactFeedbackGenerator` steps on a timer. Engine created lazily, auto shutdown on, dropped on `didEnterBackground`. No entitlement or Info.plist change (CoreHaptics needs none).
- **Privacy.** Only beats cross the channel. Nothing is logged.

## Builder assumptions
- The Dart API is exactly as listed above; `play` has one extra optional named argument `reduceMotion` (non-breaking), and `ZHaptics.reduceMotion` / `ZHaptics.hits` / `ZHaptics.channel` are additions. The existing `ZHaptics.enabled` is the app setting; no settings screen wiring was in scope.
- The Android "touch feedback off" check reads `Settings.System.HAPTIC_FEEDBACK_ENABLED`; unreadable counts as on.
- No XCTest for `HapticsHost.parse` (adding a test target file means more pbxproj surgery with no Xcode here); the Android pure builder has the unit test and the Dart side has the channel tests.

## Device feel check (owed to the PO)
1. Android phone with a good haptic motor (Pixel or Samsung flagship, API 30+): trigger payday, saved, oops, bird tap from the T-294/T-295 screens. Payday should feel like a rising rain of ticks, one clear thud at the bird pop, then two soft taps.
2. Android older or cheap phone (no primitives or no amplitude control): same patterns should still buzz in a plausible rhythm (fallback).
3. Android Settings > Sound > Touch feedback off: no vibration at all.
4. iPhone 8 or newer: same four patterns; check the thud lands with the bird pop. iPhone without CoreHaptics (SE 1st gen): impact steps.
5. App haptics setting off: silent. Reduce motion on (OS or app toggle): one light tick only.
6. Tell us which beat offsets feel early or late; they are one table in `z_haptics.dart`.
