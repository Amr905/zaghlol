## Design note (builder)
**FU-332.** `ShareJob.abandonCommit` is a second watchdog that applies only while a commit is in progress and no outcome is set; `ShareActivity` starts it (`ShareLimits.COMMIT_TIMEOUT_MS`, 20 s) from the `mayCommit` hook, when `beginCommit()` succeeds, and cancels it when the worker finishes. It sets the existing `Rejected(UNREADABLE)` outcome ("couldn't save") and records it for Dart like `giveUp`. If the stalled commit lands later, `complete` already refuses (first outcome wins), so nothing is shown twice, and `ShareJobs.finish(..., discardLate = store::discard)` removes the share it stored, so Dart's pending list does not show a second item either.

**FU-113 native to `diag_log` bridge: left OPEN.** It needs a new contract: a Pigeon `FlutterApi` (or a host `drainNativeDiagCodes(): List<String>`) in `pigeons/`, regenerated Kotlin and Swift, a durable native buffer (codes and counts only; extensions and receivers run with no engine, so a push channel is not enough), and a Dart drain at start/resume into `DiagLogger` with codes checked against `DiagCodes.all`. That touches the contract doc and three generated files that cannot be compiled here, so it is not half-built. Proposed shape: `NativeDiagHostApi.drain() -> List<NativeDiagEntry{code: String, count: int}>`; Android buffer next to `SmsDiagStore` in `noBackupFilesDir`, iOS buffer in the App Group via `NativeDiagHook.handler`; unknown codes dropped in Dart. Done now: the Swift `NativeDiagHook.handler` is lock-guarded (review item 21-5).

## Builder assumptions
- "Couldn't save" outcome = the existing `Rejected(UNREADABLE)`; no new reject reason (would change the Pigeon enum).
- Commit bound is 20 s from commit start (the task's example), independent of the 23 s intake bound.
- Kotlin and Swift were not compiled locally (no SDK); CI is the gate.
