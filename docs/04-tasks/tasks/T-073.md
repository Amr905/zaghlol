## Description

## Technical details
Amount/currency adjacency, direction keyword dictionaries AR/EN, last-4, merchant span heuristic; always review; 'always capture' after 3 confirmations (A-66); unseen-format test set.

## Design note
Written by the implementer for the C3 class (the architect note was not produced; spec: parsing-engine.md §7 and "As built (T-033)").

**Where it sits.** `packages/zaghlol_parsing/lib/generic/`: `generic_parser.dart` (pure `parseGeneric`), `generic_keywords.dart` (AR/EN dictionaries, data only) and `generic_policy.dart` (A-66). The pipeline's `unknownSource` hook calls it after the drop stage (an OTP from an unknown sender is still dropped).

**Eligibility (who may reach the generic parser).** Same rule as platform-channels.md: the source is in `generic.alwaysCapture`, or the channel is `shortcutMessage`, `applePay` or `share` (no reliable sender), or `senderHints` matches the source and `bodyHints` matches the body. Anything else stays `ParseUnrecognized(unknownSource)`.

**Result.** New sealed subtype `ParseGeneric` (not `ParseParsed`: no institution, template or event exist). It carries amount (`Money`, integer minor units), nullable `direction` (null = unknown, never defaulted), `last4`, `merchant`, `occurredAt` (always the receipt time, source `receivedAt`: the generic parser reads no dates), integer permille confidence and `GenericReason` codes. `needsReview` is always true. Unusable eligible messages return `ParseUnrecognized` with `genericNoAmount` or `genericDeclined`. No message text in any result.

**Amount and currency.** Scan the folded body (foldKey) once for number runs. A run is a candidate only when a currency marker (ISO code, symbol, or an AR/EN currency word) touches it, before or after, separated by spaces only. A marker that sits between two numbers goes to the number that has no other marker; if both or neither lack one it is used for neither. Numbers after a balance keyword (`balance`, `avail`, `limit`, `رصيد`, `متاح`, `الحد`) are excluded. Parsing uses `parseAmount` (standard locale), so excess precision or a bad grouping drops that candidate. A candidate without a marker is never taken: no fallback currency (`ريال` and `دينار` alone are ambiguous and give no currency). The winner is the candidate nearest a direction keyword; two distinct amounts with no clear winner (no keyword, or equal distance) pick the first and add `amountAmbiguous`.

**Direction.** Keyword dictionaries, folded, Latin on word boundaries. Decline words (`declined`, `failed`, `رفض`, `مرفوض`, `لم تتم`) give `genericDeclined` (a failed attempt is not spend). Expense and income keywords: the one nearest the chosen amount wins; opposite keywords within 20 characters of each other give null direction plus `directionConflict`; none gives null plus `directionUnknown`. Ambiguous verbs never set a direction: bare `sent` is not a keyword (`Ahmed sent you EGP 500` is income), only `you sent` and `sent to` (and Arabic `قمت بارسال`, `ارسلت الى`) mean expense, and a keyword whose object is the reader (`paid you`, `sent to you`, `دفع لك`) is ignored, so those messages come out null plus `directionUnknown`. Amounts in two currencies with nothing to separate them add `currencyAmbiguous` (x700); the pick is never converted.

**last4.** Registry `globalLast4` patterns first, then a built-in marker pattern (`**1234`, `ending 1234`, `card no 1234`, `رقم البطاقة 1234`); a bare four-digit number is never taken.

**Merchant.** After a marker word (`at to from`, `لدى عند الى من`) take up to 4 tokens, stopping at stop words, digits, currency markers and punctuation; Latin spans must start with a capital in the original text; then `cleanMerchant`. No marker or an empty span gives null. No guess.

**Confidence.** Base 600 permille; factors `amountAmbiguous` 700, `directionConflict` 800, `directionUnknown` 800, `sparseFields` 900 (no last4 and no merchant), `currencyAmbiguous` 700. Hard cap `kGenericMaxConfidencePermille = 700` below the auto-accept threshold.

**A-66 policy.** `genericDisposition(confirmedCount, alwaysCapture)` returns `review` unless `alwaysCapture` and `confirmedCount >= 3` (`kGenericConfirmationsRequired`), then `autoSaveLowConfidence` (saved, still `low_confidence`). Counting confirmations and the `capture_senders` row belong to the ingest layer (T-046); this task ships the pure rule and the guarantee that a generic result is never auto-acceptable.

**Safety.** Linear scans, no nested quantifiers; body cap 4000 is the pipeline's. Tests run 4000-character adversarial bodies through the parser, and the lint probe now also covers `drop` and `last4` pattern lists (T-033 M-2). Taken from the T-033 review: M-2 (probe plus 4000-size test), M-5 (test naming, printed benchmark mean), N-2. Not taken (outside generic scope, logged as FU-073 and FU-074): M-1 negative balances, M-3 lint isolate timeout, M-4, N-1. The probe now takes the best of three runs before reporting a slow match (a loaded runner cannot flag a clean pattern).

**Unseen set.** `test/fixtures/generic/unseen_set.json`: synthetic AR/EN messages in formats the registry does not know, with expected amount and currency (and direction, last4, merchant where stated). A test prints precision on the suggested cases (the 80% of AC 1 refers to this) and the coverage over all cases, and asserts both (precision >= 80%, coverage and correct-over-all >= 70%).
