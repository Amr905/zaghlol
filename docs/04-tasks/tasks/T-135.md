## Description
Optional account that only carries Gold: verified sign-in that links and protects purchases, moves seats under the one-phone rules, and never loses the link on a refused move.

## Technical details
- **Verification:** Google (`aud` ∈ our client IDs, `iss`, `exp`, JWKS) and Apple (`aud` = Services ID or bundle ID, `iss = https://appleid.apple.com`). Apple `authorizationCode` → encrypted refresh token used only to revoke on deletion.
- **Nonce and replay (R2-9, ADR-016 am. 2/3):** raw nonce required for both providers (`^[A-Za-z0-9_-]{22,128}$`); constant-time compare of `hex(SHA-256(nonce))` with the token's `nonce` claim; missing nonce or claim → `422 ID_TOKEN_INVALID`; `iat` > 10 min old → `422`; single use via `replay_guard`. **The `replay_guard` insert is committed on its own, before and outside the account and seat transaction (R3-5).** An `Idempotency-Key` replay returns the stored result before this check.
- **Element-0 check (§4.6 step 5, R4-1(1)):** an iOS `seatKeys` whose element 0 isn't this install's registered key → `400 SEAT_KEY_MISMATCH`, checked before step 1 so nothing is linked; Android `seatKeys` → `400 VALIDATION_FAILED`; proofs verified by T-182 (`op = signin`, `challenge = SHA-256(nonce)`). A first valid element 0 registers **untrusted** (R5-2).
- **After verification, one transaction that always commits steps 1–4 (R3-5):** (1) upsert account; (2) link install; (3) **attach** (D-54): `account_id` + `account_linked_by = 'signin'` only on purchases with no account and `purchases.install_id` = this install; (4) seat at attach time: if the holder isn't linked to the account, the **account-attach reclaim** once per purchase (`attach_reclaim_used_at IS NULL`; sets it, counts as the move, `seat_move:account_attach`; never cleared, D-58/R3-3), else an ordinary step-5 move; (5) seat moves for account-linked purchases via T-184: same-iPhone rebind within the D-63 cap; over the cap the D-65(a) over-cap rebind **only when `device_key_trusted`**, otherwise an ordinary move with `restoreSuggested: true` (R5-3(b)); otherwise a move under the cooldown (`proof = account`).
- **Refused move (R3-5):** this install becomes a pending claimant (`channel = signin`); response **200** with `accountToken`, `moveRefused: true`, `nextMoveAt` (earliest refused), `restoreSuggested` when applicable, and an entitlement without those purchases. Sign-in never answers `409 MOVE_COOLDOWN`.
- `409 INSTALL_LINKED_TO_OTHER_ACCOUNT` with `replaceLink: true` confirmation (EC-46). Account JWT `{sub, iid, iat, exp: +30 d, kid}`.
- **Account token validity (R3-6):** a token whose account no longer exists, or whose install is no longer linked, → `401 ACCOUNT_TOKEN_EXPIRED` even before `exp` (shared auth handler).
- **Sign-out (D-61(c)):** unlinks the install, doesn't move seats; returns **200 signed** `{entitlement, serverTime, timeNonce}` with account-linked purchases now `paused` here.
- **Delete account:** removes account and links, revokes the Apple token, deletes every `idempotency_records` row with this `account_id` (R3-6); purchases keep seats and `attach_reclaim_used_at`; `account_id` and `account_linked_by` become NULL.
- **Android Apple callback (CR-05, FU-008):** `POST /v1/apple/android-callback` (`form_post`), per-field patterns (`400` otherwise), drop `user` unread, `303` to `intent://callback?…#Intent;package=<applicationId>;scheme=signinwithapple;end` built with a URI builder; body and `Location` never logged.
- Sign-in and sign-out 200s are signed and echo `timeNonce` (T-123 filter).

## Acceptance criteria
- [ ] FR-GOLD-07: buy on Android, sign in on iPhone → Gold (the move follows the cooldown rule).
- [ ] Delete removes account and links, revokes the Apple token (fake), and deletes that account's idempotency rows (R3-6, test).
- [ ] R2-9: a Google sign-in without `nonce`, or with an ID token lacking a `nonce` claim → `422 ID_TOKEN_INVALID`; a reused ID token + nonce → `422` (tests).
- [ ] R3-5: a sign-in whose move is refused by the cooldown returns 200 with `moveRefused: true`, `nextMoveAt`, a committed link and attach; the same ID token + nonce replayed afterwards is refused by `replay_guard` (test).
- [ ] R3-3/D-58: sign in (reclaim), delete the account, sign in again on the buying install → the second attach is an ordinary move under the cooldown, not a second free reclaim (test).
- [ ] D-54: a sign-in from an install that isn't the buying install never sets `account_id` on that purchase (test).
- [ ] R3-6: an account token for a deleted account → `401 ACCOUNT_TOKEN_EXPIRED` before `exp` (test).
- [ ] R4-1(1): a sign-in whose element 0 differs from the registered key → `400 SEAT_KEY_MISMATCH`, nothing linked, `replay_guard` row present (test).
- [ ] R5-2: plain sign-in registers element 0 with `seat_key_trusted = false` (test).
- [ ] D-63/D-65(a)/R5-3(b): over-cap sign-in match against a **trusted** seat key → seat passes, window restarts, `seat_rebind_over_cap:signin`, alert metric; against an **untrusted** key inside a cooldown → `moveRefused: true`, `restoreSuggested: true`, claimant row, `seat_rebind_over_cap:signin` event (tests).
- [ ] Sign-out returns 200 signed with a fresh token in which account-linked purchases are `paused` (test).
- [ ] Apple callback injection test: for each field, inputs containing `#`, `;`, `%23`, CR/LF or `&` get `400` or a `Location` with exactly one `#Intent;package=…;scheme=signinwithapple;end` tail (backend-api §4.6).
- [ ] R4-2: sign-in and sign-out 200s echo `timeNonce`.
- [ ] FU-011: live response-vs-spec tests for sign-in, sign-out, delete and the Apple callback.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
