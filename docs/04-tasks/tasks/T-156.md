## Design note
Required — solution-architect (Opus) writes it before the Sonnet implementer starts (C3).

**Bank-agnostic part built 2026-11-18 (implementer's note; per-bank templates still wait on OQ-04 samples).**
- Extraction: `pdfrx` 3.0.0 (MIT, PDFium, opens from memory, no network, no temp file) behind the pure-Dart port `PdfTextExtractor` (`packages/zaghlol_parsing/.../statements/pdf/pdf_text_types.dart`); adapter `app/.../export_import/data/pdfrx_text_extractor.dart`. Architecture §"pdfrx" already names it; no new ADR. Fragments carry x in permille of page width and y in points, so saved templates survive page sizes.
- Table: fragments -> lines -> cells (Arabic cells joined right to left) -> column edges from a saved template, else a recognised English/Egyptian-Arabic header, else the gaps in the data lines. A line with a parseable date in the date column is a row; a dateless single-column line close below is a wrapped description.
- Mapping: roles date / description / debit / credit / amount (signed) / balance / ignore, plus day-first and number locale and currency. Header hit with a valid mapping = confident (no prompt); otherwise the mapping step (`statement_mapping_step.dart`) asks once and the answer is saved per bank as `import.stmt_tpl.<bank>` in the encrypted `settings` table (no migration).
- Rows: `parseAmount` (integer minor units in the statement currency, sign from column, `-`, `(..)`, trailing `-`, `DR/CR`, `مدين/دائن`); dates DD/MM/YYYY, YYYY-MM-DD, textual English and Egyptian Arabic months, Arabic-Indic digits.
- Dedupe: statements have a day, not an instant: same account, local day, direction, amount and currency (merchant not compared), multiset like T-155. New `CsvImportStore.existingBetween`; `ImportedTxn.source` (default csv, `pdf` here).
- Privacy: picked bytes zeroed right after extraction (success or failure); password is a call parameter only; typed failures; nothing logs.
- Not done (needs samples/PO): per-bank sample fixtures (AC 1), enabling the CIB/NBE/QNB/Misr tiles (`ImportSourceDef.available`), card mapping and ignored-card skip, wiring the mapping/password UI into the T-158 flow, PDFium-backed test of the adapter (needs the native library; tests use a fake extractor and synthetic fragments).

**Missing l10n keys (no ARB edits in sprint; the UI takes labels from the caller):** statement mapping title, hint, "column N", seven role names (date, description, money out, money in, amount (+/-), balance, skip), day-first switch, currency label, confirm, invalid-mapping hint; password dialog title, body, field label, wrong-password hint, confirm, cancel; failure copy for passwordRequired/wrongPassword/unreadable/noText/noRows.

## T-156b follow-up (generic layouts, balance check, scanned PDFs)

- Header synonyms (Paid In/Out, Money In/Out, Amount In/Out, Deposits/Withdrawals, Detail/Narrative, Arabic); "Payment Type" is ignored.
- Several tables: sections start at each header; the table with a Balance column is chosen, a later section that repeats an earlier one (date + amount + similar description, 80%) is dropped.
- Year-less dates (`MM/DD`, `Oct 10`): year from the latest full date printed outside the table, else today; Dec to Jan rollover in both row orders. Month-first or day-first is read from the dates (a part above 12); date cells are rewritten to `yyyy-mm-dd`.
- Running balance: opening balance from a "Balance Brought Forward" / "Opening balance" line, each row checked against the previous balance; a row that does not add up is never dropped: it is returned in `StatementParseResult.review` (reason `balanceMismatch`) and the user keeps it, fixes its direction or skips it; unsigned amount columns take their direction from the balances, and an unsigned amount that nothing can direct is flagged `directionUnknown` with the direction unset (never income); newest-first statements are checked in reverse; closing balance compared.
- Currency markers (`$ £ € EGP ج.م جنيه`) are stripped; one marker proposes `StatementTable.suggestedCurrency`; nothing is converted.
- Scanned PDFs: `ScannedPdfTextExtractor` (text layer first; on `noText` renders pages with pdfrx, seals into the OCR spool, recognises on device, deletes the plain PNG in a `finally`; max 30 pages).
- Missing l10n keys: a label for "rows that do not match the running balance" (currently counted under the bad-amount problem), "this looks like a scan, reading it on your phone" progress text, and "currency found: USD/GBP, confirm".
- Year: when dates lack a year and the statement prints no full date, `StatementTable.yearSource == today` and `anchorYear` is only a suggestion; `ImportStatementPdfUseCase.run` throws `yearNotConfirmed` until the user passes `confirmedYear`. Flagged rows throw `reviewRequired` until each has a `StatementReviewChoice` (keep / asExpense / asIncome / skip; keep is invalid when the direction is unset).
- Missing l10n keys for the review and year UI (ar Egyptian / en), to be added with T-087: `statementReviewTitle` ("Check these rows" / "راجع الصفوف دي"), `statementReviewBalanceMismatch` ("The balance after this row doesn't add up" / "الرصيد بعد الصف ده مش مظبوط"), `statementReviewDirectionUnknown` ("We can't tell if this was money in or out" / "مش عارفين دي فلوس دخلت ولا خرجت"), `statementReviewKeep` ("Keep as is" / "سيبها زي ما هي"), `statementReviewAsExpense` ("Money out" / "فلوس خرجت"), `statementReviewAsIncome` ("Money in" / "فلوس دخلت"), `statementReviewSkip` ("Skip this row" / "تخطّى الصف ده"), `statementYearTitle` ("Which year is this statement from?" / "الكشف ده بتاع سنة كام؟"), `statementYearHint` ("The statement doesn't print the year, so confirm it before importing." / "الكشف مش كاتب السنة، أكّدها قبل ما تستورد.").
- Android OCR: `ocrEngineProvider` returns `PigeonOcrEngine` on Android (T-159 host: Tesseract ara + ML Kit Latin) as on iOS; images are deleted after OCR and nothing is uploaded. Amount-only tables without a balance column (page 2 alone) cannot tell debit from credit.
