## Description
Add `ai_merchant_suggestions(merchant_norm PK, category_id, confidence, source, state ∈ unconfirmed·confirmed·corrected·no_answer, created_at, decided_at)` and `llm_cat_queue(merchant_norm PK, txn_count, first_queued_at, last_seen_at, attempts, next_attempt_at)` with DAOs; outbox kinds `llmCatConfirmation` / `llmCatCorrection`; `CategorySource.ai('ai')`; export column `category_source` maps `ai` + unconfirmed → `ai_unconfirmed`. Both tables are cleared by "Delete everything" and included in the encrypted backup like other categorisation data.

## Acceptance criteria
1. Migration test from the current schema version on a populated synthetic DB; new tables empty and usable.
2. **Negative proof 1:** every existing transaction's category id and source, every rule and every outbox row are byte-identical after the migration.
3. **Negative proof 2:** a restore of a backup made before the migration upgrades cleanly and loses nothing (existing backup round-trip test extended).
4. Export test: an `ai` + unconfirmed row exports `ai_unconfirmed`; confirmed rows export as rules do today.
5. "Delete everything" empties both tables.
