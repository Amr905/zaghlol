## Evidence
In run 45385531585 the Arabic `variants-a` pass logged `left-app` on Home's mascot tip, the emulator's Bluetooth HAL aborted (`assertion 'waiting_command_ == op_code' failed ... SET_EVENT_MASK`), then the test hit `'_pendingExceptionDetails != null': A test overrode FlutterError.onError but either failed to return it...` and hung until the 1200 s alarm (exit 142). Job log: `gh api repos/Amr905/zaghlol/actions/jobs/$(gh api repos/Amr905/zaghlol/actions/runs/45385531585/jobs --jq '.jobs[]|select(.name=="explorer variants-a")|.id')/logs`.

## Scope
1. Turn Bluetooth off on the CI emulator before tests (e.g. `adb shell cmd bluetooth_manager disable` / `svc bluetooth disable`, and the emulator's `-feature -Bluetooth` or hw.bluetooth config if the AVD setup allows) in `.github/scripts/device-flows.sh` and the other device scripts; the app doesn't use Bluetooth.
2. When the explorer sees `left-app`, it waits briefly for the app to return (the existing keeper brings it back) and records whether a system dialog/crash of another process caused it (logcat check in the script after the run is enough), so such a record is reported as an emulator fault, not an app issue; never hide a real `left-app` caused by the app.
3. Fix the explorer's `FlutterError.onError` override so it is always restored (try/finally), so an issue never turns into a hang.
4. Confirm the Home mascot tip tap doesn't leave the app by itself (widget test: tapping the tip keeps the app; it plays the tap mood and rotates the line, T-215).
## Acceptance criteria
`device-flows` explorer jobs green on `ci/T-239` (report run id); widget test for item 4; `dart analyze`, `dart format` clean; `bash -n` on scripts.
