## Description
On-device OCR for Arabic and English.

## Technical details
OcrHostApi; bundled ara fast model; merge lines by bounding box; decrypt image in memory; delete temp in finally.

## Design note
(Written by the implementer at the lead's request, 2026-11-11; no separate architect note.)

**Contract.** Implements `OcrHostApi` exactly as in platform-channels section 4 (`recognize`, `supportedLanguages`, `OcrResult`, `OcrLine`). One clarification, not a widening: on Android `encryptedImagePath` is the **share id** of an entry in the T-060 `ShareStore` (`noBackupFilesDir/share/`, 28 hex chars). Anything else is refused. No new file location is introduced.

**No image on disk.** `ShareStore.read(id)` decrypts into memory; the bytes are decoded to a bitmap and the plaintext array is zeroed. Neither ML Kit (`InputImage.fromBitmap`) nor Tesseract (`setImage(Bitmap)`) needs a file, so there is no temp file to delete; `finally` recycles the bitmap and zeroes the buffer. The OCR host never discards the share (Dart owns that, FU-067). The only file the host writes is the public `ara.traineddata` model (below).

**Untrusted input (T-060 F9/S5).** Bounds are re-probed with `inJustDecodeBounds`; more than 64 MP is refused. The decode uses a power-of-two `inSampleSize` so the decoded bitmap is at most 8 MP. Wrong or corrupt bytes give `OCR_FAILED` without echoing anything. A 40 s deadline stops Tesseract (`stop()`); a timeout gives `OCR_FAILED`.

**Engines.** `en` -> ML Kit Text Recognition v2 Latin, **bundled** (`com.google.mlkit:text-recognition:16.0.1`; no Play Services model download, no network). `ar` -> Tesseract4Android `4.9.0` (standard, non-OpenMP: smaller, one thread, no `libomp`), `ara` from tessdata_fast (Apache-2.0, 1,432,056 bytes), bundled in `assets/tessdata/`, LSTM only, `PSM_AUTO`. The asset is copied to `noBackupFilesDir/tessdata/` and checked against a pinned SHA-256 (a unit test checks the asset against the same constant). A mismatched copy is replaced from the APK; that is safe because it is public, re-creatable data.

**Merge (pure Kotlin, `OcrMerger`).** Tesseract lines that contain Arabic letters are kept. An ML Kit line whose box overlaps one (intersection over the smaller area >= 0.5) is dropped, but its ASCII-digit/Latin tokens that are missing from the Tesseract text (compared after digit normalisation) are appended to that line, because ML Kit reads digits better. Other ML Kit lines are kept; Tesseract lines without Arabic letters are dropped as duplicates or noise. Output is sorted top to bottom (box y, then x). Boxes are normalised to the decoded image; confidence is 0..1 (Tesseract 0..100 / 100). Thresholds are unvalidated because the SPK-02 results do not exist yet (T-010 is TODO); see "Open points".

**Threading.** `@async`; one single-thread executor, so recognitions are serialised (memory, and Tesseract is not shared). A fresh `TessBaseAPI` per call, ended in `finally`.

**Errors.** `OCR_FAILED` (undecodable, too large, timeout, engine failure, no supported language requested), `SPOOL_DECRYPT_FAILED` (share deleted by the store, as in T-060), `IO_ERROR` (unknown id, transient read). `NOT_AVAILABLE` if the Arabic model cannot be installed while `ar` is the only language requested; if `en` is also requested, Latin results are returned and `supportedLanguages()` omits `ar`.

**Logging.** None of recognised text, ids, or sizes.

**Supply chain.** Pinned: ML Kit 16.0.1, Tesseract4Android 4.9.0, tessdata_fast `ara` by SHA-256. Licences: ML Kit (Google ML Kit terms; bundled model, on-device), Tesseract4Android (Apache-2.0), tessdata_fast (Apache-2.0). Size notes are in the report and in `docs/03-technical/adr/ADR-009-ocr.md`.

**Open points.** SPK-02 accuracy cannot be reproduced because T-010 has no results; AC1 is limited to a synthetic-image instrumented test plus a documented manual run. Maven Central is not reachable from the authoring sandbox, so dependency resolution is verified only by the PC runner.

### Manual device steps
1. Install a devNoSms build on a device with Android 8+; share a screenshot of an Arabic InstaPay receipt to Zaghlol; run `recognize` (via the T-161 flow once it exists, or the instrumented test).
2. Check lines contain the amount, reference and Arabic labels, boxes are inside 0..1, and top-to-bottom order is right.
3. Put the phone in airplane mode and repeat: results must be the same.
4. After a run, `adb shell run-as <id> find files no_backup cache -type f`: only `no_backup/ocr/tessdata/ara.traineddata` plus the pending share files; no image or `.tmp` file.
5. Share a 60 MP image (or a long scrolling screenshot): refused or decoded with a sample size, no crash.
Results: not run (no device in the authoring environment).
