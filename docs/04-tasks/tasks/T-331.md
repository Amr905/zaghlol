## Description
Typed sealed `Plan` classes for every variant, parsed from the reply JSON; constants generated from the pinned schema (`planVersion = 1`, plan names, enums, ranges, allowed blanks per plan) by a script with a regen check. `PlanValidator` applies §2.4 steps 1–6 on the phone, plus the phone-only check that no string names an account/card/bank from the user's registry or the mask sources in plain text (takes a `MaskSources`-like lookup).

## Acceptance criteria
1. All shared vectors pass with the same outcome as the .NET validator (T-330).
2. Phone-only check: a plan with `account:"CIB"` in plain text or a `ref` not in the sent text → fallback; `mention:"Carrefour"` for "how much on groceries?" → fallback.
3. Regenerating constants from the schema produces no diff (test or script check).
4. Template grammar rejects every §2.3 class (same list as T-330) in both languages.
5. Pure Dart, no `double`; `dart analyze`, `dart format`, package tests green.
