## Description
Local, privacy-safe diagnostics that can be shared by the user.

## Technical details
DiagEvent API with allow-listed field types (codes, counts, durations, versions, institution codes); ring buffer 7 days/2000 rows; global error handlers write codes only; export as text.

## Design note
(T-021 builder, 2026-11-11; C3 note written before coding.)

**Goal:** no code path can put free text (SMS body, merchant, amount, key, address) into `diag_log`.

- **Compile-time barrier.** `DiagEvent` takes a `DiagCode` and a `List<DiagField>`. Neither has a public constructor that accepts an arbitrary `String`. `DiagCode` instances exist only as `static const` entries in the `DiagCodes` registry (the allow-list; adding a code is a code change, reviewed). `DiagField` factories are typed: `count(DiagKey, int)`, `durationMs(DiagKey, Duration)`, `httpStatus(int)`, `appVersion/registryVersion/catalogVersion(String)`, `institution(String)`, `templateId(String)`, `errorCode(DiagCode)`. The key is a `DiagKey` enum, never a string. `DiagEvent(code: 'x')` and a `String` where a field is expected fail to compile; a test proves it by spawning an isolate on a snippet that must fail to compile.
- **Residual, runtime-validated strings.** Only versions, institution codes and template ids are strings. Each is checked against a strict, length-capped regex (digits and dots; `[A-Z][A-Z0-9_]{1,15}`; `[a-z][a-z0-9_.-]{1,39}`) and a mismatch throws a code-only `DiagFieldException` (never echoes the value). Spaces and long tokens (an SMS, a hex key, a base64 blob) can't match. Residual: a short token in the right shape is accepted. Counts are plain ints under keys that name what is counted; do not pass an amount (`*_minor`) as a count. Stated plainly in the dartdoc.
- **Logger.** `DiagLogger` writes through a `DiagStore` port (adapter over `DiagLogDao`, which already has the schema CHECKs, v4) with an injected clock. `record` never throws (diag must not crash the app) and returns whether it was stored; it prunes after each append (7 days or 2000 rows, one transaction, existing `DiagLogDao.prune`). The row encoding is a small JSON object `{key: value}`.
- **Export.** `DiagExporter` renders text from the rows. It re-validates every stored key against `DiagKey` and every value against that key's shape and drops anything that fails, so a tampered row still can't leak text. Header has app version only if given.
- **Global handlers.** `installDiagErrorHandlers` sets `FlutterError.onError` and `PlatformDispatcher.onError` to record fixed codes; for a `SafeException` the code (re-checked against the UPPER_SNAKE shape, else `UNKNOWN_ERROR`) is stored as `error_code`. Error messages, stacks and `toString()` of non-Safe errors are never read. `debugPrint` is muted like `quiet_errors.dart`.
- **Follow-ups from the task file.** `BACKUP_EXCLUSION_FAILED` is in `DiagCodes`. In `BackupExclusion.swift` the `os_log` call is replaced by a `NativeDiagHook` (a static closure, default no-op) that receives the fixed code. The Dart-side bridge that drains native events into `diag_log` needs a platform channel and belongs to a native task (reported as a follow-up); Swift is not compilable in this workspace. Sensitivity note (T-012 F7/F8): `*_minor` and `Money.toStorage()/toJson()` can't reach the log, because no field type accepts them.
- **Out of scope:** the Settings -> About UI (no UI in this task, so no RTL); Riverpod providers (kept out of shared provider files).
