## Description
Local, privacy-safe diagnostics that can be shared by the user.

## Technical details
DiagEvent API with allow-listed field types (codes, counts, durations, versions, institution codes); ring buffer 7 days/2000 rows; global error handlers write codes only; export as text.

## Design note
Required — solution-architect (Opus) writes it before the Sonnet implementer starts (C3).

## Acceptance criteria
- [ ] Free-text fields rejected at compile time
- [ ] Ring buffer trims correctly
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.

## Testing requirements
- Unit tests incl. attempt to log a message body (must not compile/pass)

## Review follow-ups (added by Lead)
- From the T-012 security review F7/F8: treat `*_minor` fields and `Money.toStorage()` / `toJson()` output as sensitive (they contain amounts). Log errors only through `toString()`, never by serialising error fields.
- From the T-165 code review F5: add `BACKUP_EXCLUSION_FAILED` to the allow-listed diag codes, and replace its `os_log` call in `BackupExclusion.swift` with the native diag hook.
