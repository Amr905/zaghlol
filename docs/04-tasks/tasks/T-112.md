## Implementation notes
Files: `app/lib/features/wealth/domain/price_feed.dart` (pure: strict block parser, staleness, price resolution, ≈ conversion), `data/prices_repository.dart` (store, port `RemotePricesSource`, apply/refresh/override/read), `data/prices_providers.dart`; tests under `app/test/features/wealth/`. No schema change; reuses `PricesDao` (T-019).

- **Units and direction.** Gold price = minor units of its currency per one `g` (`_G` symbols; else `unit`). FX `base -> quote`, `1 base = rateE9/1e9 quote`. Decimal strings are parsed to integers by regex; a price with more fraction digits than the currency exponent (beyond trailing zeros) rejects the block, never rounds. Rates take at most 9 decimals and must fit the `fx_rates` CHECK (<= 2^53-1).
- **Apply** is atomic (quotes, rates, reported-stale flag in one transaction). Any parse defect rejects the whole block and keeps stored data; an `asOf` older than stored is a replay and is rejected; equal is accepted. Both `gold` and `fx` must be present and non-empty (no wipe on doubt).
- **Stale** = older than 24 h (strict), or the backend's `stale` flag for the last block, or `asOf` more than 5 min in the future (unverifiable). The flag is cached in `secure_state` key `prices.reported_stale` (no schema change) because the block `asOf` is the newest of gold and FX and would hide one stale kind. Stale data is returned and labelled.
- **Manual override** (`source = manual`) wins until `clearManualOverride`; apply never touches it; it is marked `PriceOrigin.manual` and is never labelled stale (user-set; `asOfMs` is when it was set). Prices only: `fx_rates` has no source column, so a manual FX override is not possible without a schema change.
- **≈ view.** `FxTable.convertApprox` returns `Approx` (never plain `Money`) or `MissingRate` (EC-35). Direct, inverse, or via a common base (USD); one half-even rounding on BigInt integers; stale if any leg is stale. Same currency is an exact identity.
- **Port.** `RemotePricesSource` (like T-025); `remotePricesSourceProvider` is null until T-141. Sync (T-143) calls `PricesRepository.apply(block)`.
- No logging; errors are code-only `PricesRejected`.

## Self-check (docs/workflow/self-check.md)
1. Never destroy data on doubt: applies; no delete on parse failure, replay, or unavailable port; only a valid newer block replaces backend rows. Manual rows are never touched by apply.
2. Concurrency: apply reads the stored `asOf` and writes inside one DB transaction (single writer); the two-actor race is the same transaction. Not separately tested with two connections.
3. Untrusted input: block parsed strictly, count caps (50 gold, 200 rates), digit/length caps via regex, ASCII digits only, JSON numbers rejected, errors never echo input (tested with a sentinel).
4. Fail closed: unknown/unverifiable (future asOf, malformed flag) reads stale or rejects.
5. Secrets and logs: nothing logged; amounts only in return values.
6. Docs match code: notes above reflect tests. Residual: the 5 min skew and 24 h constants are by the app clock (not the trusted clock, T-144).
7. Evidence: each AC maps to a named test above. Not C4, no negative proofs required.
