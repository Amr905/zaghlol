## Request (PO, 2026-11-23)
"When we ask the user consent to record voice it should be shown one time only and next should be added quickly."

## Today
`VoiceController._startFirst` (`app/lib/features/voice/application/voice_controller.dart`) shows the consent sheet every session when on-device ar-EG/en recognition isn't available; "Allow" only sets `state.online` for that session.

## Description
Remember the user's "Allow" for the OS online recognizer (D-42) in the app's encrypted settings, so later voice entries start listening at once. Keep it revocable: a switch in Settings → Privacy (or the voice settings row if one exists) "Use the phone's online speech recognition" with a one-line explanation (audio goes to Google/Apple, never to Zaghlol). Turning it off clears the remembered consent; the next voice entry asks again. "Not now" is not remembered (ask again next time). The OS microphone permission is separate and stays the OS's job.

## Acceptance criteria
1. First voice entry without on-device support: consent sheet; after "Allow" it listens. Second and later entries: no sheet, listening starts at once (online recognizer).
2. "Not now": nothing stored; the next entry asks again.
3. Settings switch shows the stored state; off clears it; on from Settings is allowed (same copy as the sheet).
4. If on-device support appears later (OS language pack installed), on-device is used even when consent is stored.
5. Stored in the existing encrypted app settings (`app/lib/core/platform/app_settings.dart` or its provider), never in plain prefs; included in "delete all data" reset; not included in backups unless other privacy choices are (follow what the existing privacy settings do and say which).
6. Strings in ARB + copy deck (Egyptian colloquial); privacy wording consistent with `docs/06-release/privacy-consistency.md`.
7. Unit tests for the controller paths; widget test for the Settings switch; `dart analyze`, `dart format`, voice tests green.
