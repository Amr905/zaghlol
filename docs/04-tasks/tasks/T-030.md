## As built (implementer, 2026-11-11)
Class C2, no design note. What exists and how it differs from the task text:
- `packages/zaghlol_catalog` (new, pure Dart): the seed document (`{version, ops[]}` = OpenAPI `CatalogSnapshot`, upserts only, canonical bytes), a strict decoder (unknown members, types, ranges, dangling references, duplicates, order, 8 MiB cap) and ES256 signing/verification in the backend's `Zaghlol-Signature` header form (deterministic RFC 6979 signing). It uses `pointycastle`: `cryptography` has no pure-Dart ECDSA (FU-078 2).
- `tools/catalog_build`: curated CSV (`data/catalog_curated.csv`, backend column set) to `app/assets/catalog/catalog_seed.json.gz` + `.sig`, and the normalized `data/catalog_seed.csv` for the backend T-125 import. Aliases use `merchantKey` (FU-062, tested on every vector of `merchant_key_vectors.json`), plus attached-article variants (FU-066). `--check` fails on stale outputs.
- App: `core/catalog/catalog_seed_loader.dart` (read, inflate with cap, verify, strict decode, one transaction, meta last) and `catalog_providers.dart`; `CatalogDao` gained batch upserts (`upsertMerchants/Aliases/Keywords`, same ON CONFLICT DO UPDATE rule) so the load is one round trip per table. `assets/catalog/` is declared in `app/pubspec.yaml`.
- Category names are catalog data (copy deck, "category names ... localized in the catalog seed"), so no ARB keys are needed.
- Deviations: subcategories not seeded (no parent in `CategoryOp`); dev signing key only (FU-078 1); the seed loads only when `catalog_meta` is empty; CI gains `dart test` for both new packages, the lints run over them, and `backend-ci` also triggers on the seed CSV. Backend: a test (`BundledSeedCsvTests`) feeds the generated CSV through `CatalogSeedCsv` and `CatalogValidation`.
