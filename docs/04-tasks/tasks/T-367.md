## Goal
One provider id plus display names, taken only from the signed sync `config` block, feeds the consent sheet, the Ask flow and the categoriser. A 409 is a safety net that never supplies terms.

## Acceptance criteria (row 1b)
1. One terms provider (`llmProviderTermsProvider`: id, ar/en names) fed only by `config.values["llm.provider"]` and `providerName`; consent version stays a code constant.
2. It feeds `askConsentTermsProvider` (wired in `ask_wiring.dart`, FU-425 comment removed), `askLlmTermsProvider` and `llmCatTermsProvider`; sheet and flow show and store the same provider and version (FU-431).
3. No id, bad id, or a missing name, or stale config: terms null, nothing is sent, discovery/consent UI stays hidden.
4. A changed provider id no longer matches the stored consent: re-consent.
5. 409 (Ask): consent cleared, config cursor reset, one sync (no question), re-prompt only when the synced terms differ, else the paused copy without a resend. 409 (categorise): consent cleared, queue kept, cursor reset, nothing sent. The 409 `providerId` is never used or stored.

## Design note
- `llmProviderTermsProvider` derives from `remoteConfigProvider` (already stale-aware, 14 days); validity = spec id pattern and both names non-empty.
- `RemoteConfigService.resetCursor()` makes `version` read 0 (so `configVersion` is omitted) without dropping the held values; the next applied block, even at the same version, ends the reset.
- `LlmConsentRequired` no longer carries `providerId`. `llmConfigResyncProvider` (reset, one forced sync, re-read config) is injected into the Ask flow as `resyncConfig`; `llmConfigCursorResetProvider` into the sender as `onConsentRequired`.
- `SheetConsentPrompter` passes the flow's terms to `AskConsentFlow.prompt(expect:)`, which refuses on a mismatch (no sheet, nothing stored).
- Residual: a sync already in flight is shared by `run`, so the 409's resync may not carry a block; the result is the paused copy (safe).
