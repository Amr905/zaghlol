## Scope
1. **FU-383** (`ingest_raw_messages.dart` ~1317-1361): after a cross-channel merge (T-281), mark the stored exchange as having its other-channel copy (or record the channel that produced each pair) so a **second real conversion** with the same amounts on the other channel is never merged into it; instead it is stored and flagged `possibleDuplicate` for the user. Same rule for the existing single-transaction cross-channel attach if it has the same exposure (check and write what you found). Prefer an existing column/table (source message links) over a schema change; if a schema change is unavoidable, stop and write why in this file.
2. **FU-384** (`transactions_list_screen.dart` ~291-325, bulk actions): selecting an exchange row selects both legs for every bulk action; Set category is not offered for exchanges (they have no spending category) and Set account is disabled when an exchange is selected (it would split the pair), with a short reason. Delete already uses `wholeExchanges`.

## Acceptance criteria
- Ingest test: SMS A stored, notification for a different real conversion B with equal amounts → two exchanges + a review item, not a merge. The T-281 merge test still merges a true copy.
- Bulk test: selection of an exchange row holds both legs; Set account/category cannot change one leg.
- ≤ 3 negative proofs.
