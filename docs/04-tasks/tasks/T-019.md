Inputs: this file; database-schema §2.6–2.8, §3, §4; domain-algorithms §11, §12, §14 and the voice limit (§ "Monthly limit"); error-handling-and-observability §3.1 (`diag_log`); backend-api §4.2 (sync apply, prices, outbox) and §4.3 (trusted-time state in `secure_state`); parsing-engine A-66 / FR-PAR-07 / FR-PAR-14; the T-016/T-017/T-018 code and reviews; FU-075.

**1. Version.** `schemaVersion = 4`. New DDL in `app/lib/core/db/schema/financial_c.drift` (included by `AppSchema`); dump `drift_schema_v4.json`; step `from3To4` as a **frozen** statement list in `app/lib/core/db/migrations/v4_financial_c.dart` (rule 2a): (a) the table rebuilds of §6, (b) the v4 dump's CREATE statements for every new object, in dump order, without `IF NOT EXISTS` (a stray object of the same name fails the step and the opener restores the copy). A test derives both lists from the committed v3 and v4 dumps. No FTS options change (no new FTS table), so there is no option list.

**2. Wealth, prices, Zakah (§2.6).** Every INTEGER column: `typeof(x) = 'integer'` (NULL-safe where nullable). Money: the T-017 pattern (±(2^53−1), currency `GLOB '[A-Z][A-Z][A-Z]'`) plus the T-012 pair rule (below).
- `assets`: `type` enum as specified; `name` 1–60 characters, no control characters, no NUL; `currency` NULL or ISO form; `quantity_milli` NULL or 1..2^53−1; `karat IN (24,22,21,18)` and only for `gold`/`gold_coin`; `gold` needs quantity and karat; `principal_minor`, `manual_value_minor` ≥ 0 and need `currency` (pair rule); `rate_bp` 0–100 000, `payout` (`monthly`, `quarterly`, `semi_annual`, `annual`, `at_maturity`) and `maturity_date` only for `certificate`; `maturity_date`, `acquired_at` real ISO dates (`date(x) IS x`); `purchase_price_minor`/`purchase_currency` both NULL or both set, ≥ 0; `is_liability` 0/1. Index `ix_assets_live (type) WHERE archived_at IS NULL`.
- `price_quotes`: `symbol` 1–16 of `[A-Z0-9_]` starting with a letter (a form, not a closed set: a new backend symbol must not fail the whole sync apply, FR-SYNC-03); `price_minor` > 0; `per_unit` a slug 1–16 `[a-z0-9_]`; `source IN ('backend','manual')`.
- `fx_rates`: `base`/`quote` ISO form, `base <> quote`, `rate_e9` 1..2^53−1.
- `networth_snapshots`: `taken_on` real ISO date; `unit` = an ISO code or a gold symbol (`XAU…` form); `assets_minor`/`liabilities_minor` signed money (a computed history value is never refused; for a gold unit the value is milligrams, as `quantity_milli`).
- `zakah_ledger`: `asset_id` FK **without** cascade (deleting an asset that has Zakah history fails with `DB_CONSTRAINT_FOREIGN_KEY`; history is never deleted as a side effect) + `ix_zakah_asset`; `lot_start_hijri` `YYYY-MM-DD` with month 01–12 and day 01–30 (Hijri; not a Gregorian date, so `date()` can't check it); `due_on` a real (Gregorian, local) ISO date; `unit` as above; `0 ≤ paid_minor ≤ amount_minor`; status matches the amounts (`pending` ⇒ paid 0, `partial` ⇒ 0 < paid < amount, `paid` ⇒ paid = amount).

**3. Capture controls, review, templates (§2.7).**
- `ignore_rules`: `institution_code` in the accounts form (1–32 of `[A-Za-z0-9_]`, as checked by the registry), `last4` NULL or 2–4 ASCII digits (like `accounts.last4`; never last-4 alone, EC-59: institution is NOT NULL); `channel` enum. The spec's `UNIQUE (institution_code, last4, channel)` treats NULL `last4` as distinct, so a second institution-level rule would be allowed: **`ux_ignore_institution (institution_code, channel) WHERE last4 IS NULL`** (same fix as `ux_budgets_overall`).
- `capture_senders`: `sender` 1–128 characters, no controls/NUL; `channel IN ('sms','notification','shortcut_message')`; `confirmed_count ≥ 0`; `always_capture` 0/1. DAO `recordConfirmation` is one atomic upsert (`+1`), so two engines confirming at once count twice, never once.
- `custom_templates`: `sender` as above, `channel` as above, `template_json` a JSON object ≤ 64 KiB, `sample_hash` 64 lowercase hex; `ix_templates_sender (sender, channel)`.
- `review_items`: `kind` enum; FKs `ON DELETE CASCADE` as specified; `payload` NULL or a JSON object ≤ 64 KiB; `resolution` NULL or a slug 1–64 and only with `resolved_at`; `ix_review_open` as specified plus FK child indexes `ix_review_raw`, `ix_review_txn` (partial, NOT NULL).

**4. Settings, secure state, outbox, misc (§2.8).**
- `settings`: `key` 1–64 of `[a-z0-9_.]`; `value` ≤ 16 KiB, no NUL. `secure_state`: same key form; `value` must be a BLOB (`typeof = 'blob'`), 1 B–64 KiB. `SecureStateDao`: `read`, `write`, `delete`, and `compareAndSet(key, expected, next)` (one conditional statement; two actors → one winner) for the trusted-time state (T-144). Values are never in an exception or log (code-only errors).
- `outbox`: `kind` enum; `payload` JSON object ≤ 64 KiB; `attempts ≥ 0`; index `ix_outbox_kind (kind, created_at)`. DAO: enqueue, due-list, mark attempt, delete sent ids, delete by kind (EC-48).
- `voice_usage`: `month` a real `YYYY-MM` (`date(month || '-01') IS month || '-01'`); `count ≥ 0`. DAO `increment` (atomic upsert, returns the new count) and `incrementIfBelow(month, limit)` (one conditional upsert; 20 racing callers with limit 15 → exactly 15 wins).
- `undo_batches`: `description_key` an l10n key (1–64 of `[A-Za-z0-9_.]`); `before_json` valid JSON, ≤ 8 MiB; `ix_undo_created`. DAO: insert, byId, delete, purge older than a cutoff.
- `diag_log`: `level IN ('debug','info','warn','error')`; `code` 1–64 of `[A-Za-z0-9_.:-]` (no spaces, so no free text); `fields` NULL or a JSON object ≤ 2 KiB; `ix_diag_at`. DAO: append, recent, prune (older than / keep at most), clear. The allow-list of field values is T-021's.
- Free-text CHECKs in all new tables also refuse NUL: `instr(CAST(x AS BLOB), x'00') = 0` (`length()` stops at a NUL, T-018 n-4).

**5. T-012 money pairs (task follow-up).** Every `*_minor` column in the schema (v2–v4) gets a test-enforced audit: a CHECK with `typeof = 'integer'` and the ±(2^53−1) bound, and a named currency partner; where the partner is nullable, a CHECK makes the pair both NULL or both set (`original_*`, `purchase_*`) or "minor set ⇒ currency set" (`assets.principal_minor`/`manual_value_minor`, which share `assets.currency`). Where the partner is NOT NULL, a NULL minor means "unknown" (balances) and the rule holds by construction. The test walks `PRAGMA table_xinfo` of a fresh database, so a future `*_minor` column without these CHECKs fails it.

**6. FU-075 items taken.**
- **n-3/n-4 (T-018 review), as a rebuild in the v3 → v4 step:** `catalog_merchants`, `catalog_keywords`, `merchant_rules`, `recurring_items` are rebuilt (SQLite can't add a CHECK in place): `CREATE TABLE "<t>__v4"` (the v4 DDL), `INSERT INTO "<t>__v4" (cols) SELECT cols FROM <t>`, `DROP TABLE <t>`, `ALTER TABLE "<t>__v4" RENAME TO <t>`, then re-create the table's indexes from the v4 dump. Every INTEGER column of these tables gets `typeof = 'integer'`; `catalog_keywords.keyword_norm` and the `counterparty` rule value refuse NUL. FKs are off during the step (opener), children (`catalog_aliases`, `recurring_occurrences`) keep their FK text, and `PRAGMA foreign_key_check` runs before commit. Rowids/ids are copied, so `catalog_alias_fts` (on `catalog_aliases`, not rebuilt) stays consistent. **Data preservation:** columns copied by name, row counts compared inside the step (a mismatch aborts → restore). A row that breaks a new CHECK (a REAL `1.5` written outside the DAOs, which can't bind doubles) fails the step, and the opener restores the byte-identical v3 copy: nothing is coerced or dropped. **7. DAOs.** One plain class per table group in `app/lib/core/db/daos/` (the T-017 style: writes through `guardWrite`, reads with user/external text through `guardRead`, nothing logs, Money in/out via `money_columns.dart`): `AssetsDao` (+ `ZakahLedgerDao`), `PricesDao` (quotes, FX), `NetworthSnapshotsDao`, `CaptureControlsDao` (ignore rules, capture senders), `CustomTemplatesDao`, `ReviewItemsDao`, `SettingsDao`, `SecureStateDao`, `OutboxDao`, `VoiceUsageDao`, `UndoBatchesDao`, `DiagLogDao`. A test lists every table of a fresh database and fails if one has no DAO entry.

**8. Migration tests (how upgrade is proven).** `schema_v3_database.dart` builds a real populated v3 file (v1 dump + frozen v2 + frozen v3 steps + synthetic rows in every v3 table, incl. catalog merchants with aliases, rules, recurring items with occurrences, plus the v2 rows). Through `openAppDatabase` on an encrypted file: copy made and deleted; every v2/v3 row kept (row-by-row compare of the rebuilt tables before/after); live shape = fresh v4 = v4 dump; FK check clean; alias trigram search still finds the copied aliases; FK cascade from a rebuilt parent still works; new tables usable; `1.5` now refused in a rebuilt column. Failure: a v3 file holding `due_day = 1.5` (and one with a stray `assets` table) → `DB_MIGRATION_FAILED(restored)`, every file byte-identical, still v3. v1 → v4 and v2 → v4 run all steps (existing tests follow `appSchemaVersion`); FakeNext runs the real v3 → v4 first. The device suite's v3 → v4 case is not added (no new FTS/sqlite3mc feature in v4; the existing v1 → latest device test runs the step).

**Deviations from the design note.**
- §4/§6: the NUL rule is broader than written: every TEXT column other than ids, FKs, enums and dates (in new and rebuilt tables) refuses NUL, including currency/unit/key/slug forms, not only free text. The sweep test found the first gap (`recurring_items.currency`), which was then fixed. Exact-byte-length checks (`length(CAST(x AS BLOB))`) were dropped as a NUL guard: a GLOB that only forbids characters passes any prefix.
- §3: `ignore_rules.institution_code` is `[a-z0-9_]` 2–32 (OpenAPI `InstitutionCode`; the registry's codes are lowercase), not `[A-Za-z0-9_]` 1–32 as the note said.
- §6: the rebuilt tables also refuse NUL in `catalog_merchants.name_ar`, `name_en`, `logo_key` (previously unchecked) and in every `merchant_rules.match_value` kind.
- §7: `AssetsDao.insert` and `NetworthSnapshotsDao.upsertMoney` are `async`, so a `CurrencyMismatch` arrives as a Future error (no sync throw); `CaptureControlsDao.addIgnoreRule` returns false for an equal rule **or** a reused id (`ON CONFLICT DO NOTHING`).
- §8: the device suite gets no new v3 → v4 case (v4 adds no FTS/sqlite3mc feature); the existing device test "v1 → latest" runs the v3 → v4 step on device sqlite3mc. No `ci/T-019` push needed.

**Self-check (docs/workflow/self-check.md).**
