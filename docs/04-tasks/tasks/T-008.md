## Description
Measure whether a killed app processes an SMS within 10 s.

## Technical details
Minimal SmsReceiver + encrypted spool + expedited WorkManager starting a headless FlutterEngine (entrypoint ingestionMain) that logs completion; test on Samsung A-series and Xiaomi with battery optimisation on/off; measure p50/p95.

## Design note
(solution-architect, Opus, 2026-11-11. C4: crypto keys + SMS ingestion. Reviewers: challenge it. Deviations from `docs/03-technical` are marked **[doc change]** and need Lead sign-off before merge.)

**Goal and scope.** Prove (or disprove) FR-ING-A-01 "bank SMS → committed in the DB within 10 s with the app killed" on the real path: `SmsReceiver → Guard → encrypted spool → expedited WorkManager → headless FlutterEngine (ingestionMain) → parse → DB commit → ack`. Output: latency table per device and condition in ADR-005, and a yes/no on the battery-optimisation prompt. The spike is deliberately thin; T-038 (Guard), T-039 (spool + host API), T-040 (receiver) and T-041 (worker) productionise it. **Placement:** all Kotlin and manifest entries live in the `src/devSms/` source set (the `dev` × `sms` flavour combination), so no `staging*`/`prod*` artifact contains them; the Dart entrypoint is `app/lib/ingestion/ingestion_main.dart` (Dart has no flavours; without the native side it is never invoked). If the Lead prefers a throwaway branch instead, only ADR-005 and this note merge (Q5).

**1. Flavours and policy (ADR-004).** `RECEIVE_SMS`/`READ_SMS` and the receiver exist only in `*Sms` manifests; `*NoSms` keeps the `tools:node="remove"` list and also gets the `uses-permission-sdk-23 … remove` entries (T-003 F11). `src/sms/AndroidManifest.xml` gains `<uses-feature android:name="android.hardware.telephony" android:required="false"/>` (T-165 F6) and CI lints one `*Sms` variant. Play grants these permissions only via the Permissions Declaration Form under the "SMS-based money management" exception, which forbids exfiltrating non-financial SMS; the Guard-before-write design is what we show in that declaration.

**2. Receiver (`SpikeSmsReceiver`).** Manifest: `exported="true"`, `android:permission="android.permission.BROADCAST_SMS"` (only the telephony stack holds it, so other apps and `adb shell am broadcast` cannot spoof us), `directBootAware="false"`, action `android.provider.Telephony.SMS_RECEIVED`, default priority. `SMS_RECEIVED_ACTION` is one of the implicit broadcasts still allowed for manifest receivers. Never call `abortBroadcast()`; Android ignores it for this action since 4.4 anyway, and we are an observer only. `onReceive`: (a) stamp `rxWallMs`, `rxElapsedNs`; (b) `Telephony.Sms.Intents.getMessagesFromIntent`, group PDUs by originating address, concatenate in order (EC-09), read the subscription extra → `simSlot`; (c) `goAsync()` and hand off to one single-thread executor; (d) Guard → spool write → `enqueueUniqueWork` → `pendingResult.finish()` in a `finally`, with a hard 5 s budget (past it: abandon, `finish()`, count `SPOOL_TIMEOUT`). No engine, no parse, no DB in the receiver.

**3. Guard pre-filter.** Spike interface `CaptureGuard.decide(channel, source, body) → Keep(inst?, last4?) | Drop(reason)` running platform-channels §1.2. Config = `files/guard/guard.cfg.enc` decrypted with `SpoolKey` (AAD `zaghlol.guard.v1|cfg`; T-038 owns the writer), cached by mtime. Missing or malformed config → fail closed for unknown senders, keep only compiled-in senders. **Spike allowlist** is only synthetic test senders (`5550100` for `adb emu sms send`, plus the tester's second phone number set in a debug-only resource); real bank SMS on tester devices are dropped and never measured. Bodies over 4,000 chars (`maxParseBodyLength`) are dropped before any regex runs; patterns come from the linted registry export (`guard_export.dart`, T-033 regex safety).

**4. Spool.** Key: `app.zaghlol.platform.spool.SpoolKey.get()` only (FU-068: alias `zaghlol_spool_v1`, TEE AndroidKeyStore, never StrongBox, never `KeyGenerator` elsewhere). Dir `noBackupFilesDir/spool/` (excluded from every backup per T-165). Entry `<ulid>.bin` = `nonce(12) ‖ AES-GCM(payload) ‖ tag`, **AAD `zaghlol.spool.v1|entry|<ulid>`** so entries cannot be renamed or swapped. **[doc change]** payload is a versioned `DataOutputStream` record (`u8 v=1`, channel, source, `u32 len + UTF-8 body`, `i64 receivedAtMs`, `i32 simSlot|-1`, guardInst, guardLast4; spike adds `i64 rxElapsedNs`, `i32 bootCount`), not CBOR: same fields, no new dependency, same pattern as `ShareStore` meta. Write `.tmp` → `fd.sync()` → rename; `.tmp` older than 60 s is swept on every drain. Caps: 500 entries or 4 MiB; beyond, the new message is refused (diag `SPOOL_FULL`), never an old one evicted. **No spool-level dedupe:** the spool is at-least-once and the DB's unique `body_hash` (BR-ING-02) is the single dedupe authority (a hash in a file name would also be a body fingerprint). **Retention:** delete only on `ackSpool(ids)` after commit; no age purge (unlike `share/`). **Delete-only-on-proof** (as `ShareStore`): GCM tag failure, truncation or malformed record is retried 3× (100/300/900 ms) in that drain, then the entry is deleted with `SPOOL_DECRYPT_FAILED`; I/O or Keystore errors keep it. Lost/invalidated key → `KEY_INVALIDATED` mapping stays with T-039. **Drain claim:** `drainSpool` hands entries to one engine at a time (process-wide claim, released on ack, engine detach or 60 s), so the UI and headless engines never process the same entry concurrently.

**5. WorkManager.** `androidx.work:work-runtime-ktx:2.12.0` (stable 2026-09-23, minSdk 24 ≤ our 26; architecture §7 already lists WorkManager). `OneTimeWorkRequest<IngestionWorker>` (`CoroutineWorker`), `setExpedited(OutOfQuotaPolicy.RUN_AS_NON_EXPEDITED_WORK_REQUEST)`, unique name `zaghlol.ingest`, `ExistingWorkPolicy.APPEND_OR_REPLACE` (a message spooled while a run is finishing gets one follow-up run, not lost), **no constraints** (storage-not-low would defer exactly when the cap matters), exponential back-off 10 s. Worker loop: drain until the spool is empty or 60 s, then `success`; non-empty after timeout or `DB_MIGRATION_PENDING`/`DB_UNAVAILABLE` → `retry`. Android 12+: expedited jobs run via JobScheduler under App Standby quotas (active 30 min, working set 15, frequent/rare 10, restricted 5 per rolling 24 h; Android 16 also limits the active bucket); the worker **never calls `setForeground`** (background FGS starts throw on 12+). Android 8–11: expedited work falls back to a foreground service, so `getForegroundInfo()` returns a low-importance "capture" channel notification with localized `strings.xml` (en/ar) text (Q4). The spike records run time per job so quota use per day can be estimated.

**6. Headless engine.** On the main thread: `FlutterInjector.instance().flutterLoader()` `startInitialization` + `ensureInitializationCompleteAsync` (never blocking). If a UI engine is attached, do not start a second engine: call `CaptureEventsApi.onSpoolChanged` and let the worker wait until the claim clears (foreground path, target < 2 s). Else take a `FlutterEngineGroup` engine (process-wide holder; later engines in a group start faster and share memory) with `DartEntrypoint(bundlePath, "ingestionMain")`, `automaticallyRegisterPlugins = false`, and an **explicit allowlist**: `PathProviderPlugin` (DB directory; a test asserts both engines resolve the same path, FU-065 S-7), **`SecretStoreRegistration.register(messenger, appContext)` (FU-065)**, the spool host (`drainSpool`, `ackSpool`; every other `AndroidCaptureHostApi` method → `NOT_AVAILABLE`), and the spike-only `zaghlol/spike_metrics` `BasicMessageChannel` (not a contract). Dart: `@pragma('vm:entry-point') void ingestionMain()` (release builds tree-shake custom entrypoints without it) → `WidgetsFlutterBinding.ensureInitialized()`, `DartPluginRegistrant.ensureInitialized()`, `PlatformDispatcher.instance.onError` returns true after a code-only diag (uncaught errors otherwise print to logcat even in release), `ProviderContainer(overrides: [allowMigrationProvider.overrideWithValue(false)])`. If `zaghlol.db` does not exist, stop without opening (keep the spool; Q6). Open → `DB_MIGRATION_PENDING`, `DB_LEASE_*`, any failure → no ack, report `retry`. Load the registry once per engine (timed separately), `ParsingPipeline(registry).parse(ParseRequest(body, source, channel, receivedAt))` (T-033; a stub if T-033 has not merged), then one write transaction (spike: `INSERT OR REPLACE` of `db_meta` key `spike_last_ingest` = ULID + result type, no message content), **then** `ackSpool(ids)`. Ack is never sent before the commit returns; a crash between commit and ack re-delivers and the unique `body_hash` absorbs it. Engine is destroyed after drain + linger (0 s or 20 s, both measured) or on `onTrimMemory`.

**7. What is measured.** Native monotonic stamps (`elapsedRealtimeNanos`; Dart marks go over the metrics channel so one clock is used; runs with a changed `bootCount` are discarded): t0 receive, t1 spool synced, t2 enqueued, t3 `doWork` start, t4 Dart entry, t5 DB open, t6 drained, t7 parsed, t8 **commit** (primary metric = t8−t0), t9 acked. Paths: cold process, warm process/cold engine, warm engine (linger), foreground. Conditions per device: battery optimisation on/off, Doze (`dumpsys deviceidle force-idle`), standby bucket `rare`/`restricted` (`am set-standby-bucket`), burst of 5 within 2 s, OEM switches (Samsung "Sleeping/Deep sleeping apps"; Xiaomi Autostart and battery saver). ≥ 30 SMS per cell, ≥ 2 min apart for cold runs; p50/p95/max via `tools/spike/latency_report.dart` over `noBackupFilesDir/spike/metrics.csv` (ULID, path, stage deltas, flags; no sender, body or amount), pulled with `run-as` on the debuggable build. Battery: `dumpsys batterystats --reset`, 50 SMS over 2 h, per-app estimate extrapolated to 30 SMS/day against NFR-PERF-06 (< 1 %/day). **Decision rule for AC2:** the prompt is needed only if a device's default-settings p95 exceeds 10 s and the exemption brings it within 10 s; prefer the settings deep link over `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` (Q3). Force-stop is expected to block delivery until the next launch; it is recorded, not counted as a failure. The commit measured is one small row; ADR-005 notes that a real ingest transaction adds the T-017 insert/FTS cost.

**8. Logging and threats.** No `Log` call carries body, sender, last4, amount or exception messages; tags emit `ZG-SPK code=… ms=…` in debug only. Every host method catches all and returns `FlutterError(code, null, null)` (Pigeon's default `wrapError` puts `toString()` and the stack in `details`; validate codes as UPPER_SNAKE, FU-034). *Threats:* spoofed broadcast: `BROADCAST_SMS` permission on the receiver. Malicious app reading the spool: app-private dir, AES-GCM, non-exportable TEE key; WorkManager components are not exported. Spoofed SMS sender IDs / SMS flood: caps (refuse new), body length cap, linted regexes; the confirm/review flow and dedupe handle content. Storage exhaustion: caps above. Process death: before rename → lost (ms window; recovery is an inbox catch-up scan, Q7); after rename before enqueue → picked up by the next enqueue or by the UI engine draining at start; mid-worker → WorkManager reschedules; after commit before ack → dedupe. Pre-first-unlock SMS: not delivered to a non-direct-boot receiver (credential storage is locked anyway) → catch-up scan.

**9. Tests → ACs.** *JVM (Robolectric, `WorkManagerTestInitHelper`, software AES-GCM fake):* spool round-trip, AAD swap/rename → deleted after 3 attempts, truncation, transient cipher error keeps entry, caps refuse new, `.tmp` sweep, ack idempotent, ULID order, foreign file names ignored; receiver: multipart join, non-allowlisted sender and OTP write nothing (directory empty), `abortBroadcast` never set, `finish()` on every path including throws, unique work enqueued with the expedited policy; worker: success when empty, retry on timeout/migration-pending, `getForegroundInfo` uses string resources; **canary test**: body `ZG_CANARY_7731` through receiver → spool → worker with `ShadowLog`, zero hits in logs and in thrown messages; spool file bytes contain no canary. *Dart unit:* `ingestionMain` controller with fakes: order drain → parse → commit → ack; commit throws → no ack; `DB_MIGRATION_PENDING` → no ack, retry; missing DB → no open, no ack; uncaught error produces no print (zone `print` capture). *Merged-manifest checks (CI):* `devSms` has the receiver with `BROADCAST_SMS`; every `*NoSms` has neither receiver nor SMS permissions. *Instrumented/manual (emulator API 26, 30, 34, 36; Samsung A-series; Xiaomi/Redmi):* `adb emu sms send 5550100 "<synthetic>"` or a second phone, across the §7 matrix → AC1 table; battery-optimisation on/off → AC2; negative proofs: `adb shell am broadcast -a android.provider.Telephony.SMS_RECEIVED -n <pkg>/<receiver>` is denied and spools nothing, non-allowlisted sender leaves `spool/` empty (`run-as ls`), `logcat | grep ZG_CANARY` = 0, force-stop recorded. AC3 (DoD): analyze/format/tests as above; no UI beyond the notification strings (en/ar).

**Rejected.** Parsing inside the receiver (ADR-005 option 1; 10 s receiver limit, engine start in `goAsync`). `workmanager` pub plugin (no control over engine plugins or the expedited policy). Starting a second engine while the UI engine is alive (two writers, double drain). Spool-level hash dedupe (fingerprint leak, DB already dedupes). CBOR payload (dependency for 8 fields). Age-based spool purge (silent loss).

**Carried follow-ups:** T-003 F8, F11, AGP deprecation warnings; T-165 F6; FU-034; FU-042 (Pigeon stale check rejects outputs outside the three dirs); FU-065 (headless SecretStore registration, stable DB dir); FU-068 (SpoolKey only). FU-067/FU-070 are share-intake only: the spool shares `SpoolKey` and the delete-on-proof rule with `share/` but never its directory, purge or Guard bypass.
