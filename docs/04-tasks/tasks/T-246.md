## Design note (builder)

- **Domain** (`packages/zaghlol_domain/lib/salary/payday_detection.dart`, pure): `detectPayday(credits, currentPayday, typedByUser)` -> `PaydayDetection(day, apply)`. Steps: keep primary-currency credits (caller filters; the function also drops other currencies); first credit per calendar month; cap day 29-31 at 28 (A8); latest 3 months with a salary; the 3 days agree when max-min <= 2 and the earliest wins (A5). Fewer than 3 months: only the first salary seen counts when 1 month, or 2 agreeing months, and only applies when the payday was never set (A7). With 3 agreeing months: apply when never set; when auto/default payday, apply if it differs by more than 2 (no flapping); when typed by hand, apply only if all 3 months differ from it by more than 2 (A6).
- **Pattern memory** (`PaydayAutoState`, setting `payday_auto`, JSON): `autoDay` (last day the app set), `previous` (value before, null = never set), `bannerPending`, `suppressed` days (Undo). A payday is "typed" when it is configured and differs from `autoDay`, so the settings screen needs no change.
- **App**: `PaydayAutoService.run()` reads salary credits of the last 12 months from the DB (income direction, not internal, posted, not deleted, category `sys:income` - what the salary template and the "this is my salary" mark both give - or tied in `salary.state`), runs the rule, applies via `PaydayScheduleStore.setPayday` (EC-21), records state. It runs from a post-persist hook (income credits only) and the daily housekeeping job `payday_auto`. A Home banner shows once with "Undo" (restore previous value, suppress that day) and a close button. The old FR-ONB-10 payday card is no longer produced by `nextSetupSuggestion`. No schema change; `payday_suggestion` review kind stays.

## Scope (plan §6, assumptions A4–A10)
1. Pure domain function in `packages/zaghlol_domain/lib/salary/` : input = salary credits (date, currency) of the primary currency for the last 12 months, the current payday setting and whether the user typed it; output = detected payday (1–28) or none, and whether to apply it. Rules: first salary per calendar month; latest 3 months with a salary; same day ±2, earliest wins; 29–31 → 28; typed payday changed only when all 3 disagree; fewer than 3 months → apply only if payday never set. Salaries = transactions with the salary category / `salary` event / user-marked salary (whatever `salary_rules.dart` already treats as salary).
2. Run it after ingest of a salary credit and in the daily housekeeping job; apply through the existing payday setting so cycles recompute (EC-21: current cycle ends early). Record that the payday was auto-set.
3. One banner/notification in Egyptian colloquial + English: "خلّيت يوم القبض X لأن مرتبك بينزل يوم X — تراجع" with Undo restoring the previous value and suppressing the same auto change for that pattern.
4. Replace the old D-68 late-month suggestion (payday = 1 for day 29–31) and the `payday_suggestion` review item flow where it conflicts; keep the review kind in the schema (no migration needed for removal).
## Acceptance criteria
Property/unit tests for the domain rule (examples: salaries 24 Sep, 23 Oct, 24 Nov → 23; 25 + 5 in the same month → 25; 30 Oct, 31 Nov, 29 Dec → 28; typed 1 with 23/24/23 → 23; typed 1 with 23/1/24 → stays 1; two months only and never set → set); app test: salary SMS ingest flips the setting and shows the banner once; Undo restores; widget tests `ar`/`en`.

## Builder assumptions
- "Salary credit" = income-direction, non-internal posted row with category `sys:income` (salary template event and user mark both set it), or tied in `salary.state`. Other `sys:income` credits the user picks count too.
- Auto-set payday that differs by <= 2 days from the detected one is left alone (avoids flapping); typed paydays within 2 days of the pattern count as agreeing.
- Undo of a first-ever auto-set restores day 1 (the default, now an explicit value) and suppresses the pattern.
- Banner is a Home banner (no push notification).
