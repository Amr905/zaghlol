## What happens today (Lead reading of `main` @ 1d69f761)
- `packages/zaghlol_parsing/lib/ocr/receipt_parser.dart` reads a till receipt only when a **total label** (`total`, `grand total`, `amount due`, `net total`, `total amount`, `الاجمالي`, `اجمالي`, `المجموع`, `المطلوب`, `صافي المبلغ`) is followed **within 32 characters** by a number. Otherwise `genericNoAmount`.
- OCR engines (ML Kit Latin + Tesseract Arabic on Android, Vision on iOS) often emit an RTL receipt's amount **before** the label on the same line, **on the next line**, or as a **separate column block** (all labels, then all numbers). All three fail today.
- Common Egyptian pharmacy wording is missing: `صافي`, `الصافي`, `المستحق`, `المبلغ المستحق`, `المطلوب سداده`, `قيمة الفاتورة`, `الاجمالي النهائي`, `net`, `net amount`, `total price`, `total l.e`, `amount`. `L.E` / `LE` / `ج` are not currency markers.
- `scan_confirm_screen.dart` shows the same "couldn't find a payment" screen for `ScanFailed` (OCR failed / no text) and `ScanEmpty` (text but no total), so the PO can't tell which happened, and nothing read (merchant, date) is kept.

## Scope (Lead assumptions; PO asked to assume rather than block)
1. **Amount position:** for each total label, look (a) after it on the same line, (b) before it on the same line, (c) on the next 1–2 lines; prefer an amount with a currency marker or two decimals. Never take a number that is part of a date, time, phone, percentage, quantity column (`x2`, `qty`) or a 6+ digit code.
2. **Column layout fallback:** if labels and numbers come as separate blocks, map the total label's row index to the same row in the number block when the counts match; else go to 3.
3. **Last resort:** with no labelled amount, take the largest currency- or 2-decimal amount on the receipt that is not a date/phone/code, with lower confidence. The confirmation screen is always shown and nothing is auto-saved, so a wrong guess costs one edit.
4. **Labels/currency:** add the pharmacy words above (AR folded + EN), skip `subtotal`/`المجموع الفرعي`/`قبل الخصم`/`الضريبة`/`VAT`/`discount`/`خصم`/`paid`/`cash`/`change`/`المدفوع`/`الباقي` lines as the total; `L.E`, `LE`, `ج` → EGP.
5. **Screen:** separate copy for "couldn't read the text" (OCR failed or under ~10 letters/digits) vs "read it but no total": the second opens manual entry **prefilled** with the merchant and date found. Strings ar (Egyptian colloquial, `docs/02-design/06-voice-and-tone.md`) + en.
6. **Diagnostics (dev builds):** counts per scan outcome (`ocr_failed`, `no_text`, `no_total`, `found_label`, `found_fallback`) — never text.
7. **Fixtures:** ≥ 10 synthetic OCR-text receipts in `packages/zaghlol_parsing/test/ocr/` — pharmacy layouts (label-then-amount, amount-then-label, next-line, column blocks), Arabic-Indic digits, `L.E`, a subtotal+VAT+total receipt, a receipt with a phone number and a date near the total, and one with no total line. Generic names only (no real pharmacy chain or person names).

## Acceptance criteria
Each fixture gives the expected amount (minor units) or the expected "no total" outcome; existing OCR/template tests unchanged (InstaPay, Vodafone Cash, CIB screens still win over the generic reader); widget tests for both empty states in ar/en; `flutter analyze` clean; PO suite 12/12.
