## Scope
The widget (`app/lib/features/widgets_bridge/application/widget_bridge.dart` + Android/iOS widget code) shows EGP safe-to-spend and days to payday. Add one small hint line, e.g. «+ USD» / «+ USD, EUR» (ISO codes only, at most 2 then «+N»), when the Home model has currency cards (T-278 rule). Never a mixed sum, never a foreign amount. Hide-amounts rules still apply (the codes alone are fine when amounts are hidden; say so in the task file). Keep the payload contract documented in `docs/03-technical/` where the widget contract lives.

## Acceptance criteria
- Dart test of the payload (no cards → no hint; 1, 2, 3 currencies).
- Kotlin and Swift render the hint (compiled in CI only; keep the change small and mirror existing fields).

## Design note (builder)
The hint is built in Dart and appended to line two (`secondaryText` and each `secondaryTextByDay` entry, also on the "no budget" line), joined with " · ", so the pigeon schema, the encrypted store record and the Kotlin/Swift drawing code stay unchanged (no native compile risk; both platforms already draw line two with 2 lines). Hint = `+ USD`, `+ USD, EUR`, `+ USD, EUR +N` (ISO codes only, LRI/PDI isolates for RTL, `+N` in the user's digits). Source: `widgetOtherCurrenciesProvider` over `homeModelProvider.currencyCards` (T-278 rule). Contract note added in `docs/03-technical/platform-channels.md` section 5.

## Builder assumptions
- Hide-amounts: the codes stay visible (they carry no amount). While the app is locked the hint is omitted, since which currencies are held is financial information.
- The provider reads the Home model, so it follows the Home card filter (codes only; low risk).
- No ARB keys: the hint has no words.
- Kotlin/Swift unchanged: nothing native compiles differently; native renders the longer line two as before.
