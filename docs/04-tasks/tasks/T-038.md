## Description

## Technical details
GuardConfig parse: bundled base part (asset) + encrypted user part (`noBackupFilesDir/guard/guard.user.enc`); the bundled base part replaces the old "compiled-in fallback sender list" (T-035 split, [doc change] 2026-11-11); algorithm per platform-channels §1.2; consumes the shared golden file in place in JUnit (JVM) and in an instrumented test (device ICU regex).

## Design note
(solution-architect, Opus, 2026-11-11. C4: SMS/notification ingestion. Reviewers: challenge it. Carries FU-082 (production part), FU-097 items for T-038 (foldKeyLines, fold vectors, emoji/UTF-16 and step-0 cases, L-1, L-2 AC), T-035 I-6. **Goal.** A Kotlin port of `packages/zaghlol_parsing/lib/guard/` that passes `test/fixtures/guard/golden.json` byte-for-byte as the Dart Guard does, plus the native reader/writer of the two-part config. Pure Kotlin except two thin Android seams (asset, Keystore), so almost everything runs on the JVM.

**1. Files** (all new, `app/android/app/src/main/kotlin/app/zaghlol/platform/guard/`, main source set: the notification listener T-043 is in every flavour). `TextFold.kt` (`foldKey`, `foldKeyLines`), `StrictJson.kt`, `GuardConfig.kt` (parse + compile → immutable `GuardConfig`, `mode`), `CaptureGuard.kt` (`decide`, `guardLast4`), `SenderRateLimiter.kt`, `GuardTypes.kt` (wire names identical to Dart `GuardDropReason.wire` / `GuardKeepKind`), `GuardPolicy.kt` (mirrors `guard_policy.dart`: `USER_CONFIG_FAILURE = KEEP_WITH_BASE`, `SHORTCUT_MESSAGE_USES_SMS_TOGGLE = true`, each KDoc pointing at the PO question), `GuardUserConfigStore.kt` (encrypted user file), `GuardRuntime.kt` (process-wide snapshot), `BaseConfigSource.kt` (`AssetManager` reader of `flutter_assets/assets/guard/guard_base.json`, ≤ 200 KB read bounded). T-038 does **not** touch `platform/capture/`, `platform/spool/`, `capture_api.dart` or `src/devSms` (owned by T-039 / T-041, see T-039 §10).

**2. Port rules** (each pinned by golden or a named test).
- `foldKey`/`foldKeyLines`: loop over `Char` (UTF-16 code units) exactly as `text_normalizer.dart` `_transform`; tables copied from it (whitespace incl. U+0009–000D, U+0085, U+00A0, U+2009, U+202F, U+2028/2029; line breaks U+000A–000D, U+0085, U+2028/2029; invisible marks; tatweel/harakat; digits U+0660–0669, U+06F0–06F9, `٫`→`.`, `٬`→`,`; alef/ya/ta). Lowercase only `'A'..'Z'` by `+32`; never `lowercase()`, `Normalizer`, `Locale`. One pass producing `lines`, `key` = `lines.replace('\n', ' ')` (the identity the Dart fuzz test proves). Trim is on the folded result, so neither form ends in `\n` (matters: Java `$` also matches before a final line terminator, Dart `$` does not; test asserts no trailing `\n` for every golden `fold`/`cases` body).
- Lengths: `body.length > 4000` / `source.length > 256` (Kotlin `String.length` = UTF-16 units) before any fold or regex; step order exactly as §1.2 incl. T-035 deviation 2 (`config_invalid` first).
- Regex: `Regex(p)` (no options), `containsMatchIn` for drop/hints/sender regex, `findAll` for last4 (per pattern the first match whose group 1 is exactly 4 ASCII `0-9`, then the next pattern; T-035 deviation 4). Never `matches()`, never `RegexOption.IGNORE_CASE`. Global drop on `lines`, everything else on `key`. Sender regex on `foldKey(source)`; `notification` source only `trim()` (Kotlin `trim()` trims `Char.isWhitespace`; Dart `trim()` trims a different set: port Dart's set explicitly, golden `nf.*` source cases decide).
- `decide` is total: `catch (Throwable)` → `Drop(config_invalid)` (Dart parity) except `VirtualMachineError` other than `StackOverflowError` (OOM is rethrown). The receiver path (T-040) runs it on its own thread; JVM `java.util.regex` recurses and could overflow on a pathological pattern, ICU (device) does not: the 4,000-char adversarial golden bodies run in the **instrumented** suite too.
- Rate limiter: a line-for-line port of `sender_rate_limiter.dart` (sliding 60 s, boundary comparison exactly as Dart, LRU 64 keys, same key), monotonic clock injected (`SystemClock.elapsedRealtime` in prod), `@Synchronized` (receiver and listener threads may share it; Dart's is single-owner). In memory only (never persisted: would write sender ids).
- Results: `Keep(kind, inst, last4)` and `Drop(reason)`; `toString()` prints kind/reason only, as in Dart (never last4).

**3. Config reader** (`GuardConfig.parse(base: ByteArray, user: ByteArray?, userUnreadable: Boolean)`). Same schema, caps and error codes as `guard_config.dart` (`GuardConfigErrorCode` names; size check before decode; strict UTF-8 via `CharsetDecoder` REPORT; unknown key, wrong type, empty string, > 256 chars, pattern > 600, list > 5,000, regex compile failure are errors; user ≤ 64 KB, ≤ 1,000 ignore, ≤ 200 senders; rule without `inst` is an error). JSON: own `StrictJson` (RFC 8259, ~150 lines, depth ≤ 16, no dependency; `org.json` is lenient (single quotes, unquoted names) and is a stub in JVM tests). Parity with Dart `jsonDecode`: duplicate key = last wins; a number with `.`/`e` is not an int (`"v": 4.0` → `wrongType`). Errors carry code + JSON path, never a value (`GuardConfigException(code, path)`, `message` = `"$code at $path"`).

**4. Modes and failure handling** (T-035 Q1 provisional default `KEEP_WITH_BASE`).

| Situation | Mode | Native behaviour |
|---|---|---|
| base asset missing, unreadable, > 200 KB, invalid, old `v` | `invalid` | every message `config_invalid` (build defect); retried on the next load attempt (not cached, so a transient `AssetManager` error heals) |
| user file absent | `baseOnly` | normal (fresh install) |
| user file: GCM tag failure, malformed, unknown `v`, rule without `inst` | `baseOnly`, `userState = UNREADABLE` | cached until the next successful `writeUser`; the file is **kept** (Dart rewrites it on every start, T-047); state surfaced to Dart through T-039's `getSpoolStatus().guardState` |
| user file: I/O or Keystore error (not proof) | `baseOnly` for this message | not cached; next message retries |
| lost spool key (SpoolKey recreated it) | tag failure → row 3 | T-039 reports `keyInvalidated`, T-047 rewrites |

**5. User part writer** (`GuardRuntime.writeUser(json: ByteArray)`, called by the host's `writeGuardConfig`, T-039 §6). Under one process lock: size ≤ 64 KB, parse with the §3 reader (invalid → throw `GuardConfigWriteException(CONFIG_INVALID)`, old file and snapshot unchanged) → AES-256-GCM with `SpoolKey.get()` (never `KeyGenerator`; FU-068), output `nonce(12) ‖ ct ‖ tag(16)`, **AAD `zaghlol.guard.v1|user`** → `noBackupFilesDir/guard/guard.user.enc.tmp`, `fd.sync()`, atomic rename, best-effort directory fsync (`Os.fsync`) → publish the new immutable snapshot (`AtomicReference`). Keystore/I/O failure → `GuardConfigWriteException(IO_ERROR)`, tmp deleted, old file kept. `finally { json.fill(0) }` and the decrypted plaintext zeroed after parse. Its own 25-line cipher (`GuardUserCipher` seam + Keystore impl) so it does not import T-039 classes (parallel build); unify with the spool cipher in a follow-up. A `.tmp` left by a crash is ignored by the reader and overwritten by the next write.
- **[doc change] L-1:** path is `noBackupFilesDir/guard/guard.user.enc` (platform-channels §1.1 said `files/guard/…`). Test asserts the resolved path is under `context.noBackupFilesDir` and never under `filesDir`/`cacheDir`.
- **I-6 (generation counter in AAD): rejected.** Replaying an older user file needs write access to the app sandbox (root), which defeats every other control; T-047 rewrites the file on every app start, which bounds a rollback anyway. Recorded in ADR-005 *Threats*.

**6. Runtime and concurrency.** `GuardRuntime` is one per process (held by the capture runtime T-039/T-040 wire): `current(): GuardSnapshot` (config + mode + userState; lazy first load: base asset + user decrypt, ≤ 20 ms parse/compile target plus one Keystore op), `writeUser()`, `state()`. Readers take the snapshot reference once per message (no lock on the hot path); `writeUser` and the first load are serialized by one lock; a message decided during a write uses the old or the new rules, never a mix. All capture components run in the default process (same assumption as `SpoolKey`).

**Deviations from the design note**
1. **`last4`: first match per pattern, not `findAll`** (note §2). The Dart code (`guardLast4`: `p.firstMatch`, then the next pattern) and platform-channels §1.2 step 4 say "first match"; the note's "first match whose group 1 is exactly 4 digits" would differ only for a pattern whose group 1 can be other than four digits, which the portable-regex lint (`[0-9]{4}`, one group) already excludes. Followed the Dart code (parity is the goal), pinned by `last4UsesTheFirstMatchOfEachPatternOnly`.
2. **`GuardConfig.parse(base, user, userUnreadable)`** returns `GuardConfigLoad` with `userFailed` (= Dart `userError != null`, or the file failed authentication); a separate `validateUser` is the writer's check. Same modes as Dart.
3. **Dart's `Utf8Decoder` drops one leading BOM** (probed); Java's does not, so the reader drops one leading U+FEFF after decoding (a second BOM is `invalidJson`, like Dart).
4. **Duplicate package quirk mirrored**: in Dart `packages.putIfAbsent(key, () => _inst(o, 'inst'))` never reads `inst` for a duplicate package, so `finish()` fails `unknownKey` and the whole base is `invalid` (probed). Kotlin does the same for parity (`duplicatePackageMakesTheBaseInvalidLikeDart`). See open question 1.
5. `GuardRuntime.decide()` (Guard + per-process `SenderRateLimiter` with the injected monotonic clock) was added for T-040's convenience; `current()`/`state()`/`writeUser()` are as in §6. Instrumented timing goes to an instrumentation status value, not to logcat.
6. The adversarial golden set covers four more shapes than the note listed (`otp\n`, `رمز التحقق\n`, `1 `, `, 1234 `).

## Builder self-check (docs/workflow/self-check.md)
1. **Never destroy data on doubt** — applies. The store never deletes the user file; an authentication failure is reported (`UNREADABLE`) and the file kept; I/O and Keystore errors are `Transient` (not cached, not proof); `readBounded` distinguishes "absent" (`NoSuchFileException`) from any other error. Write order: validate → encrypt → tmp + fsync → atomic rename → dir fsync; any failure leaves the old file byte-identical and removes the tmp (fault-injection tests at each step). Negative proof: deleting on tag failure → red.
2. **Concurrency** — applies. Immutable `GuardSnapshot` swapped through an `AtomicReference`; first load and `writeUser` under one lock; `SenderRateLimiter` `@Synchronized`. Two-actor tests: 4 readers vs 2 writers (no mixed rules, no error, no tmp left), 8 threads on one limiter budget. Single default process assumed (as `SpoolKey`).
3. **Untrusted input** — applies. Body ≤ 4,000 and source ≤ 256 UTF-16 units before any fold or regex; base ≤ 200 KB (asset read bounded at 200 KB + 1), user ≤ 64 KB (file ≤ 64 KB + 28) before decoding; strict UTF-8 (`CharsetDecoder` REPORT); strict JSON with depth ≤ 16; unknown keys, types, empty/over-long values, list counts, pattern length, regex compile all checked; Unicode cases pinned by golden (`fold.class.*`, emoji, Dart trim set); fuzz never throws; `decide` catches `StackOverflowError`; errors never echo input.
4. **Fail closed** — applies. Invalid or missing base → every message `config_invalid`; unknown channel → drop; any exception in `decide` → drop; an over-size or malformed user part is rejected before writing.
5. **Secrets and logs** — applies.
