## Scope
1. **Pure domain** (reuse/extend approx_view, integer math only, no `double`): "≈ money in this month in EGP" = EGP money in + for each other currency: the part already exchanged to EGP is **not** added again (its EGP is already in EGP money in); the part still held (money in − exchanged out, floored at 0) × the daily rate. Rate order: (1) the bank's implied rate (`impliedRateE9`) for exchanged money, (2) the daily feed for the rest. **Any currency without a rate → no line** (never a partial total). Rate older than 24 h → "old rate" flag.
2. **Widget `HomeApproxLine`** in `app/lib/features/home/presentation/home_approx_line.dart` + provider: «≈ {amount} دخلك كله تقريباً» and the rate note under it («سعر البنك + سعر {date}» / «سعر قديم»). Always shows "≈" and the word «تقريبي» to screen readers. Tap → sheet listing each currency, its amount, the rate used and where it came from (bank / daily feed + date), with the plan's §6 body text. Hidden when the setting is off or a rate is missing. Do **not** edit `home_screen.dart`; the Lead plugs it into T-278's `homeApproxSlotBuilder` at merge.
3. **Q2 assumption:** the first time a second currency has activity, the ≈ setting turns on once (persisted flag so it never re-enables after the user turns it off) and Captain Zaghlol shows `mascot.fx.firstForeign`-style line with a «اقفلها» link that turns the setting off. EGP-only users never see it.
4. The Money tab ≈ net worth keeps working and uses the same rate order (bank rate first only where it applies; otherwise unchanged).
5. Strings ar (Egyptian) + en (plan §6 `home.approx.*`).

## Acceptance criteria
- PO story numbers (plan §2 step 5): 29,700 + 400 × 49.60 = **≈ 49,540** EGP, computed in minor units; KWD (3) and JPY (0) exponents tested.

- ≤ 3 negative proofs: never a partial total; never an exchanged amount counted twice; never shown without "≈".
- Widget test ar/en for the line and the sheet; goldens through the app-regen workflow.
