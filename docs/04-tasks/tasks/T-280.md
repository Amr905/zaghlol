## Scope
1. **Pure domain** (reuse/extend approx_view, integer math only, no `double`): "≈ money in this month in EGP" = EGP money in + for each other currency: the part already exchanged to EGP is **not** added again (its EGP is already in EGP money in); the part still held (money in − exchanged out, floored at 0) × the daily rate. Rate order: (1) the bank's implied rate (`impliedRateE9`) for exchanged money, (2) the daily feed for the rest. **Any currency without a rate → no line** (never a partial total). Rate older than 24 h → "old rate" flag.
2. **Widget `HomeApproxLine`** in `app/lib/features/home/presentation/home_approx_line.dart` + provider: «≈ {amount} دخلك كله تقريباً» and the rate note under it («سعر البنك + سعر {date}» / «سعر قديم»). Always shows "≈" and the word «تقريبي» to screen readers. Tap → sheet listing each currency, its amount, the rate used and where it came from (bank / daily feed + date), with the plan's §6 body text. Hidden when the setting is off or a rate is missing. Do **not** edit `home_screen.dart`; the Lead plugs it into T-278's `homeApproxSlotBuilder` at merge.
3. **Q2 assumption:** the first time a second currency has activity, the ≈ setting turns on once (persisted flag so it never re-enables after the user turns it off) and Captain Zaghlol shows `mascot.fx.firstForeign`-style line with a «اقفلها» link that turns the setting off. EGP-only users never see it.
4. The Money tab ≈ net worth keeps working and uses the same rate order (bank rate first only where it applies; otherwise unchanged).
5. Strings ar (Egyptian) + en (plan §6 `home.approx.*`).

## Design note (builder)
- **Domain** `app/lib/features/wealth/domain/income_approx.dart` (pure, integer only): `buildIncomeApprox(target, inputs, rates, nowMs)`. Total = target held part `max(0, moneyIn - exchangedOut)` + for every other currency `held = max(0, moneyIn - exchangedOut)` converted once with `FxTable.convertApprox` (daily feed, one half-even rounding per currency). The exchanged part is never converted again, so it cannot be counted twice. Any currency with `held > 0` and no rate (or an overflow) gives `IncomeApproxNone`: never a partial total. A target-only user gets none. The bank rate (`impliedRateE9`) is carried only as display info per row (it explains the exchanged part in the sheet); it needs no math because that EGP is already in `moneyIn`.
- **Provider** `home/application/home_approx_providers.dart`: reads the current cycle's totals for all cards (no card filter), the setting, the target and the stored rates. The bank rate is attached to a row only when exactly one foreign currency has exchange activity (otherwise it cannot be attributed, so it is left out). Q2: `homeApproxAutoOnProvider` turns the setting on once when two or more currencies have activity, guarded by the persisted `approx_view.auto_on_done` flag, and raises `approx_view.first_foreign_notice` for the Captain's line.
- **Widget** `home/presentation/home_approx_line.dart`: `HomeApproxLine` (notice + line, tap opens the sheet). Hidden for setting off / no line. Screen readers read "تقريبي" first.
- **Money tab** (item 4): unchanged. It sums per-currency net worth with the daily rate only; the bank rate does not apply to balances.

## Builder assumptions
- The line's target currency is the existing `approx_view.target` setting (default EGP), not hard-coded EGP.
- The line counts the current cycle across all cards (the Home card filter does not change it).
- "Activity" for the Q2 trigger = a non-zero money in, spending or exchanged out in the current cycle, in two or more currencies.
- The notice has two actions: «اقفلها» (turns the ≈ setting off, notice gone) and «تمام» (dismiss only). The notice is also gone once the setting is off.
- The rate note when only the daily feed was used reads «سعر {date}», and when only the bank rate was used «سعر البنك» (the plan has only the combined text).
