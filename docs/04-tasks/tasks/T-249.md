## Design note (builder)
Safety property: nothing is marked paid or closed on doubt.
- FU-301: `_applyTo` also writes `due_day` of the reminder item (the card's day after the notice rule), so `syncCardDues` sees no change.
- FU-302: `CardDues.onPayment` runs in one drift transaction (a savepoint inside ingestion): the counted marker and the reminder update commit together or not at all; the hook still swallows the error, so the transaction row is kept.
- FU-304: `CardDue.nothingDue` = every amount the notice carries is zero and it carries at least one; `isPaid` is true then (card shows the paid line, payments are not counted). An existing reminder is moved to the next cycle (amount 0, no payment counted) only when it points at exactly that due date; none is created.
- FU-303: `card_due_line_golden_test.dart` (due, partial, paid x ar/en x light/dark); PNGs from app-regen.

## Builder assumptions
- A zero total with a non-zero minimum (or the reverse) is not "nothing due" (doubt).
- A reminder pointing at an earlier date than a zero statement stays (an older unpaid due is not closed).
- The parser drops zero amounts today, so a real zero SMS stores no amounts; the rule is tested at the dues layer.

## Scope
1. **FU-301:** when a newer notice moves the card's `statement_due_day`, update the reminder item's `due_day` in the same write, so the next `syncCardDues` does not move the date back. Test: notice moves due day → sync → date unchanged.
2. **FU-302:** the payment hook must not leave "counted" in settings while the reminder update failed: do both writes in one transaction (or write the reminder first and the counted marker last), and on failure leave neither. Test with an injected failure.
3. **FU-304:** a statement with zero total and zero minimum is "nothing due": no reminder (or the existing one is closed), card shows the paid/nothing-due line, never "Due EGP 0.00". Test.
4. **FU-303:** add the due-line states (due, partial, paid) to the card detail goldens in `ar`/`en`, light/dark; generate them via the app-regen workflow (`[regen-goldens]` commit on the task branch, see `.github/workflows/README.md`), not locally (local fonts differ).

## Acceptance criteria
Tests for 1–3 fail on the old code; goldens committed by app-regen; `flutter analyze` clean.
