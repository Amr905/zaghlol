## Description
`releaseResponseKeys` and `releaseEntitlementKeys` are empty, so a release build verifies no sync response and grants no Gold (fail-closed until T-140 creates the production keys).

## Acceptance criteria
1. The production response-signing and entitlement public JWKs are pinned for the `prod` flavor; staging keys for `staging`; the dev key stays refused in release.
2. A CI check fails any `prod` release build while either list is empty.
3. A release build on a device syncs the catalog and receives a signed entitlement from staging.
4. Key rotation path documented (two keys pinned during overlap).
