## Description
- `LlmConsentStore`: `ask.llm_consent` and `cat.llm_consent` = `{provider, v, at}` (encrypted); `needsConsent(feature, activeProvider, v)`; clear on switch-off and "Delete everything".
- `LlmQuotaSnapshot`: `ask.llm_quota` / `cat.llm_quota` = last `{limit, remaining, resetsAt}`; unknown before first contact or after `resetsAt`; `ask.llm_paused_until_sync`.
- `LlmAttestation`: JCS + SHA-256 binding per feature prefix; platform proof through T-341's channel; `dev` HMAC proof only in debug builds with a key from `--dart-define`.
- `LlmGatewayClient`: `POST /v1/ask/plan` and `/v1/categorise` with the existing install token and `Zaghlol-App` headers, ULID `requestId`, 12 s timeout, cancellation for Stop, problem bodies mapped to typed errors (quota extension, `providerId`), quota snapshot updated from every reply.

## Acceptance criteria
1. **Negative proof 1:** binding vectors (ask and cat) reproduced byte-exactly by the Dart code.
2. **Negative proof 2:** in a release-mode build configuration the dev proof path is unreachable (`kReleaseMode` guard throws; test via a build-mode seam) and no dev key is bundled.
3. Error mapping test per row of the §4.1 table (403/409/503/422/429/502/400) and timeout at 12 s; cancellation aborts the request.
4. The client never logs request or response bodies (log capture with a marker question).
5. Consent and quota stores encrypted; cleared by "Delete everything"; provider or version change → `needsConsent` true.

## Notes for the builder
- Shared by both features; no Ask- or categorise-specific logic here.

## Design note (builder, 2026-11-26; written before the code)
**Files.** `app/lib/core/llm/`: `llm_feature.dart` (the two features: settings prefix `ask`/`cat`, flag, binding prefixes), `llm_consent.dart`, `llm_quota_snapshot.dart`, `llm_attestation.dart`, `llm_gateway_client.dart`. Small additions in `core/backend/` (no new path to the network): `BackendClient.askPlan`/`categorise` (generated DTOs only, as every other call), `BackendFailure.llmQuota`/`providerId` (the problem extensions, read only for `LLM_QUOTA_EXHAUSTED`/`LLM_CONSENT_REQUIRED`), and an `AbortSignal` on `BackendRequest` that the client races and the `dart:io` transport turns into `HttpClientRequest.abort()`, new kinds `TransportFailureKind.cancelled`/`BackendFailureKind.cancelled`. Not touched: `core/config`, the sync request/orchestrator, T-342's `features/ask/application/plan_executor.dart`.

**Stores (encrypted).** Both live in the `settings` table of the SQLCipher DB through `SettingsRepository` (so they are in the encrypted backup like every setting and go with the DB on "Delete everything"). Keys: `ask.llm_consent`, `cat.llm_consent` = JSON `{provider, v, at}` (at = UTC ms); `ask.llm_quota`, `cat.llm_quota` = `{limit, remaining, resetsAt}`; `ask.llm_paused_until_sync`, `cat.llm_paused_until_sync` (bool; cat follows T-358 "503 pauses until next sync"). `needsConsent(feature, activeProvider, v)` is true when nothing is stored, the provider or `v` differ, the active provider is empty/not a wire id, or the stored text doesn't parse (fail closed). Quota: unknown (null) before first contact, after `resetsAt`, or on unreadable text; `exhausted` = known and `remaining == 0`.

**Gate (fail closed, before any I/O, in this order):** flag fresh ON (`FlagsService.isOn`, stale/never synced = OFF) → not paused → consent matches the caller's active terms → local quota snapshot not exhausted. Any refusal throws `LlmBlocked(reason)`; no install registration, no attestation, no request. The gate is repeated in T-343/T-358 for UX; this one is the backstop.

**What is sent.** Ask: `{planVersion:1, requestId, q, lang, consent{provider,v}, attestation}` with `q = MaskResult.sentText` (the gateway takes the `MaskResult`, never raw text); categorise: `{v:1, requestId, lang, merchants, consent, attestation}`. `requestId` is a ULID from the client's CSPRNG (the `IdempotencyKey` generator). Headers come from the existing operation table (install token, `Zaghlol-Install`, `Zaghlol-App`, optional account token). Nothing else.

**Binding.** `bodyHash = SHA-256(prefix ‖ 00 ‖ installId ‖ 00 ‖ JCS(body − attestation))`, using the existing RFC 8785 `jcs.dart` and strict JSON parser of the restore binding (lone surrogates and duplicates refused → nothing sent). Hash input is the generated DTO's `toJson()` without `attestation`; after the proof is added the final request is re-hashed and must match (else nothing is sent). Android: `attest(bodyHash)` → Play Integrity standard request (`requestHash = b64u(bodyHash)` natively); iOS: `attest(clientDataHash = SHA-256(clientDataPrefix ‖ 00 ‖ bodyHash), forceNewKey)` → `{keyId, assertion, attestationObject?}` (T-341 note). A proof of the wrong type for the platform fails closed. On `422 DEVICE_ATTESTATION_FAILED` the gateway does **not** retry by itself; it returns `LlmAttestationFailed` and the caller's one "Try again" passes `forceNewKey` on iOS only if the previous proof had no `attestationObject`.

**Dev proof (debug only).** `{"type":"dev","proof": b64u-nopad(HMAC-SHA256(key, bodyHash))}`; key from `--dart-define=ZAGHLOL_LLM_DEV_KEY=…` read through `const kReleaseMode ? '' : String.fromEnvironment(…)`, so a release or profile build has no key constant. `DevLlmProver` takes a `BuildMode` seam (default from `kDebugMode`/`kReleaseMode`); any mode but debug throws `StateError` at construction and at `prove`. The provider chooses the dev prover only in debug with a non-empty key, else the platform prover. The backend's Fake mode format is fixed here: unpadded base64url of the 32-byte HMAC (43 chars, fits the OpenAPI pattern).

**Timeout and Stop.** 12 s from just before attestation to the reply (FR-LLM-51); on expiry or Stop the gateway aborts the `AbortSignal` (the transport aborts the socket) and throws `LlmTimeout`/`LlmCancelled`. A reply that arrives after Stop is dropped (no snapshot update). Backend decides counting.

**Error mapping (§4.1).** 403 `LLM_QUOTA_EXHAUSTED` → `LlmQuotaExhausted(snapshot)` and snapshot stored; 409 `LLM_CONSENT_REQUIRED` → consent for that feature cleared, `LlmConsentRequired(providerId)`; 503 `LLM_SERVICE_PAUSED` → pause stored, `LlmServicePaused`; 422 → `LlmAttestationFailed`; 429 → `LlmRateLimited(retryAfter)`; 502/503 `UPSTREAM_UNAVAILABLE`, other 5xx, install reset → `LlmUpstreamUnavailable`; 400 → `LlmRequestRejected` (bug); offline → `LlmOffline`; malformed 2xx → `LlmUpstreamUnavailable`. Local attestation failure → `LlmAttestationUnavailable(failure)`. Every error is code-only. Every 200 updates the quota snapshot.

**Logging.** The gateway has no logger; BackendClient logs codes + HTTP status only. Test: a marker question through success, every error and timeout with `debugPrint`/`print`/DiagLogger captured, marker absent; errors' `toString` checked too.

**Clearing the pause on the next sync** needs a hook in the sync orchestrator, which a parallel fix agent is changing: `LlmQuotaStore.resumeAll()` is provided and the call is a follow-up for T-343 (reported).
