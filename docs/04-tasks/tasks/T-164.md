## Implementation notes (T-164 builder)
- Engine: `packages/zaghlol_parsing/lib/custom/custom_template.dart` (`buildCustomTemplate`, `CustomTemplateSpec` incl. untrusted `fromJson`, `testCustomTemplate`, `tokenizeSample`, `parseWithCustomTemplate`); `Registry.ofInstitutions` / `Registry.withExtra` added to the registry.
- Safety: user never writes a regex; generated shapes are bounded (`{1,60}`, `{0,N}?` <= 300, no unbounded wildcards), length-capped (600), run through `backtrackingProblems`, and must parse their own sample. Stored JSON is re-linted on load.
- App: `features/capture/application/template_builder.dart`, `data/drift_template_builder_store.dart`, `presentation/template_builder_screen.dart` (S-65). Gold gate `GoldCapability.customSmsRegex` via `GoldGate`/`gateOrPaywall` on `entitlementStateProvider`.
- Only the SHA-256 of the folded sample is stored (`sample_hash`); the Guard config follows from the `custom_templates` table watch (T-047).
- Missing l10n keys: none (all `templatesBuilder*` keys already in the ARBs on this branch).
- Not done: (1) pushing `onOpenTemplates` of `CaptureSettingsScreen` to `TemplateBuilderScreen` (router owner); (2) feeding saved templates into the ingestion pipelines (`ParsingPipeline` is built once per run from a static registry in `ingestion_runner.dart` and `capture_providers.dart`; use `Registry.withExtra` with `CustomTemplateSpec.fromJson(row).toInstitution(row.id)`), and the T-076 re-parse hook (`customTemplateSavedHookProvider`, default no-op). Built-in senders win over a custom template for the same sender.
