## Description
On-device OCR on iPhone.

## Technical details
VNRecognizeTextRequest accurate; runtime language support; same result shape.

## Design note (sprint: written by the implementer)
- Pigeon `OcrHostApi` filled in per platform-channels section 4 (`recognize`, `supportedLanguages`, `OcrResult`/`OcrLine`); box origin fixed to top-left for both platforms.
- Swift: `OcrHost` over three seams (`TextRecognizing` = Vision rev 3 `.accurate`, `OcrImageSource` = AES-GCM spool file, `SpoolFileKeyProvider`) so XCTest can fake Vision. Minimum iOS 17 (ADR-019); revision 3 is the one that can list Arabic, the list is read at runtime.
- Languages: requested codes are kept only if Vision lists them; none listed -> English; English unlisted -> engine default.
- Privacy: no logging, code-only errors, decrypted bytes zeroed after use, encrypted file deleted in `defer` (kept only for NOT_AVAILABLE), paths outside the app container are rejected and never deleted.
- Dart: `OcrEngine` port (`lib/core/ocr/ocr_port.dart`) shared with the deferred Android host (T-159); `PigeonOcrEngine` adapter.
- Open: the iOS spool file key and file format (`nonce||ct||tag`, AAD `zaghlol.spool.v1|file|<name>`) are assumed to match the Android spool; `UnprovisionedSpoolKeyProvider` returns NOT_AVAILABLE until the Share Extension task provisions the key.
