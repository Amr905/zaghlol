## Description
Fast, correct aggregates per currency, card and period.

## Technical details
SQL aggregations for charts 1–12 (cash flow, donut, burn curve, 50/30/20 via buckets, day/hour pattern, top merchants, month vs 3-month avg, installment timeline, subscriptions ×12, cards split per currency, net worth (from snapshots), personal inflation); memoization keyed by (chart, period, filter, currency); 'not enough data' states (EC-23).

## Design note
Short note by the implementer (sprint mode, PO 2026-11-13); code in `app/lib/features/insights/`.
- **One currency per query.** Every chart takes a `ChartFilter(currency, accountIds)`; there is no cross-currency sum. `currenciesWithActivity` lists what a period holds. The only combined figure is `approxChartTotal` (wraps T-115 `buildApproxView`, off by default).
- **Same counting as the cycle engine, in SQL.** Spend = expense/fee/transfer_out, income = income/transfer_in/refund, posted or pending, live, `is_internal = 0`. Expenses count net of active offset links (refund/reimbursement sources live and posted/pending); income-side rows count net of what they funded. Split shares are reimbursement links, so paid shares leave spend and unpaid shares stay spend (BR-XFR-06). A test asserts the cash-flow chart equals `CycleRepository.totals` to the minor unit. Local day comes from each row's stored offset, via integer SQL on `occurred_at + offset`.
- **Periods** are inclusive local-date ranges (`ChartPeriod`: cycle, month, custom). Callers pass cycle lists from the schedule (T-051); the layer never reads the clock.
- **Memo** keyed `(chart, period, filter, currency, extra)`, bounded (128), cleared by `invalidate()`. The provider rebuilds the repository when `cycleDataVersionProvider` bumps (TransactionsChanged). Charts that read budgets, recurring items or snapshots (burn curve, installments, subscriptions, net worth) are never memoized, so they cannot go stale.
- **EC-23 "not enough data"** is a typed `ChartNotEnoughData(reason, have, need)`: no data; day/hour < 10 spend rows; average < 2 complete earlier cycles (a cycle is complete when the user's first transaction is on or before its first day); net worth < 2 snapshots; inflation < 3 repeated merchants; 50/30/20 needs income; burn projection after 3 days. `CashFlowPoint.isPartial` marks the bucket that contains the first transaction.
- **Month vs average** compares the current cycle so far with the earlier cycles over the same number of days, mean of up to 3.
- **50/30/20**: needs = needs + obligations; wants; savings = savings-bucket spend + unspent income (never negative); other = giving, income-bucket and uncategorized spend.
- **Personal inflation**: merchants only; per repeated merchant the median purchase per month against its first month; per month the median ratio, in basis points; needs 3 merchants.
- **Gate (FU-123)**: `chartGateIndex` maps Free's 4 core charts to cash flow, category donut, top merchants (5 rows) and budget progress bars (T-095); `decideChart` uses `GoldGate.chart`.
