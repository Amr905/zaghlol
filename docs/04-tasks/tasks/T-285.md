## Scope
`app/lib/features/export_import/application/export.dart` (CSV/Excel, Gold): add a column "pair" (header ar/en per the existing header rule) holding a short stable id shared by both legs of a transfer pair (exchange or own-account transfer), plus "kind" values `exchange` / `transfer` where the existing type column cannot say it. No converted amount column (FR-EXP-07). The CSV importer (`import_csv.dart`) must still read old and new exports (ignore or use the column; write which).

## Acceptance criteria
- Export test: an exchange exports two rows with the same pair id, own-account transfer likewise, ordinary rows empty.
- Round-trip import test of a new export.

## Builder assumptions
- Columns `pair` and `kind` are appended after `note` (header stays the fixed English list). `pair` = 10 hex digits of FNV-1a over the stored pair id (not the raw id). `kind` = `exchange` for `fx_conversion`/`cross_currency` pairs, otherwise `transfer`; empty for ordinary rows. Without a pair-kind lookup every pair exports as `transfer`.
- Importer reads old (14-column) and new (16-column) files and ignores `pair`/`kind`: pairs are rebuilt by the existing post-import pairing hooks.
- `TransactionRecord` gained optional `transferPairId`.
