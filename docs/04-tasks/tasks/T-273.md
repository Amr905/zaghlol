## Description
One expand-only migration creating the six tables exactly as specified, with all CHECK constraints, primary/unique keys and grants. No change to existing tables. No services (they come in T-284, T-285, T-289, T-302, T-303).

## Acceptance criteria
1. Migration applies on an empty database and on the current `main` schema; `backend-ef-migration` bot output is clean and the snapshot matches.
2. Column lists match the spec exactly (a schema test reads `information_schema` and compares).
3. Grants: `app_rw` R/W on counters, ledger, cache, confirmations/corrections insert+select, R on `remote_config`; `worker_rw` DELETE on counters, ledger, cache, confirmations, corrections; `ops_rw` select + update `status`/`operator_id`/`resolved_at` on corrections and confirmations; tested per role.
4. **Negative proof 1:** no table among the six has a column that could hold a question text or an install/account id, IP or app version, other than `llm_quota_counters.subject_id` (schema test listing every text/bytea/uuid column).
5. **Negative proof 2:** inserting a `merchant_norm` with a 6-digit run (Western, Arabic-Indic, with separators) or containing `@` into the cache, confirmations or corrections fails on the CHECK.
6. `month_key` CHECK 202601…209912, `confidence` 0…100, enum CHECKs (`feature`, `subject_kind`, `source`, `status`) rejected out-of-range values in tests.
