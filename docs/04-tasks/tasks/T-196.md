## Description
Detection today (`detectAndSuggest`, `RecurrenceCadence { monthly, yearly, weekly, customDays }`) only finds **monthly** chains and only **suggests** them (review item, user confirms). The PO wants charges that repeat every **1, 3, 6 or 12 months** added as bills.

## Technical details
- Add `quarterly` and `semiAnnual` cadences (or `everyNMonths(n)` with n ∈ {1, 3, 6, 12}); migrate stored values; next-due and yearly-cost math for each (`yearlyOf`).
- Detection: same merchant/counterparty and currency, amount within tolerance, intervals matching the cadence ± a few days; minimum chain: 2 occurrences for 12-month and 6-month, 3 for 3-month and monthly; look-back raised from 400 days to ~760 days so a yearly chain can be seen twice.
- **Auto-add:** a detected chain becomes an active bill right away, marked "اتضافت لوحدها" with a one-tap **Not a bill** (undo) in the Bills list and a single notification; dismissed chains are never re-added. Only categories where the same merchant repeats by coincidence are excluded (groceries, dining / food delivery, ride-hailing / transport, fuel, cash withdrawals), plus transfers to own accounts and income; rent, utilities, bills, installments, education, insurance and subscriptions DO auto-add.
- Due reminders (`send_due_reminders.dart`) cover the new cadences.

## Acceptance criteria
1. Unit tests: monthly, 3-, 6- and 12-month chains detected; near-misses (irregular gaps, varying merchants, own-account transfers) not detected.
2. A detected chain appears in Bills without user action, with undo; undo removes it permanently for that chain.
3. Next due date and yearly cost correct for each cadence, including month-end days (31st → 30/28).
4. Migration test from the current schema; ar/en goldens for the auto-added badge; no hard-coded strings.
