## Description
`ClientScrub.apply(text)` replaces phones, e-mails, InstaPay addresses and digit runs ≥ 8 with neutral tokens (kinds kept for the UI). `ReferenceMasker.mask(text, MaskSources)` → `MaskResult{sentText, map, tokens}` or `MaskUnresolved(candidates)`. `MaskSources` is an interface (accounts: label, nickname, institution + type, last-4; registry aliases ar/en with an "ordinary word" flag; the user's merchant names); the Drift adapter is T-293. Folded matching (Arabic letters, Arabic-Indic digits, case, tatweel, diacritics), longest match first, token-boundary aware, numbering by first appearance, repeated references reuse their token.

## Acceptance criteria
1. FR-LLM-03 example: no phone, IPA or `1234` in output; «صرفت كام» kept.
2. FR-LLM-18 ar: output exactly «صرفت كام بكارت ⟦CARD_1⟧ في ⟦MERCHANT_1⟧ من حسابي في ⟦BANK_1⟧؟»; en: exactly the SRS sentence with ⟦ACCOUNT_1⟧, ⟦BANK_1⟧, ⟦CARD_1⟧ and "Uber" kept; «صرفت 4321 جنيه» keeps `4321`; Arabic-Indic «٤٣٢١» next to «كارت» is masked.
3. FR-LLM-20: no such card, registry bank with no account, «بنك الزغاليل», two cards with the same last-4 → `MaskUnresolved` with the user's matching cards/accounts as candidates.
4. Word-like aliases («مصر», «الأهلي», "Liv") are masked only next to a bank/account/card word.
5. **Negative proof 1:** inspection test over the synthetic fixture sources and the SRS §10.1 question list: no `sentText` contains a fixture last-4 within 3 words of a card/account word, a registry alias, an account nickname/label, or a fixture merchant name (folded comparison).
6. **Negative proof 2:** `MaskResult.toString()`, `map.toString()` and any `Exception` message from the masker contain no source name (redaction test with marker names).
