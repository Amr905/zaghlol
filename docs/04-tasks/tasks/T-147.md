## Description
Carry Gold across platforms, then leave cleanly.

## Technical details
- `google_sign_in`; `sign_in_with_apple` (iOS native, Android web flow with the backend callback); S-69 UI; sign-in never required for any non-Gold feature.
- **Nonce (R2-9, ADR-016):** a raw nonce of ≥ 128 bits from a CSPRNG, base64url, held in memory only, sent once; the provider gets `hex(SHA-256(raw))`. Prove that a **fresh** nonce can be set for every Google attempt with `google_sign_in` 7.x (`initialize(nonce:)` or a narrow host API over Credential Manager / GoogleSignIn-iOS).
- Android Apple web flow: random single-use `state` (≤ 10 min), Custom Tab with explicit Chrome package when installed; check `state` on return.
- `POST /v1/accounts/signin` is an anchoring request (T-144 time anchor). The account token and entitlement go through T-144's binding check.
- **iOS `seatKeys` on sign-in:** own key plus up to 4 earlier keys from T-179, signed over `op = signin`, `challenge = SHA-256(raw nonce)` (T-183 builder); omitted when T-179 reports the own key unusable or unavailable.
- **`SEAT_KEY_MISMATCH` (R4-1(1), R5-6):** retry once with a **fresh ID token and nonce** and no `seatKeys`; after a successful retry, persist "own seat key unusable" through T-179 and stop sending `seatKeys`.
- **Outcomes:** `moveRefused` + `nextMoveAt` (R3-5; linked, no Gold here yet); **`restoreSuggested` (R5-3(b))**: call T-145's `hasStoreKitTransactionFor(purchase)`; **with** a transaction, offer Restore; **without** one (Play purchase, other Apple ID), do **not** offer Restore — show `nextMoveAt` (locale-formatted) and the support path (link + support code), in copy that says Gold is safe; `409 INSTALL_LINKED_TO_OTHER_ACCOUNT` → confirm and resend with `replaceLink` (EC-46); verify `accountRequired` (R4-4) leads here with a "sign in with the account that owns Gold" prompt.
- After purchase on the buying phone: "sign in on this phone to protect your Gold" suggestion (D-54).
- **Sign-out:** keeps local data; T-144 drops the cached token even if the call fails; account-linked Gold shows `paused`.
- **Delete account:** removes backend links; clears the account token.
- Device tests (with T-172): Samsung Internet and Firefox as the default browser for the Android Apple flow.

## Acceptance criteria
- [ ] Sign-in never required for any non-Gold feature.
- [ ] Delete account removes backend links.
- [ ] R2-9: two consecutive Google sign-in attempts send different raw nonces, and the provider receives `hex(SHA-256(raw))` each time (test with a fake plugin; device check recorded for `google_sign_in` 7.x).
- [ ] R3-5: a `moveRefused` 200 stores the account token and shows the cooldown copy with `nextMoveAt`.
- [ ] **R5-3(b):** with `restoreSuggested: true`, Restore is offered only when `hasStoreKitTransactionFor` is true; otherwise the screen shows `nextMoveAt` and the support path and no Restore button (widget tests for both, `ar` and `en`; store sandbox case "third reinstall sign-in for Play-bought Gold" in T-172).
- [ ] **R5-6:** after a `SEAT_KEY_MISMATCH` confirmed by a successful retry (fresh nonce, no `seatKeys`), later sign-ins send no `seatKeys` and don't hit a second 400 or a second provider prompt (test).
- [ ] Android `seatKeys` never sent (test).
- [ ] D-54: the "sign in on this phone" suggestion appears on the buying phone after a verified purchase and nowhere else.
- [ ] Android Apple flow: a `state` that is unknown, reused or older than 10 min is rejected on return (test).
- [ ] Sign-out offline: the account-linked purchase shows `paused` immediately (test with T-144 fake).
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
