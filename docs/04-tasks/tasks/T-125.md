## Description
Versioned catalog with tiny deltas, edited through a keyed draft workspace with tombstones.

## Technical details
- Draft workspace; publish → immutable version with change log; delta (a, b] including tombstones; full snapshot (gz) plus `.sig` to object storage/CDN; `GET /v1/catalog/{version}/full` returns `{version, ops[]}`; seed import from `tools/catalog_build` CSV.
- **Draft keys (§5.2):** path `{id}` per entity: `categories` = `code`; `merchants` = integer id (server-allocated by `POST /admin/v1/catalog/draft/merchants`, never reused); `aliases` = `<merchantId>:<b64u(alias)>`; `keywords` = `<lang>:<b64u(keyword)>`. Keys must be canonical (no padding, re-encoding reproduces the input, valid UTF-8, already normalized, ≤ 64 chars) else `400 VALIDATION_FAILED`. Keys only in the path; bodies hold non-key fields.
- **Tombstones:** `DELETE` marks deleted (204); publish writes `deleted = true`; never-published entries are removed outright; `PUT` revives. Deleting a merchant tombstones its aliases, listed before the merchant delete in the delta.
- **Conflicts:** deleting a category still referenced, or referencing a non-live category/merchant → `409 ADMIN_CONFLICT`; missing or deleted key → `404`. Add `ADMIN_CONFLICT` to `ErrorCodes`.
- Admin writes require the operator auth and roles of T-136 (`catalog_editor`) once it lands; until then the endpoints are wired behind the role policy with a test principal.

## Design note
Recorded 2026-11-10 before coding (C3).

**Storage.** One new table, `catalog_drafts` (migration `AddCatalogDrafts`, T-125's own): the *whole* working copy of the catalog, one row per `(entity, entry_key)` with `body jsonb` (non-key fields), `deleted`, `published` (has ever been written to the live tables) and `changed` (differs from the live tables). Tombstoned rows stay, so `PUT` can revive a published tombstone; a delete of a never-published row removes it. `entry_key` stores the *decoded* canonical key (`812:koshary el tahrir`, `ar:صيدلية`) so publish can run as set-based SQL. A surrogate `seq integer GENERATED ALWAYS AS IDENTITY` is the **merchant id allocator** (FU-026 forbids any sequence grant, and an identity needs only INSERT): merchant `id` = the draft row's `seq`, never reused. Publish writes live merchants with `OVERRIDING SYSTEM VALUE`; the live identity is unused. Grants: `ops_rw` SELECT/INSERT/UPDATE/DELETE, `ops_ro` SELECT, appended to `GrantMatrix` as a frozen `CatalogDrafts` list and rendered in the migration (hand-added SQL after CI generates it).

**Writes.** All draft writes and publish run in one transaction under `pg_advisory_xact_lock`, so operators are serialised. Every write inserts one `audit_log` row in the same transaction (no key text beyond the path id, no notes). Reference rules (§5.2): category/merchant referenced by merchants, aliases and keywords must be live in the draft else `409 ADMIN_CONFLICT`; merchant canonical is unique across all draft merchants; merchant delete cascades to its aliases. Publish with no `changed` rows is `409` (declared in the spec).

**Publish.** New version = max+1. Set-based `INSERT ... ON CONFLICT DO UPDATE` per entity from `changed` drafts (version = new, `deleted` copied); then build the full snapshot from live non-deleted rows as canonical JSON `{version, ops[]}` (hand-written `Utf8JsonWriter`, fixed field and row order), SHA-256 it, gzip it, sign the JSON bytes with the T-123 Sync key (`ISigner`), put `full.json.gz` and `full.json.sig` in `ICatalogSnapshotStore`, insert `catalog_versions`, commit. An upload or KMS failure rolls the whole publish back (503). The store is a port; the shipped adapter writes to a directory (`Catalog:Snapshots:Directory`, `BaseUrl`), the CDN/S3 adapter belongs to T-140.

**Delta and full.** `ICatalogReader.DeltaAsync(a, b)` = live rows with `version` in `(a, b]` incl. tombstones, ordered upserts first (categories, merchants, aliases, keywords) then deletes children first (keywords, aliases, merchants, categories), so alias deletes precede the merchant delete. `a >= b` is empty. `GET /v1/catalog/{version}/full` is anonymous (CDN origin, per-network rate limit), reads the stored gz, checks it against `catalog_versions.full_snapshot_sha256` and returns the exact JSON; `ResponseSigningMiddleware` signs it. The signing buffer cap becomes per-endpoint metadata (8 MiB for this endpoint, 1 MiB elsewhere): T-123 I-5 resolved (a 10k-op catalog is about 1 MB).

**Keys.** Pure code in `Zaghlol.Application.Catalog` (`CatalogKeys`): charset pattern, no `=`, base64url decode then re-encode must equal the input, strict UTF-8, decoded text equals `CatalogText.Normalize`, 1-64 chars. Normalization is structural (lower-case, collapse spaces, fold Arabic-Indic digits, drop tashkeel/tatweel/combining marks/zero-width, unify alef forms and alef maqsura); alias text must also be printable ASCII (merchant_norm is a Latin transliteration done by the app tooling). `string.Normalize` is avoided because the host runs with invariant globalization.

**Auth.** T-136 has not landed: `IOperatorAuthenticator` (default: deny all, so production answers 401) feeds an `Operator` scheme and a `catalog_editor` role policy; tests supply a principal. No admin route uses `WithIdempotency` (FU-052 S-2): `PUT`/`DELETE` are idempotent by key, `POST merchants` and publish are not retried blindly (publish with nothing changed is 409). No new metric instruments, so the FU-049 tag-set rule has nothing to apply to.

**Seed import.** `CatalogSeedCsv` parses the catalog_build CSV (`entity,key,...` columns documented in the type) and `ICatalogAdminStore.ImportSeedAsync` loads it into the draft in one transaction with one audit row; publishing is the normal call.

## Acceptance criteria
- [ ] Delta for an up-to-date client is empty.
- [ ] Snapshot signature verifies in an app-side test vector.
- [ ] FU-009: an alias key with `=` padding, with non-zero trailing bits, or decoding to non-normalized text gets `400` (one test each); a keyword key `ar:2LXZitiv2YTZitip` round-trips.
- [ ] Deleting a merchant produces alias deletes before the merchant delete in the next delta (test).
- [ ] Deleting a referenced category → `409 ADMIN_CONFLICT` (test).
- [ ] FU-011: live response-vs-spec test for each admin catalog operation.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
