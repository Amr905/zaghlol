## Description
Versioned catalog with tiny deltas, edited through a keyed draft workspace with tombstones.

## Technical details
- Draft workspace; publish → immutable version with change log; delta (a, b] including tombstones; full snapshot (gz) plus `.sig` to object storage/CDN; `GET /v1/catalog/{version}/full` returns `{version, ops[]}`; seed import from `tools/catalog_build` CSV.
- **Draft keys (§5.2):** path `{id}` per entity: `categories` = `code`; `merchants` = integer id (server-allocated by `POST /admin/v1/catalog/draft/merchants`, never reused); `aliases` = `<merchantId>:<b64u(alias)>`; `keywords` = `<lang>:<b64u(keyword)>`. Keys must be canonical (no padding, re-encoding reproduces the input, valid UTF-8, already normalized, ≤ 64 chars) else `400 VALIDATION_FAILED`. Keys only in the path; bodies hold non-key fields.
- **Tombstones:** `DELETE` marks deleted (204); publish writes `deleted = true`; never-published entries are removed outright; `PUT` revives. Deleting a merchant tombstones its aliases, listed before the merchant delete in the delta.
- **Conflicts:** deleting a category still referenced, or referencing a non-live category/merchant → `409 ADMIN_CONFLICT`; missing or deleted key → `404`. Add `ADMIN_CONFLICT` to `ErrorCodes`.
- Admin writes require the operator auth and roles of T-136 (`catalog_editor`) once it lands; until then the endpoints are wired behind the role policy with a test principal.
