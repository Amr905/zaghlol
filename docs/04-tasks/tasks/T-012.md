## Description
One exact money type used everywhere.

## Technical details
Money{minor:int, currency}; Currency from bundled currencies.json (active ISO codes, exponents incl. 3-decimal KWD/BHD/OMR/JOD/TND/LYD/IQD, 0-decimal JPY/KRW); +,−, compare with CurrencyMismatch; allocate(weights) with remainder distribution; MultiCurrencyTotal; no double anywhere.

## Design note

### Design note (solution-architect, 2026-11-05)

**Scope.** This task covers exact money values, the ISO table, arithmetic, rounding, allocation, per-currency totals and storage/JSON round-trips. It is pure Dart in `packages/zaghlol_domain/lib/money/`, exported from `zaghlol_domain.dart`, with no new runtime dependencies. The only new dev dependency is `glados: ^1.1.7` (verified on pub.dev, 2026-11-05).

**Files.** `currency.dart`, `money.dart`, `money_errors.dart`, `rounding.dart`, `allocation.dart`, `multi_currency_total.dart`, `src/iso4217_table.g.dart` (generated), `data/currencies.json` (source), plus `tool/gen_currencies.dart` and `tool/iso4217/list-one.xml` (a pinned SIX snapshot) at the package root.

**API shapes**
```dart

final class Currency {                        // private ctor; canonical instances only
  final String code;                          // 'EGP' (A–Z ×3)
  final int numeric;                          // 818

  final CurrencyStatus status;
  static Currency of(String code);            // throws UnknownCurrency
  static Currency? tryOf(String code);        // strict: uppercase ASCII only, no trimming
  static Iterable<Currency> get active;       // pickers; historic codes are excluded
  static const featuredCodes = ['EGP','USD','SAR','EUR','AED','QAR','KWD','BHD']; // D-22 order
  // == and hashCode use `code` only
}
final class Money implements Comparable<Money> {
  static const int maxMinor = 9007199254740991;   // 2^53 − 1

  static Money? tryMinor(Currency c, int minor);                    // boundary: null if out of range

  static Money? tryParse(String canonical, Currency c);
  String toCanonicalString();                // '1.250' (KWD), '1500' (JPY), '-0.05' (EGP)
  Money operator +(Money o); Money operator -(Money o); Money operator -();
  Money abs(); bool get isZero; bool get isNegative; bool get isPositive;
  bool operator <(Money o); /* <=, >, >= */ int compareTo(Money o);   // CurrencyMismatch if currencies differ

```
Errors are `final class … extends Error`: `CurrencyMismatch(a, b)`, `MoneyOverflow(currency, op)`, `UnknownCurrency(code)` and `CorruptMoney(code)`. They are programming or data-integrity bugs, not user errors. **`toString()` carries currency codes and the operation name only, never an amount** (NFR-SEC-03; balances are sensitive). The boundary APIs (`tryMinor`, `tryParse`, `tryOf`) are how untrusted input such as SMS, CSV or backups enters without throwing.

**Invariants and overflow.**
- Dart `int` is a wrapping int64 on the VM and AOT, so every operation checks its result explicitly.
- The bound is |minor| ≤ 2^53 − 1. That is about 90 trillion EGP, or 9 trillion KWD/IQD. It keeps every value exact in JSON (backup `settings.json`, CSV) and anywhere a double-based consumer might read it.
- Inputs are bounded, so `+`/`−` cannot wrap, and the result is range-checked. `times` checks `|minor| > maxMinor ~/ |factor|` first.
- `mulDiv` and the allocation remainder step use `BigInt` whenever an intermediate product could exceed int64.
- On overflow the operation throws `MoneyOverflow`. It never clamps or wraps.
- Parsers reject out-of-range amounts at the boundary, so an absurd SMS amount becomes a review item (T-033), not a crash.

**Parsing/formatting boundary.** The domain accepts only the **canonical ASCII form** `-?[0-9]+(\.[0-9]{1,e})?`, where `e` is the exponent. There is no `.` when `e = 0`. It has no `+`, no grouping, no whitespace and no exponent notation.
- More fraction digits than `e` → `FormatException`. Never round (BR-MON-03; T-013 AC "failure, not rounding").
- Fewer digits are padded: EGP `1.5` → 150.
- `-0` and `-0.00` → zero.
- Non-ASCII digits are **rejected** here, which a test asserts, so that callers must normalize first.

The canonical form is also the CSV export format (BR-EXP-01). Everything locale-aware lives elsewhere:
- Arabic-Indic digits, `٫`/`٬`, grouping styles and currency words in SMS, OCR and voice → `packages/zaghlol_parsing/lib/normalize/` (T-013), which emits canonical strings or `(minor, Currency)`.
- User-typed amounts → `app/lib/core/l10n/digits.dart`.
- Rendering (digits per setting A-29, grouping, `ج.م`/`EGP` placement, RTL) → `app/lib/core/l10n/money_format.dart`.
- Localized currency names → ARB files.

`MoneyFormat` **must pass `currency.exponent` as `decimalDigits` explicitly**. CLDR/`intl` digit tables differ from ISO for some codes (for example IQD, which ISO 4217 gives 3 decimals), and BR-MON-03 follows ISO.

**`currencies.json` source and format.**
- **Source:** SIX Financial Information "List One" (`list-one.xml`), the ISO 4217 maintenance agency's current-codes list. Commit the snapshot current at implementation time (≥ Amendment 180, Sept 2025; check SIX for later amendments) and record its `Pblshd` date in the JSON header.
- **Format:**
  ```json
  {"source":"ISO 4217 List One","published":"YYYY-MM-DD",
   "currencies":[{"code":"KWD","numeric":414,"exponent":3,"status":"active"}, …]}
  ```
  The file is sorted by code.
- **Inclusion:** every List One code with a numeric `CcyMnrUnts` gets one entry. Each code appears once, though List One repeats codes per country.
- **Excluded:** entries with `N.A.` minor units:
  - precious metals XAU, XAG, XPT, XPD;
  - XDR, XSU, XUA;
  - bond-market units XBA–XBD;
  - XTS and XXX.

  Gold is not a currency in Zaghlol. It is a quantity in grams in `wealth/` (`price_quotes.symbol` `XAU21_G`, …).
- **Funds codes** (BOV, CHE, CHW, CLF, COU, MXV, USN, UYI, UYW) are included as `active`, because D-28 says any ISO code is supported. They are not in `featuredCodes`, and their exponents (for example CLF 4, UYW 4) are respected.
- **Historic codes:** the table is **append-only**. A code removed from List One in a later refresh stays in the table with `status: historic`. Stored rows and backups that use it still load and render, and it is hidden from pickers. A test fails if a refresh deletes any code.
- **Codegen:** pure Dart cannot read assets at runtime. `tool/gen_currencies.dart` turns the JSON into `src/iso4217_table.g.dart`, a const list. A test regenerates it in memory and asserts it is byte-identical to the committed file.
- **Exponent verification (tests):**
  1. Every active JSON entry equals the List One XML snapshot, parsed with a `RegExp` and no `xml` dependency, on code, numeric and minor units.
  2. A hard-coded oracle independent of the XML: KWD/BHD/OMR/JOD/TND/LYD/IQD = 3; JPY/KRW/VND/CLP/ISK/XOF/XAF/UGX/PYG = 0; EGP/USD/EUR/SAR/AED/QAR/GBP = 2.
  3. All codes match `^[A-Z]{3}$`, and codes and numerics are unique.

**Allocation (largest remainder / Hamilton).**
1. Validate the weights:
   - an empty list, any negative weight, or all weights zero → `ArgumentError`;
   - a list longer than 10,000 entries → `ArgumentError`.
2. Let `W = Σw`, `a = |minor|` and `s = sign`.
3. For each weight: `q_i = (a × w_i) ~/ W` and `r_i = (a × w_i) % W`. Compute in `BigInt` if `a × w_i` could exceed int64.
4. Let `R = a − Σq_i`, where 0 ≤ R < n. Give +1 to the `R` indices with the largest `r_i`, **ties broken by lower index**, and **never to a zero weight**.
5. Multiply every share by `s`.

Results:
- Negative amounts are allocated symmetrically: `allocate(−x) == allocate(x).map(-)`.
- Zero weights always get exactly zero.
- The output is deterministic, has the same length as `weights`, and every share is in the same currency.

**Rounding.** `roundDiv` implements the five modes on exact `BigInt` quotient and remainder:
- `halfEven` for the ≈ view;
- `floor` for safe-to-spend;
- `halfAwayFromZero` for Zakah, if T-115 or the Zakah note picks it.

The money API has no implicit default rounding mode.

**Equality and hashing.** `Money ==` holds when `currency.code` and `minor` are equal; `hashCode = Object.hash(currency.code, minor)`. Comparing different currencies with `==` returns `false` and does not throw. `compareTo` and the `<`-family operators throw `CurrencyMismatch`, so sorting a mixed list is a bug that shows up loudly. Because exponents are fixed per currency, EGP 1.5 and 1.50 cannot differ in scale.

**Serialization.**
- **DB:** columns are `<name>_minor INTEGER` + `<name>_currency TEXT` (database-schema conventions).
  - The domain provides `toStorage`/`fromStorage`. The Drift `TypeConverter`/row mapper lives in `app/lib/core/db/` (T-016/T-017) and is never imported into the domain.
  - `fromStorage` with an unknown code or an out-of-range value throws `CorruptMoney`.
  - Nullable pairs are both NULL or both set.
  - Request for T-017/T-019: add a `CHECK ((x_minor IS NULL) = (x_currency IS NULL))` constraint and `CHECK (abs(x_minor) <= 9007199254740991)`.
- **JSON:** `minor` is a JSON integer and `currency` is the code. The JSON never holds a decimal string or a double.

**Property tests (glados, `test/money/`).**
- **Generators:**
  - `any.currency` picks from the table, biased so that exponents 0, 2 and 3 each appear at least 25% of the time;
  - `any.minor` covers ±maxMinor, mixing `any.intInRange` with a fixed edge pool {0, ±1, ±9, ±10, ±999, ±1000, ±(maxMinor−1), ±maxMinor};
  - `any.money` combines the two (`combine2`);
  - `any.weights` is a non-empty list (length 1–50) of ints 0..10^6 with at least one non-zero entry, plus a separate generator with weights up to maxMinor to exercise the BigInt path.

  Use `ExploreConfig(numRuns: 1000)` with the default fixed seed.
- **Properties:**
  1. `+` is commutative and associative where it does not overflow; zero is the identity; `a + (−a) == 0`; `a − b == a + (−b)`.
  2. Overflow is exact: `a + b` throws iff the `BigInt` sum exceeds the bound. The same holds for `times` and `mulDiv`.
  3. Different currencies: `+`, `−` and `compareTo` throw `CurrencyMismatch`, and `==` is false.
  4. Allocation is exact: `Σ allocate(w) == amount`, length matches, and zero weights get zero.
  5. Each share is within one minor unit of its quota: `|share_i·W − amount·w_i| < W`, checked in `BigInt`.
  6. Allocation is monotonic (for non-negative amounts, `w_i > w_j ⇒ share_i ≥ share_j`) and sign-symmetric.
  7. `allocateEven` shares differ by at most 1.
  8. `parse(toCanonicalString(m)) == m`, `fromStorage(toStorage(m)) == m` and `fromJson(toJson(m)) == m`.
  9. `MultiCurrencyTotal.of(xs)` does not depend on input order. `of(xs)[c]` is the sum of the `xs` in `c`, and `+` is associative.
  10. `roundDiv` matches a rational oracle for each mode, including exact .5 ties.
- **Example tests:** the AC values (KWD `1.250` ↔ 1250, BHD `0.375` ↔ 375, JPY `1500` ↔ 1500), EGP + USD throws, KWD `1.2345` rejected, JPY `1.5` rejected, `١٫٢٥٠` rejected and `allocate(EGP 1.00, [1,1,1]) == [0.34, 0.33, 0.33]`.
- **No-double test:** a test reads `lib/money/**/*.dart` and fails on `double`, `num `, `toDouble` or `parseDouble`.

**Non-goals.** No FX conversion or rates (the ≈ view is T-115 and uses `roundDiv`), no formatting or localization, no cash rounding increments (CHF 0.05), no gold or other non-currency units, and no Drift/JSON-codegen dependency in the domain.

**Rejected alternatives.**
- `Decimal`/`BigInt` as storage: slower, and SQLite INTEGER is int64 anyway.
- `package:money2`: its exponents follow its own table, it carries a formatting/locale surface we do not want in the domain, and it adds a dependency.
- Clamping on overflow: it silently loses money.
- Distributing the remainder to the first indices instead of by largest remainder: its biased splits are visible to users.

## Design note amendment (Lead, 2026-11-07; review CR13)
The implementation's deviations from the design note were ruled **accepted** by the code reviewer. The full table of 20 rulings is in `docs/05-reviews/T-012.md`, under "Deviations from the design note". In summary:
- **Currency API:** `Currency.isFund`, `Currency.all`, and a JSON `fund` key written only when it is true. `featuredCodes` holds the 10 A-59 codes.
- **Errors and parsing:** typed errors `CorruptMoney(code, CorruptMoneyReason)` and `MoneyOverflow(currency, MoneyOp)`. Non-throwing `tryFromJson` and `tryFromStorage`. `Money.maxParseLength = 64`, and leading zeros don't count toward the 16-digit cap.
- **Arithmetic and totals:** `allocate` always uses BigInt and lives in `src/`; only `maxAllocationParts` is exported. `MultiCurrencyTotal` sums exactly in BigInt and checks the range once.
- **Generator:**
  - `--fresh` (allowed once, guarded by `freshAllowed` and `sentinelPublished`; the bypass is `--i-know`);
  - `--allow-change=` for exponent and numeric changes;
  - `excludedCodes = {'XAD'}` (D-67). Excluded codes are dropped, not kept as historic. A code that has already shipped must never be added to that set without a data-migration task.
- **Snapshot:** genuine SIX List One, Pblshd 2026-09-17, sha256 `33139b43…a1b0ff`.
