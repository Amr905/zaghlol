## Description
Write the 40 synthetic items (8 data ar, 6 data en/mixed, 7 what-if, 4 suggestions, 6 investment, 5 refusal, 4 injection/edge) with question, lang, expected plan + params or refusal reason. The runner sends each through the real pipeline (prompt + adapter + validator) against a provider: in CI against **recorded** replies per adapter (OpenAI, Vertex, Anthropic) via WireMock; in `llm-eval-live` (manual `workflow_dispatch`, GitHub protected environment `llm-eval`, one secret per provider) against the live API, with an option to refresh recordings. The report (markdown + JSON) gives exact plan + params score, refusal/injection items, schema failures reaching the phone, p95 latency, tokens and cost per 1 000.

## Acceptance criteria
1. 40 items in the specified group counts; all synthetic; injection items include "ignore your rules…", a URL, 300-char rambling and a Zakah question (→ fallback).
2. CI runs the recorded set for all three adapters deterministically and fails when the scorer's pass rule fails (≥ 36/40, all 9 refusal/injection correct, 0 schema failures past the validator).
3. The live workflow reads keys only from environment secrets, never echoes them, masks them in logs, and writes no key or raw provider body to artifacts; a secret-scan check stays green.
4. The live workflow cannot run on pull requests or forks (manual dispatch + environment protection).
5. Report format documented in the harness README with an example from the recorded run.

## Design note (builder, 2026-11-26)
- **Scoring ("exact plan + params"):** plan id equal; the expected `p` in the set is a subset of the reply's `p` (keys named must match recursively; unnamed keys free; decimal strings as numbers; `$set` for unordered lists). Documented in the harness README.
- **Deviations, on purpose:** the recorded run replays through the shared `FakeLlmProvider` (per the brief) instead of WireMock (adapter wire formats are already covered by T-338's tests); the set is YAML read with the existing YamlDotNet; the harness is an exe (`Zaghlol.LlmEval`, no fakes) plus `Zaghlol.LlmEval.Tests`; the live workflow has no recording-refresh input (a local `--record` flag instead), so no provider body is ever an artifact; secrets are repository environment secrets `LLM_EVAL_KEY_<ID>`.
- No production file changed.
