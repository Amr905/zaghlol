## Description
`LlmAskFlow.ask(question)` emits a sealed `AskLlmState` stream: local answer (engine `AskUnderstood`) → digits fold → scrub → mask (`MaskSourcesDrift`: accounts, registry aliases, the user's merchants) → clarification → gate (flag, paused, quota snapshot 0 before `resetsAt`, online, consent via an injected `ConsentPrompter` implemented by T-345) → send → phone validation (T-331) → execute (T-342) → answer with `sentText` kept on the in-memory message only. Errors: 409 clears consent and re-prompts; 503 sets paused; 403 updates the snapshot; 422/429/502/timeout → their states; Stop cancels. Nothing is queued for later.

## Acceptance criteria
1. Fake-client tests for every UX §1 state: local answer, clarify, consent declined, quota 0, offline, paused, 409, 422, 429, 502, timeout, Stop before reply, valid answer.
2. **Negative proof 1:** a capturing HTTP client over the fixture DB and the SRS §10.1 question list: every request body has exactly the FR-LLM-02 fields and no body, header or URL contains any fixture amount, merchant, account label, nickname, last-4 near a card word, registry alias or SMS string.
3. **Negative proof 2:** local answer, clarification, consent declined, quota 0, offline and flag off make **zero** requests.
4. After the answer, no stored row, setting or log holds the placeholder map or `sentText` (DB + settings dump + log capture).
5. With backend validation bypassed (fake returns an invalid plan), the phone answers PL-FALLBACK.

## Design note (builder, T-343)
State machine of `LlmAskFlow.ask(question, {stop})` (`app/lib/features/ask/application/llm_ask_flow.dart`):
1. > 300 chars -> `TooLong` (no send). Engine understands -> `Local`. Flag off, scrub failed (`ScrubResult.failed`), masker threw or `failed`, provider unknown -> `Local(fallback)` (no send).
2. Scrub -> mask (`MaskSourcesDrift`: accounts, registry aliases incl. short forms, every merchant by `merchant_norm`) -> `MaskUnresolved` -> `Clarify` (no send).
3. Gate in UX order: paused -> `Paused`; quota snapshot 0 before `resetsAt` -> `QuotaOut`; offline -> `Offline`; no consent -> `ConsentPrompter` (T-345) -> declined -> `ConsentDeclined`; Allow -> grant stored by the flow.
4. `Sending` -> `LlmAskClient.plan(masked: MaskResult)` (the only way text leaves; the gateway sends `sentText`, lang, consent, id, proof). 409 -> prompt again once and resend; 422 (iOS, no attestation object) -> one retry with a new key; 503 -> `Paused`; 403 -> `QuotaOut`; 429/502/5xx/timeout/422 -> `Failed(kind)`; Stop -> `Stopped`. Nothing is queued.
5. `Computing` -> `PlanValidator` (T-331) on the reply with the sent text and mask map. Rejected -> `LlmFallbackAnswer` (never executed). Else `PlanExecutor.execute` -> `Answered(answer, sentText, counted, template)`; a template is dropped when the grammar failed or the answer is a fallback/refusal/not-found.
`sentText` and the mask map live in locals and on the emitted state only; no store, setting or log gets them.
Gaps carried (see report): provider id source, connectivity check, gold/FX prices for the executor.
