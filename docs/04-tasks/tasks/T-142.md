## Description
Opt-in anonymous contributions that can't leak personal data.

## Technical details
Off by default; queue {merchantNorm, institutionCode, categoryCode} when user categorizes an unknown merchant; BR-SYNC-04 filters on device; opt-out deletes queue (EC-48).

## Design note
Written by the implementer (PO cost rules 2026-11-13); see the header of `app/lib/features/categorization/application/contributions.dart`.
- `ContributionQueue.offer` re-reads the opt-in (default OFF) and queues only what `ContributionInput.toJson()` (the OpenAPI allow-list: merchantNorm, institutionCode, categoryCode) can carry, into the existing outbox as kind `contribution`. No new schema, no new API field.
- Device filter (security-model §3): person-to-person, custom/unknown category, `@` (also fullwidth), `+<digit>`, a run of 5 digits in any script (up to 3 non-letters between digits; invisible and combining characters ignored), over 64 characters, and a first-name / two-capitalized-words heuristic. The at-sign and digit-run check is `core/backend/outbound_text_filter.dart`, shared with "request my bank" (T-049, run length 6 there).
- Duplicate triples are queued once; queue cap 200. `setOptIn(false)` writes the setting and deletes queued contributions in one transaction (EC-48).
- Accepted residual: a person name outside the heuristic (no dictionary beyond a short list) is not caught on device; the server filter, the A-48 threshold and operator review cover it.
