## Design note (builder, Sonnet; T-110)
- **Split.** `packages/zaghlol_parsing/lib/chat/` is pure grammar: `parseAskQuestion(text, entities:)` returns `AskUnderstood(intent, slots, score)` or `AskUnrecognized(reason)` and never a figure. `app/lib/features/ask/` holds the query plans and answers (`AskEngine`), the period resolver, the roast picker and the entity loader.
- **Grammar.** Weighted cues per intent (data in `ask_grammar.dart`, AR colloquial / MSA / EN). Words are folded with `foldKey` (digits, alef/ya/ta-marbuta, tatweel, harakat) and compared as tokens with glued article / preposition / possessive variants (`بكارت`, `الشهر`, `رصيدي`). The best intent needs a score of at least 60 and a lead of 15 over the second, else `noIntent` / `ambiguous`. Two periods, or a "more than last month" cue on a spend question, make it a comparison. Cue words that name a category (`الفواتير`) are discounted for other intents when a spend verb is present.
- **Slots.** Period grammar (day, Saturday-start week, month, year, cycle, last N days, month name with year, all time); currency words (`بالدولار`, `USD`, `$`; a bare `جنيه` is not a currency slot); top-N from digits or number words (T-109 lexicon); category / merchant / card matched against the user's own names, with Jaro-Winkler (>= 0.92, length >= 5) as the typo tolerance. A card name may match several accounts (`CIB` is debit and credit): ties are kept, a longer name that fully matches wins.
- **Never a wrong number.** A target after `على / في / عند / with / بكارت` that matches nothing gives `unknownTarget` (no answer about "everything" instead). Input caps: 300 chars, 60 words, 3000 entities per kind. The parser catches everything and never echoes the text; all result types print `<redacted>`.
- **Answers.** One figure per currency (never summed). Spend / compare / top merchants / biggest / savings use the T-105 queries (`categoryDonut`, `cashFlow`, `topMerchants`, plus two small reads added to `ChartRepository`: `merchantSpend` and `biggestExpense`, both on the same net-of-links spend rule); balance uses the accounts repository (asset accounts only unless a card is named, then `liability` is set); budget = cycle budget minus cycle net spend; dues = `installmentTimeline` (installments only: subscriptions have no next-due date in the chart layer). Roast uses one currency (the one with the most spend) and picks one fact deterministically (`pickRoastFact`), preferring kinds not shown lately. Answers are data; the screen (T-111) renders text from ARB keys.

## ARB keys the screen (T-111) needs (not added here: SPRINT.md, no ARB edits)
Exact names are T-111's call; the engine returns data for each of these:
- Spend: one line per currency for each `AskTarget` (everything / category / merchant / card) and a "this month (assumed)" variant when `periodDefaulted`; period names (today, yesterday, this / last week, month, year, cycle, last N days, month name, all time).
- Compare: "more / less / same" with the change in percent (`deltaBp`), and "no earlier spend" when `deltaBp` is null.
- Top merchants header and row; biggest-expense line (merchant, date); savings line (positive, negative, partial period); budget line (left, over by, no budget); dues list (overdue, due on, total, nothing due); balance line (as of date, liability variant, single-account label).
- No-data per `AskNoDataReason` (noTransactions, noBudget, noAccounts, noDues, noIncome), the fallback message per `AskUnrecognizedReason` (noIntent / ambiguous / unknownTarget / empty / tooLong) and the "could not read your data" message.
- Roast: at least two templates per `RoastKind` (topCategory, merchantRegular, lateNight, weekendHeavy, biggestExpense, subscriptions, calm), humour only about the spending (A-18).
- Chips: label and question text for each of the 10 `AskChip` values (the chip is answered by `AskEngine.askChip`, the question text is only shown in the transcript).
- Category names for the seeded aliases come from the DB; no ARB needed.

## Known limits (T-110)
- Category matching is by exact category id; a parent category does not include its children.
- "Last 3 months" is 90 days, "last month" with no number is the previous calendar month.
- Dues cover installments only; budget answers use the cycle basis budget (overall, else sum of category budgets), not a single category budget.
- Spend with a category and a merchant in one question uses the merchant.
- `AskEngine` is not wired to a screen (T-111); `askEngineProvider` is provided.
