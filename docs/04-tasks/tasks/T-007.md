## Description

## Design note
### Design note (solution-architect, 2026-11-08)

**Goal.** Prove on the Android and iOS binaries the app will actually ship (not just the CI host) that (1) the hook links SQLite3MultipleCiphers, (2) the file is SQLCipher-4-compatible AES-256 and unreadable without the key, and (3) FTS5 `trigram remove_diacritics 1` works. Then record the timings in ADR-002, keeping emulator numbers and device numbers apart.

**Dependencies (one PR; the lock comes from `[regen-lock]`).**
- **Root `pubspec.yaml`:** `hooks: user_defines: sqlite3: source: sqlite3mc`. Drift's docs say this goes in the workspace root, and the existing comment marks the place. No `url_pattern`, no per-OS map and no `source: source`, so every platform gets the prebuilt binaries.
- **`app/pubspec.yaml` dependencies:** `sqlite3: ^3.9.0` and `drift: ^2.35.3`. Drift is included so the timings cover the real open path, `NativeDatabase.createInBackground` with a `setup` callback. `drift_dev` and codegen wait for T-015/T-016.
- **`app/pubspec.yaml` dev_dependencies:** `integration_test: {sdk: flutter}`. No `path_provider` and no `flutter_secure_storage`: test files go in `Directory.systemTemp.createTemp()`, which is the app cache dir on Android and `tmp/` on iOS, both excluded by T-165.
- **Supply chain:**
  - The hook downloads prebuilt binaries from the immutable `simolus3/sqlite3.dart` GitHub releases and checks each against a sha256 embedded in the pub package. The lock pins that package by sha256.
  - Since 3.5.2 the binaries carry SLSA L3 attestations. The `host` job (below) runs `gh attestation verify --repo simolus3/sqlite3.dart` on every file in `.dart_tool/hooks_runner/shared/sqlite3/build/download-*/`.
  - ADR-002 records the resolved `sqlite3` version, `sqlite_version()` and the sqlite3mc version (3.7.1+ bundles SQLite 3.54.0 and sqlite3mc 2.6.1).
  - SQLite3MultipleCiphers is MIT-licensed. Note it for the OSS-notices task.
  - Reviewers review the regenerated lock as a dependency change (workflows README). Expected new hosted packages: drift, sqlite3, hooks, code_assets, native_toolchain_c and their transitive deps. Anything outside that set needs a justification line in the PR.
- **Nothing native added:** no Gradle, manifest, ProGuard, Podfile or Xcode change. The library is an FFI code asset. If the diff touches `AndroidManifest.xml`, `backup_rules.xml`, `data_extraction_rules.xml` or `AppDelegate.swift`, that is a review blocker (T-165). The T-165 aapt2 and XCTest checks must stay green in all 6 + 3 jobs.

**Open sequence (the contract T-015 inherits).** Run in `setup`, before any other statement. Since SQLite 3.48 any `SELECT` reads the file, so everything before the key must be a PRAGMA:
```sql
PRAGMA cipher = 'sqlcipher';
PRAGMA legacy = 4;                 -- SQLCipher 4: SHA512 HMAC/KDF, 4096-byte pages
PRAGMA key = "x'<64 lowercase hex>'";  -- raw 256-bit key: no PBKDF2 at open
PRAGMA temp_store = 2;             -- MEMORY: no plaintext temp files
PRAGMA journal_mode = WAL; PRAGMA synchronous = NORMAL;  -- database-schema.md
-- verify, else close and throw SafeException('DB_NOT_ENCRYPTED'):
SELECT count(*) FROM sqlite_master;           -- forces decryption of page 1
PRAGMA cipher;                                 -- must return 'sqlcipher' (upstream SQLite returns no row)
SELECT sqlite3mc_codec_data('cipher_salt');    -- non-NULL means the main DB really is encrypted
```
- **Test-only key:** `Random.secure()`, 32 bytes, hex-encoded. The string must match `^[0-9a-f]{64}$` before it is interpolated. The key is never printed, never put in a test name or `reason:`, and never written anywhere except the CI interop file below.
- **Real key:** bootstrapped by T-015. T-007 adds no key storage.

**Proving the file is unreadable (on all three platforms).** All synthetic data. A sentinel `ZGHL-<16 random hex>` plus an Arabic sentinel is written to a normal table and to the FTS table.
1. No key → `SQLITE_NOTADB` (26). Wrong key → 26.
2. Key applied to a plaintext file made with the same library and no key → 26. It must never silently open as plaintext. This proves the "refuse unencrypted" check.
3. The first 16 bytes are not `SQLite format 3\0`.
4. A byte scan of `.db`, `-wal` and `-shm` finds neither sentinel's UTF-8 bytes. The scan runs twice: while the connection is open with an un-checkpointed WAL, and after close.
5. The temp directory holds only those three files.
6. `rekey` round-trip: `PRAGMA rekey` to K2, reopen with K2 succeeds and with K1 fails.
7. `host` job only, using independent implementations: Ubuntu's `sqlite3` CLI says "file is not a database". `sqlcipher` CLI with `PRAGMA key="x'…'"` (default SQLCipher 4 settings) reads the sentinel count. That proves "SQLCipher-compatible", not just self-consistent. The random key goes to `$RUNNER_TEMP` only.

**FTS5 checks.**
- `PRAGMA compile_options` contains `ENABLE_FTS5`, and `sqlite_version() >= 3.45.0` (needed for trigram `remove_diacritics`).
- The `transactions_fts` DDL from database-schema.md is created as written, external content included.
- Assert: Latin case- and diacritic-insensitive match (`Café` ↔ `cafe`); Arabic substring match (`كارفور` inside a longer string); Arabic-Indic and Latin digits in `amount_text`; `LIKE '%xyz%'` served by the index.
- **Record, don't assert:** whether `remove_diacritics` strips Arabic tashkeel (expected: no, it only handles Latin), and how 1–2-character queries behave (trigram needs 3 or more characters). Both findings go to ADR-002 and to the search task: normalize in Dart and use a fallback for short queries.

**Benchmark (same harness everywhere; deterministic synthetic data, seeded `Random(7)`).**
- **Rows:** 50,000 `transactions_fts_src` rows. Merchant and counterparty come from about 300 synthetic Arabic and Latin names, plus notes and both digit forms. Rows are inserted in one transaction through the sync triggers.
- **Metrics:**
  - `open_cold_ms`: first `createInBackground` to the first verified result, including isolate spawn.
  - `open_warm_ms`: median of 10 close/reopen cycles.
  - `insert_50k_ms`.
  - `fts_ms` p50/p95/max: 20 terms × 5 reps, as `MATCH … ORDER BY rank LIMIT 50` and as the list query (join src, `ORDER BY occurred_at DESC LIMIT 50`).
  - `like_short_ms`: 2-character fallback.
  - DB size.
  - **Baselines:** the same binary with no key (plaintext), which gives the encryption overhead ratio; and one open with a passphrase key (PBKDF2 256k), for information only, to justify the raw key.
- **Output:** one line, `ZAGHLOL_DB_BENCH {json}`, with numbers, environment, mode, versions and run ID. No data, no key. The job copies it into the step summary and an artifact.
- **Budgets:**
  - CI host: p95 < 50 ms (testing-strategy §5). This is gating in the host job.
  - Emulator/simulator: < 200 ms is recorded only. It is not gating and does not prove FR-TXN-01.
  - Real devices: < 200 ms (FR-TXN-01). This decides "recommendation confirmed".

**CI (new `.github/workflows/db-platform.yml`; actions pinned to SHAs, read-only token, not a merge gate).**
- **Triggers:** `workflow_dispatch`, plus `push` to `task/**`/`main` when `pubspec.lock`, `pubspec.yaml`, `app/integration_test/db_*` or `app/test/core/db/**` change. Any sqlite3 bump therefore re-proves the binaries.
- **`host` (ubuntu):** `flutter test app/test/core/db/` (contract + `--tags benchmark`), the CLI interop of step 7, and the attestation check.
- **`android-emulator`:** `reactivecircus/android-emulator-runner` (pinned SHA, KVM udev step), x86_64, matrix:
  - **API 35:** contract + benchmark.
  - **API 26:** contract only (ADR-019 minSdk; catches a prebuilt built against a higher API).
  - Command: `flutter test integration_test/db_platform_test.dart --flavor devNoSms` (debug).
- **`ios-simulator` (macos-latest):** same test, `--flavor dev`, first available iPhone simulator (same picker as `swift-unit`).
- **Added to the existing app-ci `android` job (release APKs):**
  - `zipalign -c -P 16 -v 4` passes. That checks 16 KB page alignment, which Play requires at targetSdk 35+, and covers the sqlite3mc `.so`.
  - The sqlite3 code asset is present for arm64-v8a, armeabi-v7a and x86_64.
  - The string `ZAGHLOL_DB_BENCH` does not appear in `libapp.so`.
- **Static job:**
  - `--exclude-tags golden,benchmark`.
  - New guard: `grep -R "integration_test" app/lib` is empty.
  - The host contract test (untagged) runs here on every push. The PO's Windows runner runs it too, which gives a Windows binary for free.
- **Labelling:** every CI number in ADR-002 is labelled "emulator/simulator, debug mode, x86_64/arm64-sim on CI hardware". Debug mode is used because profile mode is unavailable on simulators and unreliable on emulators. The SQL work is native C, so debug mode mostly inflates only the Dart side. The enc/plain **ratio** is the figure that carries over to devices.

  - `app/test/core/db/sqlite3mc_contract_test.dart` (host) and `app/test/core/db/fts_benchmark_test.dart` (`@Tags(['benchmark'])`).

**R2-N1 (app-regen `commit` job).**
- Replace the grep block (`app-regen.yml` lines 193–199) with an inline `python3 -I - "$f" <<'PY'` heredoc, so the commit job still runs no repo code. PyYAML is the runner's system `python3-yaml`. If `import yaml` fails, the job fails closed: no `pip`.
- **The validator:**
  - Uses a `SafeLoader` subclass that rejects duplicate keys and anchors/aliases.
  - The top level is a mapping whose keys are exactly `{packages, sdks}`.
  - For each `packages.<name>`: `source` must be `hosted` or `sdk`.
    - `hosted` needs `description.name == <name>`, `description.url == "https://pub.dev"` and `description.sha256` matching `^[0-9a-f]{64}$`.
    - `sdk` needs `description == "flutter"`.
    - `dependency` must be one of `direct main`, `direct dev`, `direct overridden` or `transitive`, and `version` must be a string.
  - `sdks` has `dart` and may have `flutter`.
- **Self-test:** the `static` job extracts the heredoc between `# BEGIN lock-validator` and `# END lock-validator` markers and runs it against fixtures in `.github/scripts/fixtures/pubspec-lock/`:
  - good: the current lock;
  - bad: git, path, other url, missing sha256, duplicate key, alias, extra top-level key, non-mapping.
- **Order:** land this validator commit on the branch **before** pushing `[regen-lock]`, so T-007's own lock is validated by it.
