## Description
The audited support path past the 30-day cooldown and for purchases whose buying phone is gone, with a live store ownership check, an audited correction path, a dispute freeze, and a support-lead unfreeze that moves nothing.

## Technical details
- **`POST /admin/v1/support/seat:move`** (`support_agent`): `{purchaseId, toInstallId, reasonCode, ticketRef, ownershipCheck, attachToAccount?, correctsAuditId?}`; `reasonCode ∈ lost_or_broken_phone | reinstall | buying_phone_gone | correction | other`; `correction` ⇔ `correctsAuditId`; `ticketRef` `^[A-Za-z0-9_-]{1,32}$`. Response `{purchaseId, moved, attached, nextMoveAt, auditId}`.
- **`POST /admin/v1/support/purchase:detach`** (`support_agent`): `{purchaseId, reasonCode: "correction", ticketRef, ownershipCheck, correctsAuditId}`; only a support link (`account_linked_by = 'support'`) named by `correctsAuditId` with matching `attached_account_id`; sets `account_id`, `account_linked_by` NULL, `support_link_notice_pending = false`, `support_link_notice_iat = NULL`; seat untouched. Response `{purchaseId, detached, auditId}`.
- **`POST /admin/v1/support/purchase:unfreeze`** (`support_lead`): `{purchaseId, ticketRef, ownershipCheck}`; response `{purchaseId, unfrozen, auditId}`.
- **Order of checks for `seat:move`:** (1) dispute freeze: a non-correction move or attach while `now < dispute_frozen_until` → `409 ADMIN_CONFLICT`, audited `outcome: dispute_frozen`, `ownership_outcome: not_run`, **no store call**, alert; (2) R6-1 rule below; (3) **live ownership check** (T-130 Play / T-131 Apple order lookup; `422 OWNERSHIP_CHECK_FAILED`, `503 UPSTREAM_UNAVAILABLE`); (4) target and gates; (5) effect.
- **Target:** a pending claimant (agent picks one; runbook prefers the buying install); the current holder for attach alone under the gate; or for `correction` the `from_install` of the referenced `support_seat_move` row (same purchase, < 1 year, install still exists) — the move back. Account rule: target must be linked to the purchase's account. Anything else → `409 ADMIN_CONFLICT`.
- **Attach gate** (D-57(d)): no account on the purchase; target linked to an account; buying install NULL, tombstoned or `last_seen_at ≤ now − 30 d`. Sets `account_id`, `account_linked_by = 'support'`, **`support_link_notice_pending = true`** (R4-7(2); delivery via T-132). Not a reclaim.
- **Effect of a move:** T-184 support-move primitive (window restarts, claimant removed, `movedBy: support`, `device_key_hash`/`device_key_trusted` per **R5-4**). A successful correction (move back or detach) sets `dispute_frozen_until = now + 30 d` (restarts on each correction).
- **Unfreeze order (R5-5(b)):** (1) no freeze → `200 unfrozen: false`, `noop`, `not_run`; (2) different operator (below) else `409`, `refused`, `not_run`, no store call; (3) live ownership check; (4) `dispute_frozen_until = NULL`. Moves nothing.
- **R6-1 (security review, preferred server-side rule):** the unfreezing operator must differ from the operator of the correction that started the freeze **and** from the operator of the row that correction reversed (`corrects_audit_id`); and for **24 h after an unfreeze**, the unfreezing operator may not perform the next non-correction `seat:move` on that purchase (`409 ADMIN_CONFLICT`, audited `refused`).
- **Order ID:** `[Sensitive]`; never stored, logged, traced, audited or put in the idempotency store (these calls aren't idempotency-keyed).
- **Audit:** exactly one row per call, successful or refused, naming the operator; `support_seat_move` / `support_detach` details and `support_unfreeze` details per backend-api §5.3; never an e-mail, order ID or free text.
- **Alerts** (T-138 rules): > 2 support moves / purchase / 90 d; > 20 actions / operator / day; > 5 ownership failures / operator / day; any `dispute_frozen`; any `support_unfreeze`. Purchase UUID only.
- Idempotent by nature: moving to the current holder or detaching an unlinked purchase → current state, audited `noop`.

## Acceptance criteria
- [ ] Every call writes exactly one audit row (success, each refusal type, noop), and no row, log or span contains the order ID (sentinel test).
- [ ] Ownership check runs before any change; a failed check changes nothing and is audited `ownership_failed` (test).
- [ ] Target rules: a non-claimant, non-holder, non-correction-source target → `409`; an expired (> 7 d) claimant → `409`; account-linked purchase with a target not linked to that account → `409` (tests).
- [ ] Attach gate: buying install seen 29 days ago → `409`; 31 days ago → attach succeeds with `account_linked_by = 'support'` and `support_link_notice_pending = true` (tests).
- [ ] D-56: a support move restarts the window to `ceil_hour(now + 30 d)`; the previous holder's next token has `movedBy: support` (test with T-132).
- [ ] **R5-4 (shared with T-184):** the three `device_key_trusted` tests (trusted holder → untrusted claimant gives false; move back gives NULL/false; trusted claimant gives true) pass through this endpoint.
- [ ] Detach: only a support link named by `correctsAuditId` can be detached; a sign-in link → `409`; detach clears both notice columns (tests).
- [ ] **D-64/D-65(b):** after a correction, a non-correction move or attach within 30 days → `409`, audited `dispute_frozen`, **no store call** (WireMock asserts zero calls); a further correction is allowed and restarts the freeze (tests).
- [ ] **R5-5(b):** unfreeze with no freeze → `noop`, no store call; by the correcting operator → `409`, no store call; by another lead with a passing ownership check → `dispute_frozen_until = NULL`, and seat, `account_id`, `next_move_at`, `recent_rebinds` and claimants are unchanged (test compares rows before/after).
- [ ] **R6-1:** unfreeze by the operator of the row the correction reversed → `409`; within 24 h after an unfreeze, a non-correction `seat:move` by the unfreezing operator → `409` audited `refused`, while the same move by another agent succeeds (tests). *(If the PO picks disjoint role assignments instead, replace these two tests with a role-assignment check in T-137 and record the decision here.)*
- [ ] R5-7: support attach sets `support_link_notice_pending`; detach clears it and `support_link_notice_iat` (tests).
- [ ] Role checks: `support_viewer` → `403` on all three; `support_agent` → `403` on unfreeze; `support_lead` without `support_agent` → `403` on move/detach (tests).
- [ ] FU-011: live response-vs-spec tests for the three operations.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
