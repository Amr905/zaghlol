## Description

## Builder notes (device run findings)

### Product bug A (not fixed here): Home does not follow rows the SMS receiver writes while the app is open
- Repro: start the app on Home (returning user, English), then `adb emu sms send NBE 'NBE: Purchase of EGP 310.00 from NBE Visa **4567 at <shop>. Balance EGP 7000.00'`. The row is in the `transactions` table within seconds (source `sms`), but Home keeps showing the old state: "Spent this month" and the "Recent" list list only the two manual rows. Screenshot: `device-shots/0b2e0e9133d7e9b012d9376388a0b899796df2e4/llm-cat/E2ELCAT-en-00-no-card.png`. It stays stale until the providers are rebuilt (the test invalidates them).
- Providers seen stale: Home read model / `currentCycleOverviewProvider` (totals), the Recent list, and the auto-category card's `catEligibleCountProvider` -> `catCardVisibleProvider` (both autoDispose but watched all the time by `LlmCatDiscoveryCard`, so never re-evaluated; the card stays hidden after SMS arrive).
- Suspected cause (not verified): the rows are written by the ingestion path that wakes from the receiver, and no `TransactionsChanged` event / drift table-update reaches the UI providers (`cycleDataVersionProvider` is only bumped from that event). Check whether the receiver-path ingest publishes the event.
- The test works around it: `c.invalidate(catEligibleCountProvider); c.invalidate(catCardVisibleProvider)` and logs `NOTE card needed a provider refresh after the SMS (stale Home)`.

### Product bug B (fixed here): `RemoteConfigService.watch()` could miss a block applied right after the first value, so the provider names never reached the UI and the auto-category card was hidden (fail closed). Now subscribes before emitting.

### FU-450 done: `cat.card_last_shown` is recorded when a showing is counted; new `cat.card_dismissed_day` keeps the card up for the rest of that day unless "Not now" was pressed.
