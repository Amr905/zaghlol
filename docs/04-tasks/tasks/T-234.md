## Scope
A small tool the PO runs on Windows with Android Studio's emulator running and the devSms test build installed:
- `docs/qa/tools/sms_scenario.py` (Python 3, stdlib only) and a `sms_scenario.ps1` wrapper: finds `adb` (ANDROID_HOME / %LOCALAPPDATA%\Android\Sdk\platform-tools), lists emulators, then either sends one SMS (`--sender CIB --text "..."`), a named scenario file (default `app/test/fixtures/sms/scenarios/month_story.json`) with `--live` (all via `adb emu sms send`, now) or `--historical` (past-dated via `content insert`, needs `adb root` on a Google APIs image; explains if not available), or `--list` the scenario entries. Prints sender ids and counts, never bodies. Refuses to run against a physical device (serial not `emulator-*`) unless `--i-know-this-is-a-real-phone` is given.
- A short guide `docs/qa/sms-emulator.md`: create an emulator (API 34, Google APIs image, not Play Store so adb root works), install the sideload/devSms APK, grant SMS, run the tool, what to check on each screen (the expected totals printed by the tool from the same scenario).
- Unit tests for the parser/command builder (`python -m unittest`), no real adb needed.
## Acceptance criteria
Tool and guide committed; tests pass; works with the scenario format from T-233; no bodies printed; refuses real phones by default.
