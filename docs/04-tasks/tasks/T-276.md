## Scope
1. Find what happens on tap (`ZaghlolTapBubble`, `ZaghlolAvatar`, `RiveMascot`, `mascot_moments.dart`, the moods lab screen): does a mood change rebuild the widget with a new key, reload the `.riv` file / artboard / controller, swap between the still PNG, the interim art and Rive (a one-frame flash of another image or of empty space), or restart the state machine from frame 0?
2. Fix: load the Rive file once and keep one artboard/state machine alive per avatar; change mood through state-machine inputs/triggers (or a cross-fade of ≤ 150 ms between animations when inputs aren't available); never show the still or an empty frame between two animations; keep the widget's key and size stable so layout doesn't jump; preload on first build so the first tap doesn't hitch (precache the file bytes; decode off the first frame where the runtime allows).
3. Rapid taps: no queue build-up, no flicker; the last tap wins. Respect "reduce motion" (no animation → no transition needed).
4. Tests: a widget test that pumps frames across a tap and asserts the avatar never paints the fallback/still and its element is not recreated (same State object, loader called once); the moods lab switching between two moods does not reload the file.

## Acceptance criteria
Root cause in the task file; tests above; `flutter analyze` clean; manual steps for the PO (tap the bird on Home and on "حالات زغلول").
