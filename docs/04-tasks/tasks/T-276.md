## Description
Pure functions over already-aggregated inputs (per-currency monthly totals as `Money`, subscription list, cash pool figures): `whatIfCut(spendPerFullPeriod, mode, months)`, `whatIfSave(amount, months)`, `suggestSavings(inputs, thresholds)` returning ranked typed suggestions (kind S1–S4, category, monthly saving, basis periods). No repository access (the executor in T-292 feeds them).

## Acceptance criteria
1. Table tests from the SRS: dining 3 000/3 200/3 400 EGP, 50 % × 12 → **19 200.00**; 1 full period → result uses it and reports `basisPeriods = 1`; 0 full periods → `NotEnoughData`, no figure; amount mode 500 for 6 months with B 3 200 → **3 000.00**; amount above B is capped and flagged (`capped = true`).
2. PL-SUGGEST fixture of §10 → exactly [S4 cash **600.00**, S1 delivery **500.00**, S2 subscription **300.00**] in that order; dining (6 %) and rent (essential) never appear; ties ordered by category name.
3. One result per currency; nothing is summed across currencies; half-even rounding applied once per figure.
4. Thresholds come from parameters (defaults 15 / 20 / 25 %); changing them changes results in tests.
5. **Negative proof 1:** a static test fails if any file under `lib/ask/` uses `double`, `num` arithmetic on money, or `toDouble`.
6. **Negative proof 2:** a property test over random inputs never suggests an essential category (Q-25 list) for S1/S3.

## Notes for the builder
- Comparisons in minor units (e.g. S1: `last × 100 ≥ avg × (100 + pct)`), no division before comparison.
- Use the package's existing `Money` type; no Flutter imports.

## Design note (builder)
- Inputs: per-currency `List<Money>` of full-period spend, oldest first; B = half-even `sum / n` over the last <= 3 periods (rounded once), saving = `B x p / 100` (`mulDiv`, half-even) or `min(amount, B)`; total = `monthly.times(months)` (exact). `NotEnoughData` for 0 periods. Amount mode applies only to its own currency.
- S1: `last*300 >= sum*(100+pct)` in BigInt, saving = half-even `(3*last - sum)/3`. S3: strictly rising over the last 3 periods, saving latest - earliest. S1/S3 need >= 3 periods. A category offered by both keeps the larger saving. S2: largest monthly subscription (ties by name). S4: `unattributed*100 >= withdrawn*share`, saving `u x pct/100` half-even. Rank saving desc, ties category name then kind, top 3.
- Essential (Q-25) reuses `defaultEssentialCategoryIds` + `categoryCode` (strips `sys:`) and also checks `parentId` (batch-18d finding).
- Note: the SRS PL-SUGGEST fixture only holds if dining/delivery are not strictly rising (else S3 applies); the test uses non-monotonic periods with the stated averages.
