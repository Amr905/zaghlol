## Scope
1. Find what happens on tap (`ZaghlolTapBubble`, `ZaghlolAvatar`, `RiveMascot`, `mascot_moments.dart`, the moods lab screen): does a mood change rebuild the widget with a new key, reload the `.riv` file / artboard / controller, swap between the still PNG, the interim art and Rive (a one-frame flash of another image or of empty space), or restart the state machine from frame 0?
2. Fix: load the Rive file once and keep one artboard/state machine alive per avatar; change mood through state-machine inputs/triggers (or a cross-fade of ≤ 150 ms between animations when inputs aren't available); never show the still or an empty frame between two animations; keep the widget's key and size stable so layout doesn't jump; preload on first build so the first tap doesn't hitch (precache the file bytes; decode off the first frame where the runtime allows).
3. Rapid taps: no queue build-up, no flicker; the last tap wins. Respect "reduce motion" (no animation → no transition needed).
4. Tests: a widget test that pumps frames across a tap and asserts the avatar never paints the fallback/still and its element is not recreated (same State object, loader called once); the moods lab switching between two moods does not reload the file.

## Acceptance criteria
Root cause in the task file; tests above; `flutter analyze` clean; manual steps for the PO (tap the bird on Home and on "حالات زغلول").

## Design note (builder)
Root cause: `ZaghlolTapBubble` passed `avatarKey: ValueKey('tap-$_taps')` and the moods lab used `ValueKey('mood-avatar-$_plays')`. Every tap changed the key, so Flutter disposed the `RiveMascot` State and built a new one; the new one starts with no controller and shows the still PNG until its async `_load()` completes (a frame or more), then creates a new controller/artboard/state machine restarting at frame 0. That is the visible "loading another animation". Secondary: the first mount shows the interim art until `zaghlolRivePresentProvider` resolves and the still until the file loads.

Fix: no key changes; a `replay` counter on `ZaghlolAvatar`/`ZMascotBubble`/mascots replays a moment on the same widget. `RiveMascot.didUpdateWidget` only writes state-machine inputs through a `RiveMascotHandle` (injectable `riveMascotLoaderProvider`, fake in tests). Same-value replay sets a different `state` value for one frame (`endOfFrame`), then the target; a generation counter makes the last tap win with nothing queued. `preloadRiveMascot()` runs from `main` (native init, file decode, asset manifest). Reduce motion still shows the still only, never loads Rive.

## Builder assumptions
- The one-frame bounce value is `(index+1) % 15`; the file starts every one-off from the rest pose, so no other animation is visible (checked by reading the handoff doc, not rendered; PO please look at rapid taps on a device).
- Sub-150 ms cross-fade not needed because inputs exist.
- `z_mascot_bubble.dart`: only replaced `avatarKey` by `replay` (minimal; T-277 owns the text).
