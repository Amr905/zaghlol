## Report (PO, 2026-11-23, real Android phone, test build)
"When I open the app it shows like a popup but disappears quickly. It only happens when I start the app." Not on resume, only on a cold start.

## Description
Find what draws a dialog, sheet, banner, snackbar, overlay or route for a moment during a cold start and then removes it, and stop it from showing. Candidates to check (not exhaustive): `app/lib/app/onboarding_gate.dart` (routing before settings/DB load), `app/lib/app/notification_taps.dart` (a dialog at launch), the app-lock / biometric gate, the privacy/consent or "what's new" prompts, update or entitlement banners, the mascot bubble on Home (`home_mascot_slot.dart`), Android splash → first frame (launch theme vs app theme, especially True Black dark), and any provider that shows UI while it still loads (AsyncLoading → data flips). Reproduce in a widget/integration test by pumping the real app root with the real startup providers in their loading → ready order and asserting that no modal route, overlay entry or banner is mounted and then removed during start-up.

## Acceptance criteria
1. Root cause named in a short note in this file (what showed, why, and why only on cold start).
2. Fixed at the cause (no delay hacks): nothing flashes on a cold start in light or dark, ar or en, with or without app lock, first run after onboarding and later runs.
3. A test that fails before the fix and passes after it.
4. If the cause is the Android launch screen (native splash vs first Flutter frame), align the launch theme with the app's background per theme and say so; check `android/app/src/main/res/values*/styles.xml` and the iOS LaunchScreen.
5. `dart analyze`, `dart format`, related tests green.
