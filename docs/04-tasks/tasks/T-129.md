## Description
Crowd-sourced merchants reach the catalog only via operator review.

## Technical details
- Aggregate by `merchant_norm` + institution; `ready_for_review` at ≥ 5 distinct installs (A-48); raw rows purged per retention.
- `GET /admin/v1/contributions` never returns `collecting` aggregates; status enum `ready_for_review | promoted | rejected`.
- **Body-keyed actions (§5.2):** `POST /admin/v1/contributions:promote` takes `{merchantNorm, institutionCode, merchantId?, categoryCode?}` (with `merchantId` → exact alias; without → new draft merchant; `categoryCode` defaults to the top vote); `:reject` takes `{merchantNorm, institutionCode}`; both return `{merchantNorm, institutionCode, status, merchantId?}`.
- A missing key and a `collecting` key both give the same `404 NOT_FOUND` from one query that excludes `collecting` (no timing difference); `409 ADMIN_CONFLICT` only for an already `promoted`/`rejected` aggregate or a draft conflict.
