## Design / spec pointers
- `docs/03-technical/ask-llm.md` §3 (Vertex adapter details, no retention, resilience).
- ADR-027 options B/C (tool-calling fallback when a JSON Schema subset can't express `anyOf`). ADR-027 lists two adapters; the PO added claude-haiku-5-5 as a third candidate (PO_DECISIONS ASK-LLM); T-364 amends the ADR.

## Description
- `VertexGeminiProvider`: `generateContent` on a regional (EU) Vertex endpoint, `responseMimeType: application/json`, `responseJsonSchema`, minimal thinking, **no** `cachedContent`, **no** grounding tools; service-account OAuth via `Google.Apis.Auth` (secret from `ILlmApiKeyProvider`).
- `AnthropicMessagesProvider`: Messages API with JSON-schema structured output (or, if the schema is not accepted, one forced tool whose `input_schema` is the plan schema), `max_tokens` from the call, static system prompt first, no `metadata.user_id` or other identifiers.
- Both map usage (input, cached, output) to `LlmUsage` and use the shared resilience pipeline.

## Acceptance criteria
1. WireMock tests assert each request body: schema present, output cap set, no grounding/cache fields (Vertex), no identifiers (install, account, IP, attestation, app version) anywhere in body, headers or URL.
2. Outcome mapping (Ok, Invalid, Refused, Timeout, Upstream) tested per adapter with recorded replies.
3. Any schema transform needed for a provider is a pure function with a test proving the transformed schema accepts and rejects the same T-322 vectors as the original.
4. Configuration entries `Llm:Providers:{gemini-flash-lite,claude-haiku}:*` with decimal prices; no constants.

## Notes for the builder
- No vendor SDKs. Provider data-retention terms are launch-checklist items (T-365), not code.

## Design note (builder, 2026-11-26)
Vendor docs checked 2026-11-26: Anthropic [structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) and [Messages API](https://platform.claude.com/docs/en/api/messages); Gemini [generateContent reference](https://aistudio.google.com/api-reference/generate-content) (the Vertex page body did not load; the Vertex REST shape is the same message format) and Vertex [locations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/locations) (`https://{location}-aiplatform.googleapis.com`, path `/v1/projects/{p}/locations/{l}/publishers/google/models/{m}:generateContent`). The Anthropic `anthropic-version: 2023-06-01` header value and the `cloud-platform` OAuth scope come from general knowledge, not from the fetched pages; both need the live test (T-351).
- **Vertex.** Body: `systemInstruction` (static, first), one user `contents` entry, `generationConfig` = `responseMimeType application/json`, `responseJsonSchema` (supports `anyOf`, so no transform beyond stripping the root `$schema`/`$id`/`$comment`), `maxOutputTokens`, `thinkingConfig.thinkingLevel MINIMAL` (Gemini 3+; an earlier model would reject it). No `cachedContent`, tools, grounding or labels. Auth: bearer token minted by `Google.Apis.Auth` from the service-account JSON (`IVertexAccessTokenSource`; fake in `tests/Shared`). `blockReason` or finish reason SAFETY/PROHIBITED_CONTENT/BLOCKLIST/SPII -> Refused; MAX_TOKENS and anything else but STOP -> Invalid. Usage: input = `promptTokenCount`, cached = `cachedContentTokenCount`, output = candidates + thoughts.
- **Anthropic.** Strict structured output allows 16 `anyOf` parameters per request and this schema has more, so one forced tool `reply_json` carries the schema as a non-strict `input_schema`; the reply is that tool's `input`, and the server plan validation is the gate. Prompt caching is not requested (the cacheable prefix is near Haiku's minimum, and cache writes have their own price that the config has no field for); cache reads are still mapped if the API reports them. `stop_reason` refusal -> Refused; max_tokens, end_turn (prose) or no tool block -> Invalid. Usage: input = input + cache read + cache creation, cached = cache read.
- **Schema transform.** `LlmSchemaTransforms.ForProvider` is pure; it removes only root annotations. Test: same verdict on all 89 T-322 plan vectors (`Zaghlol.Contract.Tests/LlmSchemaTransformTests`).
- **Duplicate properties** are Invalid for all three adapters (Anthropic: the whole envelope is parsed without duplicates).
- **FU-406** fixed in `LlmCallGuard` (a result of a call that is not the probe is ignored once the circuit is open; `IOException` while reading the body is Upstream). **FU-411** fixed through `IKnownLlmProviderIds` (`PUT llm.provider` refused with 400 for an id with no configured provider) when the host registers `AddZaghlolLlm`; a host that does not (the admin host today) stays permissive.
