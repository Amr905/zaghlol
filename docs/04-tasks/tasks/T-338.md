## Design / spec pointers
- `docs/03-technical/ask-llm.md` §3 (Vertex adapter details, no retention, resilience).
- ADR-027 options B/C (tool-calling fallback when a JSON Schema subset can't express `anyOf`). ADR-027 lists two adapters; the PO added claude-haiku-5-5 as a third candidate (PO_DECISIONS ASK-LLM); T-364 amends the ADR.

## Description
- `VertexGeminiProvider`: `generateContent` on a regional (EU) Vertex endpoint, `responseMimeType: application/json`, `responseJsonSchema`, minimal thinking, **no** `cachedContent`, **no** grounding tools; service-account OAuth via `Google.Apis.Auth` (secret from `ILlmApiKeyProvider`).
- `AnthropicMessagesProvider`: Messages API with JSON-schema structured output (or, if the schema is not accepted, one forced tool whose `input_schema` is the plan schema), `max_tokens` from the call, static system prompt first, no `metadata.user_id` or other identifiers.
- Both map usage (input, cached, output) to `LlmUsage` and use the shared resilience pipeline.

## Acceptance criteria
1. WireMock tests assert each request body: schema present, output cap set, no grounding/cache fields (Vertex), no identifiers (install, account, IP, attestation, app version) anywhere in body, headers or URL.
2. Outcome mapping (Ok, Invalid, Refused, Timeout, Upstream) tested per adapter with recorded replies.
3. Any schema transform needed for a provider is a pure function with a test proving the transformed schema accepts and rejects the same T-322 vectors as the original.
4. Configuration entries `Llm:Providers:{gemini-flash-lite,claude-haiku}:*` with decimal prices; no constants.

## Notes for the builder
- No vendor SDKs. Provider data-retention terms are launch-checklist items (T-365), not code.
