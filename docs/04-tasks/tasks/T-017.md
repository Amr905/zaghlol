## Input from T-016 (2026-11-10)
- **Short-query FTS (T-016 design note §8(b)).** Measured on the host (debug, encrypted, 50k rows, median of 3 passes after a warm-up): `like_short_ms` p95 **497 ms** (the LIKE fallback misses FR-TXN-01) vs `short_prefix_ms` p95 **20.7 ms** with a second FTS5 table (build 141 ms). Emulator figures: db-platform run on `ci/T-016` (`ZAGHLOL_DB_BENCH` line, `short_prefix_ms`). Proposed DDL for §2.2, kept in sync by the same triggers as `transactions_fts`: `CREATE VIRTUAL TABLE transactions_fts_short USING fts5(merchant, counterparty, tokenize='unicode61 remove_diacritics 2', prefix='1 2');` queried with a quoted word prefix (`"ab"*`) for 1–2 character searches. Digit-only short queries (e.g. `١٢`) find nothing there (no amounts in the table); Search should send them to `transactions_fts`/amount filters.
- **Schema versioning.** T-016 shipped `schemaVersion = 1` with `db_meta` only, dumped in `app/drift_schemas/app_database/drift_schema_v1.json`. Adding tables means either `schemaVersion = 2` with a `stepByStep` migration (exercises the T-016 safety net), or, since no build has shipped, regenerating v1; the architect's design note should pick one. Code generation runs through `app/tool/generate_drift.sh` (drift_dev can't resolve in the workspace; see `tools/drift_codegen/pubspec.yaml`). Put every drift-annotated file in `app/lib/core/db/schema/` and import only `package:drift` and siblings there (the generator copies that folder).
- **Migration tests.** drift_dev's `SchemaVerifier` / `validateDatabaseSchema()` are unavailable at runtime for the same reason; use `schemaShapeOf` (`lib/core/db/schema_shape.dart`) and the dump's `fixed_sql`, as in `test/core/db/app_database_test.dart`, and the safety-net patterns in `test/core/db/migration_harness_test.dart`.
