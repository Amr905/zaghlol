## Description
Everything the onboarding and degraded mode need from Android.

## Technical details
Capabilities incl. smsFlavor; runtime permission request; settings intents; permission change callbacks (EC-13); POST_NOTIFICATIONS on 13+.

## Design note (builder, sprint 2026-11-13)
- No contract change: `AndroidCaptureHostApi` and `CaptureEventsApi` stay as in platform-channels.md section 2. `CaptureHostPort` (Dart) gains `requestSmsPermission`, `openNotificationAccessSettings`, `isIgnoringBatteryOptimizations`, `requestIgnoreBatteryOptimizations`.
- Kotlin: `UiPermissions` / `ActivityPermissions` (Activity seam, JVM-testable) given to the UI host only; `MainActivity` forwards `onRequestPermissionsResult` (request code 4417, below 65536 for FragmentActivity) and calls `CaptureRuntime.checkPermissions()` on resume and after a prompt. `smsFlavor` is the only gate before the system prompt; `*NoSms` manifests also lack the permissions.
- Prominent disclosure for notification access is Flutter UI: T-056 (this task only opens the settings list).
- Open for the notifications owner: `POST_NOTIFICATIONS` request and manifest declaration (no request method in the contract). Restricted-settings on Android 13+ sideloaded installs: the user may need "Allow restricted settings" in App info before notification access can be switched on (device test).
