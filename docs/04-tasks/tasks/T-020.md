## Implementation notes
- `app/lib/core/settings/`: `setting_key.dart` (`SettingKey<T>`: name, default, decode/encode; bool, bounded int, optional int, enum, currency, optional `Money`, slug set; `SettingsException` code-only), `settings_keys.dart` (`Settings.*`, 29 keys with defaults), `settings_repository.dart` (`get`/`watch`/`set`/`reset` over the T-019 `SettingsDao`; no schema change), `settings_providers.dart` (`settingsRepositoryProvider`, `settingProvider(key)` helper, providers for the common keys). Nothing else touched; no shared provider file edited.
- Behaviour: an unset, corrupt or out-of-range stored value reads as the default (never thrown, never echoed). A write whose value doesn't round-trip (e.g. payday 0 or 29-31, depth 25) throws `SettingsException('SETTING_INVALID_VALUE')` and writes nothing. Setting a nullable key to null unsets it. `updated_at` comes from an injectable UTC ms clock. Last writer wins per key (single upsert).
- Money: income target is stored as `<minor>:<CODE>` through `Money.tryFromStorage`; no double.
- Defaults: language system, digits auto (Arabic-Indic in ar, A-29), theme system, payday 1 (A-43), primary currency EGP, "≈" view off with target EGP (A-54), all notification types on, quiet hours on 23:00-08:00 (A-27, minutes after midnight), app lock off with 60 s timeout (A-10), hide-amounts: share cards on (A-26), notifications and widget off, capture sources (sms, notifications) on, contribution opt-in off, scan depth 6 months (A-11, 1-24), setup progress empty, paywall last shown null.
- Tests: `app/test/core/settings/settings_repository_test.dart` (13): default and round trip per key (AC1), range refusals, garbage-reads-default with a sentinel, watch, two repositories, provider, and the plain-prefs scan over `lib`, `ios`, `android/app/src` and `pubspec.yaml` ignoring comment lines (AC2; runs in CI as part of `flutter test`).
- Not done: no UI; no keys for dismissed suggestions (FR-ONB-10) or backup schedule (those belong to their tasks; `secure_state` holds the schedule per schema).

### Self-check (docs/workflow/self-check.md)
1. Never destroy data: only `reset` deletes, called explicitly by the caller; no error path deletes or resets. N/A otherwise.
2. Concurrency: a single upsert per write; test with two repositories on one database. Watch streams filter by key.
3. Untrusted input: stored text is strictly decoded (ASCII digits only, no sign/padding/overflow, length-capped slug set); bad text falls back to the default. Errors carry a code only (sentinel test).
4. Fail closed: unknown enum value reads as the default; unknown currency code reads as default/null.
5. Secrets/logs: no logging; income target never in errors (`Money.toString` omits amounts).
6. Docs match code: database-schema §2.8 already says "typed accessors in core/settings"; no contract change. The key names are part of the backup format (stated in `settings_keys.dart`).
7. Evidence: AC1 -> "every key ... default" and "every key round-trips"; AC2 -> "no plain preferences anywhere in the app"; local analyze, format, tests and lints green.
