## Scope
1. Add → Scan offers **Camera** and **Gallery** (bottom sheet per the Add sheet style). Camera uses `image_picker` `ImageSource.camera` (system camera intent: no CAMERA permission in the manifest; if the manifest already declares it, handle denial with a message and the Gallery option). iOS: `NSCameraUsageDescription` present and accurate (ar/en InfoPlist strings if the project localises them).
2. The photo follows the existing path in `app/lib/features/capture/application/scan_providers.dart` (encrypted spool → OCR → confirm). The captured file is deleted after reading, including on failure and cancel; nothing lands in the gallery.
3. Large photos: downscale before OCR only if the existing path does; otherwise keep it.
4. **Dev builds only** (same gate as SMS diagnostics): the scan confirmation and both empty states get a "what I read" button showing the OCR text on screen (never logged, never stored, not in release). This is how the PO can tell us what the phone read when a total is wrong.
5. Strings ar (Egyptian colloquial) + en; widget tests ar/en; no hard-coded strings.

## Acceptance criteria
Widget tests: both sources offered; camera result flows to the confirm screen; cancel leaves no file; dev-only button absent in release flavour. `flutter analyze` clean.

## Design note (builder)
- `ScanImagePicker` now takes a `ScanImageSource` (camera or gallery). Both go through `image_picker`; the existing finally-block deletes the plain file after sealing, on failure and on cancel (no file exists on cancel). Camera denial (`camera_access_denied`) throws `ScanCameraDeniedException`; the choose screen then shows a banner and only the Gallery button.
- Dev-only "what I read": `scanReadTextEnabledProvider` (= `kIsDevBuild`, compile-time constant). `ScanService.keepReadText` keeps the OCR text of the latest scan in a memory field only; never logged, stored or put in an outcome. The button is an app-bar action on the confirm editor (via new `TransactionEditScreen.extraActions`) and on the no-text and no-total screens.

## Builder assumptions
- The "bottom sheet" in the scope is the existing S-32 choose screen with two buttons (Take a photo, Choose from gallery) rather than a second sheet on top of the Add sheet; the Add sheet's Scan tile is unchanged.
- No CAMERA permission is in the Android manifest, so the system camera intent is used; the denial path is kept for OEMs that still raise it.
- No downscaling is added (the existing path has none).
- Added NSCameraUsageDescription (Info.plist) with ar/en entries in InfoPlist.xcstrings.
- The "what I read" button also shows on the no-text screen after an OCR failure (empty text, "Nothing was read.").
