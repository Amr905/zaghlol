## Scope
1. One shared domain function `cycleLabelMonth(cycleStart)` : start day ≥ 21 → next calendar month, else the start's month. Used everywhere a cycle is shown as a month.
2. Apply to: Home cycle header, budgets, chart period labels ("this cycle"/"last cycle" titles and any month-named cycle), the monthly summary / weekly summary copy where it names the month, Ask answers that name a month for a cycle ("this month" when the user's cycle is the reporting unit), widget data. Calendar-month periods (D-68 chart presets "this month", "last month") stay calendar months.
3. Strings via l10n; Arabic month names Egyptian usage.
## Acceptance criteria
Unit tests for the function (20 → same month, 21 → next, Dec 24 → January next year); widget/golden updates for Home and charts in `ar` and `en` with pinned clocks; Ask test for "how much did I spend this month" with payday 24.

## Design note (builder)

- **Domain** (`packages/zaghlol_domain/lib/budget/cycle_label.dart`): `cycleLabelMonth(CivilDate cycleStart) -> ({int year, int month})`; start day >= 21 is the next calendar month (Dec rolls to January of the next year), else the start's own month. `ZDateFormat.cycleMonthName(start, lang, {short})` renders it (month names only, no digits).
- **Where a cycle is named as a month**: Home hero label when a payday is set and there is no budget ("Spent in December", new ARB `homeHeroSpentInCycleMonth`; the calendar fallback "Spent this month" stays); Budget screen cycle line ("December . 24 Nov to 23 Dec . 7 days left"); chart bars that are payday cycles (`cashFlow` cycle bucket labels, saved-per-month, in/out and category-trend bars and their a11y strings) via `cycleLabelMonth(bar.from)`. Calendar-month buckets (D-68 "this month" / "last month" presets, rolling and year ranges) stay named by their own month: the `month` bucket branch is unchanged and calendar bars start on day 1 anyway.
- **Ask**: `AskPeriodKind.month` (offset k) and `monthOfYear` now resolve to the payday cycle named after that month (the cycle holding today is "this month", the one before "last month"). With payday 1 a cycle is the calendar month, so nothing changes there. The answer text names the current / previous cycle "this month" / "last month" (builder gets the schedule).
- **No change needed (no month is named today)**: weekly summary (seven days, range only), widget snapshot (days to payday only; a new field would change the Pigeon contract), "this cycle" / "last cycle" chart phrases.
- **FU-296** (all in the same change): m-1/m-2 `PaydayAutoService.onPersisted(txnId)` runs the rule only when the stored row is itself a salary credit; salary credit = income, posted, not internal, and (tied in `salary.state`, or category `sys:income` with source `heuristic` (template salary event) / `user_rule`, or a salary word in merchant / counterparty / note). m-3 `detectPayday` compares the capped days on a 28-day ring (28 and 1 are neighbours, tolerance 2), the arc start wins (28 over 1). m-4 `setPayday` + the `payday_auto` write (and Undo) are one `db.transaction`. m-6 `PaydayDetection.salaryDay` / `PaydayAutoState.salaryDay` (JSON key `d`, optional, old state reads as null) feed `paydayAutoBannerCapped`. n-1 `SetupSuggestionKind.payday`, `SetupSuggestion.paydayDay`, `HomeCards.salary`, `acceptPayday` and the card branch are removed (the stored slug `payday` in old `setup_suggestions_handled` is harmless). m-5 see assumptions.

## Builder assumptions
- "This month" in Ask follows the cycle once a payday other than 1 is set (D-82 "Ask uses the same name"). The existing Ask period/engine tests that pinned calendar November for payday 25 were updated. An explicit month name ("in October") resolves to the cycle named October; if none of the cycles around the 15th of that month carries the name (odd payday history) it falls back to the calendar month.
- Salary credits the user only filed under Income by hand (source `user`, no salary word, not tied in `salary.state`) no longer count for the payday rule. Credits added through "My salary / It arrived" are tied in `salary.state` and do count.
- m-3 works on the capped days (29-31 already become 28), so "30 -> 28, 1" agrees with a 28 and a 1; two paydays 3 or more days apart on the ring do not.
- m-5: Home goldens use a budgeted fixture, so the banner is not in them. Added goldens of the banner itself (plain and capped, ar and en) in `test/features/salary/presentation/goldens/` and Home hero goldens for the named cycle (`home_cycle_named_*`). Generated locally; CI's golden job is the judge for font differences.
- Month names in Arabic are the Egyptian-usage names intl gives for `ar` (يناير ... ديسمبر).
