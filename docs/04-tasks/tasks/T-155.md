## Design note (builder, T-155)
- `application/import_csv.dart`: `parseCsv` (strict RFC 4180, BOM, caps 64 MiB / 200000 rows / 4096-rune cells) and `ImportCsvUseCase` over the `CsvImportStore` port; `data/drift_csv_import_store.dart` is the Drift adapter. One write transaction: all valid rows or none. No schema change.
- Header must equal `exportHeader`. Bad rows are skipped and counted by reason (`ImportRowProblem`) with at most 100 row numbers; whole-file problems throw `ImportCsvException` (codes only). Nothing echoes cell content.
- Amounts: digit-normalised, `Money.tryParse` (exact), negatives rejected. Dates: ISO `...Z` only, years 2000-2099. Unknown account: row invalid (an import never creates accounts); unknown category: dropped (stored uncategorised).
- Duplicates: skipped and counted (no review items). Key = account + instant (ms) + type + `Money.toStorage()` + trimmed merchant, compared as a multiset: a file with the same purchase twice imports twice into an empty book and zero times when both exist. Ids are not preserved (the repository generates them), so the key, not the id, is what matches.
- Stored as source `csv` (the original source is not round-tripped), user-verified, status kept. `TransferPairing`/`RefundMatching` hooks are not called (the task does not ask).
- Residuals: a note/merchant that truly begins with `'=`, `'+` etc. loses its apostrophe (indistinguishable from `neutralizeFormula`); a soft-deleted row inside its Undo window is not counted as existing; `id`, `source` and `category_source` are not restored. No UI yet (T-157/T-158 are the callers).
