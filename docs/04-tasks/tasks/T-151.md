## Description
Backups in the user's iCloud container.

## Technical details
Ubiquity container Documents/Backups; availability check; upload/list/download/delete with coordination; error codes.

## Design note
Written by the implementer (C4, PO cost rule 3; not crypto/keys: the bytes are already encrypted by T-148/T-149). Mirrors T-150 (Drive): same names, verify-then-prune, `.partial` handling, code-only errors. Not here: schedules, Free/Gold slot choice (T-152), backup/restore UI (T-153).

**1. Layers.**
- Native `ios/Runner/Platform/ICloud/`: `ICloudBackupHost` (Pigeon `ICloudBackupHostApi`) over `ICloudBackupFiles` (the file work, testable on a plain directory) and an `ICloudEnvironment` port (container URL, complete listing, download wait). Production environment: `FileManager.ubiquityIdentityToken` + `url(forUbiquityContainerIdentifier:)` (off the main thread), `NSMetadataQuery` in `NSMetadataQueryUbiquitousDocumentsScope` for the listing (it sees items that are not downloaded), `startDownloadingUbiquitousItem` + polling `ubiquitousItemDownloadingStatus` for the download. Every call runs on one serial background queue, so a call Dart gave up on (timeout) still finishes before the next one starts. Writes, moves, reads and deletes use `NSFileCoordinator`.
- Dart `data/icloud_store.dart`: `ICloudBackupStore` (availability, list, verified upload, `planICloudPrune` + `prune`, download, delete); `data/icloud_backup_exception.dart`; `application/icloud_backup_service.dart` (`backupNow`, `list`, `restore`); `application/icloud_backup_providers.dart`.

**2. Names and place.** `<container>/Documents/Backups/`. Same names as Drive (`zaghlol-backup-<seq>-<createdAtMs>.zaghlol.enc`, in flight `+ .partial`), checked by the same strict regexes on both sides; native refuses any other name (`INVALID_ARGUMENT`) and the listing returns only our names, so nothing else in the container is ever touched. Container: `iCloud.app.zaghlol` in prod (contract); dev/staging use `iCloud.app.zaghlol.dev` / `.staging` (`iCloud.$(PRODUCT_BUNDLE_IDENTIFIER)`), so test backups never mix with real ones. The identifier is read from Info.plist `ZaghlolICloudContainer`; missing → unavailable (fail closed).

**3. Upload (verify-then-prune).** Dart stages the encrypted stream in `<temp>/zaghlol_backup_upload_icloud/` (its own directory: the Drive service wipes `zaghlol_backup_upload`), `verifyFile` decrypts it once and MD5 is computed in the same read (as T-150). Native: the final name must not exist (also no `.<name>.icloud` stub) → else `ALREADY_EXISTS`, nothing overwritten; copy to `<name>.partial` with MD5 of the source, `synchronize()`, read the partial back and compare (mismatch → the partial, ours and provably wrong, is deleted, `UPLOAD_UNVERIFIED`); coordinated move to the final name (`moveItem` never replaces); read the final back and return its size and MD5. Dart checks name, size and MD5 against the local file, else `uploadUnverified`.

**4. "Verified complete" for iCloud.** A local write is not a backup: iCloud uploads later and can fail (quota). Pruning needs the new file to be **uploaded** (`NSMetadataUbiquitousItemIsUploadedKey`). After the upload the service polls the listing (3 s, up to 120 s by default) until the new file is reported uploaded with the right size; otherwise the run ends with `prune.skipped` and `uploaded = false` and nothing is deleted (the next successful run prunes the leftovers, which are then older). A quota error reported for the new file → `quotaExceeded`. Before staging a new backup, a quota error on any of our files → `quotaExceeded` up front (no more full copies piling up locally).

**5. Pruning (self-check §1).** `planICloudPrune` = T-150's `planPrune` with iCloud fields: needs a complete listing that holds `protect` exactly once, with the same size, `isUploaded`, no upload error and a creation time; any doubt → null (no deletes). Candidates: our final names with a creation time; kept: `protect`, every file created at or after it, the newest `keep`; undated never deleted. `.partial` files only when created ≥ 24 h before `protect`. Times are file-system creation times from the creating phone's clock (iCloud has no server time here): a phone with a slow clock can make another phone's newer backup look older and delete it, but its own just-uploaded backup is always kept, so at least one complete backup always remains (accepted residual). Deletes stop at the first error other than `NOT_FOUND`.

**6. Download.** Only our final names from our listing, size known and ≤ 1 GiB. Native starts the download, waits up to 10 min for the current version (else `TIMEOUT`), copies it under a coordinated read to `tmp/zaghlol_backup_download/<uuid>` and returns the path. Dart streams it with the listed-size cap (more or fewer bytes → `corruptDownload`) and deletes the copy in `finally`.

**7. Availability (AC "iCloud off").** `isAvailable` = identity token present and container URL obtainable. Every store operation checks it first and throws `ICloudBackupException(unavailable)` (`ICLOUD_UNAVAILABLE`), whose `offersDrive` is true: the UI (T-153) shows `backup_settings_errorIcloud` and offers Google Drive (T-150). No new l10n keys.

**8. Errors and limits.** Native codes: `ICLOUD_UNAVAILABLE`, `INVALID_ARGUMENT`, `NOT_FOUND`, `ALREADY_EXISTS`, `UPLOAD_UNVERIFIED`, `TOO_LARGE`, `TIMEOUT`, `IO_ERROR` (message and details always null). Dart `ICloudBackupErrorCode`: `unavailable`, `timeout`, `quotaExceeded`, `notFound`, `uploadUnverified`, `tooLarge`, `listTooLong` (> 1,000 of our files), `corruptDownload`, `notOurFile`, `busy`, `io`. Dart timeouts: metadata 30 s, upload 60 s + 1 s per 25 KB, download 11 min. Nothing logs on either side.

**9. PO setup.** Apple Developer portal: create the iCloud containers `iCloud.app.zaghlol`, `iCloud.app.zaghlol.dev`, `iCloud.app.zaghlol.staging`; enable iCloud (CloudKit/iCloud Documents) on the App IDs `app.zaghlol`, `.dev`, `.staging` and assign each its container; regenerate the provisioning profiles. Until then signed builds fail to provision and iCloud reports unavailable.

## Implementation notes (T-151 build)
**Files.** Native: `app/ios/Runner/Platform/ICloud/ICloudBackupFiles.swift` (names, verified copy → move, list filter, download copy, delete; coordinated), `ICloudBackupHost.swift` (`SystemICloudEnvironment` with `NSMetadataQuery` + download wait, Pigeon host on a serial queue, registration), `IcloudApi.g.swift` (regenerated, now in the Xcode project), `RunnerTests/ICloudBackupTests.swift`, `Runner/Runner.entitlements` (new), `Info.plist` (`ZaghlolICloudContainer`), `AppDelegate.swift` (one registration line), `project.pbxproj` (files + `CODE_SIGN_ENTITLEMENTS` on the 9 Runner configurations). Pigeon: `app/pigeons/icloud_api.dart` (pigeon 26.3.2 from the lockfile). Dart: `data/icloud_store.dart`, `data/icloud_backup_exception.dart`, `application/icloud_backup_service.dart`, `application/icloud_backup_providers.dart`. CI: the iCloud Swift sources join the no-logging check. The Drive code is unchanged (the iCloud service repeats its ~80-line staging/verify step rather than refactor reviewed T-150 code; candidate follow-up: one shared staging helper).

**Entitlements (each needed for the ubiquity container):** `com.apple.developer.icloud-container-identifiers` and `com.apple.developer.ubiquity-container-identifiers` = `iCloud.$(PRODUCT_BUNDLE_IDENTIFIER)`; `com.apple.developer.icloud-services` = `CloudDocuments` (iCloud Documents, not CloudKit). No `NSUbiquitousContainers` in Info.plist, so the folder is not shown in the Files app. No keychain-access-groups entry is added, so the default access group (and the T-015 key items) is unchanged. No new permission prompts.

**l10n.** No new keys. T-153 (UI) maps `ICLOUD_UNAVAILABLE` / `offersDrive` to `backup_settings_errorIcloud` plus the Drive choice (`backup_restore_optionDrive` / `backup_settings_where`), `ICLOUD_QUOTA_EXCEEDED` to `backup_settings_errorStorage` (provider iCloud), `ICLOUD_TIMEOUT` to `backup_settings_errorNetwork`, everything else to `backup_settings_errorGeneric`. A run that ends with `uploaded = false` is a success for the user ("iCloud finishes uploading in the background").

**AC → test.**
- iCloud off → clear error and Drive offer: `icloud_backup_service_test.dart` "AC: iCloud off → ICLOUD_UNAVAILABLE that offers Drive; nothing is written, uploaded or deleted"; `icloud_store_test.dart` "upload iCloud off → unavailable, offers Drive, nothing sent"; Swift `testICloudOffIsUnavailableForEveryCall`, `testHostErrorsCarryACodeOnly`.
- Restore from iCloud (FR-BAK-01): service "an iPhone backup in iCloud restores on the other phone, data identical; only ciphertext reaches iCloud".
- Verify-then-prune / never destroy on doubt: store `planICloudPrune` group, `prune` group, `waitUploaded` group; service "not yet uploaded → nothing pruned…", "iCloud full…", "stored bytes differ…", "a snapshot failure…", "two phones back up at once with keep 1…", "Free twice → one file; Gold 7 times keep 5". Swift: `testUploadNeverOverwritesAnExistingBackup`, `testUploadNeverOverwritesAnExistingPartial`, `testNamesThatAreNotOursAreRefusedEverywhere`, `testDeleteRemovesOnlyTheNamedBackupAndReportsAbsence`, `testUploadWritesTheFinalNameLeavesNoPartialAndReportsTheMd5`.
- Channel with a fake platform: store "PigeonICloudFiles over a fake platform channel" (values both ways; native errors become code-only exceptions; no handler → `io`).

**Negative proofs (run locally).** (1) `planICloudPrune` without the `isUploaded` check → "nothing when protect is not uploaded…" and "a not-yet-uploaded protect deletes nothing" go red. (2) Service prunes even when `waitUploaded` returned null (and the plan ignores `isUploaded`) → "not yet uploaded → nothing pruned…" goes red. (3) Store skips the MD5 comparison → "upload MD5 mismatch" and "stored bytes differ…" go red.

**Manual device test (not run: needs a signed build with the iCloud capability, PO portal setup below).** On an iPhone signed in to iCloud with iCloud Drive on: (1) Back up now → a file `zaghlol-backup-1-….zaghlol.enc` appears under Settings → Apple ID → iCloud → Manage Storage → Zaghlol; the outcome reports uploaded within 2 min on Wi-Fi. (2) Back up again with keep 1 → after upload only the new file remains. (3) Airplane mode, back up → outcome `uploaded = false`, both files remain; back online, back up again → only the newest remains. (4) Settings → Apple ID → iCloud → iCloud Drive off for Zaghlol (or sign out) → Back up now fails with `ICLOUD_UNAVAILABLE` and the Drive offer. (5) Second iPhone, same Apple ID, fresh install → restore lists the backup (not downloaded yet), downloads and restores identical data. (6) Full iCloud storage → `ICLOUD_QUOTA_EXCEEDED`, previous backup intact. Results: not run in this build.

**Residuals.** Creation times come from the creating phone's clock (design note §5). A Dart timeout leaves the native call running on its serial queue; the next call waits for it. `NSMetadataQuery` may lag a just-written local file; a file it can't see is never deleted.
