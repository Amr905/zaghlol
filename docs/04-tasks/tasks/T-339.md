## Description
After **every** provider call (counted or not) upsert `llm_spend_daily` (UTC day, feature, provider, model) with tokens and `cost_usd` from configured decimal prices (input, cached, output per 1M). `SpendGuard.IsPaused()` uses the UTC-month total cached 60 s per process against `llm.spend_cap_usd` (default 10.00): ≥ 80 % → one alert per month per feature through the existing ops notifier; ≥ 100 % → both features paused until the next UTC month or a cap raise. Counters-only metrics per day (requests, plans by name, fallbacks, refusals by reason, validation failures, 429s, attestation failures, quota hits, latency p50/p95, cost). Ledger rows older than 13 months purged.

## Acceptance criteria
1. Cost math in `decimal` with cached tokens priced separately; a table test for each candidate's price shape.
2. 80 % alert sent once per month per feature (second crossing in the same month → no alert); next month re-arms.
3. At 100 % `IsPaused()` is true for ask and cat; raising `llm.spend_cap_usd` resumes within 60 s.
4. Metrics carry no tags with text, install or account ids (test enumerates tag keys).
5. Purge keeps 13 months.

## Notes for the builder
- Overshoot ≤ 60 s × global rate × worst call cost is accepted; document it next to the guard.
