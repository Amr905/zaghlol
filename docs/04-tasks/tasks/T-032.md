## Design note
Short note, written before implementation.

**Layering.** All logic is pure Dart in `packages/zaghlol_parsing/lib/registry/` and takes file contents as `Map<String, String>` (path to text). No `dart:io` there. `tools/registry_lint` is a thin CLI that reads the directories and calls the library. The package owns: models, strict schema validation, loader, backtracking heuristic, a minimal template matcher/extractor (needed by the fixture runner; T-033 wraps it with stages 0, 5, 7 and the generic fallback), fixture runner, cross-match detection and the Guard-config export.

**Bundle layout** (`<registry>/`): `registry_manifest.json` (`{schema, registryVersion, institutions[]}`), `shared.json` (global drop and last4 patterns, shortcut keywords, generic hints, `merchantCleaning` lists), `institutions/<code>.json` (parsing-engine §3). Fixtures live outside the bundle in `app/test/fixtures/sms/<institution>/<case>.json` (CLAUDE.md §8); each has `sender`, `channel`, `body`, `receivedAt` and `expect`. `expect.outcome` is `matched` (default), `dropped` (an institution or global drop pattern fired) or `unmatched`. T-032 ships only test registries under `packages/zaghlol_parsing/test/fixtures/registry/`; real institutions are T-036/T-037/T-068/T-069.

**Strict schema.** Unknown keys, wrong types, duplicate template ids, unknown `event`/`direction`/`lang`/`channel` values, a missing `amount` group (except `balance_only`, `declined`) and a `baseConfidence` outside 0..1 are errors. Issues carry path and code, never the offending text. Caps: file size, institutions, templates per institution, pattern length.

**Matching text.** Body and pattern are folded with the same rules: the body goes through `foldKey` (digits, separators, tatweel, harakat, alef/ya/ta-marbuta, lowercase) and the pattern literals go through a new `foldArabicVariants` (no lowercasing, so `\S` and `\D` stay intact). Patterns compile with `caseSensitive: false`. Captured text is therefore lower-case; merchant cleaning upper-cases, and currency codes are upper-cased before lookup. Display text is never taken from folded input except the merchant (which is cleaned anyway).

**Regex safety.** Static heuristic only (Dart has no regex timeout): reject an unbounded quantifier on a group that itself contains an unbounded quantifier, a quantified group with duplicate or empty alternatives, more than 6 unbounded wildcards, and patterns over 600 characters. The result is a heuristic, not a proof; the docs say so. Nested lookarounds and backreferences are rejected.

**Loader.** `RegistryLoader.load(files)` returns `RegistryLoadResult` (registry or issues), never throws. It validates, compiles every pattern once (eager, per-instance cache = per isolate), checks `registryVersion` equals the max template version and the manifest lists exactly the institution files. The benchmark test loads 80 generated institutions with 5 templates each under 150 ms.

**Fixture runner and cross-match.** The runner resolves the institution by sender, applies drop patterns, tries the templates of the fixture's channel in order and compares `expect`. Cross-match rule (testing-strategy: "no fixture may match two templates"): a fixture body matched by more than one template of its institution is an error, so templates must be disjoint on the fixtures; a wrong first match shows up as a template mismatch.

**Currency and number policy (FU-051).** `$`: when the fallback currency is not in the symbol's candidate set, the symbol resolves to its default (USD) like `£`/`€`, since an explicit marker beats a guess. `﷼` has no default and still fails. A trailing `.` or `,` after a number is dropped in `parseMoneyText` and by the extractor. Grouped input with a leading-zero first group (`0,123`) is rejected. U+2060 and U+00AD are stripped as invisible. The vacuous no-echo fuzz check is replaced by a structural assertion.

**Guard export.** `exportGuardConfig(registry)` produces `{v, registryVersion, senders, packages, shortcutKeywords, drop, last4, generic}` in sorted, deterministic order and fails if the JSON exceeds 200 KB or a regex does not compile. `ignore` is DB state and is added by the app.

**FU-066.** Merchant cleaning lists come from `shared.json` (merging with the seed defaults). The "stable" test is renamed, non-leading articles are documented in the vectors, and mid-name cities and alphanumeric terminal IDs are pinned with rows. `ALMARAI` versus `AL MARAI` is left to catalog_build (alias variants); recorded in the report.
