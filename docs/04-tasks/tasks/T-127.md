## Description
Gold per karat per gram (EGP, USD) and FX, served from cache.

## Technical details
- `IPriceProvider`; adapter for the contracted local gold-market feed (D-41; contract pending — build against the interface plus a fake until credentials exist); FX adapter (licensed source); hourly worker; karat derivation where the feed lacks a karat; stale flag.
- Prices are `numeric` in the DB and decimal strings on the wire with a separate ISO 4217 `currency`, never JSON numbers.
- **Operator override (§4.8):** `PUT /admin/v1/prices/override` takes `{symbol, currency, price, reason, expiresAt?}`; `expiresAt` defaults to 24 h and is capped at 7 days (`price_quotes.override_expires_at`); after expiry the feed applies again; audited.

## Design note
*Written 2026-11-10 by the implementer at the Lead's request (≤1 page); the architect may amend.*

**Parts.** `IPriceProvider { Name; FetchAsync }` returns gold quotes (symbol, currency, decimal per gram) and USD-based FX rates. Real adapters (D-41 local feed, licensed FX) come at go-live; now there is a deterministic `fake` adapter, refused in Production, selected by `Prices:Providers` (comma list, in priority order; unknown name stops startup). `PriceNormalizer` merges providers (first one that supplies a symbol/currency wins) and derives what is missing: a missing karat from any karat present (`price24 = p * 24 / k`, `pk = price24 * k / 24`), and a missing USD gold price from EGP gold / `fx[EGP]`. Gold is closed to `XAU24_G`, `XAU21_G`, `XAU18_G` in `EGP`/`USD`. Derived gold is rounded to 2 dp (away from zero); every value is validated (> 0, fits `numeric(20,6)`); FX rates are kept at up to 8 dp on the wire (`DecimalString`) and `numeric(24,12)` stored.

**Worker.** `PriceFetcherService` (Workers) runs `PriceFetchJob` at start and every `Prices:IntervalMinutes` (default 60) on the worker login. One provider failing is isolated (metric outcome `failed`) and never stops the others; nothing at all fetched leaves the cache untouched (so an outage serves the last value). Metrics use fixed tag sets: `provider` in {fake, local_gold, fx, spot_gold, none}, `outcome` in {ok, failed, empty}; the existing `zaghlol.price.age` gauge is fed per symbol.

**Storage and override.** One row per (symbol, currency) in `price_quotes`. New migration `AddPriceFeedColumns` adds `feed_price numeric(20,6)` and `feed_as_of` (the last feed value, kept while an override is active), CHECKs `price > 0` and `is_override = (override_expires_at IS NOT NULL)`, and widens the digit-run backstop (FU-018, below). The worker upserts in one statement: it always writes `feed_*`, and writes `price/as_of/source` only if no unexpired override is on the row. An override upsert (Admin login, one transaction with one `audit_log` row `price_override`, target `price:<symbol>:<currency>`) sets `price`, `is_override`, `override_expires_at` and leaves `feed_*`. **Effective value** is a pure function of (row, now): an override with `override_expires_at > now` wins; otherwise `feed_price` (falling back to `price` for a non-override row). So after expiry the feed value returns at once, with no sweeper and no dependence on the next run (tested with a frozen clock). **Stale** = the newest feed time (`feed_as_of`) is more than 24 h old; the block `asOf` is the newest feed time. A block with no rows is `null` (T-128 sends `prices: null`).

**Override endpoint.** `PUT /admin/v1/prices/override`, role `prices_admin` (added to the existing policy list; the validator seam stays fail-closed), not idempotency-keyed (absolute state; FU-052 S-2). Strict DTO (`UNKNOWN_FIELD`), then: symbol in the closed set, currency EGP/USD, `price` is an ASCII decimal string with at most 12 integer and 6 decimal digits (the `numeric(20,6)` column) and is > 0, `reason` has no `@` (the audit CHECK would refuse it, so the API must first), `reason` 3-200 chars, `expiresAt` omitted = now + 24 h, must be in the future and at most now + 7 d, otherwise `400 VALIDATION_FAILED`. Response `{symbol, currency, price, asOf}`. Clearing before expiry is a service method (`ClearOverrideAsync`, audited; it sets the expiry to now, because `ops_rw` has no DELETE on `price_quotes`) with no HTTP route, because the signed-off contract has none; T-137 decides how the CLI reaches it.

**FU-018 / T-122 F7.** The CHECK regex becomes `([digits][[:space:].,/_،-]{0,3}){6,}`. `ContributionPrivacy` (Application) folds all four digit scripts to ASCII, strips separators and applies the same rules before any INSERT; a test runs every rejected-by-CHECK case through the filter and shows the filter rejects first, so the DB CHECK is never the control that fires.

**Tests.** Unit: normalizer, derivation, effective/stale with a `FakeTimeProvider`, validators, job with fake providers. Integration (Testcontainers): stores, grants, upsert-vs-override race order, audit row, migration/CHECKs. API + live contract test (FU-011) for `adminOverridePrice`.
