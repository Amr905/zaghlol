## Description
`ClientScrub.apply(text)` replaces phones, e-mails, InstaPay addresses and digit runs ≥ 8 with neutral tokens (kinds kept for the UI). `ReferenceMasker.mask(text, MaskSources)` → `MaskResult{sentText, map, tokens}` or `MaskUnresolved(candidates)`. `MaskSources` is an interface (accounts: label, nickname, institution + type, last-4; registry aliases ar/en with an "ordinary word" flag; the user's merchant names); the Drift adapter is T-343. Folded matching (Arabic letters, Arabic-Indic digits, case, tatweel, diacritics), longest match first, token-boundary aware, numbering by first appearance, repeated references reuse their token.

## Design note (builder)
- **Folding.** One "loose" fold per call: `foldKeyIndexed` (letters, Arabic-Indic digits, case, tatweel, harakat, invisibles) then apostrophes and dots dropped, `- _ /` read as spaces. Aliases, nicknames and merchants go through the same fold; spans map back to the user's original text through the origin table, so everything outside a replaced span is left exactly as typed (trailing harakat of a replaced word are consumed).
- **Token boundaries.** A match must start and end on a letter/digit boundary. A start may sit after an Arabic clitic prefix (`و ف` + `ب ل ك` + `ال`, `لل`): `بكارفور` -> `ب⟦MERCHANT_1⟧`. Aliases that start with `ال` are also tried without it.
- **Order.** `ClientScrub` first (e-mail, handle@x = IPA, phone, digit runs >= 8, kinds kept as `⟦EMAIL⟧ ⟦IPA⟧ ⟦PHONE⟧ ⟦NUMBER⟧`); then the masker: collect candidates (account names, registry aliases, merchants, 4-digit tokens near a card/account word), drop word-like aliases that have no bank/account/card word within 2 tokens, pick non-overlapping spans longest first, resolve each (FR-LLM-20), number per kind by first appearance, one token per entity.
- **Resolution.** Unknown last-4, two accounts with that last-4, a registry bank without an account, two entities for one name, or a bank word followed by an unregistered name (`بنك الزغاليل`) -> `MaskUnresolved` with the user's accounts as candidates. A 4-digit token next to a card word and followed by a currency word, with no matching last-4, stays (an amount).
- **Fail closed.** Any unexpected error in a source or the matcher returns `MaskUnresolved(failed)`; nothing is thrown, nothing is sent. Typed `⟦ ⟧` characters are stripped (except the four scrub tokens) so users cannot forge placeholders. Every `toString` is redacted.

## Acceptance criteria
1. FR-LLM-03 example: no phone, IPA or `1234` in output; «صرفت كام» kept.
2. FR-LLM-18 ar: output exactly «صرفت كام بكارت ⟦CARD_1⟧ في ⟦MERCHANT_1⟧ من حسابي في ⟦BANK_1⟧؟»; en: exactly the SRS sentence with ⟦ACCOUNT_1⟧, ⟦BANK_1⟧, ⟦CARD_1⟧ and "Uber" kept; «صرفت 4321 جنيه» keeps `4321`; Arabic-Indic «٤٣٢١» next to «كارت» is masked.
3. FR-LLM-20: no such card, registry bank with no account, «بنك الزغاليل», two cards with the same last-4 → `MaskUnresolved` with the user's matching cards/accounts as candidates.
4. Word-like aliases («مصر», «الأهلي», "Liv") are masked only next to a bank/account/card word.
5. **Negative proof 1:** inspection test over the synthetic fixture sources and the SRS §10.1 question list: no `sentText` contains a fixture last-4 within 3 words of a card/account word, a registry alias, an account nickname/label, or a fixture merchant name (folded comparison).
6. **Negative proof 2:** `MaskResult.toString()`, `map.toString()` and any `Exception` message from the masker contain no source name (redaction test with marker names).
