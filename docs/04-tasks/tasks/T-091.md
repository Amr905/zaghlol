## Description
Shared bills and friends' money back reduce real spending.

## Technical details
Participants & shares; assign incoming to one/many expenses; one incoming across several expenses; caps (BR-XFR-06); later-cycle restatement (BR-XFR-07); unassign; expense edit/delete repair (EC-40).

## Design note
(Implementer note, sprint wave 1, 2026-11-13.)
- Pure rules in `zaghlol_domain/transfers/splits.dart`: `checkShares` (Σ shares of the others <= expense), `ownShare`, `equalSplit` (largest remainder, user included), `netOfOffsets` / `unsettledShare` (floor 0, BR-XFR-04), `planReimbursement` and `linksToRemove` (EC-40).
- `planReimbursement` grants in request order `min(requested, expense remaining, named friend's unsettled share, transfer left)`. Nothing is converted. Clamps are reported per grant (`clamped`), bad requests come back as `RejectedRequest` with a reason, and what is not granted is `incomeRemainder`. One request per expense per call (schema: one link per expense and source).
- App `Reimbursements` (`features/transactions/application/reimbursements.dart`): `addParticipant` / `updateShare` / `removeParticipant` / `unsettled`; `assign(sourceId, requests)` (one transaction, triggers are the race guard, a lost race throws `REIMB_CONFLICT`); `unassign(linkId)` (reimbursement links only; income is computed from the links, so the transfer is income again); `repairForNewAmount(txnId, newAmount)` (EC-40, newest links first, both sides of a link).
- Eligible source: live, posted, non-internal, direction `income` or `transfer_in`. Eligible expense: live, non-internal, `expense`, same currency (another currency is a plan rejection `unknownExpense`, never converted).
- Not wired (same as T-089/T-090, FU-142): the edit path in `DriftTransactionRepository.edit` must call `repairForNewAmount` before it writes a new amount (the schema trigger refuses a shrink below the links), and delete paths call `RefundMatching.onRemoved` (frees links on both sides).

### Open questions for review
1. **EC-37 reading:** a link naming a friend is capped at that friend's unsettled share; the excess stays income. Links without a friend are capped only by the expense (BR-XFR-06).
2. **EC-40 removes by age across kinds:** a refund link can be removed by a reimbursement-driven shrink if it is the newest. Spec says "newest links"; kept literal. A removed refund is not remembered as "unlinked", so it may re-match.
3. **Shares above a shrunk amount** are flagged (`sharesExceedAmount`) but not changed; the UI must ask.
4. **Pending incoming transfers** cannot be assigned until posted.
