## Description
Backend schema per `docs/03-technical/backend-schema.md`, including the one-phone Gold (seat) model, same-iPhone seat-key hashes, support-correction state and the idempotency/registration-retry columns.

## Technical details
- Entities and configuration for every table in backend-schema §2; initial migration; CHECK constraints; roles `app_rw` / `worker_rw` / `ops_ro` / `ops_rw` / `migrator`; migration job; expand/contract guideline as a doc comment.
- **Installs:** `registration_key_hash`, `registration_body_sha256` (R3-6); `seat_key_hash` (set once, never replaced, R4-1(1)); `seat_key_trusted boolean NOT NULL DEFAULT false` with the R5-2 column comment (set only by an App Attest-covered request; only false → true). No `os_major` (FU-013).
- **Purchases:** `install_id` (buying install), `account_id`, `account_linked_by IN ('signin','support')` with `CHECK ((account_id IS NULL) = (account_linked_by IS NULL))`; `attach_reclaim_used_at` (never cleared, D-58); `dispute_frozen_until` (D-64); `support_link_notice_pending boolean NOT NULL DEFAULT false` and `support_link_notice_iat` (R4-7(2), R5-7). Account deletion clears `account_linked_by` in the same transaction; a `BEFORE DELETE` trigger on `accounts` is the backstop.
- **`purchase_events.cause`** values: `verify | restore | seat_bind | seat_move:<restore|signin|support|account_attach|verify> | seat_rebind:<restore|signin> | seat_rebind_over_cap:<restore|signin> | rtdn:<type> | assn:<type> | sweep`.
- **`purchase_seats`** (one row per purchase): `install_id`, `proof`, `bound_at`, `last_moved_at`, `next_move_at` (whole UTC hour), `device_key_hash`, `device_key_trusted boolean NOT NULL DEFAULT false`, `recent_rebinds timestamptz[] NOT NULL DEFAULT '{}'`; CHECKs `(install_id IS NULL) = (proof IS NULL)`, `(last_moved_at IS NULL) = (next_move_at IS NULL)`, `date_trunc('hour', next_move_at) = next_move_at`, `cardinality(recent_rebinds) <= 2`.
- **`seat_claimants`** (R3-4, R4-4): PK `(purchase_id, install_id)`, `claimed_at`, `channel IN ('restore','signin','verify')`, `device_key_hash`.
- **`app_attest_keys`**, **`replay_guard`** (`kind IN ('signin_google','signin_apple','play_integrity')`), **`idempotency_records`** (PK `(install_id, operation_id, idempotency_key)`, `operation_id IN ('verifyPurchase','signIn')`, `body_sha256`, `response_body_enc`, `account_id` + partial index, `expires_at`).
- **`audit_log`**: actions include `support_lookup`, `support_seat_move`, `support_detach`, `support_unfreeze`; `details` shapes per backend-schema §2 comments (outcomes include `dispute_frozen`; `ownership_outcome` includes `not_run`).
- **KMS key references** (configuration only, no key material in the DB): `K_seat` (seat-key keyed hashes), `K_audit` (e-mail pseudonym), the `install_hash` pepper, the idempotency-body envelope key. Provisioned by T-140; local dev uses fakes.
- DB readiness check on the health/readiness probe (FU-003).

## Design note
### Design note (solution-architect, 2026-11-06)

**Approach.** Code-first EF Core 10 model in `Zaghlol.Infrastructure/Persistence` (one `IEntityTypeConfiguration<T>` per table), one `InitialCreate` migration, and hand-added `migrationBuilder.Sql(...)` blocks in it for what EF can't model: triggers, the view, column-list grants and comments EF doesn't emit. Provider: `Npgsql.EntityFrameworkCore.PostgreSQL` 10.0.x (10.0.3 on nuget.org, needs EF Core ≥ 10.0.4; pin the latest 10.0.x). No `EFCore.NamingConventions`: a ~20-line convention loop in `OnModelCreating` gives snake_case tables, columns, keys and indexes (fewer dependencies). All objects live in schema **`zaghlol`** (`HasDefaultSchema`), and the migrations history table too; nothing goes in `public`.

**Entities and migration order** (FK order; one migration, sections in this order):
1. `installs` → `accounts` → `account_installs`
2. `purchases` → `purchase_events` → `purchase_seats` → `seat_claimants` → `app_attest_keys` → view `v_entitlements` (raw SQL; mapped keyless with `ToView`, excluded from migrations)
3. `replay_guard`, `idempotency_records`, `store_notifications`
4. `catalog_versions`, `catalog_categories`, `catalog_merchants`, `catalog_aliases`, `catalog_keywords` (`catalog_drafts` is T-125's, not here)
5. `feature_flags`, `price_quotes`, `fx_rates`, `merchant_contributions`, `contribution_aggregates`, `bank_requests`, `daily_active_counts`
6. `operators`, `audit_log`
7. Trigger functions and triggers, then grants, then comments.

`signing_keys` is **removed** from the schema. The signing key ring is deploy-time configuration (T-123 note; `backend-schema.md` §2 edited in this commit). IDs are UUID v7 generated in .NET (`Guid.CreateVersion7()`); PostgreSQL 17 has no `uuidv7()`, so there are no DB defaults for `id`.

**Constraints in EF.**
- Every CHECK goes through `ToTable(t => t.HasCheckConstraint("ck_<table>_<rule>", "<sql>"))` with the SQL copied verbatim from `backend-schema.md` §2, so the names are stable for the negative tests.
- Text enums are `text` with an `IN (...)` CHECK. On the C# side, enums with an explicit `HasConversion` to the snake strings; no `int` enums.
- Added hardening (doc §2 updated):
  - `octet_length(x) = 32` on every SHA-256/HMAC `bytea`.
  - `char_length(idempotency_key) = 26`.
  - Length caps of 64 on `merchant_norm`, `institution_code`, `category_code` and `bank_requests.institution_name_norm`, and the `!~ '[0-9]{6,}'` digit-run CHECK on both free-text norms.
  - A regex CHECK on `purchase_events.cause` covering exactly the documented values: `rtdn:`/`assn:` followed by `[A-Za-z0-9_]{1,64}`.
  - `audit_log` `CHECK (NOT (details ?| array['email','order_id','orderId']))`.
- R5-2 comment: `HasComment(...)` on `installs.seat_key_trusted` (lands in the snapshot; the test reads `col_description`).

**Two triggers are needed so the documented CHECKs survive FK actions:**
- `BEFORE DELETE ON accounts`: `UPDATE purchases SET account_id = NULL, account_linked_by = NULL WHERE account_id = OLD.id`. The FK's own `SET NULL` alone would violate `(account_id IS NULL) = (account_linked_by IS NULL)`, because FK actions fire after the row is gone. It never touches `attach_reclaim_used_at`.
- `BEFORE DELETE ON installs`: `UPDATE purchase_seats SET install_id = NULL, proof = NULL, bound_at = NULL WHERE install_id = OLD.id`. Without it, `ON DELETE SET NULL` breaks `(install_id IS NULL) = (proof IS NULL)`. `device_key_hash`, `device_key_trusted`, `last_moved_at`, `next_move_at` and `recent_rebinds` are kept (D-55).
- Both functions are `SECURITY DEFINER`, owned by `migrator`, with `SET search_path = zaghlol, pg_temp`, so the deleting role needs no UPDATE grant on the other table.

**Crypto stays in the app layer, never in the DB.**
- No `pgcrypto`: a test asserts `pg_extension` holds only `plpgsql`.
- Every hash and ciphertext column is a plain `byte[]`. EF value converters do **no** crypto (KMS calls are async and must be explicit).
- Plain SHA-256 values (`token_hash`, `registration_*`, `body_sha256`, `payload_digest`, `replay_guard.key_hash`) are computed by the owning handler with `SHA256.HashData`.
- Keyed hashes (`seat_key_hash`, `device_key_hash`, `install_hash`, the audit e-mail pseudonym) come from `IKeyedHasher` (T-123).
- `idempotency_records.response_body_enc` and `accounts.apple_refresh_token_enc` come from `IEnvelopeCipher` (T-123 note). T-122 only declares the columns.
- The KMS key references are configuration (`Kms:*`, `KeyedHash:*`); no key material and no key ID table in the DB.

**Roles (least privilege).**
- Cluster roles are created **outside** migrations by `backend/deploy/db/bootstrap-roles.sql`, run once by the provider admin (T-140) and by the test fixture as superuser. Groups `app_rw`, `worker_rw`, `ops_ro`, `ops_rw` are `NOLOGIN`; logins `zaghlol_api`, `zaghlol_worker`, `zaghlol_ops_ro` are members.
- `migrator` is `LOGIN NOCREATEROLE NOCREATEDB`. It owns schema `zaghlol` and every object in it. `REVOKE ALL ON SCHEMA public FROM PUBLIC`; `GRANT USAGE ON SCHEMA zaghlol` to the four groups.
- **Explicit per-table GRANTs** live in the migration that creates the table (no `ALTER DEFAULT PRIVILEGES`, which would over-grant). The matrix is one C# table, `Persistence/GrantMatrix.cs`, rendered to SQL and asserted by a test against `information_schema.role_table_grants` / `column_privileges`. Principles:
  - No role but `migrator` has DDL, `TRUNCATE`, `REFERENCES` or `TRIGGER`.
  - `audit_log`: `INSERT` for `ops_rw` only; `DELETE` for `worker_rw` only (retention); **nobody** has `UPDATE`.
  - `app_rw` (the `/v1/*` endpoints): only what install, purchase, sync, account and notification-ingest handlers write. No catalog, flag, price, operator or audit writes.
  - `ops_rw` (the `/admin/v1/*` endpoints): catalog and draft writes, flags, price overrides, contribution review, the support-correction columns of `purchases` / `purchase_seats` / `seat_claimants`, `purchase_events` insert, and `audit_log` insert. **The API registers two connection strings**, `app_rw` for `/v1` and `ops_rw` for `/admin/v1`, chosen by endpoint group, so an injection in `/v1` can't write catalog or audit rows.
  - `worker_rw`: the notification processor, sweeper, aggregator, price fetcher and `RetentionPurger` deletes.
  - `ops_ro`: `SELECT`, minus column grants on `installs.token_hash`, `accounts.apple_refresh_token_enc` and `idempotency_records.response_body_enc`.
  - Later tasks extend the matrix in their own migrations; reviewers check the diff.
- Expand/contract rule: an XML doc comment on `ZaghlolDbContext`. Additive in N; the API N-1 must run against N; drop only in N+1; `Down()` methods are never run in production.

**Retention indexes** (added to `backend-schema.md` §4):
- `installs(last_seen_at)` (existing).
- `installs(deleted_at) WHERE deleted_at IS NOT NULL`.
- `installs(first_seen_at) WHERE registration_key_hash IS NOT NULL`.
- `store_notifications(received_at)`.
- `merchant_contributions(received_at)`.
- `bank_requests(received_at)`.
- `audit_log(at) WHERE action IN ('support_lookup','support_seat_move','support_detach','support_unfreeze')`, plus a plain `audit_log(at)`.
- `replay_guard(expires_at)`.
- `seat_claimants(claimed_at)`.
- `idempotency_records(expires_at)`.

**Generating the migration without a local SDK.**
- A `dotnet-ef` 10.0.x local tool goes in `backend/.config/dotnet-tools.json`.
- A new `workflow_dispatch` workflow, `backend-ef-migration.yml` (input `name`, `permissions: contents: read`), runs `dotnet ef migrations add <name>` on the pushed branch and uploads `Migrations/` as an artifact. The implementer runs `gh workflow run`, then `gh run download`, then appends the raw-SQL blocks and commits. The workflow never pushes.
- `backend-ci` gains `dotnet ef migrations has-pending-model-changes`, which fails when the model and the snapshot diverge.
- **Deploy:** `dotnet Zaghlol.Workers.dll --migrate` (same image) runs `Database.MigrateAsync()` as `migrator`; the EF 9+ migration lock serializes concurrent runs. Compose gets a one-shot `migrate` service that api and worker wait on, plus `bootstrap-roles.sql` in `docker-entrypoint-initdb.d` with dev-only passwords.

**Readiness (FU-003).**
- `GET /v1/health` runs `SELECT 1` as `app_rw`, with a 1 s timeout and the result cached for 2 s, so the unauthenticated endpoint can't hammer the DB.
- When the DB is unreachable it returns `503 UPSTREAM_UNAVAILABLE` (problem+json). Add that 503 to `getHealth` in the OpenAPI file in this task.
- The orchestrator uses it for readiness only. Liveness stays a process-level check (T-140).

**Tests (Testcontainers `postgres:17`, CI only).** The fixture runs the bootstrap script as superuser, migrates as `migrator`, then connects as `zaghlol_api` / `zaghlol_worker` for the assertions, which also proves the grants. Tests:
- **Doc diff:** a parser reads the SQL fence of `backend-schema.md` §2 (split on top-level commas; skip `CHECK`/`UNIQUE`/`PRIMARY KEY` and comments) and compares name and type per column with `information_schema.columns` for **every** table. The six tables named in the acceptance criteria are therefore covered.
- **Forbidden columns:** a denylist regex (`order_id|nonce|seat_key$|public_key|imei|android_id|idfa|idfv|ad_id|serial|phone|device_id|email`) over all columns, with exactly two allowed exceptions: `accounts.email` and `app_attest_keys.public_key` (the App Attest credential, not a seat key).
- **One negative test per CHECK in the acceptance criteria** (assert SQLSTATE `23514` and the constraint name), plus the digit-run and length-cap CHECKs.
- **Cascades:** account delete (both purchase columns NULL, `attach_reclaim_used_at` kept); install delete (claimants and attest key gone; seat vacant with `proof` NULL; `device_key_hash` and `device_key_trusted` kept).
- **Grants:** the matrix equals `GrantMatrix.cs`; `app_rw` gets `42501` on `UPDATE audit_log` and on `CREATE TABLE`.
- R5-2 default and comment; R5-7 column present.
- Migrating twice is a no-op; `has-pending-model-changes` is clean.
- Readiness: stop the container, expect 503; start it, expect 200 within 5 s.

**Out of scope (owned elsewhere).**
- Every behaviour that writes these columns: registration and idempotency (T-124), seat service (T-184), attestation (T-181), seat-key hashes (T-182), support actions and the freeze (T-186), sign-in, sign-out and account deletion (T-135), retention jobs (T-139), the `catalog_drafts` table (T-125).
- KMS adapters (T-123 / T-140) and cloud role provisioning (T-140).

**Rejected alternatives.**
- **DB-first SQL migrations (DbUp):** a second source of truth beside the EF model.
- **`pgcrypto`:** keys would reach the DB session and statement logs.
- **Roles created inside migrations:** `migrator` would need `CREATEROLE`.
- **One API role for `/v1` and `/admin`:** loses the injection boundary.
- **Hand-written model snapshot:** drifts silently.

## Acceptance criteria
- [ ] Migration applies on empty PostgreSQL 17 (Testcontainers) and the model matches backend-schema §2 column by column (a test diffs the EF model against the documented column list for `installs`, `purchases`, `purchase_seats`, `seat_claimants`, `idempotency_records`, `audit_log`).
- [ ] Privacy CHECKs present (contribution digit run, length caps) and no column exists for a raw seat public key, an order ID, a time nonce or a device identifier (test enumerates columns).
- [ ] `purchase_seats` CHECKs reject: a holder without `proof`; `next_move_at` not on a whole hour; `recent_rebinds` with 3 elements; `last_moved_at` set without `next_move_at` (one negative test each).
- [ ] `purchases` CHECK rejects `account_id` set with `account_linked_by` NULL and vice versa; deleting an account leaves `account_linked_by` NULL on its purchases and keeps `attach_reclaim_used_at` (test).
- [ ] `seat_claimants` and `app_attest_keys` rows cascade when their install is deleted; `purchase_seats.install_id` becomes NULL and `device_key_hash` is kept (test).
- [ ] R5-2: `installs.seat_key_trusted` defaults to false and carries the documented column comment.
- [ ] R5-7: `purchases.support_link_notice_iat` exists next to `support_link_notice_pending`.
- [ ] FU-003: readiness probe fails while the DB is unreachable (Testcontainers stop/start test).
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
