## Description
Turn a raw message into typed fields with direction and confidence.

## Technical details
Institution resolve; language detection; ordered template match; typed extraction (Money incl. original/billed amount, last4, merchant, counterparty kind, balance/available, ref, date/time with nearest-past year policy); direction from event; sanity penalties; confidence threshold constant (A-12).

## Design note
Short note, written before implementation (builds on the T-032 branch; reuses `normalize/`, `merchant/`, `registry/`).

**Shape.** `ParsingPipeline(Registry).parse(ParseRequest)` in `packages/zaghlol_parsing/lib/pipeline/`. Pure, synchronous, never throws, never logs. `ParseRequest` = body, source (sender or package), channel, `receivedAt` (device wall clock as a UTC-flagged `DateTime`, EC-10). `ParseResult` is sealed: `ParseParsed` (typed fields, direction, event, template id and version, confidence, reasons, `needsReview`), `ParseDropped` (institution or global drop pattern fired) and `ParseUnrecognized` (typed reason: empty or over-long body, unknown source, no template, invalid amount or currency). Stage 8 (generic fallback) is T-073: an unknown source returns `ParseUnrecognized(unknownSource)`, which is the hook it will take over.

**Stages.** 1 fold once (`foldKeyIndexed`, same text as `foldKey` plus a map back to the original offsets). 0 guard re-check on that text: body size cap (4000), global and institution drop patterns. 2 resolve institution (`Registry.resolveSource`); detect language by Arabic-letter ratio and try the templates of that language first, then the other (stable order, channel filtered). 3 first template that matches wins. 4 typed extraction by the existing `extractFields`. 5 direction is template-declared (generic keyword rules belong to T-073). 6 merchant cleaning (existing). 7 confidence.

**Original-text captures (T-032 review M-2).** Regexes still run on the folded text. For `merchant`, `counterparty`, `ipa`, `phone` and `ref` the match span is mapped back through the offset map to the original text and passed through `foldForMatching` (digits, tatweel, harakat only; case and letter variants kept). Dart reports no group offsets, so the capture is located by its folded text inside the matched region; if that text occurs twice there the group falls back to the folded capture (never a wrong span). The fixture runner uses the same path, with an Arabic counterparty fixture.

**Fields never guessed.** A field with no group, or a group that did not participate, is null. Only `occurredAt` is resolved by policy (parsing-engine §4): date with no year takes the nearest past year, no time takes the time of `receivedAt`, time with no date takes the received date (previous day if that would be in the future), nothing at all takes `receivedAt`. `occurredAtSource` says which rule applied, and `date` / `time` stay null when the message had none. Without a `last4` group the institution `last4` patterns, then the shared ones, are tried (data-declared, first hit). Currency comes from the template (explicit `cur` or institution default); an unresolvable marker is fatal, never a fallback.

**Confidence (A-12).** Integer permille, no floating point: `base x product(penalty/1000)`, floored per step. Penalties (each a `ParseReason`): date out of range (more than 3 days ahead or 2 years back) 700; invalid original amount/currency 700; invalid date or time 700; invalid last4, balance, available or empty merchant 800; no account or party identifier at all (sparse) 900. A missing or invalid `amount` or `currency` is not a penalty: the message becomes `ParseUnrecognized` and goes to review with the raw text. `kAutoAcceptThresholdPermille = 850`; below it `needsReview` is true (still saved, with a `low_confidence` item, §4.5).

**T-032 minors handed over.** (M-1) cold-load assertion tightened to `first < 150`. (M-3) the heuristic also flags a bounded repeat (upper bound above 3) of a group that holds an unbounded quantifier, `x|x?` and prefix-overlapping literal alternatives in a repeating group; the fixture runner times matching per fixture and the lint runs three adversarial bodies per template at 64, 128, 256 and 512 characters, stopping at the first size over the limit (default 100 ms, injectable), so a high-degree polynomial pattern is caught small instead of hanging the lint. Dart has no regex timeout, so this bounds polynomial blow-up only; exponential shapes stay the heuristic's job (documented). (M-4) the `closed` placeholder in the heuristic becomes nullable.

**Fixtures and tests.** A separate pipeline test registry (`packages/zaghlol_parsing/test/fixtures/pipeline/`) so the T-032 registry counts stay stable: NBE (Arabic and English, spec §8 example), an InstaPay-style template with an Arabic counterparty, a refund, a decline, missing balance, Arabic digits, year wrap, time forms, sanity-penalty cases. Fixture files keep the T-032 format; `expect` gains `confidence`, `needsReview`, `occurredAt`, `language`, `reasons`, `counterpartyKind`, so the lint covers the pipeline. Plus unit tests per stage, an invariants/fuzz test (never throws, no input echo in results), a sentinel test that no result string contains the body, and a mean-time benchmark (< 2 ms).
