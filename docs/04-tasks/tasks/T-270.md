## Scope
1. Reproduce from code what "exporting backup is not working" can be on an Android dev build: Settings → Backup → make a backup (Drive sign-in, OAuth client id per flavour, passphrase step, snapshot, upload) and Settings → Export (CSV/Excel is Gold). Check flavour config (is a Google OAuth client configured for `dev*`/`staging*`? if it needs the PO's Google Cloud project, that is the cause — say so), error mapping (`backupSettingsError*`), and whether any step fails silently.
2. Fix code defects. Where configuration from the PO is missing, the screen must say so plainly in dev builds and offer **"Save backup file to this phone"** (encrypted backup written through the system file picker / share sheet) so a manual backup works without Drive — only if D-33 (Free keeps one manual backup slot) allows a local file; if the SRS forbids local backup files, don't add it and report instead.
3. Restore from the same file/slot round-trips in a test.
4. No keys or passphrases in logs; backup stays encrypted end to end (C4: crypto untouched unless a defect is found — then stop and describe it).

## Acceptance criteria
Root cause(s) in the task file; tests for each fixed step and the round trip; clear error for missing configuration.

## Design note (builder)

**Root causes found in code (Android dev build):**
1. **Missing OAuth configuration (main cause).** `GoogleSignInDriveAuthorizer` needs `ZAGHLOL_GOOGLE_SERVER_CLIENT_ID` (Android) / `ZAGHLOL_GOOGLE_IOS_CLIENT_ID` (iOS) as `--dart-define`. No build passes them: not the workflows, not the release scripts, not the run docs. So on every current build "Back up now" fails with `DRIVE_NOT_CONFIGURED` before any network call. This needs the PO's Google Cloud project: a Web OAuth client (its ID is the server client ID), plus an Android OAuth client per package (`app.zaghlol`, `app.zaghlol.dev`, `app.zaghlol.staging`) with the signing certificate SHA-1 (debug key for local dev builds, upload/Play key for store builds), and the Drive API enabled with the `drive.appdata` scope on the consent screen. The account sign-in (`id_token_source.dart`) reads the same define, so it is affected the same way.
2. **The failure was not named.** `backupErrorKindOf` did not map `DRIVE_NOT_CONFIGURED`, so S-66 showed the generic "The backup didn't work. Try again." and a Try again that can never succeed. It also came *after* the passphrase step, so a first-time user chose a passphrase (KDF run) and then failed. On S-04 the same code showed "Signing in to Google Drive didn't finish. Try again." — wrong reason.
3. **iCloud "unconfirmed" showed as done.** `backupNow` returns `unconfirmed` (iCloud still uploading; not counted as a backup) without throwing, and S-66 showed "Backup done". Not the PO's Android case, but a silent misreport.
4. Settings → Export (CSV/Excel) — checked: Free gets the preview and the paywall (FR-EXP, by design); Gold writes through `FilePicker.saveFile` (SAF on Android, with bytes) and reports saved / backed out / failed. No defect found.

**Fix:**
- `driveBackupSetupProvider` (`DriveBackupSetup.ready | missingInDevBuild | missingInRelease`) from the compile-time defines and the flavour (`dev*`/`staging*` = dev wording). S-66 checks it before the passphrase step: when Drive is the target and setup is missing, it shows a plain banner (dev builds name the missing define and what to do; release builds say Drive backup isn't available in this version and the data is safe) and disables "Back up now" for Drive. No Try again.
- New `BackupErrorKind.notConfigured` and `RestoreFailureKind.notConfigured` for `DRIVE_NOT_CONFIGURED` thrown later (same text, no Try again on S-04).
- `BackupActions.backupNow` returns whether the backup is confirmed; S-66 shows a "saved, still uploading" note for `unconfirmed` instead of "done".
- Crypto, the snapshot, Drive/iCloud stores: untouched (no defect found).

**Local backup file — not added.** D-33 / FR-BAK-08 define the Free slot as "one encrypted backup slot **on Google Drive or iCloud**"; FR-BAK-01 names Drive/iCloud as the destinations; security model §5 "Storage" lists only Drive `appDataFolder` and the iCloud container; FR-SEC-05 says Zaghlol's own backup is the only transfer path. The SRS does not allow a local backup file, so adding one would be a new data path the PO has not approved. Reported as a PO question instead.

**Round trip:** the existing T-150 AC1 test covers backup → list → restore on another phone through Drive. Added: the Free slot round trip (back up, change data, back up again with keep 1 → one file; restore it on phone B → equals the second state).

## Builder assumptions
- A1: `staging*` builds get the same detailed (developer) message as `dev*`; only `prod*` (and builds without a flavour) get the user wording.
- A2: When Drive is not configured and the phone offers iCloud, the user can still pick iCloud; only the Drive choice is disabled.

## Needs the PO
- **Google Cloud setup** (cause 1): create the OAuth clients listed in the design note and give the Lead the Web client ID (Android) and iOS client ID; then the builds (local run docs, app-ci/release workflows) must pass them as `--dart-define` (`docs/03-technical/deployment.md` §2). Until then, Drive backup cannot work in any build, and the screen now says so.
- **Local backup file** ("Save backup file to this phone"): not built, because D-33 / FR-BAK-08 name only Drive/iCloud. If the PO wants it, it needs a new decision (the same encrypted `.zaghlol.enc` written through the system save dialog, and a matching "restore from file" on S-04).
