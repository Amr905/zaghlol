## Scope
1. Reproduce from code what "exporting backup is not working" can be on an Android dev build: Settings → Backup → make a backup (Drive sign-in, OAuth client id per flavour, passphrase step, snapshot, upload) and Settings → Export (CSV/Excel is Gold). Check flavour config (is a Google OAuth client configured for `dev*`/`staging*`? if it needs the PO's Google Cloud project, that is the cause — say so), error mapping (`backupSettingsError*`), and whether any step fails silently.
2. Fix code defects. Where configuration from the PO is missing, the screen must say so plainly in dev builds and offer **"Save backup file to this phone"** (encrypted backup written through the system file picker / share sheet) so a manual backup works without Drive — only if D-33 (Free keeps one manual backup slot) allows a local file; if the SRS forbids local backup files, don't add it and report instead.
3. Restore from the same file/slot round-trips in a test.
4. No keys or passphrases in logs; backup stays encrypted end to end (C4: crypto untouched unless a defect is found — then stop and describe it).

## Acceptance criteria
Root cause(s) in the task file; tests for each fixed step and the round trip; clear error for missing configuration.
