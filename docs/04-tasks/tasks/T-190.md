## Description
The PO sees the app at about 150 MB. Assets are only ~1.7 MB, so the size comes from code and native libraries: the Flutter engine, PDFium (pdfrx), Tesseract4Android plus its Arabic model, ML Kit text recognition (two OCR engines), SQLite3MultipleCiphers, Rive, Glance/Compose. A universal APK carries each of these for three ABIs, and a debug build is several times larger than release.

## Technical details
1. **Measure first:** which build was 150 MB (debug / release, APK / AAB, universal / per-ABI, iOS)? Produce a size report: `flutter build appbundle --release --analyze-size --target-platform android-arm64`, `bundletool get-size total` per device spec, `apkanalyzer` breakdown by native lib / dex / assets / resources; iOS `flutter build ipa --analyze-size` and the App Thinning report. Commit the report to `docs/05-reviews/T-190-size.md`.
2. **Ship per-ABI:** Play gets an AAB (per-ABI splits are automatic); any side-loaded APK uses `--split-per-abi`; drop `x86_64` from release.
3. **Shrink:** R8 `isMinifyEnabled` + `isShrinkResources` on release (keep rules for Pigeon, Tesseract, ML Kit, Glance); `--obfuscate --split-debug-info` (symbols uploaded to the CI artifact, never shipped).
4. **One OCR engine:** keep either ML Kit (bundled model, Latin + Arabic?) or Tesseract + `ara` model, based on the T-010 accuracy spike and size; or move OCR (and PDFium) to a Play Feature Delivery on-demand module / iOS on-demand resource, downloaded the first time the user scans or imports. Decision recorded as an ADR.
5. **Smaller wins:** subset IBM Plex Sans Arabic to the glyphs used (Arabic + Latin); check `googleapis` (huge generated package) — import only Drive v3; tree-shake icons (`--tree-shake-icons`); compress the mascot PNG / prefer the Rive file.
6. **Guard:** a CI step prints release sizes per ABI / platform on every release build and fails if they grow by more than 10 % or pass the NFR-PERF-07 budget.

## Acceptance criteria
1. The size report names the 150 MB artifact and breaks the release AAB (arm64) and IPA down by component.
2. Release Play download for arm64 and App Store download meet NFR-PERF-07 (targets confirmed with the PO after step 1), or the report explains the remaining gap with options.
3. OCR, PDF import, voice, backup and purchases still work (existing device suites / smoke run on the PC runner or an emulator).
4. ADR for the OCR / on-demand decision; CI size guard in place.
