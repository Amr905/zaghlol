## Description
Refunds reduce the original expense.

## Technical details
Match refund to most recent same-merchant expense ≥ refund within 60 days; partial/oversized refunds (EC-17); unmatched → refund income; invariants enforced.

## Design note
(Implementer note, PO cost rules 2026-11-13.)
- Pure rule `decideRefund` in `zaghlol_domain/transfers/offsets.dart`: same currency, account and non-empty `merchant_norm`; expense local date from refund day minus 60 to refund day; positive remaining (amount minus all links). Among expenses that absorb the whole refund the most recent wins; if none does (EC-17) the most recent takes what it can. Linked = min(refund, remaining); the rest is not linked, so it stays income. Same-instant ties are ambiguous: review item, never linked.
- App `RefundMatching` (`features/transactions/application/refund_matching.dart`): `onPersisted(refundId)` (one transaction, idempotent, triggers cap the sums so a race can only lose), `unlink(linkId)` (remembered, no auto re-link), `onRemoved(txnId)` (frees links on either side, announces cycles of both, lets freed refunds re-match). Events come from the shared `transactionsChangedFor`; `bulk_edit` now uses it too (FU-127 duplicate removed).
- Ambiguous refunds reuse review kind `reimbursement_suggestion` with payload `type: refund_ambiguous`: the `review_items.kind` CHECK has no refund kind and a new one needs a migration (open question for the review UI task).
- Pending refunds are skipped until posted. Edit-shrinks-expense (EC-40) and reimbursement allocation are T-091.
