## Description
Shortcuts can hand bank SMS and Apple Pay payments to Zaghlol (FinArt/Say approach).

## Technical details
LogBankMessageIntent(message, sender?), LogWalletTransactionIntent(amount, merchant, card); Guard → spool; amount-free dialog «زغلول سجلها ✓»; per-intent last-run timestamps; AppShortcutsProvider; immediate processing if SPK-03 says go.

## Design note
Required — solution-architect (Opus) writes it before implementation (C4).

**Implementer's note (2026-11-14, sprint rule: C4 builder writes it).**
1. **Where it runs.** Both intents live in the Runner target (platform-channels §3), so `perform()` runs in the app process, launched in the background when the app is closed (`openAppWhenRun = false`; `supportedModes` needs the iOS 26 SDK and CI builds with Xcode 16.4). New code in `app/ios/Runner/Capture/`.
2. **Order inside `perform()`.** (a) `GuardRuntime.decide(channel: .shortcutMessage | .applePay)`. On a drop, return the "not a bank message" dialog: no spool write, no engine. (b) On a keep, write the encrypted spool entry (`SpoolStore.write`, class `priority` for registry/user keeps, `generic` otherwise, with `guardInst`/`guardLast4` from the decision). (c) Only after `.written`: `HeadlessIngestion.attempt(timeoutS: 8)`. A refusal or a thrown write leaves no entry (the store cleans its `.tmp`) and never starts an engine. (d) Record the per-intent last-run time (wall clock, encrypted with the spool key, `capture/intent_runs.bin`, AAD `zaghlol.capture.v1|intent_runs`) on every run, kept or dropped, because the T-064 checker needs to know that the automation fired.
3. **Dialogs.** Four fixed string-catalog entries with no interpolation, so they can never carry an amount, sender or body: saved (`زغلول سجلها ✓`, the engine drained ok), saved for later (the entry is in the spool, the engine did not finish), not a bank message (Guard drop), couldn't save (refused or write failed).
4. **Record fields.** Message: `source` = trimmed sender, or `shortcut` when Shortcuts passes none (the record needs a non-empty source). Wallet: `source` = trimmed card name (or `wallet`), `body` = `amount` + `\n` + `merchant` (trimmed, empty parts left out). This adds to the §3 contract and is documented there.
5. **One spool key (FU-196 / 061-1).** `KeychainSpoolKeyProvider` uses `SpoolKeychain` (service `app.zaghlol.spool`, shared access group). Reads go through a new `SpoolKeychain.existing()`, which never creates (unusable means unavailable). Writes use `loadOrCreate()`, the spool's own policy. The Guard user file then shares the key with the spool, as §1.1 says. The old item (service `app.zaghlol.keys`) was never written in production because nothing called `GuardRuntime`, so nothing migrates.
6. **Re-read before delete (062-1).** `SpoolCipher.reloadKey()` re-reads the Keychain once (non-creating). `SpoolStore.read` calls it before every delete-on-proof, including the lost-key shortcut. If the key changed, it decrypts once more under the new key: a success returns the entry, and only a fresh failure deletes it. If the key can't be read (missing, locked or unusable), the entry is kept.
7. **`writeGuardConfig` on iOS.** Pigeon `IosCaptureHostApi.writeGuardConfig` (listed in §3, missing from the Pigeon file) goes to the process-wide `CaptureGuard.runtime` (`GuardRuntime` over the App Group `guard/` directory and the shared spool key). The intents use the same instance, so a write reaches the next intent at once; a later process reads the file. `getSpoolStatus.guardState` reports the runtime's state. Dart: `IosCaptureHostPort` (same `CaptureHostPort` interface, Android-only calls answer `NOT_AVAILABLE`), picked by `captureHostPortProvider` on iOS. Starting the writer on iOS is T-066 (the coordinator is Android-only until then).
8. **Spike.** T-063 replaces the T-009 spike (ADR-006 addendum: "T-061 deletes it"; T-061 deferred it). Deleted: `Runner/Spike/`, `IosIntentSpikeTests`, `lib/ingestion/ios_intent_spike.dart` and its test, the `spikeIntentMain` entrypoints, and the `ios-intent-spike` CI job and must-pass list. The headless path it proved is now `HeadlessIngestion` (T-062).
