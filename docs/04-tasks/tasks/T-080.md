## Implementation notes (builder)
Built on T-079 + T-087 + T-091. Files: `presentation/detail/` (S-12), `presentation/edit/` (S-13, `quickAddSelected` for Quick add "type it"), `application/transaction_editor.dart`, `data/transaction_detail_reader.dart`, `DriftTransactionRepository.editWithOutcome` + `onAmountChange` hook (EC-40 repair runs inside the edit transaction before the write; wired in `transactionRepositoryProvider`). The list opens S-12 by default; the empty-state Add opens S-13.

**Missing l10n keys (no ARB edits, per SPRINT):**
- `transactionsEditLinksRemoved` — notice after an amount edit removed money-back/split links (EC-40). Placeholder in use: `transfersAssignErrorExceedsExpense`.
- `transactionsEditFromAccountA11y`/currency-picker names: the currency picker lists ISO codes only (no localized names exist).
- Rule prompt "Also apply to N past" checkbox (A-13): `categorizationRuleApplyPast` exists but `BulkEdit.SetCategory` has no past-apply option, so the checkbox is not shown.

**Open questions / left undone:**
1. Contextual cards on S-12 (refund link, reimbursement suggestion, duplicate warning, reimbursed summary) are not built: they need read models from T-091/refund matching that no provider exposes yet. Strings exist.
2. `TabRoots.addSelected` is added; the composition root must pass `quickAddSelected` (and `TransactionsListScreen` / `TransactionDetailScreen` S-15/S-16 callbacks `onSplit`, `onLinkTransfer`, `onMoneyBackFor`) when it exists. Rows for S-15/S-16 are hidden until those callbacks are given.
3. Transfer add stores both legs only when both accounts hold the amount's currency; otherwise only the out leg (no conversion), and pairing waits for its match. Multi-currency account balance choice ("Which balance?") is not built.
4. Editing a transfer leg's account is allowed; T-079 open question 5 (`BULK_PAIRED`) is not addressed here.
