## Description
Lead review of the current charts (goldens `charts_*`, `gold_charts_*`, `chart_detail_*` and code, 2026-11-19):
- **No interaction:** touch is disabled on every chart (`BarTouchData(enabled: false)`, `PieTouchData(enabled: false)`, `LineTouchData(enabled: false)`), so values can't be read and nothing drills down.
- **No scale:** no value axis and no gridlines (`FlGridData(show: false)`, empty `leftTitles`), so bars can't be compared by value.
- **One long scroll:** all 12 charts stack as equal cards with no summary on top; the most useful ones aren't first.
- **Crowded labels:** cycle labels under the cash-flow bars run together.
- **Thin data:** with little history the line charts (net worth, gold) are near-flat 2-point lines and the installment timeline is almost empty; there is no "not enough data yet" state.
- **No comparison:** nothing says whether this period is better or worse than the last.

Research (finance apps and chart UX, 2026-11-19): users expect a period picker with relative presets (Monarch), month-over-month and year-over-year category comparison (Copilot), the previous period overlaid on the same chart plus category-level change (Finny), a per-category % change vs the previous period and average daily spend (Money Lover), a savings rate for the period (Lunch Money), and tap / press-and-drag scrub tooltips on mobile (SAP Fiori). Touch targets 44 pt iOS / 48 dp Android.

## Technical details
1. **UX note + mockups (Opus `ux-designer`, PO sign-off before build):** the charts screen top-to-bottom: summary strip (spent, earned, saved, savings rate, each with % vs previous period), then charts ordered by usefulness (cash flow, category donut, top merchants, budget, month vs average, then the rest), with the period chip from T-188.
2. **Interaction:** enable touch on bar/line/pie; tap shows a value bubble, press-and-drag scrubs; tap a bar / slice / merchant row opens the transactions list pre-filtered to that category / merchant / period.
3. **Scale:** a light value axis (3–4 gridlines, compact labels: ١٫٢ألف / 1.2K) where values are compared; data labels on donut legend.
4. **Comparison:** totals and category rows show the change vs the previous period of the same length; cash flow can overlay the previous period as a faint series.
5. **Clarity:** top 5 + "Other" in donut and merchants; label thinning on crowded x-axes; per-chart empty / thin-data state with a Zaghlol line ("محتاج شهرين كمان عشان الرسم ده يبان").
6. **Accessibility:** each chart gets a text summary for screen readers; colour is never the only cue.
7. Respects T-187 hidden-amounts mode (no values shown when on).

## Acceptance criteria
1. PO approved the mockups (recorded in the task file) before implementation.
2. Every chart responds to tap; bar, slice and merchant taps open the right filtered transaction list (widget tests).
3. Summary strip and category changes compute correctly vs the previous period, per currency (unit tests).
4. Empty and thin-data states shown below each chart's minimum data rule.
5. NFR-PERF-04 still met; goldens `ar`/`en`, light/dark; RTL verified; no hard-coded strings; screen-reader summaries present.
