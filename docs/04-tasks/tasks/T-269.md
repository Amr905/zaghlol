## Scope
1. `app/lib/features/export_import/presentation/import_source_screen.dart` shows "Coming soon" for bank statements. Wire the built parser (T-156/T-156b, `packages/zaghlol_parsing/lib/statements/**`, batch 41–42 notes in `docs/workflow/LEAD_HANDOFF.md`): pick a PDF (text or scanned) or image(s) → parse on device (OCR for scans/images) → review screen.
2. Review: rows with date, description, amount, direction; decisions surfaced by the parser — direction unknown, rows that don't reconcile with the running balance, year not printed (ask once), possible duplicates of existing transactions (settled-only dedupe) — each row can be kept, edited or dropped; nothing is saved until Confirm.
3. Account: choose or create the account the statement belongs to; currency from the statement.
4. Failure states with reasons (password-protected PDF, no table found, OCR not available on this phone). Files are read in place and never copied outside the encrypted spool; temp files deleted.
5. Strings ar/en; goldens via app-regen only. If the three sample layouts' parser has gaps that block the UI, list them; don't rewrite the parser here.

## Acceptance criteria
Widget tests of the flow with synthetic parsed statements (happy path, year prompt, unknown direction, duplicate, failure); nothing saved before Confirm; `flutter analyze` clean.

## Design note (builder)
- One new screen, `StatementImportScreen` (choose PDF or photos -> reading -> column mapping only when the layout is not recognised -> review -> confirm -> done screen). The four Egyptian-bank rows in the import list become available and open it; the bank id is the saved-layout key. Online-bank CSVs stay "coming soon" (T-157).
- Parser use: the T-156 `ImportStatementPdfUseCase` is used as built. Three small additive changes: `openFragments` (text already read, for photos), decisions on clean rows (skip, flip direction), and `keepDuplicates` plus `ImportSummary.duplicateRows` (a dry run lists duplicate rows so the review can show them).
- Photos: `OcrStatementImageReader` writes each image to the app temp dir only to hand it to the OCR host's sealed spool, then deletes it; bytes are zeroed. Same fragments and table detector as a scanned PDF.
- Nothing is saved before Confirm: review runs `parse` and a dry run; a new account is created in the same step as the rows.
- Ports (`statement_import_ports.dart`) make picker, use case, accounts, image reader and OCR probe overridable in tests.

## Builder assumptions
- "Edit a row" means change its direction or drop it; the date, amount and description are not editable (money edits risk silent errors). Listed as a gap for the PO.
- Currency comes from the statement (`suggestedCurrency`, else EGP) and can be changed on the review from a short list (EGP, USD, EUR, GBP, SAR, AED, KWD); only accounts in that currency are offered, plus "New account".
- Year prompt offers this year and the two before; none is pre-selected so the user must tap one.
- A flagged row has no default answer: Confirm stays disabled until every flagged row is answered.
- A duplicate is skipped unless the user taps "Add anyway"; duplicates are only checked once an existing account and (if needed) the year are chosen.
- "OCR not available" is detected by probing `supportedLanguages()` after a no-text failure, so no parser change was needed.
- The mapping step widget (T-156) keeps its own Material styling; not restyled here.
- Multi-page statements: one PDF, or up to 12 photos.
