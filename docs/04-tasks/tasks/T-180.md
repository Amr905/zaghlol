## Description
One consistent clock sample per call — wall clock, a monotonic clock that keeps counting in deep sleep, and a boot reference — so T-144 can judge Gold against trusted time.

## Technical details
- Pigeon contract exactly as platform-channels §4b: `sample() → ClockSample {wallMs, monotonicMs, bootCount?}`, synchronous.
- **Android:** `wallMs = System.currentTimeMillis()`, `monotonicMs = SystemClock.elapsedRealtime()`, `bootCount = Settings.Global.BOOT_COUNT` (API 24+, below minSdk 26).
- **iOS:** `wallMs` from `Date().timeIntervalSince1970`, `monotonicMs = clock_gettime_nsec_np(CLOCK_MONOTONIC_RAW) / 1e6` (continuous time; **not** `systemUptime` or `CLOCK_UPTIME_RAW`, which stop in sleep), `bootCount = null` (no public boot identifier; `kern.bootsessionuuid` is not used).
- The three values are read back to back in one call so they are consistent.
- **Privacy manifest:** declare the required-reason API category for elapsed time with reason 35F9.1 in `PrivacyInfo.xcprivacy`. The sample never leaves the device.
- No algorithm here: `hw`/`lb`, interval classes and the tamper test are Dart (T-144).

## Acceptance criteria
- [ ] Pigeon contract matches platform-channels §4b; stale-generation check passes.
- [ ] Unit tests: the iOS implementation calls `CLOCK_MONOTONIC_RAW` (source check plus a mock seam); Android returns `elapsedRealtime` and `BOOT_COUNT`.
- [ ] **Device test, iOS (real hardware, recorded in `docs/05-reviews/T-180-device.md`):** sample, lock the phone and let it sleep ≥ 15 min, sample again: `Δmonotonic` is within 2 s of `Δwall` (proves the clock counts sleep).
- [ ] **Device test, Android (real hardware):** the same sleep check under forced Doze; and `bootCount` increments by 1 after a reboot while `monotonicMs` restarts low.
- [ ] Device test, iOS: after a reboot `monotonicMs` is lower than before (the signal T-144 uses).
- [ ] `PrivacyInfo.xcprivacy` declares the elapsed-time API with reason 35F9.1 (file check in CI).
- [ ] Clock values are never logged.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
