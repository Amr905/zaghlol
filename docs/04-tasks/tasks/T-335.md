## Description
`PreCheck(feature, install, account?, requestId)` → `{limit, used, remaining, resetsAt}` or `Exhausted` (a retry with the same `requestId` passes even at the limit); `Commit(feature, subjects, requestId, n)` with the single-statement update/insert-on-conflict per subject and `last_request_hash = SHA-256(requestId)`. Limits from remote config (`ask.quota_*`, `cat.quota_*`). Month = Africa/Cairo calendar month; startup self-check of the time-zone id (failure disables the LLM module). Purge rows of months before the previous one; delete flows remove the subject's rows.

## Acceptance criteria
1. Cairo month tests: 30 Nov 23:50 and 1 Dec 00:05 Cairo map to different months; DST transitions; `resetsAt` is the first instant of the next Cairo month in UTC.
2. Gold seat holder → 50 / 150; paused Gold and non-holder installs → 5 / 15; account counter uses the calling install's limit; either counter at limit → `Exhausted`.
3. Categorise commit adds `n` and trims to the lower remaining of install and account.
4. **Negative proof 1:** two parallel commits with the same `requestId` (Testcontainers) → `used` grows by exactly 1 (or `n`).
5. **Negative proof 2:** after `DELETE /v1/installs/me` / `DELETE /v1/accounts/me`, no `llm_quota_counters` row for that subject remains; purge leaves only the current and previous month.
6. `ask` and `cat` counters are independent (a cat commit never changes the ask row).
