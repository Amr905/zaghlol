## Description
`PreCheck(feature, install, account?, requestId)` → `{limit, used, remaining, resetsAt}` or `Exhausted` (a retry with the same `requestId` passes even at the limit); `Commit(feature, subjects, requestId, n)` with the single-statement update/insert-on-conflict per subject and `last_request_hash = SHA-256(requestId)`. Limits from remote config (`ask.quota_*`, `cat.quota_*`). Month = Africa/Cairo calendar month; startup self-check of the time-zone id (failure disables the LLM module). Purge rows of months before the previous one; delete flows remove the subject's rows.

## Design note (builder, 2026-11-26)
- **Month:** `CairoMonth` (Application) uses `TimeZoneInfo` id `Africa/Cairo`; `MonthKey(utc)` = yyyymm of the Cairo local time, `ResetsAt(utc)` = first Cairo instant of the next month converted to UTC (an invalid local midnight is moved one hour on), `PreviousKey` feeds the purger. `SelfCheck()` runs when the quota module is built; on failure `ILlmQuotaStore` answers `Unavailable` (the endpoint maps that to `LLM_SERVICE_PAUSED`) and logs a fixed message.
- **Tier:** Gold only when `EntitlementRules.Build(install, facts, presentedAccount)` says Active/Grace, i.e. the install holds the seat and an account-linked purchase counts only with the validated account of the call; Paused/none = Free. Limits come from `remote_config` (`ask.quota_free|gold`, `cat.quota_free|gold`), defaults 5/50 and 15/150 (PO rows ASK-LLM, LLM-CATEGORISE); a missing, non-integer or negative value falls back to the default. The caller has already validated the account token; the store never sees it.
- **Counters:** raw SQL, no EF entity (so the ModelTests allowance stays unchanged). One row per (feature, subject_kind, subject_id, month). `PreCheck` reads install (+ account) rows: a row whose `last_request_hash` equals `SHA-256(requestId)` means a retry and passes; otherwise either subject at the limit gives `Exhausted`.
- **Commit:** `n` is first trimmed to the lower remaining of install and account, then one statement per subject: `INSERT ... ON CONFLICT DO UPDATE SET used = used + LEAST(@n, @limit - used), last_request_hash = @h WHERE used < @limit AND last_request_hash IS DISTINCT FROM @h`. The `IS DISTINCT FROM` guard is what makes parallel commits with one `requestId` count once (the loser's UPDATE is re-evaluated after the winner commits). Ask and cat are separate rows (the key has `feature`).
- **Purge / delete:** retention rule `llm_quota_months` deletes `month_key < previous Cairo month` (cut-off computed in C# from `CairoMonth`); install delete and account delete remove their subject's rows in their existing transaction.

## Acceptance criteria
1. Cairo month tests: 30 Nov 23:50 and 1 Dec 00:05 Cairo map to different months; DST transitions; `resetsAt` is the first instant of the next Cairo month in UTC.
2. Gold seat holder → 50 / 150; paused Gold and non-holder installs → 5 / 15; account counter uses the calling install's limit; either counter at limit → `Exhausted`.
3. Categorise commit adds `n` and trims to the lower remaining of install and account.
4. **Negative proof 1:** two parallel commits with the same `requestId` (Testcontainers) → `used` grows by exactly 1 (or `n`).
5. **Negative proof 2:** after `DELETE /v1/installs/me` / `DELETE /v1/accounts/me`, no `llm_quota_counters` row for that subject remains; purge leaves only the current and previous month.
6. `ask` and `cat` counters are independent (a cat commit never changes the ask row).
