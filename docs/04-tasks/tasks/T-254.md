## Design note (builder)

Checked every FU against `main` @ `36b91fe3` first. Already fixed by later tasks (closed with evidence, no code): FU-081 (F3 `HeadlessEngine` main-thread re-check + `aUiEngineSeenOnTheMainThreadPreventsTheStart`; F4 `ingest_store.dart` `_forgetFailedOpen` + `FU-081 F4` test; F5 ADR-005 live/retry split; F6 `SpikeMetricsTest`; close-before-destroy `ShutdownSequence`), FU-082 (T-038 registry Guard: `TextFold` normalisation, broad EN/AR OTP `drop.global`, shared golden in Kotlin/Dart), FU-083 (T-041 production `ingestionMain`; spike registry behind `kIsSpikeBuild`, CI greps prod `libapp.so`), FU-093 (N1 channel `lockscreenVisibility`, N2 ADR-005 note, N3 behavioural `ShutdownSequenceTest`, N4 class doc), FU-086 I-1…I-4. What is left and how:

1. **FU-086 I-5 (SMS receiver budget).** `BoundedDispatch.run` gets an optional `onAbandoned` callback, called once when the 5 s budget (or an executor rejection) finishes the broadcast before the work did. `SmsReceiver` passes one that records the SMS as missed (`CaptureStatusStore.recordMissed("sms", wallMs)` → `firstMissedSmsAtMs`), so the next catch-up starts at or before it even if later SMS move the watermark. It runs on its own daemon thread (`zaghlol-sms-missed`), never on the timer thread, so a Keystore stall in the status write can't delay the `finish()` of later broadcasts. Only a time is written (no sender, no body); a work that completes late after all just means a deduped catch-up overlap.
2. **FU-070 share intake.** C2: when the provider reports a MIME, only that MIME decides the kind (unknown → `unsupportedType`); the intent type is used only when the provider reports none. S2: `ShareUriPolicy` refuses the authorities our permissions unlock (`sms`, `mms`, `mms-sms`, `call_log`, `com.android.contacts`, `contacts`). C3: `ShareJob.beginCommit()` (atomic with `complete`): the intake commits only if no outcome was set; the give-up timer does not override a commit already in progress, so a share is never both listed and announced `unreadable`. S1: `IntentShareSource.open` uses `openAssetFileDescriptor(uri, "r", CancellationSignal)` and `cancel()` cancels the signal; the single worker becomes `ShareWorkers` (pure Kotlin, 2 threads, queue of 8, rejection → `unreadable` at once), so one provider that never returns can't block later shares. C4/C5: documented (T-060 manual steps, platform-channels §2.1); no code (HEIC below API 28 is already refused as `unsupportedType` by the bounds probe, the refusal copy is generic).
3. **FU-121 048-3.** On an `INVALID_ARGUMENT` restart `scanned` and `skipped` are reset to their values at scan start (so `first` is true again and the first page is small), and a duplicate of a row this scan already imported is not counted as skipped.
4. **FU-050 (CI/ADR).** `gh attestation verify` pinned with `--signer-workflow …/compile_sqlite.yml` and `--deny-self-hosted-runners`, `gh` by absolute path (I-4); APK regex `libsqlite3mc[.]so` (#3); ADR-002 states attestation covers the host binary only (#2; shipped ABIs stay on the T-171 release checklist, L-1), cites the final-head runs and the proofs (#4), notes `open_cold_ms` is first-open-in-process (#7); contract test asserts code 26 (#5); benchmark cleanup no longer hides the real error (#6). L-3 already done (trap).
