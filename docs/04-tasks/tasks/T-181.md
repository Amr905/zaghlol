## Description
Verify device attestation proofs on the server, bound to the install-bound restore hash, without storing or logging anything but the App Attest public key, its counter and replay hashes.

## Technical details
- **Interfaces:** `IPlayIntegrityVerifier.VerifyAsync(token, expectedRequestHash) → {ok | failure(reason), proofLevel: device|basic}`; `IAppAttestVerifier.VerifyAssertionAsync(installId, keyId, assertion, clientDataHash)` and `RegisterAttestationAsync(installId, keyId, attestationObject, clientDataHash)`. Failure reasons map to error-handling §3.2 codes: `hash_mismatch`, `stale`, `replayed`, `app_unrecognized`, `no_integrity`, `counter`, `key_unknown`, `chain`. Upstream 5xx/timeouts/quota → `unavailable` (the endpoint maps it to `503 UPSTREAM_UNAVAILABLE`, never `422`).
- **Play Integrity (standard request):** `Google.Apis.PlayIntegrity.v1` `decodeIntegrityToken`; require `requestDetails.requestHash == b64u(bodyHash)`, `requestPackageName` = our package, `timestampMillis` ≤ 5 min old (the only "expired" case, D-53), `appIntegrity.appRecognitionVerdict = PLAY_RECOGNIZED`, and `deviceRecognitionVerdict` containing `MEETS_DEVICE_INTEGRITY` (→ `device`) or else `MEETS_BASIC_INTEGRITY` (→ `basic`); no label → `no_integrity`. **Optional verdicts ignored (R2-7):** the decode DTO has no members for `deviceAttributes`, `recentDeviceActivity`, `appAccessRiskVerdict`, `environmentDetails`; they are never stored or logged. Single use: SHA-256(token) into `replay_guard` (`play_integrity`, 15 min).
- **App Attest, in-house** (`System.Formats.Cbor`, `System.Security.Cryptography`; no Apple .NET library):
  - *Attestation* (first use of a key): CBOR decode; x5c chain to the **Apple App Attestation Root CA**; nonce extension (OID 1.2.840.113635.100.8.2) equals `SHA-256(authData ‖ clientDataHash)`; `keyId` = SHA-256 of the credential public key; RP ID hash = SHA-256(`<TeamID>.<bundleId>`); counter 0; `aaguid` = production (development allowed only in staging config). Register the key to **the install named by the install token**; a `keyId` already registered to another install is refused; one key per install (re-attest replaces).
  - *Assertion:* load **this install's** key from `app_attest_keys`; verify the ECDSA signature over `nonce = SHA-256(authenticatorData ‖ clientDataHash)` with the stored public key; RP ID hash; counter strictly greater than stored, then update it **in the caller's transaction** (T-185 rolls it back on `SEAT_KEY_MISMATCH`, R5-6).
  - `clientDataHash` is computed by the caller (T-185): `SHA-256("zaghlol-restore-attest-v1" ‖ 0x00 ‖ bodyHash ‖ seatKeysDigest)` (R4-1(3)); this module checks exactly the hash it is given.
- **Fakes** for both verifiers (deterministic, configurable outcomes) used by T-185 and T-135 tests, plus a test-only App Attest signer that produces structurally valid attestations/assertions under a test root.
- Never logged: tokens, decoded payloads, assertions, attestation objects, key IDs (reason code only).

## Design note
Written by the implementer (Opus, acting as the Opus note for this crypto task, 2026-11-13).

1. **Placement.** Ports and results in `Zaghlol.Application.Purchases.Attestation` (`IPlayIntegrityVerifier`, `IAppAttestVerifier`, `IAppAttestKeyStore`, `AttestationResult`, `AttestationFailure`). Implementations in `Zaghlol.Infrastructure/Attestation`. There is no `Zaghlol.Testing` project; fakes and the test signer live in `backend/tests/Shared/` (namespace `Zaghlol.Testing`, linked into test projects), as the other shared fakes do. `AddZaghlolAttestation()` registers everything; **T-185 wires it into the API** (not wired here, so no new startup requirement lands before restore exists).
2. **Play Integrity client deviation.** Not `Google.Apis.PlayIntegrity.v1`: its generated `TokenPayloadExternal` has members for all four optional verdicts, which R2-7 forbids ("the DTO has no member for them"). Instead a typed `HttpClient` (as T-130's Play client) POSTs `v1/{package}:decodeIntegrityToken` with a source-generated DTO holding only `requestDetails{requestPackageName, requestHash, timestampMillis}`, `appIntegrity{appRecognitionVerdict}`, `deviceIntegrity{deviceRecognitionVerdict[]}`; unknown members are skipped by the reader and never materialised. OAuth scope `https://www.googleapis.com/auth/playintegrity` from the same `Purchases:Google` credential (separate token source; the Play Developer token keeps only `androidpublisher`). Resilience: 10 s total, 1 retry on transient, 3 s per attempt. No budget charge on the Play Developer budget (Play Integrity has its own quota; restore's own limits, 5/h per install and 10/day per purchase, bound it).
3. **Play rules, in order:** decode (`400` → `chain`, the token can't be verified; `401/403/404/408/429/5xx`, timeout, network, unparseable 2xx → `unavailable`); package ≠ ours → `app_unrecognized`; `requestHash` ≠ `b64u(bodyHash)` (fixed-time) → `hash_mismatch`; `timestampMillis` older than 5 min or more than 1 min in the future → `stale`; `appRecognitionVerdict` ≠ `PLAY_RECOGNIZED` → `app_unrecognized`; `MEETS_DEVICE_INTEGRITY` → `device`, else `MEETS_BASIC_INTEGRITY` → `basic`, else `no_integrity`; then `INSERT … ON CONFLICT DO NOTHING` of `SHA-256(token)` into `replay_guard` (`play_integrity`, now + 15 min) on its own autocommit connection (like sign-in, R3-5) → 0 rows → `replayed`. Only a token that passed every check takes a row.
4. **App Attest attestation** (`RegisterAttestationAsync`): size caps (object ≤ 16 KiB, each cert ≤ 4 KiB, `keyId` 32 bytes, `clientDataHash` 32 bytes); `System.Formats.Cbor` reader, strict conformance, the top map must hold exactly `fmt`, `attStmt`, `authData`; `fmt = "apple-appattest"`; `attStmt` holds `x5c` (exactly 2 byte strings) and `receipt`. Chain: `X509Chain`, `CustomRootTrust` with the pinned root as the **only** anchor, `ExtraStore` = the intermediate, no revocation, no downloads, verification time = now, exactly 3 elements, element 2 fingerprint = pinned. Nonce: the leaf extension `1.2.840.113635.100.8.2`, parsed with `System.Formats.Asn1` as `SEQUENCE { [1] EXPLICIT OCTET STRING }` (DER), must equal `SHA-256(authData ‖ clientDataHash)` (fixed-time) → else `hash_mismatch`. Leaf key must be P-256; `keyId` = SHA-256(uncompressed point) and = the supplied `keyId` and = `credentialId` → else `chain`. `authData`: RP ID hash = SHA-256(`<TeamID>.<bundleId>`) → else `app_unrecognized`; counter 0 → else `counter`; `aaguid` = `appattest\0×7` (production) or `appattestdevelop` (only when `AllowDevelopmentEnvironment`, refused in Production) → else `app_unrecognized`. Anything malformed → `chain`.
   - **Registration** in the caller's transaction (`IAppAttestKeyStore`, `NpgsqlAppAttestKeyStore` over the caller's `NpgsqlConnection`/`NpgsqlTransaction`, exposed as `ISeatTransaction.AppAttestKeys`): lock the install row (`FOR UPDATE`; gone → `key_unknown`); a `keyId` registered to **another** install → `key_unknown` (refused); the **same** `keyId` already registered to this install → kept unchanged (a replayed `attestationObject` must never reset the counter to 0); otherwise delete this install's old key and insert the new one (`ON CONFLICT (key_id) DO NOTHING`, 0 rows → `key_unknown`, a concurrent registration elsewhere won).
5. **App Attest assertion** (`VerifyAssertionAsync`): cap 2 KiB; CBOR map of exactly `signature`, `authenticatorData`; `authenticatorData` ≥ 37 bytes. Load this install's row `FOR UPDATE` in the caller's transaction; none, or its `key_id` ≠ the supplied `keyId` → `key_unknown`. ECDSA P-256 / SHA-256 verify (DER signature) over `nonce = SHA-256(authenticatorData ‖ clientDataHash)` → else `hash_mismatch`; RP ID hash → `app_unrecognized`; counter > stored → else `counter`; then `UPDATE sign_count` in that transaction (T-185 rolls it back on `SEAT_KEY_MISMATCH`, R5-6). `clientDataHash` is checked exactly as given (T-185 builds it, R4-1(3)).
6. **Root pinning.** `AppleAppAttestationRootCA.cer` (DER, 549 bytes) embedded as a resource; its SHA-256 `1cb9823ba28ba6ad2d33a006941de2ae4f513ef1d4e831b9f7e0fa7b6242c932` (subject `CN=Apple App Attestation Root CA, O=Apple Inc., ST=California`, serial `0BF3BE0EF1CDD2E0FB8C6E721F621798`, valid 2020-03-18 to 2045-03-15) is asserted on load, and a mismatch stops startup. apple.com is not reachable from the build workspace, so the bytes were taken from two independent published copies (npm `node-app-attest` 1.0.1 and PyPI `pyattest` 1.0.5) whose fingerprints agree; **PO to confirm the fingerprint against apple.com/certificateauthority before launch.** `Attestation:AppAttest:TestRootCertificate` replaces it only in Development and Testing.
7. **Test vectors.** (a) A self-built chain under a test root (`AppAttestTestSigner`: P-384 root and intermediate, P-256 leaf with the nonce extension) produces structurally valid attestations and assertions for every rule test; (b) one **real Apple production attestation** (public test fixture of `node-app-attest`, MIT, attributed in the fixture) verifies against the pinned production root at its own issue time, proving the CBOR/ASN.1/authData handling matches Apple's real format.
8. **Logging.** Verifiers log one line per failure with the provider and reason code only (`attestation_failed`); never the token, decoded payload, assertion, attestation object, key ID or hashes. Sentinel test over logs and activities.
9. **Failure codes.** Exactly the eight of error-handling §3.2 plus `unavailable` (Play only; App Attest makes no upstream call). DB errors propagate as exceptions (the endpoint's 5xx path), never as a verification failure.

## Acceptance criteria
- [ ] Play Integrity: one test per rule (hash mismatch, wrong package, 6-min-old timestamp, not `PLAY_RECOGNIZED`, basic-only → `basic`, no label → `no_integrity`, replayed token → `replayed`).
- [ ] R2-7: a decoded payload containing all four optional verdicts verifies normally and none of their values reaches the DB, logs or spans (sentinel test).
- [ ] App Attest attestation: valid test attestation registers the key to the calling install; wrong chain, wrong nonce, wrong RP ID, non-zero counter, wrong `aaguid` for the environment, and a `keyId` already registered to another install are each refused (tests).
- [ ] App Attest assertion: valid assertion over the given `clientDataHash` passes and raises the counter; a counter that doesn't increase, a key of another install, and an assertion over a different `clientDataHash` (e.g. one seat public key changed) fail (tests).
- [ ] R4-1(3): a test using `restore-binding-v1.json` `clientDataHashHex` shows an assertion made over that hash verifies, and one made over the hash with the seat keys reordered fails.
- [ ] The counter update participates in an ambient transaction: rolling it back leaves the stored counter unchanged (test).
- [ ] Upstream failure → `unavailable`, never a verification failure (WireMock test).
- [ ] Log/trace sentinel test: no token, payload, assertion, attestation object or key ID appears.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
