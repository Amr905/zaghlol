## Description
Order: network bucket → install token → `Zaghlol-App` → strict closed JSON ≤ 4 KB (`UNKNOWN_FIELD`) → flag per install → spend pause → consent = active provider + version → install/account/global buckets → attestation (T-336) → tier + quota pre-check (T-335) → provider (`ask-plan-v1` prompt: static prefix first, question last, `max_output_tokens` 300) → validator (T-330) → `ask_llm_invest` gate → commit → 200 `{serverTime, plan, counted, quota}`. Valid PL-FALLBACK/PL-REFUSE count; validator failure or blocked INVEST → PL-FALLBACK `counted:false`. Provider call cancelled with `RequestAborted`. Prompt hash recorded in metrics.

6. OpenAPI and problem bodies match T-322.

## Design note (builder, Sonnet)
- **Gate order (cheap first, fail closed)** in one reusable `LlmGateChain` (Application; T-352 reuses it with `LlmFeature.Categorise`): body parse (closed JSON, `UNKNOWN_FIELD`; 4 KB, 16 KB only with `attestationObject`) -> flag per install (`ILlmFeatureGate`, read per request) -> spend pause (`ISpendGuard.IsPausedAsync`, cached 60 s) -> consent (= active provider id and consent version 1; a provider with no key is paused here) -> account token validated once (`IAccountTokenValidator`; none or invalid = no account, never an error) -> buckets (install 3/min + 20/day, account the same, /24 30/min, global 120/min, in process; a refusal never reaches the provider) -> attestation (`ILlmAttestationVerifier`, absent member = `null` = 422 `missing`) -> quota pre-check (`ILlmQuotaStore`, read only). Only then `ISpendGuard.ReserveAsync` and the provider.
- **What is counted:** only after the reply was validated, via `CommitAsync` with `CancellationToken.None` (Stop after validation counts, Stop before does not, FR-LLM-10). Counted: a valid plan, including valid PL-FALLBACK and PL-REFUSE. Not counted (and the provider call is still charged to the spend ledger): provider timeout/5xx/open circuit (502 `UPSTREAM_UNAVAILABLE`), invalid or provider-refused reply, validator failure, PL-INVEST while `ask_llm_invest` is off (all three answer 200 `PL-FALLBACK/unsupported`, `counted:false`), every gate refusal. A commit that finds the counter at its limit (race over the burst) answers 403 `LLM_QUOTA_EXHAUSTED` and withholds the plan. A retry (same `requestId` inside the 2-minute window, T-335) passes the pre-check at the limit, calls the provider again and is not counted twice.
- **Question handling:** `q` is held as `LlmSensitive<string>` from the parser on, scrubbed server-side (phones, e-mails, InstaPay addresses, digit runs of 8 or more; the phone's own `⟦...⟧` tokens are kept) after the trim and NFC, and only the scrubbed text goes to the provider and the validator (`sentText`). Plans leave the pipeline as `LlmSensitive<byte[]>` and are written to the response only by the endpoint. Logs carry fixed reason codes; metrics carry a prompt hash prefix and fixed tags; a provider exception is caught, its message dropped.
- **Contract reconciliation:** `attestation` leaves OpenAPI `required` (ask-llm §5 "As built": absent = 422, not 400); the body schema stays closed. `PlanValidator` rejects control characters in `p` strings (FU-404: `$` accepted a trailing `\n`) and checks `source.whatIf.target.currency` (PL-INVEST).
