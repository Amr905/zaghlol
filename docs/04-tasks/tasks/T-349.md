## Description
Order: network bucket → install token → `Zaghlol-App` → strict closed JSON ≤ 4 KB (`UNKNOWN_FIELD`) → flag per install → spend pause → consent = active provider + version → install/account/global buckets → attestation (T-336) → tier + quota pre-check (T-335) → provider (`ask-plan-v1` prompt: static prefix first, question last, `max_output_tokens` 300) → validator (T-330) → `ask_llm_invest` gate → commit → 200 `{serverTime, plan, counted, quota}`. Valid PL-FALLBACK/PL-REFUSE count; validator failure or blocked INVEST → PL-FALLBACK `counted:false`. Provider call cancelled with `RequestAborted`. Prompt hash recorded in metrics.

## Acceptance criteria
1. Integration tests (Testcontainers + fake provider) for every row of the §4.1 table and for counted/not-counted per outcome, duplicate `requestId` in parallel, account counter across two installs, 6th Free question on 30 Nov 23:50 Cairo refused and allowed at 1 Dec 00:05.
2. Flag turned off while the app's cache says on → first request `LLM_SERVICE_PAUSED`; spend cap reached → same.
3. **Negative proof 1:** a marker question and marker template sent through success, fallback, validation-failure, timeout and exception paths are absent from the log sink, the in-memory OTel exporter, metrics and a dump of every table.
4. **Negative proof 2:** missing/invalid attestation, quota exhausted, paused, flag off, consent mismatch, rate-limited → fake provider call count 0.
5. The provider request built by the pipeline carries only the system prompt, sent text and language (FR-LLM-34; captured by the fake).
6. OpenAPI and problem bodies match T-322.
