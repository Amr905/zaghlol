## Today

## Scope
1. **Trigger**: a salary transaction (any currency, D-85) that has not been celebrated yet — from SMS/notification/statement, or a **cash income marked as salary**. Celebrate once per salary transaction (store the last celebrated salary id/day; no repeats on reinstall restore of the same salary, no celebration for salaries older than 7 days found by the first inbox scan).
2. **Cash salary**: in the manual add flow for income (cash or any account), a «ده مرتب؟» switch (default off; on when the category is Salary). On saving with it on, the transaction is a salary (same flag/category the SMS path uses, so payday automation D-81 also sees it).
3. **When**: shown on the Home screen at the next app start (or right after the cash save returns to Home), never over another screen or mid-task; at most once per app start.
4. **Sheet (artboard B)**: bottom sheet over Home with the Rive bird in the `payday` moment, falling coins (simple Flutter animation, ≤ 1.6 s), «وصل المرتب!», the amount in its own currency (`+29,700.00 EGP` / `+1,000.00 USD`), «زغلول حسبها: تقدر تصرف حوالي {perDay} في اليوم لحد المرتب الجاي.» (only when an EGP pay cycle and a per-day figure exist; else hide the line), buttons «خطّط الشهر» (opens budget) and «تمام» (closes). Tap outside / swipe down closes. Coins and bird beats follow `ZHaptics.timelineMs(ZHapticPattern.payday)` and `ZHaptics.play(ZHapticPattern.payday)` fires when the sheet opens.
5. Remove the old payday bubble from the Home mascot slot (the sheet replaces it).
6. Reduce motion: still bird, no coins, one light haptic tick. ar/en, RTL, 1.3×, light/True Black dark, screen-reader label announcing the amount.

## Design note (builder)
- **Trigger model.** `paydayCelebrationProvider` now emits a `PaydayCelebration(txnId, Money amount)` (any currency) instead of a date. Candidates are every `SalaryEntry` in `salary.state` (captured or hand-entered, so a cash salary counts) whose txn id is not in the new setting `mascot.payday_celebrated_txns` (capped list of ids, in the encrypted settings, so a restore of the same data never repeats) and whose anchor is newer than the legacy `mascot.payday_celebrated` epoch day (kept read-only for upgrades). A pure function `paydayDecision` splits candidates into fresh (anchor within 7 days of today) and stale (silent). The provider loads the newest fresh candidate's transaction, requires a live income row (else silent), marks ALL candidates celebrated, and emits the newest one. Amount is the transaction's own `Money`.
- **Where.** `HomeMascotSlot` listens to the provider and opens `showPaydaySheet` once per txn id per app session after the frame (Home only; it is mounted only on Home). The old payday bubble is removed.
- **Sheet.** `PaydaySheet` (features/mascot/presentation/payday_sheet.dart): `ZSheetBody` + `ZaghlolAvatar(moment: payday)` + a `PaydayCoins` Flutter animation (1.6 s, beats from `ZHaptics.timelineMs(ZHapticPattern.payday)`) + amount + optional per-day line from `currentCycleOverviewProvider` (EGP `safeToSpend` only) + buttons. Reduce motion (OS or app): still bird, no coins, one `ZHaptics.light()`; otherwise `ZHaptics.play(payday)` on open. Coins ignore pointers; the bird never covers a button.
- **Manual add.** The existing `txn-salary-switch` in the income form is relabelled «ده مرتب؟», and turns on when the user picks the Salary category (`sys:income`). Saving with it on already goes through `SalaryService.recordManual` (same state entry the SMS path writes), so D-81 payday automation and the celebration both see it.
- **T-293 dependency.** T-293 is not merged: `z_haptics.dart` gets `ZHapticPattern`, `ZHaptics.play` and `ZHaptics.timelineMs` stubs in the agreed shape; the Lead takes T-293's version at merge.

## Builder assumptions
- "At most once per app start" is read as: one sheet per newly celebrated salary per session, never repeated for the same txn; a cash salary saved in-session celebrates when Home is next shown/mounted slot sees it.
- A cash salary dated more than 7 days back is recorded silently (same freshness rule as SMS).
- Per-day line uses the current cycle's EGP safe-to-spend and hides when null or not positive.
- Salary category is `sys:income` (the id the salary service and SMS path use).
- Fix 83 (batch review): the payday sheet now waits as pending until Home is the current route on the Home tab (retries on pop and tab switch); the txn mark is stored only once the sheet opens, and the shown-this-session set lives in `paydayShownThisSessionProvider`.
