## Description
v1 operator tooling (D-37) including the interim support path, the support runbook, and the privacy-notice and store-disclosure requirements the one-phone Gold design adds.

## Technical details
- **Sign-in (R3-9):** OIDC **authorization code + PKCE with a loopback redirect** (RFC 8252); no device-code flow; FIDO2 enforced by the IdP for support roles (T-136). Tokens held in memory or the OS credential store, never in a plain file, never printed.
- **Commands:** catalog draft/import/publish, flags get/set, prices override, contributions review/promote/reject, support lookup, bank-requests list, and the interim support path: `support move --purchase <uuid> --to <installId> --reason <code> --ticket <ref> [--attach] [--corrects <auditId>]`, `support detach --purchase <uuid> --ticket <ref> --corrects <auditId>`, `support unfreeze --purchase <uuid> --ticket <ref>`.
- **Order ID (D-57):** all three support commands read the order ID from a **no-echo prompt**; there is no flag or environment variable for it; it is never written to shell history, a config file, a log or an error message.
- **Support runbook** (`docs/ops/support-runbook.md`): ownership-proof standard (store order ID; ask for the latest receipt); claimant choice with the **buying-install preference** (`isBuyingInstall`, R4-7(3)); correction path (move back, detach); the dispute freeze and the unfreeze route to a support lead; one action per alert: `>2 support moves / purchase / 90 d` (a lead other than the agent reviews within 2 business days), `>20 actions / operator / day` (suspend role), `>5 ownership failures / operator / day`, `dispute_frozen` (lead takes the ticket), `support_unfreeze` (a **second** lead checks within 2 business days), `seat_rebind` (check events for a relay pattern), `MOVE_COOLDOWN` spike, attestation-failure spike, Play Integrity quota > 50 %; the IdP FIDO2 conditional-access policy recorded as the control (R4-6); quarterly review of `support_agent` and `support_lead` assignments (named staff only).
- **Helpdesk (OQ-16):** record whether the helpdesk vendor is a PDPL processor (processing agreement) and set ticket retention so order IDs aren't kept longer than the ticket needs.
- **Privacy notice and store disclosures (security-model §2a)** (`docs/ops/privacy-disclosures.md`, input to the copy deck T-028 and the store forms T-176/T-177): (1) D-62 same-iPhone seat keys and in-transit linkability; (2) R4-8 iOS "Delete everything" keeps the seat keys on the phone and a keyed hash on the server; (3) R4-2 time nonce; (4) R4-7(2)/R5-7 support-link notice repeated until delivered; plus the helpdesk link of support code and order ID to contact details.
