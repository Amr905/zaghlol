## Description
Renewals, cancels and refunds update Gold within minutes.

## Technical details
- **Order of checks:** the authentication handler verifies the Pub/Sub OIDC JWT **before the body is read** (JWKS signature, `iss` = `https://accounts.google.com` or `accounts.google.com`, `aud` = pinned push audience, `email` = push service account, `email_verified = true`, `exp`); failure → `401` without buffering the body.
- **Open envelope (FU-007):** `{message: {data, messageId, publishTime, attributes?, orderingKey?}, subscription, deliveryAttempt?}`; unknown fields ignored, never stored or logged. DTOs list exactly the fields read: no `[JsonExtensionData]`, no `JsonElement`/`JsonNode` catch-all, no dictionary "rest" properties. The operation carries `x-third-party-body: true`.
- Store only the extracted `store_notifications` columns plus `payload_digest`; dedupe on `messageId`; return `204` immediately; the worker re-reads the authoritative state from the Play API (v2 calls of T-130); retries (10) then dead-letter with alert; daily `voidedpurchases.list` reconciliation.
- State changes write `purchase_events` (`rtdn:<type>`); the next token reflects the new state (T-132). An RTDN never moves a seat.

## Design note
*solution-architect (Opus), 2026-11-11. Inputs: T-130 design note §1–3 and as-built code (`PlayVerification`, `PlayStateMapping`, `PlayDeveloperApiClient`, `StoreCallBudget`, `PurchaseWriter`, `GrantMatrix`); T-134 design note and as-built code (`AppleNotificationIngest`/`Processor`/`ReconciliationJobs`, `AppleCallBudget` + `AppleBudgetHandler`, `OidcKeyCache`); FU-098 (code 2, 3, 4, nits 5–7, I-2), FU-092 item 9, FU-077 M-2/L-3; backend-api §1, §4.5; backend-schema `purchases`, `store_notifications`; error-handling §2. Google facts checked 2026-11-11: Pub/Sub "Authentication for push subscriptions" (RS256 token with `iss`, `aud`, `email`, `email_verified`, `exp`, `iat`; tokens "may be up to an hour old"; check signature, `aud`, `email`, `email_verified`), Pub/Sub "Push subscriptions" (ack = 102/200/201/202/204, anything else is redelivered; nacks back off **the whole subscription**, 100 ms–60 s), "Subscription properties" (retention default 7 d, max 31 d; dead-letter attempts 5–100), Play "RTDN reference" (`DeveloperNotification` fields and type numbers below; "call the Google Play Developer API after receiving" an RTDN; dedupe on `messageId`), Play "Voided Purchases API" + `voidedpurchases.list` (`startTime` ≥ now − 30 d, `endTime` ≤ now, `type=1` adds subscriptions and requires keying by `orderId`, `maxResults` ≤ 1000, `tokenPagination.nextPageToken`; quota 6 000/day and 30 per 30 s per package). Not verifiable from Google's pages: the v2 state after a revoke (RevenueCat's RTDN table says `EXPIRED`; the design does not depend on it, §3).*

**0. Model.** Same as T-134 §0: an RTDN is an **authenticated trigger, never the source of state**. The endpoint authenticates, extracts columns, stores, answers 204; a worker re-reads the purchase from the Play Developer API (`subscriptionsv2.get` / `productsv2.getproductpurchasev2`, the T-130 calls and state table) and writes under the monotonic `last_verified_at < @read_at` guard. Duplicates, out-of-order and late messages converge on Play's current answer. The single place the payload matters is the **label** of a non-entitling state (§3 step 6), never whether Gold is granted. **Not T-133:** seats (T-184; worker has SELECT only on `purchase_seats`), tokens (T-132), acknowledge (T-130 sweeper), `ReviewRefund` answers (PO question 4).

**1. Endpoint `POST /v1/notifications/google`** (API, `app_rw`). Each step only if the previous passed; nothing is written before step 7.
1. **Rate limit** `notifications-google`: 1 200/min per /24, instead of the general per-network bucket (as Apple).
2. **Authentication handler `PubSubPush`** (runs before the endpoint; never touches `Request.Body`): exactly one `Authorization: Bearer <jwt>`, ≤ 4 096 chars, 3 segments; header `alg = RS256` only (`jku`/`x5u`/`jwk`/`x5c` ignored, never fetched); `kid` resolved through a **Google key cache** = `OidcKeyCache` generalised by issuer (discovery `https://accounts.google.com/.well-known/openid-configuration`, discovered `issuer` must equal it, 24 h refresh, unknown `kid` forces ≤ 1 refresh / 5 min, last good keys ≤ 7 days); signature via `Microsoft.IdentityModel.JsonWebTokens` (already a dependency, 8.23.0; no new package); `iss ∈ {https://accounts.google.com, accounts.google.com}`; `aud` a **single string** equal (ordinal) to `Purchases:Google:Rtdn:Audience`; `email` equal (ordinal, case-sensitive) to `Rtdn:PushServiceAccount`; `email_verified` the JSON boolean `true`; `exp > now − 60 s`; `iat ≤ now + 5 min`. Any failure → **401** generic problem (no detail). Keys unavailable (no last good set) → **503**, so Pub/Sub retries (fail closed, recoverable). Missing `Rtdn:*` config: Production refuses to start; Development/Testing answer 401.
3. **After authentication, every non-infrastructure outcome is 204.** A nack backs off the whole subscription for every later message, so an authenticated message we can't use is acknowledged, not stored, and alerted (`outcome=ignored_*`). Only a database failure answers 503. (Deliberate difference from Apple's 400.) The contract's 400/413/415 stay declared for the spec rule but are not returned once authenticated.
4. **Envelope** (body ≤ 256 KB, `application/json`, its own source-generated context: `UnmappedMemberHandling.Skip`, `AllowDuplicateProperties = false`, case-sensitive): DTO fields read are exactly `message.data`, `message.messageId`, `message.publishTime`, `subscription`. Not read: `attributes`, `orderingKey`, `deliveryAttempt`, `message_id`, `publish_time`. Checks: `messageId ~ ^[A-Za-z0-9_-]{1,100}$` (no `:`, so it can't collide with the job keys of §4), `publishTime` RFC 3339 within `[now − 32 d, now + 5 min]` (32 d > Pub/Sub's 31-day max retention and < the 90-day `store_notifications` retention, so every redelivery hits the dedupe key; share one retention constant with `RetentionStore`, FU-098 nit 5), `subscription` equal to `Rtdn:Subscription` when configured. Else `ignored_malformed` / `ignored_stale` / `ignored_subscription`.
5. **Payload:** `data` base64 (≤ 16 KB decoded) → `DeveloperNotification` (own context, same options; `eventTimeMillis` accepts string or number): fields read `packageName`, `eventTimeMillis`, `subscriptionNotification.{notificationType, purchaseToken}`, `oneTimeProductNotification.{notificationType, purchaseToken, sku}`, `voidedPurchaseNotification.purchaseToken`, and presence only of `testNotification` / `pendingRefundReviewNotification` (member-less DTO types). `packageName` ≠ configured → `ignored_package` (paged: config error). Not exactly one kind present → `ignored_malformed`. `purchaseToken` must match `PlayStateMapping.TokenPattern` → else `ignored_malformed`. `version` is not checked (the re-read model doesn't depend on payload semantics).
6. **Type** (fixed vocabulary, `^[A-Z0-9_]{1,64}$`): subscription 1–13, 20 by RTDN name; one-time `ONE_TIME_PRODUCT_PURCHASED` / `_CANCELED`; `VOIDED_PURCHASE`; `TEST`; `PENDING_REFUND_REVIEW`; an unknown subscription / one-time number → `SUBSCRIPTION_OTHER` / `ONE_TIME_PRODUCT_OTHER` (re-read: an unknown event may change state).
7. **Store:** `INSERT … ON CONFLICT (store, external_id) DO NOTHING`: `id` v7, `store='google_play'`, `external_id = messageId`, `type`, `subtype NULL`, `product_id` = `sku` only if in `Purchases:Google:Products` (else NULL; never a drop reason, unlike Apple L-3), `store_key` = token (NULL for TEST/review), `environment NULL` (known only from Play's read), `event_time = eventTimeMillis`, **`payload_digest` = SHA-256 of the decoded `data` bytes** (stable across redeliveries; the body differs by `deliveryAttempt`). Types outside the reconcile set (§3) are inserted `processed_at = now()`. Answer 204 (`stored` / `duplicate`). No Play call in the request path.

**3. Processor (`PlayNotificationProcessor`, Workers, `worker_rw`)**: advisory lock `play-rtdn-processor`, batch 50, 5 s idle poll, pick as T-134 (`ix_store_notifications_due`, `store='google_play'`).
- **Reconcile set:** subscription 1 RECOVERED, 2 RENEWED, 3 CANCELED, 4 PURCHASED, 5 ON_HOLD, 6 IN_GRACE_PERIOD, 7 RESTARTED, 9 DEFERRED, 10 PAUSED, 12 REVOKED, 13 EXPIRED, 20 PENDING_PURCHASE_CANCELED, `SUBSCRIPTION_OTHER`; `ONE_TIME_PRODUCT_PURCHASED`, `_CANCELED`, `_OTHER`; `VOIDED_PURCHASE`; `EXPIRY_SWEEP` (§4). Recorded and ignored: 8, 11, 17, 18, 19, 22, `TEST`, `PENDING_REFUND_REVIEW`.
- **Per row:**
  0. **Refuse what ingest never produces** (FU-098 I-2): type outside the reconcile set, `store_key` not matching `TokenPattern`, non-NULL `environment`/`subtype`, an `external_id` form that doesn't fit its type (`voided:` ⇔ `VOIDED_PURCHASE`, `sweep:` ⇔ `EXPIRY_SWEEP`, plain ⇔ an RTDN type) → processed `REFUSED`, alerted, no Play call.
  1. Purchase by `(google_play, store_key)`. None → `NO_PURCHASE`, no call. **The worker never inserts a purchase** (verify alone knows the buying install). This settles **FU-092 item 9**: a successor token's `SUBSCRIPTION_PURCHASED` that beats verify leaves no row, so verify still inserts and `IsNewPayment = Inserted && Predecessor != null` holds.
  2. Kind from the **stored** `product_id` through the catalog (not from the payload). Unknown product → counted `UNMAPPED`.
  3. `readAt = now`, then the read on lane `Notification` through **`PlayPurchaseReader`**, extracted unchanged from `PlayVerification.ReadSubscriptionAsync`/`ReadProductAsync` with a `lane` parameter (verify calls it; its tests stay green). The returned product must contain the stored `product_id` → else `CONTRADICTION`. `testPurchase` ≠ stored `environment` → `ENV_MISMATCH` (alerted, no write).
  4. Play answers: 410 → processed `TOKEN_GONE`, no write (alerted when the stored state still entitles); 400/404 → counted `NOT_FOUND`; 401/403 → counted `STORE_AUTH` (existing page); 5xx/timeout → counted `STORE_ERROR`; 429 / budget / open circuit → uncounted deferral, run stops (T-134 §3). Unknown state → `UNMAPPED`. `PENDING_PURCHASE_CANCELED` → write `expired` only if the stored state is `pending`, else processed with no write.
  5. **Refund floor**, by time not by attempts (FU-098 nit 6): for `VOIDED_PURCHASE` and `SUBSCRIPTION_REVOKED`, a mapped entitling state (`active`, `in_grace`, `canceled_active`) while `now − received_at < 40 min` → counted `REFUND_NOT_REFLECTED`; after that Play's answer is applied and `zaghlol.rtdn.refund_not_reflected` warns (refund without revoke, PO question 3).
  6. **Settle the label** (pure `PlayStateMapping.Settle(stored, mapped, type)`, called after the row lock): an entitling or non-`expired` read is written as read. A read of `expired` becomes `refunded` for `VOIDED_PURCHASE` and `revoked` for `SUBSCRIPTION_REVOKED`; otherwise a stored `refunded`/`revoked` is kept (Play never says "refunded" for a subscription, so a later plain `expired` read must not erase it). Product `CANCELLED` keeps its T-130 mapping (`refunded`). Gold depends only on Play's read: the label chooses between two non-entitling states. **`PurchaseWriter`'s Google path calls the same `Settle(stored, mapped, null)` under its existing `FOR UPDATE`**, so verify and restore can't flip `refunded` back to `expired` [code change in T-133].
  7. One short transaction (`IPlayNotificationStore.ApplyAsync`): `SELECT … FOR UPDATE`, `Settle`, `UPDATE purchases SET state=@s, expires_at=@e, last_verified_at=@read_at WHERE id=@id AND store='google_play' AND last_verified_at < @read_at`, a `purchase_events` row (`rtdn:<type>`, or `sweep` for `EXPIRY_SWEEP`) when the state changed, and the processed mark. Guard lost → processed, `superseded`.
- **Robustness (FU-098 code 2):** any non-cancellation exception on one row → counted `INTERNAL` (constant code) through `FailAsync`, then the next row; only a failing `FailAsync` aborts the run. The backlog gauge is refreshed in `finally` (its own failure swallowed and counted). A per-store **heartbeat** (`zaghlol.notification.processor_heartbeat_age{store}`, in memory, set when a run completes, including "lock held elsewhere") is alerted on `min` over replicas > 10 min, which also catches a processor that never runs (FU-077 L-3).
- **Expected outcomes (test table):** RENEWED/RECOVERED/RESTARTED/PURCHASED/DEFERRED → `active`, expiry advanced; CANCELED → `canceled_active` (or `expired` after expiry); IN_GRACE_PERIOD → `in_grace`; ON_HOLD → `on_hold`; PAUSED → `paused`; EXPIRED → `expired`; REVOKED (read EXPIRED) → `revoked`; VOIDED subscription (read EXPIRED) → `refunded`; VOIDED / ONE_TIME_CANCELED lifetime (read CANCELLED) → `refunded` (AC 1); ONE_TIME_PURCHASED for a known row → `active`.

**4. Reconciliation (Workers; both jobs only enqueue rows, so the processor's retries, dead letter and refusal apply to them too).**
- **Voided, daily** (lock `play-voided-reconcile`): `voidedpurchases.list` with `startTime = now − 30 d + 1 h`, `endTime = now`, `type = 1`, `maxResults = 1000`, following `tokenPagination.nextPageToken`, ≤ 10 pages (more → `truncated`, warn). DTO fields read: `voidedPurchases[].{purchaseToken, orderId, voidedTimeMillis}`, `tokenPagination.nextPageToken`. For an entry whose token is a known Google purchase: insert `VOIDED_PURCHASE` with `external_id = 'voided:' || hex(SHA-256(orderId ‖ 0x00 ‖ purchaseToken ‖ 0x00 ‖ voidedTimeMillis))` (one row per voided order, `type=1` caveat), `payload_digest` = the same hash, `event_time` = voided time, `ON CONFLICT DO NOTHING` (the 30-day window is inside the 90-day retention, so a void is enqueued once). Unknown tokens are counted, never stored. `zaghlol.rtdn.recovered` counts inserted rows whose token has no RTDN `VOIDED_PURCHASE` row (warn: delivery is failing). Play failure → `failed`, next day repeats the full window.
- **Expiry sweep, hourly** (lock `play-expiry-sweep`): Google subscriptions in `active|in_grace|canceled_active` with `expires_at` in `[now − 7 d, now − 10 min]` and `last_verified_at < expires_at`, ≤ 200, enqueue `EXPIRY_SWEEP` with `external_id = 'sweep:' || purchase_id || ':' || epoch(expires_at)`. A purchase whose sweep row already exists for that expiry (pending, done or dead-lettered) is skipped, so stuck rows never block the rest (**FU-098 code 3**), and a renewal (new `expires_at`) gets a new key. Needed because `v_entitlements` checks only `state`: a lost `SUBSCRIPTION_EXPIRED` would otherwise keep Gold.

**5. Retries and dead letter.** T-134 §3 unchanged: `next_attempt_at = now + min(1 min · 3^(n−1), 8 h)` ± 10 %, dead letter at 10 (≈ 30 h), uncounted deferrals stop the run. Extract the schedule into a shared `StoreNotificationSchedule` (Apple's class delegates). Google counted codes: `STORE_ERROR | STORE_AUTH | NOT_FOUND | UNMAPPED | REFUND_NOT_REFLECTED | CONTRADICTION | INTERNAL`; informational: `NO_PURCHASE`, `ENV_MISMATCH`, `REFUSED`, `TOKEN_GONE`. Play client: like Apple FU-092 item 3, a 429/503 with `Retry-After` > 5 s is not retried inside the pipeline (the worker defers for it); the `Retry-After` date form uses the injected `TimeProvider` (FU-098 nit 7). Pub/Sub side: retention 7 days, retry policy 10–600 s, **no Pub/Sub dead-letter topic** (a message there is lost to us; our sweeps fill gaps instead), PO question 2.

**6. Budget** (FU-077 M-2, FU-098 code 4) [doc change]
- **Per attempt:** a `PlayBudgetHandler` inside the resilience pipeline (as `AppleBudgetHandler`) draws one permit per HTTP attempt; a denial throws `PlayApiException(BudgetDenied)`, which the retry predicate doesn't handle. The pre-call `TryAcquire` in `PlayDeveloperApiClient` goes.
- **Partition** as Apple: `Purchases:Google:Budget:WorkerShare` (default 0.2) of the configured total; the worker partition serves `Ack` + `Notification`, the API partition `Verify` + `Ack` + `Support` + `Restore` (it refuses `Notification`, the worker refuses the rest; mixing partitions throws). API share ÷ `Budget:Replicas` (API replicas). Worker share ÷ `Budget:WorkerReplicas` (default 1), because each lock holder can sit on a different replica. **Ack reserve:** in the worker partition, `Notification` is refused while ≤ 25 % of the bucket remains, so a notification flood can't miss the 3-day acknowledge deadline. All checks and acquisitions under one lock (FU-092 item 2 lesson).
- **Cost:** 1 read per reconcile-set row with a known purchase; 0 for refused/no-purchase rows and for forged traffic (no call in the request path); voided job ≤ 10 calls/day (separate 6 000/day voided quota); sweep ≤ 200 reads/hour worst case.

**8. Threats.** Forged push: OIDC checks before the body. Stolen bearer token (valid ≤ 1 h, not bound to the body): can only enqueue re-reads of tokens we already store, or label a purchase Play already reads as `expired`; it can't grant, extend or move a seat. Topic spoofing: only `google-play-developer-notifications@system.gserviceaccount.com` may publish (deployment). Worker-login row injection: §3 step 0 + CHECK. Poison message: 204 + alert, never a subscription-wide backoff. DoS: rate limit, token size cap before decode, throttled JWKS refresh, no Play call in the request path.
