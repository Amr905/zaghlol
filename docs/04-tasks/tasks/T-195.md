## Description
Some salaries never arrive as an SMS (cash, a bank without SMS, a notification the user didn't enable). The user must be able to record the salary as income; when the bank SMS for the salary **does** arrive, that one is shown and counted, never both.

## Technical details
- **Expected salary:** in payday settings (and from onboarding), the user can add "My salary": amount, currency, payday, account (default the payday account or Cash). On each payday a pending **expected income** appears ("المرتب — متوقع").
- **Confirm or match:** if an incoming SMS / notification credit in the same currency lands within the window (payday −3 … +5 days, amount within ±15 %, or the sender/description says salary/مرتب/راتب), it **replaces** the expected item: the captured transaction is tagged Salary and the expected one is closed. If nothing arrives by the end of the window, the user gets one nudge: "المرتب نزل؟" → *Yes, add it* (records it as a manual income on the chosen account) / *Not yet* / *Skip this month*.
- **Manual income any time:** the add flow offers Income → Salary for one-off entries; the same matching rule prevents a later SMS from double counting (the later SMS merges into the manual one, keeping the SMS details, with an undo).
- Expected income is not counted in totals until confirmed or matched.

## Acceptance criteria
1. A salary with no SMS can be recorded and counts as income in Home, budgets and charts.
2. When the salary SMS arrives (before or after a manual entry) the result is exactly one income transaction (unit tests for both orders, amount drift, early/late payday, two currencies).
3. Nudge appears once per payday at most and follows notification settings.
4. ar/en goldens for the expected-salary row and the nudge; RTL verified; no hard-coded strings.
