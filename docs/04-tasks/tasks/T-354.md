## Description
Query groups `(merchantNorm, aiCategory, userCategory, votes, firstSeen, lastSeen, status)` open first by votes; resolve with `promote` (upsert merchant + alias into the **draft** catalog through existing catalog ops), `reject`, `prompt_issue` (the case is exported as a candidate eval item: `zaghlol-ops llmcat corrections export-prompt-issues` prints synthetic-ready YAML). Confirmed list = ≥ `cat.confirm_n` distinct installs agreeing and no open correction; promote/reject. Role `catalog_editor`; every action audited.

## Acceptance criteria
1. Responses contain groups only: no per-install rows, no hashes (schema test).
2. Promoting a `custom` correction → 400; promote writes to the draft catalog only (published catalog unchanged until the normal publish).
3. Confirmed query returns a merchant at 3 distinct confirmations and hides it while an open correction exists.
4. Each resolve writes one audit row; non-`catalog_editor` → 403.
5. CLI commands mirror the endpoints; `--help` text written.
