## Description
`confirm(merchant)` → user merchant rule through the existing rule service (removes the AI chip on all its rows) + suggestion state `confirmed` + outbox `llmCatConfirmation`. `correct(merchant, chosenCategory)` → rule + state `corrected` + outbox `llmCatCorrection` with `userCategory` = system code or `custom`. Picker cancelled → nothing changes. `undo()` within 5 s removes the rule, restores the previous state and deletes the outbox row. The sync request includes up to 50 feedback items from the outbox while the flag is on and consent is present; accepted items are removed.

## Acceptance criteria
1. Right on Zawya → rule saved, chip gone on all 3 rows, one confirmation outbox row; sync body carries it once, then it is removed.
2. Wrong groceries → Education → rule + correction row; a custom «كتب» → `custom`, and «كتب» appears nowhere in the sync body (test).
3. Undo within 5 s → no rule, no outbox row, rows back to `ai`/unconfirmed; after 5 s Undo is gone.
4. Flag off or consent cleared → feedback stays local, not sent; more than 50 items → sent across calls.
5. Body items contain only the five closed fields.
