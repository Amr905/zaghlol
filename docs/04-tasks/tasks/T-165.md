## Description
Only Zaghlol's own encrypted backup moves data between phones.

## Technical details
allowBackup=false, dataExtractionRules exclude all (cloud + device transfer); iOS isExcludedFromBackup on DB/spool/temp dirs; verification script.

## Design note

### Design note (solution-architect, 2026-11-05)

**Goal (FR-SEC-05).** No OS mechanism copies Zaghlol's sandbox off the phone. This covers Android Auto Backup, adb backup, device-to-device (D2D) and OEM transfer, iCloud/Finder backups and iPhone migration. A second layer covers any copy that still gets through: it is unreadable, because the keys never travel (`ThisDeviceOnly` / Keystore), and the app treats it as orphaned data (see "Cross-task requirement" below).

#### Android (`app/android/app/src/main/`)
Manifest `<application>` attributes, all in the **main** manifest so every flavor and build type inherits them:
```xml
android:allowBackup="false"
android:fullBackupContent="@xml/backup_rules"
android:dataExtractionRules="@xml/data_extraction_rules"
android:hasFragileUserData="false"
```
- **API 26–30:** `allowBackup="false"` disables Auto Backup, key/value backup and `adb backup`. `fullBackupContent` is ignored while backup is off. It is still set to exclude everything, as defense in depth if a merged library manifest ever flips `allowBackup`.
- **API 31+** (targetSdk 36): `allowBackup="false"` disables cloud backup but **does not disable D2D transfer**. The old `fullBackupContent` rules no longer apply to D2D either. Only `<device-transfer>` in `dataExtractionRules` controls it, so both sections exclude every domain.
- **`hasFragileUserData="false"`** (explicit; it is also the default). If it were `true`, Android 10+ would offer "keep app data" on uninstall. That leaves a DB whose Keystore key was deleted with the app, which is exactly the half-readable state FR-SEC-05 forbids.
- **Manifest merger:** if a plugin declares `allowBackup`, the merger fails. In that case add `xmlns:tools` and `tools:replace="android:allowBackup"`. Do not add it pre-emptively. The CI assertion on the **final APK** is the guarantee.

`res/xml/data_extraction_rules.xml`. The `<device-transfer>` section has the same 9 excludes:
```xml
<data-extraction-rules>
  <cloud-backup disableIfNoEncryptionCapabilities="true">
    <exclude domain="root" path="."/>          <exclude domain="file" path="."/>
    <exclude domain="database" path="."/>      <exclude domain="sharedpref" path="."/>
    <exclude domain="external" path="."/>      <exclude domain="device_root" path="."/>
    <exclude domain="device_file" path="."/>   <exclude domain="device_database" path="."/>
    <exclude domain="device_sharedpref" path="."/>
  </cloud-backup>
  <device-transfer> <!-- same 9 excludes --> </device-transfer>
</data-extraction-rules>
```
`res/xml/backup_rules.xml` is `<full-backup-content>` with the same 9 `<exclude … path="."/>` lines. `noBackupFilesDir` (spool, T-039), `cacheDir` and `codeCacheDir` are never backed up by the OS, so they need no rule.

#### iOS (native only, no Pigeon; T-004 is not needed)
- **Helper.** `app/ios/Shared/BackupExclusion.swift` is compiled into Runner now, and later into the Share Extension and the widget (T-062/T-063 add it to their targets).
  - `ZaghlolDirectories.ensureExcluded(_ url: URL) throws` creates the directory with intermediate directories, sets `URLResourceValues.isExcludedFromBackup = true`, reads the value back, and throws if it is not `true`. It is idempotent.
  - `ZaghlolDirectories.applyAll()` runs it on the directory set below.
- **Directories.** The exclusion goes on **directories**, not files. SQLite `-wal`/`-shm` files, restore swaps (rename) and atomic writes then stay covered, even though a "safe save" resets the attribute on the file itself.

  | Directory | Why |
  |---|---|
  | `Library/Application Support/` (app container root) | Drift DB `zaghlol.db` (+ WAL/SHM, restore temp) via `path_provider.getApplicationSupportDirectory`. Excluding the root also covers anything Dart or plugins create below it, so Dart never needs a channel. |
  | `Documents/` | Not used by Zaghlol. Excluded defensively in case a plugin writes there. |
  | `Library/Caches/` and `tmp/` (`NSTemporaryDirectory()`) | Encrypted staging (exports, images, OCR inputs; Dart `getTemporaryDirectory` maps to Caches). iOS already skips both in backups. Marked anyway (no cost) so the XCTest asserts one uniform rule. |
  | App Group container: `spool/`, `Library/Application Support/`, `Library/Caches/` | Spool, guard config, widget snapshot (platform-channels §1.3, §3). |

  **The App Group entitlement does not exist yet.** `containerURL(forSecurityApplicationGroupIdentifier:)` returns nil today, so `applyAll()` skips the App Group directories when the URL is nil. T-062 must pass its group ID and turn on the App Group test.
- **When.**
  1. First statement of `AppDelegate.application(_:didFinishLaunchingWithOptions:)`, **before** `super`, so it runs before the Flutter engine and plugins start. It is synchronous and costs a few syscalls. It also runs when an App Intent cold-launches the app in the background.
  2. Again on every launch (it is idempotent, and re-asserting is cheap).
  3. Every native directory creation goes through `ensureExcluded`, for example the spool in T-062 and the Share Extension's first write.
  4. After "Delete everything" (FR-ONB-08) recreates the directories. That flow calls `applyAll()` natively, through the same entry point used at the restart into first-launch state.
- On failure: no crash. Native code records diagnostic code `BACKUP_EXCLUSION_FAILED`, with no path contents, through the native diag hook once T-021 exists. Until then it uses `os_log` with `privacy: .public` for the code only.
- **Out of scope, but a policy for later tasks:** no app data in `UserDefaults` or App Group `UserDefaults`, because `Library/Preferences` is backed up and cannot be reliably excluded. Settings live in the encrypted DB. `flutter_secure_storage` uses the Keychain only.

#### Cross-task requirement (for T-015/T-016)
Startup must detect **orphaned data**, meaning a DB file is present but there is no `K_db` (Android: an OEM transfer or a kept-data uninstall; iOS: an iCloud restore that leaked something despite the exclusion). In that case the app deletes the DB, spool and temp files, then starts in first-launch state with "I already use Zaghlol" (restore). It never prompts, crashes or partially opens. On iOS, Keychain items can survive an uninstall, so the reverse case (key present, DB absent) means "create a new DB and rotate the key". `security-model.md` §7 has been updated to match.

#### CI verification (no device)
- **Android** (extends the `app-smoke.yml` aapt2 step, for every variant built, including the release APKs):
  - `aapt2 dump xmltree --file AndroidManifest.xml $APK` must contain:
    - `android:allowBackup(0x01010280)=false`
    - `android:hasFragileUserData(…)=false`
    - `android:fullBackupContent` → `@xml/backup_rules`
    - `android:dataExtractionRules` → `@xml/data_extraction_rules`
  - `aapt2 dump xmltree --file res/xml/data_extraction_rules.xml $APK` must contain both `cloud-backup` and `device-transfer`, each with exactly the 9 domains, each with `path="."`, and **no `include` element**.
  - The same check runs on `res/xml/backup_rules.xml`.
  - **Negative control:** a tiny shell function test feeds a fixture xmltree with `allowBackup=true` and expects failure.
- **XML source lint:** `./gradlew :app:lintDevNoSmsDebug` with `AllowBackup`, `DataExtractionRules` and `FullBackupContent` raised to errors in `lint.xml`. These checks validate domains and paths.
- **iOS:** a new macOS job runs `xcodebuild test -workspace app/ios/Runner.xcworkspace -scheme dev -configuration Debug-dev -destination 'platform=iOS Simulator,name=<latest iPhone>'`, after `flutter build ios --simulator --debug --flavor dev` generates the config. `RunnerTests` is hosted by Runner (`TEST_HOST`), so `AppDelegate` has already run. Tests:
  1. Each directory in the set exists and `resourceValues(forKeys:[.isExcludedFromBackupKey]).isExcludedFromBackup == true`.
  2. `ensureExcluded` on a fresh temp subdirectory returns true, survives delete-and-recreate, and is idempotent.
  3. A file created **inside** an excluded directory after the fact is still under that directory. The test does not assert a per-file flag, because exclusion is inherited from the directory and the device check below verifies it.
  4. App Group test: `XCTSkip` while there is no entitlement.

#### Manual on-device script (release candidate; `docs/05-reviews/T-165-device.md` records the results)
Use a debuggable dev build where `run-as` is needed and a Play internal-track release for the UI checks. Seed data first (import fixtures, set a backup passphrase).
1. **Android Auto Backup (API 30 and 35/36):**
   ```
   adb shell bmgr enable true
   adb shell bmgr transport com.android.localtransport/.LocalTransport
   adb shell settings put secure backup_local_transport_parameters 'is_encrypted=true'
   adb shell bmgr backupnow app.zaghlol.dev
   ```
   Expect "Backup is not allowed", or a success with no app payload. Then reinstall from the pulled APK (`pm path`, `pm uninstall --user 0`, `install-multiple`). The app must open at Welcome.
2. **adb backup (API 26–30 emulator):** `adb backup -noapk -f z.ab app.zaghlol.dev`, then decompress the archive past the 24-byte header and list it with `tar t`. It must contain no `apps/app.zaghlol.dev/` data entries.
3. **D2D (API 31+):**
   ```
   settings put secure backup_enable_d2d_test_mode 1
   bmgr transport com.google.android.gms/.backup.migrate.service.D2dTransport
   bmgr init <same>
   bmgr backupnow app.zaghlol.dev
   ```
   Reinstall as in step 1. Expect Welcome, and `run-as app.zaghlol.dev ls -R` shows only first-launch files. Reset the test mode and transport afterwards.
4. **OEM transfer:** Samsung Smart Switch on the A-series reference device, and Pixel "Copy apps & data" by cable. The target must show Welcome. If any file is copied, the orphan path must reset cleanly. Record the result either way.
5. **iOS:**
   - (a) Make an encrypted Finder backup, then inspect it with an open-source backup reader: `AppDomain-app.zaghlol*` must contain no `zaghlol.db*`, `spool/` or staging files.
   - (b) Settings → Apple Account → iCloud → Manage → Backups → this iPhone: Zaghlol shows a size in KB only.
   - (c) Restore the iCloud backup to a second iPhone, and separately test Quick Start migration. Zaghlol must open at Welcome, and the restore-from-Zaghlol-backup flow must work.

**Rejected alternatives.**
- `allowBackup="false"` alone: it leaks through D2D on API 31+.
- An `include` of a non-existent path in the rules: obscure and lint-hostile.
- Per-file exclusion on iOS: atomic saves reset it.
- A Pigeon or MethodChannel for Dart to mark directories: not needed once the roots are excluded, and it would block on T-004.
- A custom `BackupAgent` returning nothing: more code, and D2D still reads the rules.
