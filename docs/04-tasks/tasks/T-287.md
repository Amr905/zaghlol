## Design / spec pointers
- `docs/03-technical/ask-llm.md` §4.6, §6 "Flags".
- Existing flags pipeline (T-025: OFF after 14 days without sync; signature verification).

## Description
Add `FeatureFlag.askLlm('ask_llm')`, `askLlmInvest('ask_llm_invest')`, `llmCategorise('llm_categorise')`. Read the signed `config` block from sync, verify it like flags, store it in encrypted settings with its version, and send `configVersion` on the next sync. Expose a typed `RemoteConfig` Riverpod provider (quotas, thresholds, invest keys, `cat.*`, `llm.providerName` per language) with bundled defaults when missing or stale (> 14 days). Flags stay fail-closed.

## Acceptance criteria
1. Valid signed block → stored and exposed; bad signature → ignored, previous values kept.
2. Missing or > 14 days stale → bundled defaults; the three flags read OFF.
3. `configVersion` sent on the next sync; unchanged version → no block expected.
4. Unit tests for each key's typed parsing and range fallback to default on bad values.
5. Stored config cleared by "Delete everything".
