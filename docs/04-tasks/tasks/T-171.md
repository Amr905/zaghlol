## Description
Proof that the privacy promises hold for every release.

## Technical details
Scripted session; scan sandbox for plaintext amounts/digits/merchants/message text; recording client asserts every request ⊆ BR-SYNC-03 schema; ignored-card SMS leaves no trace; OS backup exclusion check.

### Findings (product code not changed)

- **T-171-F1 (major, functional; owners T-144/T-147): sign-out never reaches the server.** `EntitlementService.signOut()` deletes `accountToken` from the store and only then runs `_backend.signOut` → `BackendClient.signOut()`, whose operation is `auth: installAndAccount`; with no account token `_call` throws `BackendFailure(notSignedIn)` before sending. `AccountService.signOut()` then returns `SignedOut(serverConfirmed: false)` every time. The unit tests use fake backends, so they don't see it. Effect: D-61(c) server-side bookkeeping for sign-out never happens. Pinned by the skipped test "sign-out reaches the server (D-61(c), backend-api §4.6)" in `data_boundary_flows_test.dart`; unskip after the fix (e.g. read the account token for the call before deleting it, or let `signOut` take the token explicitly).
- **T-171-F2 (minor, privacy hardening): share-card PNG staged unencrypted.** `StagedShareSheet` writes the rendered PNG (spending figures as pixels) to `getTemporaryDirectory()` in plaintext for the OS share sheet and deletes it afterwards (tested). It is user-initiated export, the tmp/cache dirs are excluded from OS backups, but CLAUDE.md §2.2 says temp files are encrypted; a crash between write and delete leaves it until the next temp sweep. Suggest: name it in the reviewed exceptions of security-model §2/§4, or sweep `share_*.png` at startup.
- **T-171-F3 (info): the privacy screen list is not generated from the allow-list.** security-model §2 item 5 says the screen copy is "generated from the same allow-list"; `ServerKnows` is a hand-written enum. The new tests tie every wire class to a `ServerKnows` entry shown on that platform, which closes the gap for drift in one direction; doc wording should say "checked against" instead of "generated from".
- **T-171-F4 (info): proxy capture can't use a user CA.** `BackendClient` runs on `dart:io` `HttpClient`, which ignores `network_security_config` and user CAs (comment in the NSC file), so a mitmproxy capture of a release candidate is not possible without code changes. Procedure B uses a recording backend on the host instead.
- Residuals for T-175: Gradle's fully resolved transitive graph and the built IPA's frameworks are not visible to the host scan (procedure D).

### Manual procedure on the release candidate (device-only parts)

Run on one Android phone (API 34+) and one iPhone (iOS 17+), with the RC commit. Record each step PASS/FAIL with the date and build in `docs/05-reviews/T-171-device.md`. Synthetic data only: use the SMS fixture texts from `app/test/fixtures/sms/` and the canaries in `plaintext_scan_test.dart` (`7391.42`, `Zglcanary Mart`, card `8642`, `ZGLSMSCANARY`, `ZGLNOTECANARY`).

**A. Sandbox scan (checks 1, 3; D-55).** Android: build the RC commit as a debuggable build of the shipping flavour (`flutter build apk --debug --flavor prodSms`) so `run-as app.zaghlol` works; the release APK itself is not debuggable. iOS: install the RC commit from Xcode and use *Devices and Simulators → Download Container*.
1. Fresh install, onboarding, grant SMS/notification capture. Take a synthetic purchase fixture of a supported bank from `app/test/fixtures/sms/` and edit it to carry amount `7391.42`, merchant `Zglcanary Mart`, card `8642`; also send one unparseable message containing `ZGLSMSCANARY` from the same sender. Inject them (Android emulator: `adb emu sms send <sender> "<text>"`; device: from a second phone; iOS: Shortcuts "Log bank message"). Add a note `ZGLNOTECANARY` to the transaction. Add an ignore rule for that bank's card `9753`, then inject the same fixture with amount `6283.17`, merchant `Zglignored Shop`, card `9753`. Share a share card once. Run a backup to Drive/iCloud (Gold test account).
2. Force-stop the app. Android: `adb exec-out run-as app.zaghlol tar -cf - . | tar -xf - -C sandbox/`; `adb shell ls /sdcard/Android/data/app.zaghlol` must fail (no external storage). iOS: download the container and the App Group container (`xcrun devicectl device copy from … --domain-type appGroupDataContainer`).
3. `grep -rIal -e 7391.42 -e '٧٣٩١' -e 'Zglcanary' -e 'zglcanary' -e ZGLSMSCANARY -e ZGLNOTECANARY -e 6283.17 -e Zglignored sandbox/` and the same with `grep -rl --binary-files=text` and on a UTF-16LE copy (`iconv -t UTF-16LE`). Also `grep -rl 'SQLite format 3' sandbox/`. **PASS = no hits.** (Card digits are too short for a blind grep; check them only in non-binary files: `grep -rIl 8642`.) iOS: also `defaults read` the app's plist in `Library/Preferences` must hold no app keys (F7).
4. Logcat / Console: `adb logcat -d | grep -e ZGLSMSCANARY -e 7391.42 -e Zglcanary` and the iOS Console stream filtered on the app process during step 1. **PASS = no hits.**
5. "Delete everything" (iOS): then dump the Keychain items of the app's access groups (debug build: Xcode memory/Keychain inspector or a test host `SecItemCopyMatching` all classes). **PASS = only the seat-key service items remain** (D-55/D-62); containers and App Group empty. Android: after "Delete everything", `adb shell run-as app.zaghlol ls -R` shows no files (empty directories only), and on a rooted emulator the app UID's Keystore aliases are gone.

**B. Data-boundary capture (check 2).** Proxy interception of the RC is not possible (F4). Instead: run the backend locally with request-body logging enabled (`backend/` dev profile, or any HTTP server that writes each request to a file), start an emulator/simulator debug build of the RC commit with `--dart-define=ZAGHLOL_API_BASE=http://10.0.2.2:<port>` (iOS simulator: `http://127.0.0.1:<port>`); debug builds allow loopback http and dev response keys. Walk the session of step A.1 plus purchase (Play/StoreKit test account), restore, sign-in, sign-out, contributions opt-in, "request my bank" and "Delete everything". Feed the captured requests through the allow-list: copy them into a JSON list and run `checkRequest` (a scratch test that reads the file). **PASS = no violation, no canary, Android capture has no `seatKeys`.** Note in the report whether `POST /v1/accounts/signout` appeared (F1).

**C. OS backup exclusion (check 4).** Re-run `docs/05-reviews/T-165-device.md` on the RC (Android: `adb shell bmgr backupnow`, Smart Switch / device transfer; iOS: encrypted Finder backup and iCloud backup, restore to a second device). **PASS = every row PASS** (T-165 F3).

**D. Release artefacts (for T-175).** `cd app/android && ./gradlew :app:dependencies --configuration prodSmsReleaseRuntimeClasspath > deps.txt` and grep it for the `nativeDenied` list in `dependency_scan_test.dart`; unzip the RC IPA and list `Payload/Runner.app/Frameworks/` against the same list. **PASS = no hits.**
