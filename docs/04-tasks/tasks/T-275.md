## Scope
1. Reproduce from code in `app/lib/features/voice/**` (speech_to_text, on-device ar-EG): what happens on the FIRST listen of a session — `initialize()` still running when `listen()` is called; the microphone permission dialog or the recogniser's cold start eating the `pauseFor`/`listenFor` window; an early `notListening`/`done` status or `error_no_match`/`error_speech_timeout` from the cold recogniser treated as "heard nothing"; the screen starting to listen in `initState` before the route transition/focus ends; a stale session from a previous screen being stopped.
2. Fix: await initialisation (and the permission result) before the first `listen`; start the "no speech" timer only once the recogniser reports it is listening (or the first sound level arrives); on a first-attempt `no_match`/`speech_timeout` within ~2 s of start with no partial result, restart listening once silently instead of showing "didn't hear anything"; keep the user's stop/cancel immediate.
3. The "didn't hear anything" message appears only after a real listening window with no speech. Never auto-save anything from a retry.
4. Tests with the existing speech fake: first-listen cold start (status sequence listening→notListening quickly, then a normal second run) shows no error and keeps listening; a genuine silence still ends with the message; permission denied still shows the permission state.
5. If the cause is in the Android recogniser availability (on-device ar-EG model missing → falls back / fails fast), surface that state clearly instead of "didn't hear anything" and note what the PO should check on the phone.

## Acceptance criteria
Root cause in the task file; tests above; `flutter analyze` clean; manual device steps listed for the PO.
