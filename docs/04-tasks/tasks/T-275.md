## Scope
1. Reproduce from code in `app/lib/features/voice/**` (speech_to_text, on-device ar-EG): what happens on the FIRST listen of a session — `initialize()` still running when `listen()` is called; the microphone permission dialog or the recogniser's cold start eating the `pauseFor`/`listenFor` window; an early `notListening`/`done` status or `error_no_match`/`error_speech_timeout` from the cold recogniser treated as "heard nothing"; the screen starting to listen in `initState` before the route transition/focus ends; a stale session from a previous screen being stopped.
2. Fix: await initialisation (and the permission result) before the first `listen`; start the "no speech" timer only once the recogniser reports it is listening (or the first sound level arrives); on a first-attempt `no_match`/`speech_timeout` within ~2 s of start with no partial result, restart listening once silently instead of showing "didn't hear anything"; keep the user's stop/cancel immediate.
3. The "didn't hear anything" message appears only after a real listening window with no speech. Never auto-save anything from a retry.
4. Tests with the existing speech fake: first-listen cold start (status sequence listening→notListening quickly, then a normal second run) shows no error and keeps listening; a genuine silence still ends with the message; permission denied still shows the permission state.
5. If the cause is in the Android recogniser availability (on-device ar-EG model missing → falls back / fails fast), surface that state clearly instead of "didn't hear anything" and note what the PO should check on the phone.

## Acceptance criteria
Root cause in the task file; tests above; `flutter analyze` clean; manual device steps listed for the PO.

## Design note (builder)
Root causes found in code (not reproduced on a device):
1. `speech_to_text` is a singleton. Closing the screen calls `cancel()`; Android reports that session's "notListening"/"done" (or `error_no_match`) late, after the next visit already called `start()`. The new sink received it and the recording ended at once with an empty transcript. Fix: `SpeechToTextPort` ignores end events and no-match/timeout/client/busy errors until the recognizer reports "listening" for the current session.
2. Cold recognizer on the first listen after launch (no previous session) can end within a moment with no text. Fix: `VoiceController._quickRetry` restarts listening once, silently, when the first attempt of a visit ends (done or no-match) with no transcript in under 2 s (`voiceQuickEnd`, time source `voiceMonotonicProvider`). Never after the user's Done, never twice, nothing is saved from it. "Try again" is a user action and starts a fresh attempt.
3. (a) `start()` already awaits `initialize()` (which also awaits the permission result) before `listen()`; no change needed. (c) The "didn't hear anything" screen now shows only when the session lasted 2 s or more, or after the one retry.
4. (e) If on-device ar-EG is unavailable the screen already shows the online-consent sheet, and if the online recognizer also fails the "unavailable" explainer (not "didn't hear anything"); unchanged, covered by the existing test "online also fails".

## Builder assumptions
- The 2 s window is measured from when `start()` returns (listening requested), not from the plugin's first sound level.

## Manual device steps (PO, Android)
1. Force-stop the app, open it, tap Add > Say. Expect the mic screen to keep listening (a brief restart is invisible); speak "50 for vegetables"; expect an item.
2. Close the voice screen and open it again at once; speak. Expect it to keep listening.
3. Stay silent for 5 s: expect "I didn't catch an amount".
4. Tap Done at once without speaking: expect the message, no restart.
5. If step 1 still ends at once: Settings > System > Languages > Speech (Google) > offline recognition: check Arabic (Egypt) is installed, and send logcat of the first attempt.
