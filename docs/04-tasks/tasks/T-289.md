## Scope
1. **FU-366**: the "did you exchange currency?" balance-rise question uses 500 major units for every currency. Use a per-currency threshold (e.g. the EGP threshold converted with the last known daily rate, with a sane minor-unit floor per exponent; fall back to today's rule when no rate) and do not raise items from the `inboxScan` catch-up for jumps older than 14 days. Integer math only.
2. **FU-369**: `cycle_repository.dart` `cachedTotals` (cold start) overlays the exchange figures like the live totals, so money in / left don't jump when the live totals arrive.
3. **FU-370**: check that importing a bank statement whose debit line matches a manually recorded exchange leg (`transfer_out`, internal) is detected as a duplicate and never stored as spending. If it isn't, fix it in the statement duplicate matcher (T-269 rules) and add the test.

## Acceptance criteria
- FU-366 tests: JPY/KWD thresholds, no-rate fallback, old inbox-scan jump raises nothing, recent one still asks once.
- FU-369 test: cached and live totals equal for a cycle with an exchange.
- FU-370 test: statement line matching a manual exchange leg → duplicate, no new spending.
- ≤ 3 negative proofs.

## Design note (builder)
- FU-366: `balanceJumpMinMinor(currency, {egpPerUnitE9})` = 500 EGP expressed in the currency (integer BigInt math, rounded up), floor 1 major unit (100 units for exponent 0), plain "500 major" when no rate, for EGP, or on overflow. The store reads the rate (`fx_rates`: direct `X->EGP`, else the inverse of `EGP->X`) into `BalanceJumpFacts.egpPerUnitE9`; display rate used only to size a threshold, nothing converted. Age cap: `_checkBalanceJump` returns when the balance is older than 14 days vs the clock (covers inbox-scan catch-up without threading origin).
- FU-369: `cachedTotals` goes through the same `_withExchanges` overlay as the closed-cycle cached path of `totals`.
- FU-370: the statement matcher keys by cash side and the store lists internal rows, so a `transfer_out` exchange leg already matches; added the regression test only. No production change.

## Builder assumptions
- Age cap uses the transaction's occurred time, not the origin: a delayed spool message older than 14 days is also not asked (stale question anyway).
- Floor: 1 major unit (100 units for JPY/KRW) is a safety bound only; typical rates sit well above it.
- The harness parser reads EGP balances only, so the rate-sized threshold is tested in the domain (JPY/KWD/USD) and the store rate lookup separately, not through an SMS in USD.
