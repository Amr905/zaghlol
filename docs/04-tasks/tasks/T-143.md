## Description
Catalog, flags, prices and entitlement stay fresh without blocking the UI.

## Technical details
- On foreground: server-time 24 h throttle (EC-43); back-off ≤ 1/h after failure; verify; apply catalog ops/flags/prices/entitlement in one DB transaction; full snapshot download path; outbox upload; re-categorize only catalog/none-sourced non-verified rows (FR-SYNC-05); About status line.
- **Sync is an anchoring request (R4-2):** it is sent through T-144's time-anchor service (fresh nonce, single outstanding), and every signed sync body, the throttle answer included, is handed to T-144 before anything else uses its `serverTime`.
- Sends `entitlementIssuedAt` = the `iat` of the cached token (R5-7 delivery proof); passes `entitlement`, `accountToken` and `supportNotice` to T-144, which applies the install-binding rule and persists the notice (never stored here directly).

## Design note
Written by the implementer (Sonnet, sprint 2026-11-13).
- **Folder:** `app/lib/features/catalog_sync/{domain,application,presentation}`. Nothing in `core/backend` changes except the wiring providers.
- **Schedule (pure Dart):** `SyncState` (`secure_state` key `sync_state`) holds the last server time, the device wall time at receipt, `nextSyncNotBefore`, the failure count, the retry-not-before wall time and an optional `pendingFullVersion`. Due = server estimate (`serverTime + elapsed wall`) >= `nextSyncNotBefore`; a wall clock that moved backwards counts as due (the server throttles anyway, EC-43). After a failure the next attempt is not before `max(1 h * 2^(n-1) capped at 8 h, Retry-After)`.
- **Single flight:** an in-process future plus a `secure_state` lease (`sync_lease`, 5 min, compare-and-set) so the UI engine and a background run never sync at once.
- **Request:** built from the stored cursors only; contributions and bank requests are re-parsed from the outbox through the generated DTOs (max 50 / 10, only while opted in). `entitlementIssuedAt` = `iat` of the cached verified token.
- **Anchoring (R4-2):** the call runs inside `EntitlementService.anchored(...)`, which draws the nonce and hands the signed body (throttle answer included) to T-144 before the apply starts.
- **Apply:** network work (full snapshot) happens first; then ONE `db.transaction`: catalog ops + `catalog_meta`, delete sent outbox rows, prices, flags. Any exception rolls back everything and the flags service reloads from the DB. A throttle answer applies nothing and keeps the outbox. If the full download fails, flags/prices/outbox still apply and `pendingFullVersion` makes the next run fetch only the snapshot.
- **After commit:** re-categorize (FR-SYNC-05) through the T-075 `Recategorizer`, which only touches `none/catalog/heuristic`, non-verified rows.
- **Not here:** ingest-path hooks, native background task (no plugin in the lockfile; `SyncOrchestrator.run` is the entry a later task schedules), About status UI strings (data only: `SyncStatus`).
