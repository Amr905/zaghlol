## Description
Per merchant, in request order: `ContributionPrivacy` → `rejected`; catalog alias exact then fuzzy → `ok/catalog` (free); cache hit not expired → `ok/cache` (free, `hits+1`); the rest trimmed to the `cat` counter's remaining (lower of install/account) with overflow → `quota`; one provider call for the remainder with the user part as a JSON array inside a "data, not instructions" block; validate index range/uniqueness, `c` in live system codes or `unknown`, `p` 0…100; `p < cat.min_confidence` → `low_confidence`; count = `ok/llm` (idempotent commit of n); upsert cache when `p ≥ cat.cache_min_confidence`. Custom categories are never sent. Buckets 2/min, 30/day per install.

## Acceptance criteria
1. Integration tests (fake provider): catalog hit free and counter unchanged; cache hit free; 5 merchants with 2 remaining → 2 sent, 3 `quota`; more than `cat.batch_max` → 400; ask counter unchanged throughout; retried `requestId` not counted twice.
2. Provider replies `"Food & Drinks"`, an out-of-range index, a duplicate index or a name echoed as `c` → `unknown` for that merchant.
3. **Negative proof 1:** a batch at quota 0 makes no provider call (fake count 0) and catalog/cache hits still return `ok`.
4. **Negative proof 2:** a marker merchant name is absent from the log sink, OTel exporter and metrics, and present only in `llm_cat_answer_cache`.
5. **Negative proof 3:** the provider request contains only the static prompt, the names array and `lang` (no install, account, IP, app version, attestation).
6. Flag off / paused / consent mismatch → the same problem codes as Ask; quota is reported per merchant, never as 403.

## Design note (builder, Sonnet)
- **Order.** Body (closed, 4 KB; 16 KB with `attestationObject`; 1..`cat.batch_max` unique merchants of 2..64 chars, key = `CatalogText.Normalize`; more than the max, a duplicate or a bad string = 400) -> the shared `LlmGateChain` with `LlmFeature.Categorise` (flag, spend pause, consent, owner buckets, attestation, shared buckets, quota pre-check) -> per merchant: privacy -> catalog -> cache -> trim to the pre-check's `remaining` -> one provider call -> validate -> commit n -> cache. A categorise pre-check at the limit is **admitted** with `remaining 0` (quota is a per-merchant status, never 403); a retried `requestId` (pre-check `IsRetry`) is not trimmed (its batch was already counted; the commit is a no-op).
- **What is counted.** Only `ok/llm`: commit `CommitAsync(Categorise, ..., n)` with `CancellationToken.None` after the reply is validated, then cache. A commit that applies fewer than n (race over the burst) turns the surplus into `quota` and does not cache them; a commit at the limit turns all LLM answers into `quota`. `unknown`, `low_confidence`, `rejected`, `quota`, catalog and cache hits never count. The ask counter is a different `feature` row and is never touched.
- **Closed set.** The reply is parsed strictly (`{"r":[{"i","c","p"}]}`, no other member). An item is usable only when `i` is an integer in range, `c` is one of the live top-level system codes or `unknown`, `p` is an integer 0..100; a duplicated index voids every item with that index; a merchant with no usable item is `unknown`. Whole reply unusable (invalid JSON, refused) = every LLM-bound merchant `unknown`, not counted. Timeout/5xx/open circuit = 502, nothing counted (the free catalog/cache hits are not returned with it; the phone retries with back-off). The schema enum is rebuilt from the live codes (fallback: the 16 contract codes when the catalog has none) and cached per catalog version.
- **Privacy.** `ContributionPrivacy` first, then a server-only stricter filter (a run of 4 or more digits in any script, `+digit`, phone shapes, IBAN shapes, e-mail, URL, `@`) -> `rejected`, never sent, never cached. Merchant strings are `LlmSensitive<string>` from the parser to the response writer; logs carry fixed codes; every database exception on the cache is caught and dropped (a PostgreSQL error detail can quote the row). The cache row holds merchant_norm, category, confidence, provider, prompt version, times, hits and **no install id**.
- **Catalog read.** `ICategoriseCatalog` (published, not deleted, rechecked every 60 s by version): exact alias, then whole-token `prefix`/`token` matches as on the phone (longest alias wins; several categories at the best level = no hit), then a conservative fuzzy step (edit distance 1, key of 6+ letters, equal digits, one category). The phone stays the authority; a miss only costs a quota unit.
- **FU-432 (shared chain).** `ILlmRateLimiter.TryAcquire` gets a stage: `Owner` (install, account) runs before attestation as the cheap pre-check, `Shared` (/24, global) only after attestation passed. `ask_llm_invest` is read with `CancellationToken.None` after the provider call.
- **Config for the operator.** `llm_categorise` flag (OFF), `cat.*` remote-config keys (existing, T-323), `RateLimits:CatInstall*`; same provider/key/attestation settings as Ask.
