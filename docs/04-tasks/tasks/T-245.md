## Scope
1. Implement the dues hook from T-241: a parsed `cc_due` / `cc_statement` notice updates the matching card account (institution + last-4): statement amount due, minimum due, due date, statement date. Where the card already has dues fields (`account.dart`, card detail, bills/recurring dues) reuse them; add columns only if missing (migration with tests).
2. No matching card: keep the notice (raw message parsed, no transaction) and apply it when that card account is created later (same institution + last-4).
3. The existing due reminders (OVERDUE-REMINDERS, FU-219 due-days) fire from these dues; a card payment (`cc_payment`) on or after the statement date marks the due paid when it covers the minimum (partial payments: record, keep reminding for the rest of the minimum). Never change the user's typed due day without a notice newer than it.
4. Card detail shows "Due EGP x (min y) by <date>" from the latest notice; strings in `ar` (Egyptian colloquial) and `en`.
## Acceptance criteria
Ingest tests: case 7/8/12 synthetic fixtures update the card's due and create no transaction; a later notice replaces an older one, an older one never replaces a newer; payment marks paid; widget test of the card due line in `ar` and `en` (light/dark goldens if the screen has goldens); `flutter analyze` clean.
