## Description
Dart side of capture on Android (iOS hooks added in M2).

## Technical details
Build the Guard user part (plaintext JSON, `buildGuardUserConfig`) and pass it to `writeGuardConfig(Uint8List userConfigJson)` on changes to ignore rules / capture senders / custom templates and on every app start; native validates, encrypts and writes it (T-035 security L-2, [doc change] 2026-11-11; `CONFIG_INVALID` → the old file stays, surface a build error); drain spool on foreground event, app start and from ingestionMain; capability/degraded state provider; setup progress state (FR-ONB-11).

## Design note
Required — solution-architect (Opus) writes it before the Sonnet implementer starts (C3).

- From the T-038/T-039 notes (2026-11-11): read `getSpoolStatus()` at app start and after each drain; `refusedFull`/`refusedGeneric`/`rateLimited`/`missedNotifications`/`keyInvalidatedAtMs`/`guardState` feed the degraded-capture state (copy: T-039 PO Q2); after acting (catch-up triggered, config rewritten) call `clearSpoolAlerts(seq)` with the `seq` read. `guardState == userUnreadable` or `keyInvalidatedAtMs != null` → rewrite the Guard user part at once.
