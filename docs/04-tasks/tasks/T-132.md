## Description
Effective Gold per install as a signed, install-bound token with short lifetimes; the seat decision on verify; the entitlement block and support-link notice in sync.

## Technical details
- **Token** (JWS ES256, `kid`): `{iss, sub: installId, acct, plan, status, exp, graceUntil, iat, nextMoveAt, movedBy, src[], v}`; `status ∈ active | grace | expired | refunded | moved | paused | none`.
- **Coverage:** only purchases whose seat this install holds (`v_entitlements`); account-linked purchases only with a valid `Zaghlol-Account` token for their account, otherwise `paused` (D-61(c)); `acct` set when the token covers an account-linked purchase.
- **`moved` + `movedBy`** (`user` for restore, sign-in, plan change or reclaim; `support` for a support move) when a seat this install held went elsewhere; no operator data.
- **Lifetimes (D-60):** every plan, lifetime included, `exp ≤ iat + 3 d`; subscriptions also ≤ store expiry; a token covering a `basic` seat `exp ≤ iat + 2 d`; `graceUntil = exp + 4 d`.
- **`nextMoveAt`** = the stored hour-rounded `next_move_at`, or `null`.
- `GET /v1/entitlement` → `{entitlement: {token}, serverTime, timeNonce, supportNotice}`; never moves a seat.
- **Verify wiring (§4.3 Seat at verify):** after T-130/T-131 verification, call the seat service (T-184): bind a seatless purchase to the buying install (`proof = binding`, not a move); same holder refresh; re-verify of an old transaction never changes the holder; a **new payment** from another install → plan-change rule: **account rule first (R4-4)** (`seatHeldElsewhere: true`, `accountRequired: true`, claimant `channel = verify`, seat stays, without a valid account token for that account), then move if no cooldown (`seat_move:verify`), else stay with claimant and `nextMoveAt`. Never turns a valid payment into an error (BR-GOLD-06). Response `{status, entitlement, seatHeldElsewhere, accountRequired, nextMoveAt, serverTime, timeNonce}`.
- **iOS verify `seatKeys`** (single element, `op = verify`, `challenge = SHA-256(signedTransaction)`): verified through T-182 only after store checks pass; registers element 0 **untrusted** if the install has none (R5-2); a bad proof or a non-registered key is ignored with a diag counter, never an error.
- **Sync entitlement block** (implements T-128's extension point): a fresh token when the cached one (`entitlementIssuedAt`) is > 12 h old or anything changed; `accountToken` refresh when < 7 d to expiry.
- **Support-link notice (R4-7(2), R5-7):** for the buying install (`purchases.install_id`) of a purchase with `support_link_notice_pending`, every signed sync and entitlement 200 carries `supportNotice: "gold_linked_by_support"` **with a fresh token**, whose `iat` is stored in `support_link_notice_iat`. Cleared only when a later `POST /v1/sync` from that install sends `entitlementIssuedAt ≥ support_link_notice_iat`. Never shown to other installs.
- **Time nonce:** every 200 of `GET /v1/entitlement` and `POST /v1/purchases/verify` echoes `timeNonce` (T-123 filter). Owner of the live contract test across the six anchoring operations (`TimeNonceIsSentAndEchoedExactlyOnAnchoringOperations` in live form) once T-135 and T-185 land; until then it covers the operations that exist.

## Acceptance criteria
- [ ] Refunded purchase → `status: refunded` in the next token.
- [ ] D-60: tokens for monthly, yearly and lifetime plans all have `exp − iat ≤ 3 d`; a basic-seat token ≤ 2 d; `graceUntil − exp = 4 d` (property test).
- [ ] `sub` is always the calling install's ID; a token never covers a purchase whose seat another install holds (test).
- [ ] D-61(c): an account-linked purchase without a valid account token appears as `paused`; with one, `acct` equals the account ID (test).
- [ ] A former holder gets `status: moved` with `movedBy: user` after a restore move, and `movedBy: support` after a support move (test with T-184 fakes).
- [ ] D-59/D-61(a): plan change from another install with no cooldown moves the seat; inside a cooldown the seat stays, the payer gets `seatHeldElsewhere: true` and `nextMoveAt`, and the payer is a claimant (tests). The purchase is acknowledged in both cases.
- [ ] R4-4: plan change on an account-linked purchase without the account token → seat stays even with no cooldown, `accountRequired: true`, claimant `channel = verify`, `next_move_at` unchanged (test).
- [ ] R5-2: a valid verify-time `seatKeys` registers `installs.seat_key_hash` with `seat_key_trusted = false`; a later verify never sets it true (test).
- [ ] A verify `seatKeys` with an invalid signature or a non-registered element 0 returns 200 and changes nothing (test).
- [ ] R5-7: after a support attach, the buying install's sync and entitlement 200s carry `supportNotice` and a fresh token until it syncs with `entitlementIssuedAt ≥ support_link_notice_iat`; a sync with an older `entitlementIssuedAt` keeps the flag; another install never sees it (tests).
- [ ] R4-2: verify and entitlement 200s are signed and echo `timeNonce`.
- [ ] FU-011: live response-vs-spec tests for `GET /v1/entitlement` and verify.
- [ ] DoD (CLAUDE.md §7): analyze clean, formatted, tests added, no hard-coded strings, RTL verified where UI, no `double` money, no raw SMS in logs.
