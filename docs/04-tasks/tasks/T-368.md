## Goal
A model plan may only use an amount the user wrote, and a `mention` never carries a number. Two holes from batch-91 C1 are closed in **both** validators with the same rule and the same shared vectors:
1. Step 4 read the index of a placeholder as a number of the question, so `"⟦CARD_1⟧ هحوش"` justified `amount:"1"`.
2. The no-digit rule of `mention` covered only the digits the schema pattern lists, so `½`, `①`, `Ⅻ` (and decimal digits of other scripts) passed.

## Acceptance criteria
1. Step 4 removes every `⟦…⟧` token from the (folded) sent text before numbers and number words are read; `"⟦CARD_1⟧ هحوش"` + amount `1` gives step 4 `AMOUNT_NOT_IN_TEXT`. Numbers outside a token still count, and the texts on both sides of a token never join into one number.
2. A `mention` holding any character of category `\p{N}` (Nd, Nl, No) is refused; a mention with `½` is refused.
3. Backend and phone validators give the declared outcome, step and reason on every vector of `ask-plan-v1.json`, the new ones included; the contract reference implementation agrees.
4. The schema (`ask-plan-v1.schema.json`) and `plan_schema.g.dart` are unchanged (`gen_plan_schema.dart --check` clean).
5. Each change has a test that fails without it.

## Design note (builder)
- **Placeholder token** = `⟦[^⟦⟧]*⟧` (U+27E6 … U+27E7, no nesting), matched on the folded text, so an Arabic-Indic or invisible-character variant inside a token is covered. Each token is replaced by **one space**, not by nothing, so `5⟦CARD_1⟧00` cannot become `500`. The result is used only for step 4 (numbers and number words); steps 2 and 3 keep the full text.
- **`mention` rule lives in step 3, reason `MENTION_NOT_IN_TEXT`.** The schema pattern stays as it is (changing it would change the copy sent to providers and the pinned copy of older phones); its `$comment` already says the no-digit rule is re-checked in step 3. The contract test requires a step 1 vector to fail the schema file itself, so the wider rule cannot be declared as step 1. No new reason code (the set in §2.4a is fixed). Backend: `Rune.IsNumber`; phone: `RegExp(r'\p{N}', unicode: true)`; the test is on the raw mention.
- **Not changed:** the template rule `TEMPLATE_DIGIT` stays `\p{Nd}` (§2.0 names `mention` only; model-written template text is the subject of §2.1, waiting on the PO).
