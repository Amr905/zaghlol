## Description
Charts today only toggle **this cycle / last cycle** (`chartsPeriodProvider` is a bool). FR-CHT-04 already asked for cycle / month / custom range and was only half built. The PO wants the user to choose the period.

## Technical details
- **Model:** replace the bool with a `ChartPeriodSelection` (preset + anchor): this cycle, last cycle, this month, last month, last 3 / 6 / 12 months, this year, custom (from–to). Resolves to a `ChartPeriod` per currency's payday cycle where relevant. Relative presets re-resolve when the date changes.
- **Picker:** a period chip at the top of Charts showing the resolved range ("٢٥ أكتوبر – ٢٤ نوفمبر"); tap opens a sheet with the presets and a custom range picker (Gregorian, Arabic digits per locale); ‹ › buttons step to the previous / next period of the same kind (disabled past today).
- **Buckets:** charts that plot over time pick day / week / month buckets from the range length (≤ 31 days → days, ≤ 6 months → weeks or cycles, else months). Each chart declares which presets make sense (e.g. payday burn-rate needs a cycle; net worth may extend); unsupported ones show a short note rather than a wrong chart.
- **Remember:** last selection stored in settings; default "this cycle".
- **Everything follows it:** all charts on the screen, chart detail, "Explain this chart" texts and the card / currency filters.
- **Performance:** NFR-PERF-04 (< 300 ms with 2 years of data) still holds for "last 12 months" and a 2-year custom range; add a benchmark case.

## Acceptance criteria
1. Every preset and a custom range resolve correctly across month ends, payday cycles and Ramadan / leap-year edge dates (unit tests).
2. Stepping works for each preset and stops at today.
3. All charts and explanations reflect the chosen period; card and currency filters still apply.
4. The selection survives a restart.
5. Benchmark: 2 years of synthetic data renders the charts screen in < 300 ms per chart on the host benchmark.
6. Goldens `ar`/`en`, light/dark, for the picker sheet and a 6-month view; RTL verified; no hard-coded strings.
