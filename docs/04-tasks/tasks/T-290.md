## Scope (`app/android/app/src/main/kotlin/app/zaghlol/platform/ocr/OcrMerger.kt` + `OcrMergerTest.kt`, ADR-009)
1. **FU-371**: one Arabic line overlapping both a strong and a weak ML Kit line must not repeat its text.
2. **FU-376**: the amount-append path must not append Arabic digits that disagree with a nearby strong ML Kit amount (e.g. `Net Sales` + separate `382.46` with noise `321146 535` at 0.62 must not yield `Net Sales 321146 535`). Prefer: append only when no strong ML Kit amount line overlaps the Arabic line's box.
3. **FU-377**: noise at 0.45–0.60 overlapping a strong line by less than 0.5 (vertical drift) is treated as overlapping for the gate (use a lower gate overlap, e.g. any vertical overlap ≥ 0.3 of the smaller height), without dropping real Arabic lines that sit on their own row.
4. **FU-378**: remove the redundant `val words = extra` alias; add tests at exactly 0.45 and 0.60.
Keep the PO-photo tests (the 1,558 case reads 436) green. Kotlin compiles only in CI: push the same commit to `ci/T-290` once (don't wait).

## Acceptance criteria
- One new test per item; all existing OcrMerger tests unchanged and passing in CI.

## Design note (builder)
- FU-371: in `mergeBoth`, when an Arabic line replaces weak lines but a strong line it also overlaps is kept, the Arabic text drops tokens the strong line already contains (line dropped if nothing is left).
- FU-376: the amount-append path is skipped when a strong ML Kit line with ASCII digits overlaps the Arabic line (>= 0.5).
- FU-377: the gate uses `sharesRow` (vertical overlap >= `GATE_ROW_OVERLAP` 0.3 of the smaller height, horizontal overlap > 0). The merge match keeps 0.5.
- FU-378: alias removed; boundary test at exactly 0.45 and 0.60.

## Builder assumptions
- FU-371 de-duplication compares by token substring against the kept strong line's text.
