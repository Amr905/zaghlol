## Scope (plan §4.2 last bullet, §4.6)
1. Pipeline: when a known sender's message misses its templates and the generic reader declines, return the generic reason (`genericNoAmount`, `genericDeclined`, `genericPromotion`) with the institution code instead of the bare `noTemplateMatched` (keep `noTemplateMatched` when the generic reader was not reached). Update any switch over the enum.
2. A pure `shapeSignature(String body)` in the parsing package: digits → `9` runs collapsed, Latin words → `A`, Arabic words → `ع`, known cue words kept (from the keyword lists), length-capped; it must not contain any letter or digit of the original except cue words. Unit tests prove no name, number or merchant survives.
3. SMS diagnostics (dev builds, Settings → About): per sender, counts per unread reason and the top 5 signatures with counts. Nothing logged, nothing leaves the phone, stored like the existing diagnostics counters.
## Acceptance criteria
Unit tests for both; a diagnostics widget test in `ar` and `en`; privacy check: signature tests with names, phone numbers, IBAN-like numbers and Arabic names show none of them.
