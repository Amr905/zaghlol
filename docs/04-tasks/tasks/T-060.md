## Description
Users can send messages/files to Zaghlol.

## Technical details
Intent filters text/plain, image/*, application/pdf, text/csv; images/PDFs copied encrypted with spool key; in-app confirmation route; paste is user-initiated only.

## Design note
(C3, short; written by the implementer because no architect note existed. Reviewers: challenge it.)

**Contract gap.** `platform-channels.md` section 2 lists share intent filters only in the manifest; `AndroidCaptureHostApi` has no method that hands a share (or a shared file) to Dart. Spool entries carry text only. This task therefore adds a small, separate Pigeon file `app/pigeons/share_intake_api.dart` (not touching T-039's capture API) and a short subsection in `platform-channels.md`. **This is a contract addition and needs lead/architect sign-off.**

**Flow.** `ShareActivity` (exported, no UI, `ACTION_SEND` only, MIME filters `text/plain`, `image/*`, `application/pdf`, `text/csv`) validates and encrypts the payload on a worker thread, then starts `MainActivity` with an internal intent that carries no content. Dart gets `onShareReceived(descriptor)` when the engine is attached, and polls `listPendingShares()` / `takePendingRejection()` at startup (cold start). Dart then calls `readShare(id)` (decrypted bytes or text, in memory only), shows the confirmation or OCR flow, and finally `discardShare(id)`. Paste is a Dart-side, user-initiated clipboard read; nothing native reads the clipboard.

**Storage.** Every share, including text, is stored as `noBackupFilesDir/spool/files/<id>.bin` (body) plus `<id>.meta` (kind, MIME, size, time), both `nonce(12) || AES-256-GCM`, using the Keystore key `zaghlol_spool_v1` (same alias and parameters as the T-039 spool, created here if absent so T-039 reuses it). Written to `.tmp`, fsynced, renamed; the `.meta` is written last, so it marks a committed share. Stale shares (older than 24 h) and `.tmp` leftovers are purged whenever the intake or the host API runs. Ids are 28 hex characters and validated before use in a path.

**Limits and validation (all enforced natively, before any Dart involvement).** Text 100,000 chars; image 15 MiB; PDF 20 MiB; CSV 5 MiB. Size is enforced on bytes actually copied, not on the declared size. Only `content://` URIs are accepted (a `file://` URI would let another app make us read our own private files), and URIs whose authority is this app's own are refused. The declared MIME must be allowed, and the content is sniffed (PNG, JPEG, WEBP, HEIC for images; `%PDF-` for PDF; no NUL bytes and valid UTF-8 for CSV and text). Failures map to `ShareRejectReason` (tooLarge, unsupportedType, unreadable, empty); the partial `.tmp` is deleted.

**Privacy.** No content, URI display name or size is logged. No `Log` calls exist in this package. The share's `EXTRA_TEXT` is never put into an intent we re-send. Nothing is written outside `noBackupFilesDir`.

**Testability.** Validation, limits, sniffing, the store and the orchestrator are plain Kotlin behind two small interfaces (`ShareSource`, `ShareCipher`), unit-tested on the JVM with a software AES-GCM cipher. The Keystore cipher and the two activities are thin Android glue, covered by one instrumented test and the manual steps below.

## Verification

Automated (all synthetic data):
- Kotlin JVM tests, `app/android/app/src/test/kotlin/app/zaghlol/platform/share/` (38 tests): MIME and magic-byte classification, limits at and over the boundary, `file://` and own-provider URIs, unreadable and mid-copy failures leaving nothing behind, encrypted-at-rest, tamper and wrong-key, stale purge, id path-traversal, host error codes.
- Dart channel test with a fake native side, `app/test/core/platform/share_intake_service_test.dart`.
- Instrumented test (device/emulator; not run by the PC runner): `app/android/app/src/androidTest/kotlin/app/zaghlol/platform/share/ShareIntakeInstrumentedTest.kt` (`./gradlew connectedDevNoSmsDebugAndroidTest`): real Keystore key round trip and tamper, real ACTION_SEND text intent, `file://` refusal.

Manual device steps (not yet run; no device available to the implementer):
1. Install `devNoSms`. In a messaging app, share a plain text (synthetic, for example "Your card ending 1234 was charged EGP 125.50 at TEST MERCHANT") to Zaghlol. Expect the app to open and `onShareReceived` (kind text) to arrive; once the confirmation UI exists, the parsed fields appear.
2. Share a screenshot (PNG and JPEG) from Photos: expect kind image, routed to OCR.
3. Share a PDF and a `.csv` from Files: expect kinds pdf and csv.
4. Share a GIF, a ZIP and a text over 100,000 characters: expect no crash and a refusal (`unsupportedType`, `unsupportedType`, `tooLarge`).
5. Share while the app is killed (cold start) and while it is open (warm start): both deliver exactly once.
6. `adb shell run-as app.zaghlol.dev ls -R no_backup/spool/files`: only `*.bin` and `*.meta`, no readable content (`strings` finds nothing); after confirming or cancelling in the app the files are gone.
7. `adb logcat`: no share content appears at any point.
8. Share a file from the app's own storage via `adb shell am start -a android.intent.action.SEND -t image/png --eu android.intent.extra.STREAM file:///data/data/app.zaghlol.dev/files/x.png -n app.zaghlol.dev/app.zaghlol.platform.share.ShareActivity`: expect a refusal.
9. Check on a real device that the share opens the existing Zaghlol task (not a new empty one) and that the sender app is left intact (launch flags in `ShareActivity.handOff`).
