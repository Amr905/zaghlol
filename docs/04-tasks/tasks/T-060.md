## Description
Users can send messages/files to Zaghlol.

## Technical details
Intent filters text/plain, image/*, application/pdf, text/csv; images/PDFs copied encrypted with spool key; in-app confirmation route; paste is user-initiated only.

## Design note
(Written by the implementer because no architect note existed; updated in the fix round below. Reviewers: challenge it.)

**Contract gap.** `platform-channels.md` section 2 lists share intent filters only in the manifest; `AndroidCaptureHostApi` has no method that hands a share (or a shared file) to Dart. Spool entries carry text only. This task therefore adds a small, separate Pigeon file `app/pigeons/share_intake_api.dart` (not touching T-039's capture API) and section 2.1 in `platform-channels.md`. **Approved by Lead 2026-11-10 (T-060 review), recorded in section 2.1.**

**Flow.** `ShareActivity` (exported, no UI, `ACTION_SEND` only, MIME filters `text/plain`, `image/*`, `application/pdf`, `text/csv`) validates and encrypts the payload on a worker thread, then starts `MainActivity` with an explicit intent that carries no content, only a per-process hand-off token. `MainActivity` announces every pending share with `onShareReceived` on every resume; Dart polls `listPendingShares()` / `takePendingRejection()` at startup and on every resume. Dart then calls `readShare(id)` (decrypted bytes or text, in memory only), shows the confirmation or OCR flow, and finally `discardShare(id)`. Paste is a Dart-side, user-initiated clipboard read; nothing native reads the clipboard.

**Storage.** Every share, including text, is stored as `noBackupFilesDir/share/<id>.bin` (body) plus `<id>.meta` (kind, MIME, size, time), both `nonce(12) || AES-256-GCM` with the id (and, for the body, the kind) as AAD, using the Keystore key `zaghlol_spool_v1` obtained only through `SpoolKey` (process-wide get-or-create lock; T-039 reuses it). Written to `.tmp`, fsynced, renamed; the `.meta` is written last, so it marks a committed share. Stale shares (older than 24 h) and `.tmp` leftovers are purged whenever the intake or the host API runs. Ids are 28 hex characters and validated before use in a path.

**Limits and validation (all enforced natively, before any Dart involvement).** Text 100,000 chars; image 15 MiB; PDF 20 MiB; CSV 5 MiB. Size is enforced on bytes actually copied, not on the declared size. Only `content://` URIs are accepted (a `file://` URI would let another app make us read our own private files), and URIs whose authority is this app's own are refused. The declared MIME must be allowed, and the content is sniffed (PNG, JPEG, WEBP, HEIC for images; `%PDF-` for PDF; no NUL bytes and valid UTF-8 for CSV and text). Images must also decode (bounds only) to at most 64 MP. At most 10 pending shares and 100 MiB on disk. The whole intake is bounded to 20 s. Failures map to `ShareRejectReason` (tooLarge, unsupportedType, unreadable, empty); the partial `.tmp` is deleted.

**Privacy.** No content, URI display name or size is logged. No `Log` calls exist in this package. The share's `EXTRA_TEXT` is never put into an intent we re-send. Nothing is written outside `noBackupFilesDir`.

**Testability.** Validation, limits, sniffing, the URI policy, the store, the job hand-off, the hand-off token, the key get-or-create lock and the orchestrator are plain Kotlin behind small interfaces (`ShareSource`, `ShareCipher`, `ImageBoundsProbe`), unit-tested on the JVM with a software AES-GCM cipher. The Keystore cipher, `BitmapBoundsProbe` and the two activities are thin Android glue, covered by the instrumented test and the manual steps below.

## Verification

Automated (all synthetic data):
- Kotlin JVM tests, `app/android/app/src/test/kotlin/app/zaghlol/platform/` (73 tests in `share/` and `spool/`): MIME and magic-byte classification, limits at and over the boundary, `file://`, own-provider, user-info, host case/port and resolves-to-us URIs, unreadable and mid-copy failures leaving nothing behind, encrypted-at-rest, tamper, truncation, wrong key, AAD swaps between shares and roles, transient decrypt failures keeping the share, pending count and byte caps, deadline (drip-feed, queued past deadline, cancelled read), pixel cap, stale purge, id path-traversal, host error codes, job hand-off and recreation, hand-off token, single key creation under 16 concurrent callers.
- Dart channel test with a fake native side, `app/test/core/platform/share_intake_service_test.dart`: events, polling, dedupe across resume re-announcements, transient `IO_ERROR` then retry, discard.
- Instrumented test (device/emulator; not run by the PC runner): `app/android/app/src/androidTest/kotlin/app/zaghlol/platform/share/ShareIntakeInstrumentedTest.kt` (`./gradlew connectedDevNoSmsDebugAndroidTest`): real Keystore key round trip, tamper and wrong AAD, concurrent `SpoolKey` callers, real ACTION_SEND text intent stored in `no_backup/share`, `file://` refusal, user-info URI with real `Uri` parsing, `BitmapBoundsProbe` on a real PNG and on a header-only 9000x9000 PNG.

Manual device steps (not yet run; no device available to the implementer; must run before M2 closes, see FU-067):
1. Install `devNoSms`. In a messaging app, share a plain text (synthetic, for example "Your card ending 1234 was charged EGP 125.50 at TEST MERCHANT") to Zaghlol. Expect the app to open and `onShareReceived` (kind text) to arrive.
2. Share a screenshot (PNG and JPEG) and a HEIC photo from Photos: expect kind image. Share a camera photo over 64 MP if one is available: expect `tooLarge`.
3. Share a PDF and a `.csv` from Files: expect kinds pdf and csv.
4. Share a GIF, a ZIP and a text over 100,000 characters: expect no crash and a refusal (`unsupportedType`, `unsupportedType`, `tooLarge`).
5. Share while the app is killed (cold start) and while it is open (warm start): both deliver exactly once. Share twice quickly: both arrive. Rotate the device during a large PDF share: it is stored once.
6. `adb shell run-as app.zaghlol.dev ls -R no_backup/share`: only `*.bin` and `*.meta`, no readable content (`strings` finds nothing); after confirming or cancelling in the app the files are gone. `no_backup/spool` holds no share files.
7. `adb logcat`: no share content appears at any point.
8. Share a file from the app's own storage via `adb shell am start -a android.intent.action.SEND -t image/png --eu android.intent.extra.STREAM file:///data/data/app.zaghlol.dev/files/x.png -n app.zaghlol.dev/app.zaghlol.platform.share.ShareActivity`: expect a refusal. Repeat with `content://x@app.zaghlol.dev.flutter.image_provider/x.png`: expect a refusal.
9. Check on a real device that the share opens the existing Zaghlol task (not a new empty one) and that the sender app is left intact.
10. Spoof: `adb shell am start -n app.zaghlol.dev/app.zaghlol.MainActivity -a app.zaghlol.action.SHARE_READY` right after a refused share while the app is open: the refusal is not consumed (Dart still gets it from `takePendingRejection()`).
11. Share 11 small texts without opening them in the app: the 11th is refused (`tooLarge`).

## Fix round (T-060 review, 2026-11-10)
- F1: acceptance criteria re-scoped (above); owners in FU-067.
- F2: pending caps (10 shares, 100 MiB), `tooLarge` when over.
- F3: 20 s intake deadline (stream closed, partial file deleted), hard give-up after 3 s more, job id in saved state so a recreated activity never ingests twice; `noHistory` removed so leaving mid-copy does not drop the read grant.
- F4: own-provider check on `Uri.getHost()` (lowercase), any user info refused, and authorities resolving to our own provider refused.
- F5: `SpoolKey` owns the alias with a process-wide lock; alias contract documented there and in FU-068 for T-039.
- F6: delete only on authentication or format failure; transient errors return `IO_ERROR` and keep the share.
- F7: per-process hand-off token on `SHARE_READY`; announce all pending shares on every resume; the received-share slot is gone.
- F8: store moved to `noBackupFilesDir/share/`.
- F9: decoded-bounds pixel cap (64 MP) with `BitmapFactory` `inJustDecodeBounds`.
- F10: contract approval recorded in platform-channels.md section 2.1.
- F11: GCM AAD binds meta to the id and body to the id and kind.
- F12: instrumented test imports tidied.
