## Description
Return to first-launch state with nothing financial left behind, while keeping the iPhone seat keys that let Gold come back without a move.

## Technical details
- Confirm; on **Android**, while this install holds a seat, the confirmation warns first that restoring afterwards counts as this month's move, with `nextMoveAt` when a cooldown runs (data from T-145; copy from T-028).
- Cancel jobs; close DB; delete DB (including tokens, trusted-time state and `supportNotice` in `secure_state`), spool, temp, widget snapshot; delete Keystore/Keychain items **except the iOS seat keys**: call `SeatKeyHostApi.rotateForNewInstall()` so the current key becomes an "earlier" key (D-55, R4-8). Delete the App Attest `keyId` item (the next install re-attests).
- `DELETE /v1/installs/me` best effort (one retry); restart.

## Design note
Written by the implementer (Opus, sprint rule: C4 that deletes user data; no separate architect note).

**Entry point.** `DeleteEverything.run()` (`app/lib/features/security/application/delete_everything.dart`) behind Settings `wipeEverythingProvider` (`wipeEverythingOverride` in `main.dart`). The confirm (S-71, T-162) stays type-to-confirm (`DELETE` / `احذف`); cancel or a wrong word returns before anything runs. On Android with a held seat the dialog adds `goldSeatDeleteWarning` (EC-69: `cooldown` with `nextMoveAt` while it is in the future, else `other`); no seat, iOS or a failed lookup: no warning.

**Order** (crypto-shred first, so a crash at any later step leaves nothing readable; a marker resumes the rest):
1. Write the marker `<appSupport>/wipe_pending` (empty file).
2. Snapshot `install_id` + `install_token` into memory (for step 9 only).
3. iOS: `SeatKeyService.rotateForNewInstall()` (D-55, R4-8). A failure is not fatal: the next install's binding check rotates anyway.
4. Cancel the backup job (`BackupWorkScheduler.cancel`).
5. Close the database (`appDatabaseProvider` instance `close()`).
6. Under the bootstrap lease delete the secret slots `dbKey` and `backupKey` (`SecretStore.delete`). After this the DB, `secure_state` (install/account/entitlement tokens, trusted-time state, `supportNotice`, seat binding) and backup key slot are unreadable.
7. Delete the DB file set in `dbWipeOrder` (main file last) and clear the temp directory.
8. Native `wipeLocalData()` (new method on the existing capture host APIs):
   - Android: cancel all WorkManager work (ingestion live/retry and any later job) and prune; cancel all notifications; forget the Guard user part (file + in-memory snapshot); delete every AndroidKeyStore alias of the app (db/backup KEKs, spool key); clear the contents of `filesDir`, `noBackupFilesDir` (spool, guard, capture, share, keys) and `cacheDir`. `databases/` (WorkManager's own DB) and `shared_prefs/` are left: the app keeps no data there (T-165 policy).
   - iOS: cancel all BGTask requests; remove pending and delivered notifications; delete every Keychain item of the app's access groups **except** service `app.zaghlol.seatkey` (so the DB key, backup key, spool key, App Attest `keyId`, Google sign-in session go); clear the contents (never the roots) of Application Support, Documents, Caches, tmp and the App Group `spool`, `Library/Application Support`, `Library/Caches`; then `ZaghlolDirectories.applyAll()` (T-165 F4).
9. Best effort, not awaited by the restart: a throwaway `BackendClient` over an in-memory state store holding only the step-2 snapshot sends `DELETE /v1/installs/me`, one retry, 10 s timeout each. Offline or failed: nothing is queued (queuing would keep a token on disk); the confirm already says the server copy expires on its own (`privacyDeleteServerCopy`).
10. Google sign-in local session: `signOut()` best effort (Android; on iOS the Keychain sweep also covers it).
11. Delete the marker; restart: the root `AppRestartScope` replaces the `ProviderScope`, so every provider (DB, backend client, entitlement, flags) is rebuilt and the app opens in first-launch state.

**Crash/resume.** `main()` checks the marker before `runApp`; when present it runs steps 3–8, 10, 11 (no backend call: the token is gone). Each step is idempotent; a failed step is recorded and the run continues; `run()` returns a `WipeReport` (step ids that failed, no paths) and the marker stays when any local step failed, so the next launch retries.

**Not touched.** The user's Drive / iCloud backup files (the confirm says so; see missing key below). Seat-key Keychain items on iOS.

**Concurrency.** The headless ingestion engine never creates a DB or key (`allowCreateOrWipe = false`), so after step 6 it defers; WorkManager / BGTask cancel in step 8 stops further runs. An in-process backup (EC-29) fails on the closed DB; its encrypted staging file goes with the temp directory.

**Missing l10n keys** (SPRINT: no ARB edits): `privacyDeleteBackupsKept` — en "Your backups on Google Drive or iCloud stay there. Delete them from there if you want." / ar "النسخ الاحتياطية اللي على Google Drive أو iCloud هتفضل زي ما هي. لو عايز تمسحها، امسحها من هناك." Until it lands the dialog shows no such line.
