### Declared deviations
- `catalog_drafts` table with identity as merchant-id allocator, `OVERRIDING SYSTEM VALUE` publish, one transaction under `pg_advisory_xact_lock`, audit row in the same transaction: accepted. Insert-only need, no sequence grant (FU-026 respected). Migration grants are `ops_rw` SIUD and `ops_ro` S only, rendered from the frozen `GrantMatrix.CatalogDrafts`; `Current` includes it so SchemaTests cover it. Live-table grants (`ops_rw` SIU) suffice for the upsert and `ON CONFLICT DO UPDATE`.
- Per-endpoint signing cap (8 MiB full snapshot, 1 MiB default): accepted; default instance unchanged, publish enforces the same `MaxSnapshotBytes`, so a too-large catalog fails the publish (rollback) instead of the served response.
- `IOperatorTokenValidator` seam plus `catalog_editor` policy: accepted; default validator rejects all, so production is 401 until T-136.
- Directory snapshot store: accepted. Atomic temp-then-move writes; files are written before commit, an orphan from a failed commit is overwritten by the next publish of the same number (publish is serialised by the lock).
- ASCII-only alias keys, no `string.Normalize`: accepted (invariant globalization).
- Publish with no changes is 409 ADMIN_CONFLICT, in openapi: accepted.

### Specific checks
- Snapshot integrity: `GET /v1/catalog/{version}/full` gunzips with a size cap (decompression-bomb guard), compares SHA-256 with `catalog_versions.full_snapshot_sha256` using `FixedTimeEquals`, throws `CatalogSnapshotCorruptException` (500) on a missing file or mismatch. It serves the stored bytes, not a rebuild. Correct.
- Delta ordering: correct as designed (see above). Tombstone rows keep their version so `(a, b]` includes them.
- Nothing admin uses `WithIdempotency`. Admin and full routes sit under the global per-network and per-operator limiters.
- Logging/audit: audit `Details` carry only entity name or counts; no alias text beyond the path id, no publish note.
