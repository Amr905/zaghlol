**BR-SYNC-03 / data minimisation.** The lookup selects no token, `store_key`, transaction or order ID. Every relation to another install (holder, claimant, buyer, silence) is computed as a boolean or count in SQL (`SupportLookupStore.cs:242-256`), so no other install's ID reaches the process. Nothing financial is returned. The response carries the purchase UUID, plan, state, store, seat status, link flag, dates and clamped counters, which matches `SupportPurchase` in the spec. The e-mail is only a bound parameter. `SupportLookupKey.ToString` is overridden, and the problem bodies never echo it. Unknown install → `200 none` and unknown e-mail → `200 []`, both after the same queries, so neither works as an existence oracle.

## Declared deviations
- **Operator lookup on the Admin login (`ops_rw`, SELECT-only grant on `operators`) instead of `ops_ro`:** accepted. Read-only is enforced by the grant, and it avoids a fourth pool.
- **Own JWKS cache instead of `ConfigurationManager`:** accepted. The 24 h refresh, ≤1 forced refresh per 5 min, last-good keys for ≤7 days and fail-closed are all implemented (`OidcKeyCache.cs:343-424`). The concurrent-refresh guard (`ReferenceEquals` + throttle under the semaphore) is correct. All of this is tested with a fake clock (`AfterRotation…`, `KeysRefreshDaily…`). HTTPS-only, a 64 KiB cap, a 10 s timeout, ≤50 keys, and private/`enc` keys skipped.
- **K_audit = `Kms:HmacKeys:Audit`:** accepted. It is a separate `KeyedHashKey.Audit`, distinct from `InstallHashPepper`.
- **No in-API dev fake issuer:** accepted (nit 5).
- **Test fake issuer as an in-process `HttpMessageHandler`:** accepted. The real validator and key-cache path run end to end, including the https-scheme checks.
- **Lookup requires `support_viewer` exactly:** accepted. It matches OpenAPI `x-required-roles: [support_viewer]`, which wins over the design note's "or higher". The seed script tells operators to grant viewer to agents.
- **Failed audit insert → 500:** accepted (the design note said 503). The write is rolled back, and the test asserts 5xx with no row.
- **Unknown install → 200 `none`:** accepted (nit 7).
