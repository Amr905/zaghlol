## Findings

**F-1 (major) Composite Semantics labels read the glyphs, not "amount hidden" (AC 7).**
`commonAmountHidden` is used only inside `ZMoneyText` (`core/ui/z_money_text.dart:90-97`). Every label that embeds a masked string and sets `excludeSemantics: true` still announces `****`/`-**** ج.م`: `txn_row.dart:140` (`transactionsRowLabelA11y`), `bills_screen.dart:379`, `budget_screen.dart:573`, `assets_section.dart:343`, `prices_screen.dart:204,269`, `zakah_screen.dart:491`, `compare.dart:158`, chart summaries (`chart_bodies.dart:43,225,478`, `gold_chart_bodies.dart:124,191,292,392,472,572,659,717,766`). Not a data leak, but AC 7 and the task text are not met for lists and charts. Required: when `hidden`, pass `l.commonAmountHidden` in place of the amount argument in these labels (or one helper `a11yMoney(fmt, m)`), plus a test over a row and one chart summary.

**F-2 (minor) Lint is heuristic and easy to bypass.** `tools/lints/lib/src/checker.dart:176-235` catches `MoneyFormat.format` without `hidden:`/with literal `false`, `NumberFormat`, `toStringAsFixed/Precision`, `toCanonicalString`. It does not catch `'${m.minor}'`, `m.minor.toString()`, `digits.render('${...minor...}')`, `formatMilli`-style helpers (`wealth/presentation/asset_format.dart:7`, which prints gold grams, masked only by hand at `assets_section.dart:238,292`), `hidden: someConstFalse`, or a `ZMoneyText(text: <any string>)`. Also `UnitAmountArg` is masked by hand (`chart_explain_l10n.dart:45`). Suggest: flag `.minor`/`.quantityMilli`/`netMinor` inside interpolation or `.toString()` in `presentation/` and `application/`, and `ZMoneyText(text:)` whose argument is a string literal or interpolation. Acceptable to merge as is; the rule is a good first net (it fails on its fixture and the repo is clean).

**F-3 (minor) Cold-start notification text.** `notification_providers.dart:146`, `housekeeping_providers.dart:68,199,226` use `ref.read(hideAmountsProvider)`, which is fail-closed (true while the setting loads). A notification built before the setting resolves (ingest on cold start) says `****` for users who did not hide. Safe direction, but a spurious regression. Read the setting with `await settings.get(Settings.hideAmountsApp)` as `_service` does at line 203.

**F-4 (minor) Already-scheduled notifications.** `ref.listen(hideAmountsAppProvider, redact)` (`notification_providers.dart:178`) redacts on change only. Alerts scheduled before an app start with the setting already on are not redacted at startup (same limitation exists for the older `hide_amounts.notifications` listener). Call `redactScheduled()` once when the service is created and either flag is on.

**F-5 (minor) Share studio.** `share_studio_screen.dart:163`: the "show amounts" switch stays enabled and can read "on" while `hideAmountsProvider` forces the percent card. Disable it (with a hint) while hidden.

**F-6 (nit)**

- `preferences_screen.dart:197`: switch shows off while the setting loads, whereas amounts are hidden (fail-closed). Show it on while loading or disabled.
- `review_screen.dart:467` and `transaction_edit_screen.dart:380` use `read` for `hideAmountsProvider`; will not rebuild on toggle (edit screens: the toggle is not reachable, review: reachable only via navigation, low risk).

- `z_hide_amounts_button.dart`: `Semantics(label)` wrapping `IconButton(tooltip)` can announce the label twice on some screen readers.
