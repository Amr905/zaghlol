### What was checked and holds
- **Receiver:** stamps, assembles PDUs by sender (EC-09), `goAsync()` with `BoundedDispatch` (5 s budget, `finish()` exactly once on every path incl. rejected executor); no engine/parse/DB; never aborts; `BROADCAST_SMS` on the receiver, `directBootAware=false`.
- **Guard:** fail-closed compiled-in synthetic senders, 4,000-char cap before any regex, OTP drop; deviation 3 (no config reader before T-038) is acceptable.
- **Spool:** versioned strict binary record (trailing bytes, bad UTF-8, over-long fields rejected); AES-GCM via `SpoolKey.get()` only; AAD `zaghlol.spool.v1|entry|<ulid>`; `.tmp` → `fsync` → atomic rename; caps 500 / 4 MiB count `.tmp` and refuse new; delete only on `ack` or after 4 attempts that all prove inauthenticity; any I/O/Keystore error keeps the entry (incl. a key-init failure, so a `KeyPermanentlyInvalidatedException` does not mass-delete).
- **Claim:** one engine at a time, released on full ack / detach / 60 s; deviation 8 is sound.
- **WorkManager:** expedited with `RUN_AS_NON_EXPEDITED_WORK_REQUEST`, unique `zaghlol.ingest`, `APPEND_OR_REPLACE`, no constraints, exponential 10 s, no `setForeground`, `getForegroundInfo` low-importance channel with resource strings (API 26/30 emulator runs went through it).
- **Headless engine:** `FlutterEngineGroup`, `automaticallyRegisterPlugins=false`, explicit allowlist incl. `SecretStoreRegistration` and the JNI pair (deviation 2 is correct for path_provider_android 2.3); `@pragma('vm:entry-point')` in the root library (deviation 5).
- **Q6:** `allowCreateOrWipe` threads through `KeyBootstrap.obtain/reportRejected(mayCreate:)`, `_recoverFiles` (never deletes `.migrate.part`), the WAL-only leftover path and `MigrationGuard.allowCreate` (`user_version 0` → `DB_DEFERRED`, no `onCreate`). `headless_open_test` covers each; negative proofs listed in T-008.md went red.
- **Ack-after-commit:** `IngestionCycle` drain → parse → one transaction → ack; commit throw, ack failure, drain failure and open failure never ack; parse crash stores for review. Tests assert the order, not just the outcome.
- **Latency report:** the t9 fallback is a correct upper bound (Dart acks only after the commit returns) and those rows are counted, not dropped.
- **Placement:** `src/devSms` only; WorkManager is `devSmsImplementation`; CI checks merged manifest + dex of all six APKs.
- **Q7:** not implemented, correctly out of scope; design recorded for T-042/T-048; `kInboxCatchUpEnabled = false`. The follow-ups are still listed as "to file (Lead)" and are not yet in `implementation-status.md`.
