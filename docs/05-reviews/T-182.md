### Design-note conformance (traced in code)
- **Check order (§3).** `SeatKeyParser.Parse` (`SeatKeyProofVerifier.cs:202-252`) checks the count before decoding (steps 1→2→3→4). `Verify` (`:144-163`) runs `P256.Check` on every element with no early exit and keeps the first failing reason (`first ??=`). It records one metric sample, and `ParseAndVerify` gives exactly one per call.
- **Strict base64url.** `TryDecodeCanonical` (`:260-287`) applies an exact length of 87/86, the ASCII alphabet, `OperationStatus.Done`, consumed/written counts and an ordinal re-encode compare. Deviation 4 is accurate: the re-encode is kept as defence in depth.
- **0x04 prefix.** It is checked in the parser (step 3) and again in `P256.IsUncompressedOnCurve`. The 0x06 and 0x07 vectors give `bad_point`.
- **Distinct keys.** Pairwise ordinal comparison of the decoded points.
- **Point check.** `P256.cs:38-55` checks x < p, y < p and y² ≡ x³ + ax + b with a = p − 3. It runs before import. `P256ConstantsTests` pins the constants against `ExportExplicitParameters`.
- **r and s range.** `1 ≤ r, s ≤ n−1` is checked explicitly (`P256.cs:71-76`) before `VerifyData`. A `CryptographicException` is mapped to `bad_point` on import and `bad_signature` on verify. The key is disposed.
- **High-S** is accepted: there is no low-S check. The `restore` vector is high-S and `restore-low-s` is its low-S form; both verify. Wycheproof's high-S `valid` cases pass.
- **Uniform 400 / element 0.** The reason is internal (`SeatKeyRejection`) and reaches only the metric tags. `CheckElementZeroAsync` returns status and computed hash in one KMS call. `MatchSeatAsync` (`SeatKeyHasher.cs:92-110`) hashes every `Others` element, compares each in constant time with no early exit, and never considers element 0.
- **Keyed hashes (§4).** The inputs are 109, 101 and 22 bytes with first bytes `i`, a hex digit and `z`. Points are re-checked in `CheckPoint`. `InstallKeyHash` and `SeatKeyHash` are separate sealed classes with no shared base and no cross-type `Equals`, and the reflection test confirms it. They compare with `FixedTimeEquals`, `ToStorage` and `FromStored` copy, and a length other than 32 throws with a constant message. `SeatCheckValue.Matches` is constant-time after a lower-case hex format check.
- **K_seat wiring (§6).** `KmsSeatKeyMac` goes through `IKeyedHasher.HmacSha256Async(KeyedHashKey.Seat, …)`. `SeatKeyStartupCheck` is an `IHostedService`, registered after `KmsStartupCheck` and following the same pattern. Outside Development/Testing it refuses a missing value, a malformed value, a mismatch, or `KmsUnavailableException`. All messages are constants and no inner exception is attached. `Program.cs` calls `AddZaghlolSeatKeys()` after `AddZaghlolKms()`. `dev-keys.sh` matches `LocalKms`, which reads the key as base64 text.
- **Test signer.** `SeatKeyTestSigner.Message` builds the bytes with its own code (u8 literals and collection expressions) and shares nothing with `SeatKeyProofVerifier.Message`. DER encoding uses minimal two's-complement integers, which is correct. `NonCanonical` flips a trailing bit that the encoder pads with zero.
- **Exclusion rule.** It covers Domain, Application, Infrastructure and Api (Api.Tests), plus Workers and Ops in their own test projects. `TheRuleRecognisesTestSupport` proves the rule matches the shared fakes. `NoSourceProjectReachesIntoTests` scans the `src/*.csproj` include paths.

### Deviations
1. **`FakePriceProvider` allowlist: accepted.** It is a real production type (T-127), selected by configuration and refused in Production. A one-entry, fully qualified allowlist is the least invasive option. See finding 3 for the stale-entry risk.
2. **Internal parser with an instance entry point: accepted.** It keeps the metric in one place. `Parse`, `Verify` and `ParseAndVerify` still give T-185 the Parse → Digest → Verify split the note requires.
3. **Install-bound `VerifiedSeatKey`: accepted, and stronger than the note.** A mismatch throws a constant-message `ArgumentException` (a caller bug), and a test covers it.
4. **Decoder wording: accepted.** The behaviour is the note's; only the explanation changed.
5. **Fail when wrong, even in Development/Testing: accepted.** It is stricter and documented in `deployment.md` §3. Strict for every environment that is not Development or Testing, including `Ci`. `FakeKms.Settings()` emits a matching `SeatCheck`, so the test hosts pass.
6. **No semaphore: accepted.** `MaxKeys` = 5 bounds the fan-out at 4, and a test asserts this.

`Verify` throws `ArgumentException` when the challenge's op differs from the parsed op (`SeatKeyProofVerifier.cs:148-151`). This is a caller bug, not input, so it doesn't break the "total on input" rule, and `AChallengeOfAnotherOpIsACallerBug` covers it.
