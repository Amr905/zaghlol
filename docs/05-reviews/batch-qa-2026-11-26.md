### BUG-015
- Root cause is right. Riverpod 3 retries failed providers by default, so an autoDispose `FutureProvider` re-enters loading after each failure. The existing test only passed because it set `retry: (_, _) => null` on its own `ProviderContainer`, which hid the bug. Production `ProviderScope` (`main.dart`) sets no retry.
- Verified the new test fails without the fix: I removed the `retry` line temporarily, the test failed ("it never goes back to loading"), then I restored the file. It passes with the fix. It also asserts `calls == 1`.
- The "Try again" button (`paywall_screen.dart:365`) uses `ref.invalidate`, which still re-queries, so recovery works.
- minor, `gold_ui_ports.dart:74-96`: the reformat of the whole provider body (re-indent) makes the diff larger than the one-line change. Harmless.

### BUG-018 (`z_sheet.dart:19`, `useRootNavigator: true`)
Checked all 41 `showZSheet` call sites in `app/lib`.
- Every closure inside a sheet pops through the builder's `ctx` or through a widget's own `context`, which now sits in the root navigator, so it pops the sheet. Examples: `AddIgnoreForm`, `_SetBalanceForm`, `_OverrideForm`, `_LinkPicker`, `HomeCardFilterSheet`, `ChartPeriodSheetBody`, `passphrase_sheet`, `compare`.
- No caller pops or pushes through the caller's `context` or a branch `NavigatorState` captured before the sheet while the sheet is open. The captured `nav = Navigator.of(context)` in `capture_settings_screen.dart:473` and `:641` and `transaction_detail_screen.dart:366` are taken inside widgets that are themselves in the sheet or run after it closes.
- No go_router calls from inside a sheet. `ScaffoldMessenger` is app-level, so snackbars still work.
- The scoped `ProviderScope` in `chart_drill.dart:77` does not change anything. Sheets were never descendants of that route's subtree (popup routes are siblings in the Navigator overlay), so they never saw those overrides.
- No inherited widgets are lost: there is no shell-level InheritedWidget, `Theme`, `Localizations` or `Directionality` override above the sheets. `MaterialApp.router`'s Theme, Localizations and the root `ProviderScope` still apply.
- One behaviour change, expected and wanted: the Android back button and `PopScope` now pop the sheet from the root navigator first.
- minor, `z_sheet.dart:19`: no automated test. The justification (needs the shell on a device) is fair, but a small widget test with a `StatefulShellRoute` that asserts the sheet is found in the root navigator would lock it in. Optional follow-up.
