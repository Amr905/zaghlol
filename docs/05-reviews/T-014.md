## Judgement of implementer choices
- NetworkFailure as one class with named constructors: acceptable. Satisfies "NetworkFailure{offline|timeout|server(code)}" in error-handling §1, keeps the sealed switch at six areas, and `serverStatus` is an int so no free text. Invalid states (kind=server with null status) are unreachable through the public constructors. Approved.
- Event payloads: ids/enums/ints only, no amounts or text, consistent with architecture (events carry no PII). Shape of `TransactionsChanged`, `CatalogUpdated(version:int)` fine; see findings 3-5 for BudgetThresholdCrossed and MascotTrigger.
- publish-after-dispose no-op: appropriate (late async work after provider disposal must not crash); tested; `isClosed` exposed.
- Nothing added under app/lib/core: confirmed (diff touches only packages/zaghlol_domain). Task lists `app/lib/core/result` as an affected component and architecture §4.2 lists `result/` in the app; since the domain package is the home and the app can import it, this is a reasonable deviation. Consumers should import from `zaghlol_domain` directly rather than add a re-export shim; no conflict with docs/03-technical.
- Domain stays pure Dart (only `dart:async`); no layer violations.
