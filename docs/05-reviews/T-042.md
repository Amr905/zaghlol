**Focus points checked.**
- *Query shape:* the selection comes only from `selection(n)` (constant text and `?`). It has no `LIKE`, functions, `COLLATE` or `LIMIT`, and the fake provider rejects any other text. Each query binds at most 898 variants + 2 arguments. An address is never split across chunks, and variants are de-duplicated across addresses, so every row matches exactly one chunk.
- *Cursor:* the CRC covers the variants chunk by chunk, plus `since`. A foreign or tampered token, another sender set or another `since` gives `INVALID_ARGUMENT`. The parser is strict (length cap, anchored regex, no leading zeros). A Guard change that alters the allowlisted subset between pages changes the CRC and also gives `INVALID_ARGUMENT`. Platform-channels §2 records that T-048 then restarts the scan.
- *Paging:* `pageSize` counts rows read (kept + dropped); leftover budget carries into the next chunk. If a provider ignores `_id > ?`, the reader returns `IO_ERROR` instead of looping.
- *Guard and rate limiter:* every row goes through `guard.decide` directly, not `GuardRuntime.decide`, so the rate limiter is not applied (`twentyOneRowsFromOneSenderAreAllReturned`). The Guard snapshot is taken once per call.
- *Time bounds:* `since` is raised to now − 25 months; a future `since` returns an empty last page; rows are re-checked against `date`.
- *Multipart:* there is no joining. The device test shows the 3-part message comes back as one whole row.
- *Errors:* `NOT_AVAILABLE` is returned before the provider is touched. Not granted, or a provider `SecurityException`, gives `PERMISSION_DENIED`. Errors carry the code only.
- *Cancellation:* the reader keeps no state between calls.
- *Negative proof spot-check:* I removed the per-row re-check at `InboxReader.kt:137` in a copy of the tree. Only `aProviderIgnoringTheSelectionHasItsForeignRowsSkippedNotReturned` went red, as the report claims.

**Wiring gap.** No host gets a reader yet, so `queryInbox` returns `NOT_AVAILABLE` everywhere. This is acceptable: it fails closed, T-048 (the only consumer) is not built yet, the production reader path is proven directly by the instrumented test, and T-041's `CaptureRuntime.attachUi` already has the hook comment (`origin/task/T-041-worker` CaptureRuntime.kt:188). The headless guarantee therefore depends on one future line, and nothing tests it at the composition point yet; see m-1.

**Deviations.** `SimSlot` lives in `AndroidInbox.kt`: accepted, with a move later (m-3). The stricter checksum, which includes chunk boundaries, is accepted because it is a strict superset of the note. Moving the negative proof for the pageSize clamp to `pageSizeIsClampedTo1Through500` is accepted.
