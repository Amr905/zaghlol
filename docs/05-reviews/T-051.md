| 1 | minor | `app/lib/features/budget/data/payday_schedule_store.dart:49,68` | The setPayday race the builder admits: the cache is cleared **before** `payday_eras` is written. A closed-cycle recompute in that window re-caches under the old schedule. Rows keyed by old start dates are mostly orphaned, but a row whose start date coincides with a new cycle start (different end) would be served wrongly until the next `invalidateAll`. Window is milliseconds and only a first explicit payday (history rewrite) can change closed cycles, so rated **minor**. | Follow-up: also call `_invalidateCycles` **after** the two settings writes (one line each in `load()` reconcile and `setPayday`). Same compute-then-write non-atomicity exists in `CycleRepository.totals` (`cycle_repository.dart:48`) for any invalidation event; a generation counter checked before `replaceCycle` would close both. |
| 2 | minor | `app/lib/features/budget/data/cycle_cache_invalidator.dart:36-62` | Resume sweep maps a changed row only to its **own** cycle. A headless status change on a source row (for example a refund marked `reversed`/soft-deleted) also changes the cycle of the expense it offsets (BR-XFR-07), which is not swept; a link whose row moved date also leaves the old cycle stale. The UI path is covered by emitter obligations (T-077/T-089/T-049), the headless path is not. | Follow-up: for rows with `updated_at > since`, also add the cycles of their linked counterparts (join `offset_links` both ways). |
| 3 | minor | `app/lib/features/budget/application/budget_providers.dart:132-137` | Cache invalidation (`invalidator.attach`) lives inside `currentCycleOverviewProvider`, which re-subscribes on every `invalidateSelf`. Plus `transactionsChangedProvider` defaults to an empty stream, so until T-052 wires the bus nothing invalidates except resume sweep (itself unwired). | Follow-up (owner T-052): move `attach` and the resume `sweepSince` call to a long-lived app-level provider/lifecycle observer; add an app-level test that a bus event deletes the cache with no Home provider mounted. |

## Design-note conformance (as asked)
- Payday 1-28 enforced in `PaydayEra` and `SettingsException`; eras with `from == null` rewrite history (Q1 flag `kFirstPaydayRewritesHistory` single decision point). Conforms.
- Civil dates from the stored offset (`CivilDate.fromLocalMs` floor division, `loadRows` widened +-18 h then filtered by local date); no `DateTime.now` (grep test passes; my grep of the budget dirs found none). Conforms.
- Counting rules (declined/reversed/internal/deleted out, pending in spend and `pendingSpend`, fee and `transfer_out` spend, refund as income net of links, offsets restated on the expense's cycle) match design note §3. Floor rounding via `Money.mulDiv`; burn line uses the real cycle length. Conforms.
- Per-currency isolation: all maps keyed by currency; no cross-currency API. Conforms.
- Deviations: `sourceValid` -> `isActive` is sound (see nit 5 for the one gap); `pendingSpend` zero on cached closed cycles is not a visible bug (finding 4); empty closed cycle recompute is one indexed range read, acceptable.
- Ingest change is minimal: `cycleKeyFor` signature and key format, `BatchContext.paydayEras`, schedule in batch state; payday-25 and default tests updated to ISO keys, one new era test. T-046 behaviour is otherwise unchanged (full ingest suite green).
- Tests: meaningful (hand-derived expected minor units, encrypted-DB cache tests, sweep two-actor simulation, DST and TZ variants). Spot-checked negative proof (ceil) turns red as claimed.
