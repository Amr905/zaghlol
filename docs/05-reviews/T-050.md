## Judgement on the requested points
- **Filter semantics (FR-TXN-01):** correct. Period is half-open [from, to) on UTC ms; empty set = any; sets are OR inside, AND across; all values are bound parameters; deleted rows always excluded; deterministic order (`occurred_at DESC, id`). Covered by "period is half-open", "filters combine with AND and with text", paging/count.
- **Short-query routing:** sound. 1-2 chars use the word-prefix table; 1-2 digits (Latin or Arabic-Indic, normalised by `_latinDigits`) also match `amount_text LIKE 'N.%'` or `'N %'`. I checked the `transactions_fts_row` view: amount_text is `latin || ' ' || arabic-indic` with the currency's exponent (0: `50 ٥٠`; 2: `50.00 ٥٠٫٠٠`; 3: `50.000 ...`), no thousands separators. So "50" matches EGP 50.00, KWD 50.000 and JPY 50, not 500 or 1250. "50 → ¥50" is correct per exponent (whole units). The LIKE argument is digits only, so no wildcard injection. Semantics differ from 3+ chars (substring via trigram vs whole-unit for 1-2 digits); intentional and tested ("5" does not match 50.00), see n-1.
- **Soft delete keeps links, `active*` DAO methods:** sound. Joins on both sides with `deleted_at IS NULL`; test covers delete/Undo of each side. Callers are not forced (m-2).
- **All-or-none bulk ops:** correct. Ids de-duplicated, 1..1000, one DB transaction; the first unknown/already-deleted id throws and rolls back (tests "bulk delete with one unknown id changes nothing", "restore ... all-or-none").
- **Purge:** only rows with `deleted_at <= now - 30d`; live rows excluded (`deleted_at IS NOT NULL`); boundary (exactly 30 d purged, 29 d kept) and idempotence tested; clock moved back never purges (test "deleted_at in the future"). Cascade + FTS integrity-check tested. Clock jumped ahead purges early: acceptable under self-check §1. The rows were deleted by the user's explicit action, so the purge is not destruction on doubt; only the Undo window shortens. It needs to be stated outside code (m-3).
- **`TransactionsDao.softDelete` behaviour change:** acceptable and an improvement (live rows only; first `deleted_at` is kept, so re-deleting cannot extend the purge clock). Only other caller is `transactions_search_test.dart:211`, still passing.
- **Validation before SQL:** negative amounts, tz offset range, empty account id, id/filter-set counts, text length (merchant 200, note 1000 runes), done before the DB call; FK errors surface as code-only `DbWriteException` (tested). Currency is not forced to the account's `default_currency`, which is right because `multi_currency` accounts exist (BR-FX-03, FR-TXN-04).
- **Money:** only `Money`/int minor units; no `double` anywhere in the diff.
- **Errors:** `TransactionsException` carries constant codes only; sentinel test shows no row values in errors.
- **Riverpod:** `transactionRepositoryProvider` builds from `appDatabaseProvider`; clock and id generator injectable and overridden in tests; no singletons. See n-2 on names.
- **Self-check:** §1 destructive path reviewed above; §2 `edit` reads and writes in one DB transaction, bulk ops atomic, the trigger-based link guards still apply (tested "edit that breaks an offset link aborts"); §3 caps on text, ids, sets; §5 no logging; §6 see m-3; §7 each AC maps to a named test.
