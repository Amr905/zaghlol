## Focus checks requested by the Lead
- **Throttle claim race.** `SyncStore.ClaimAsync` runs a conditional `UPDATE ... WHERE (last_sync_at IS NULL OR last_sync_at <= @cutoff)` under READ COMMITTED. A concurrent second UPDATE blocks on the row lock, then re-checks the WHERE against the committed row and matches 0 rows. Intake and DAU run only after a 1-row claim, in the same transaction. The fast-path check (`now >= last + window`) and the SQL check (`last <= now - window`) agree. A lost claim re-reads the row and returns the winner's `nextSyncNotBefore`, or 401 if the install was tombstoned. Tests: `SyncStoreTests.ConcurrentClaimsHaveExactlyOneWinnerAndOneDailyActive` (8 claims), the endpoint `TwoSimultaneousSyncsGiveOneFullAnswerAndOneDailyActive`, and `SyncServiceTests.ALostClaimRaceIsTheThrottleAnswerOfTheWinner`. OK.
- **Nothing written on throttle.** The fast path returns before any read or write. A lost claim rolls back. OK. The only side effects of a lost race are metrics (minor 1).
- **503 vs `prices:null`.** Catalog, category codes, flags and entitlement go through `RequiredAsync` and fail with 503. Prices degrade to `null` plus `block_failure{prices}`. A missing `catalog_versions` row for full mode is 503. Transient DB failures on the read or the claim are 503 with `Retry-After: 30` (deviation 7). OK.
- **BR-SYNC-03 boundary.** `StrictJson` disallows unmapped members, is case-sensitive and has strict number handling, and this applies to every nested type. The reflection allow-list contract test pins the request members. OK.
- **Signing and nonce echo.** The endpoint has `.WithTimeNonce().RequireResponseSignature()` and no idempotency filter. `AnchoredJsonResult` exposes `Value` so the T-123 nonce filter can check the echo, and it writes the pre-serialized bytes that the signer signs. OK.
- **Metrics tag sets.** The tags are fixed, `SeedSeries` covers every combination, and `SyncMetricsTests` checks that only fixed tags are used. Flag keys are from the closed set. OK.
- **Logging.** There are three fixed-code events with a fixed-word argument. Request data, nonce, token, hash and `entitlementIssuedAt` are never logged. OK; see minor 2 for the opposite problem.
- **Declared deviations.** (1) The SECURITY DEFINER counter keeps SEC F10. Its search_path is fixed, it is REVOKEd from PUBLIC with EXECUTE for app_rw only, and `GrantTests` was updated. Accepted (see nit 2). (2) Validating the throttle answer against `SyncResponse` (whose `required` lists only `serverTime` and `nextSyncNotBefore`) plus the exact 3-key check is equivalent. Accepted. (3) Hand-rolled folding: accepted, with minor 3 on coverage. (4) `^[a-z0-9_]{2,32}$` equals the OpenAPI `InstitutionCode` and is a subset of the DB CHECK. Accepted. (5) The domain-separated label on the existing pepper is sound, and there is a known-answer test (`TheInstallHashIsAnHmacOfTheLabelledInstallId`). Accepted. (6) Size metric only on full answers: accepted, because the throttle body is constant-size. (7) Accepted.
