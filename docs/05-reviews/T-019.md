## Code review

### Migration data safety (focus)
- **Copy is lossless and checked.** `_from3To4` (`app/lib/core/db/app_database.dart:105`) creates `<t>__v4` from the v4 DDL, copies `INSERT … (cols) SELECT cols` by explicit column name, compares `count(*)` old vs new, only then `DROP` + `RENAME` + recreate indexes. A test pins the v3 `PRAGMA table_info` column list = `TableRebuild.columns`, so no column is silently left out. Rowids of `catalog_merchants` (INTEGER PK) are copied, so `catalog_aliases` FKs and `catalog_alias_fts` (on the untouched `catalog_aliases`) stay consistent; the test runs FTS `integrity-check` and a trigram query after the upgrade.
- **FKs.** `PRAGMA foreign_keys = OFF` runs outside the upgrade transaction (where it takes effect), so the `DROP TABLE` of a parent doesn't cascade to `catalog_aliases` / `recurring_occurrences`; `foreign_key_check` runs before commit; `beforeOpen` turns FKs back on. The test compares every row of all 20 v3 tables before/after (children included) and proves both cascades still work from the rebuilt parents.
- **Triggers/views.** None of the four rebuilt tables carries a trigger or is referenced by a view (checked in `financial.drift` / `financial_b.drift`), so `DROP` loses nothing the step doesn't recreate. Indexes are recreated and the test pins their count per table.
- **Failure path.** REAL `1.5`, NUL keyword, stray `assets`, stray `merchant_rules__v4` each give `DB_MIGRATION_FAILED(restored)`, byte-identical files, still v3, every row intact. Nothing is coerced.
- **Frozen.** Statement lists are constants tested against the committed dumps; no `IF NOT EXISTS` on added objects. Re-open after migration is a plain open.
- **busy_timeout / FU-094.** T-019 does not touch `encrypted_open.dart` and sets no `busy_timeout` in `app/lib` (the only hit is the existing opener line FU-094 replaces). No textual conflict. See Notes.

### CHECKs and money
- Every new and rebuilt INTEGER column has `typeof = 'integer'` (sweep test); free-text and form columns refuse NUL on the bytes (sweep test); money columns are ±(2^53−1) with a named currency partner and pair CHECKs, enforced schema-wide by `schema_audit_test` (a future `*_minor` column without them fails).
- Zakah history: FK without cascade, status ⇔ amounts CHECK, `paid ≤ amount`.
- `ux_ignore_institution` closes the NULL-`last4` hole in the spec's `UNIQUE`.

### Concurrency ("exactly one winner")
Real, on two connections to the same encrypted file (one per executor kind, `secondConnection()` in `financial_c_daos_test.dart:51`): secure-state CAS (insert-if-absent and update-if-equal, 6 racers each → 1 winner), review `resolve`, voice `incrementIfBelow` (20 racers, limit 15 → 15), and `recordConfirmation` (all count). Each is a single conditional statement; `changes()` semantics of `ON CONFLICT DO UPDATE … WHERE` are used correctly (0 when the WHERE fails).
