## Parity check (the focus areas)
- **foldKey/foldKeyLines** (`TextFold.kt:59-135`): this is a line-for-line port of `_transform` and its tables (`_isSpace`, `_isLineBreak`, `_isInvisible`, `_isMatchingMark`, `_mapChar`, `_foldLetter`) over UTF-16 code units, with ASCII `+0x20` only. The `dartTrim` set matches the Dart SDK set, and the two new golden cases pin it.
- **Regex semantics**: Dart compiles with `RegExp(p, unicode: true)` and Kotlin with `Regex(p)` with no flags. Both are case-sensitive and match by code point. Java `$` and `.` treat `\r`, U+0085, U+2028 and U+2029 as line terminators, but every one of them is folded away. `\n` survives only in `lines`, and never at the start or end (asserted for every golden body). Every match is `containsMatchIn`/`find`; there is no `matches()`. The global drop runs on `lines` and everything else on `key`. The step order matches `capture_guard.dart` exactly, `config_invalid` first. See finding 1 for compile-acceptance differences.
- **last4 (deviation 1)**: `guardLast4` takes the first match per pattern, then moves to the next pattern, which equals Dart `firstMatch`. I agree with following the code over the note: the portable lint (`[0-9]{4}`, one group) makes the note's `findAll` variant unobservable. `last4UsesTheFirstMatchOfEachPatternOnly` pins it.
- **BOM (deviation 3)**: I probed Dart myself. `Utf8Decoder` strips one leading BOM and keeps a BOM in the middle. Kotlin strips one leading U+FEFF after the strict decode, and StrictJson rejects any other U+FEFF. This is parity.
- **Duplicate package (deviation 4)**: mirroring is the right call, because the golden suite is the contract and a one-sided fix would split the platforms. The stated reason is wrong, though (finding 2).
- **StrictJson**: duplicate key keeps the last value in the first position. `-0` parses as an int in both (probed). An integer above 2^63 is a double in Dart and `wrongType` in Kotlin. The depth cap of 16 changes only the diag code for absurd input, not the mode.
- **Reader**: caps, error codes, paths and `finish()` strictness are all identical to `guard_config.dart`.
- **Rate limiter**: a line-for-line port (key, `>=` boundary, backwards clock, LRU 64), plus `@Synchronized`.
- **Concurrency**: the snapshot is immutable behind an `AtomicReference`. The fast path takes no lock. The first load and `writeUser` share one lock. Compiled `Pattern`s are thread-safe. The limiter is created under the lock with double-checked `@Volatile`.
- **StackOverflowError**: `decide` catches `Throwable` and rethrows `VirtualMachineError`, except `StackOverflowError`. The small-stack test really overflows: it would otherwise not return `config_invalid`. The adversarial golden bodies all expect keep, so an overflow on the default JVM stack would show up as red.
- **Store**: only `AEADBadTagException` (or a size the writer never produces) proves the file unreadable. Any other read, decrypt or Keystore failure is `Transient` and not cached. The file is never deleted. Writes go to a tmp file with fsync, then an atomic rename, then a best-effort directory fsync.
