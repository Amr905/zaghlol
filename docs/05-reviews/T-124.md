## Implementer deviations (judged)
| # | Deviation | Ruling |
|---|-----------|--------|
| 1 | 201 from `POST /v1/installs` is not signed | **Accepted.** backend-api §1 signs only the 200s of the six anchoring operations, and `registerInstall` is not one. The design note was wrong here. |
| 2 | Regex patterns as C# constants, guarded by a spec-drift contract test | **Accepted.** `TheServerSidePatternsAreTheSpecsPatterns` compares `appVersion` pattern and `maxLength`, the `Platform` enum and the `IdempotencyKey` pattern with the OpenAPI file. That meets the "not duplicated by hand" intent. The extra printable-ASCII guard covers .NET `\d` and `$` quirks. |
| 3 | Token hash = SHA-256 of the base64url ASCII text | **Accepted.** The note's "SHA-256(token)" leaves the input form open. Security is the same, and only the server ever computes it. |
| 4 | Registration bucket chained before the /24 bucket | **Accepted.** A registration flood that the 60/h bucket refuses no longer drains the general /24 bucket. |
| 5 | Auth handler skips endpoints without the install-token metadata and resolves the store per request | **Accepted.** It fails closed: an endpoint that has the policy but not the metadata gets `NoResult` and then a 401 challenge. |
| 6 | No test for re-signing a replay under a rotated kid | **Accepted as nit** (finding 7). The replay passes through the same `ResponseSigningMiddleware`, which T-123 tests with the active key. The test here proves the replay is signed. |
| 7 | `type: about:blank` default, transient `DbException` → 503, `installHash=unavailable`, two metrics | **Accepted.** The 503 and `unavailable` are in the design note. `about:blank` is RFC 9457 §4.2.1 and the contract requires it. The metric tags are the constants `network`, `token` and `idempotency`. The 503 mapping has no test (finding 3). |
