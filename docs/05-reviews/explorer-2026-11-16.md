# Automated app explorer, run 2026-11-16

What it is: `app/integration_test/app_explorer_test.dart` (support in `integration_test/support/explorer*.dart`). It starts the real app (Arabic, seeded synthetic data: 5 accounts, 30 transactions, 2 review items) on the Android emulator (API 34, flavor devSms), opens every screen it can reach, taps every tappable control once, goes back, and records: uncaught exceptions, RenderFlex overflows, taps that change nothing ("dead taps"), screens that stay open after Back ("dead ends"), screens that could not be reopened ("restore", an explorer limit), and the app leaving the foreground. One screenshot per screen (`device-shots` branch, `<sha>/p<part>-x-NN.png`).

Run by `.github/workflows/device-flows.yml` (manual dispatch with `explorer_only`, and on pushes to `ci/**`). Not a merge gate.

## Stability (what was wrong with the first runs)

The single 40 minute run died on an Android Java-heap `OutOfMemoryError` (heap 56 MB to 195 MB over about 46 screens) with the process killed. Fix: one app process per part (tabs 0 to 3 and the Add sheet), `pm clear` between parts, 15 minute cap per part, and `android:largeHeap` in the debug manifest only. Final run 43852505077 (head a2fb84f0): SUCCESS, no uncaught exceptions; the earlier run 43834185980 shows the numbers below: all five parts completed, no crash, about 31 minutes in total (Money tab 10 min, the rest 1 to 7 min).
