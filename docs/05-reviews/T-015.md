### State table check (key × DB)

Traced `KeyBootstrap._decide` / `_create` against design note §3: all 8 cells match. `found`+DB absent and `unusable`+DB absent delete then create (`rotatedNoDb`); `notFound`/`unusable`+DB present return `KeyInvalidated` holding the lease with no store write; `unavailable` → `KeyUnavailable` in both columns. `_create` checks `anyExists()` again just before the first write. An unreadable DB directory throws → `KeyUnavailable`, never "absent". `_guarded` maps every `SecretStoreException` and `FileSystemException` to a non-wiping outcome. Dart side: no path reaches a write or `KeyInvalidated` on a transient error. The native side has one such path (M-1).

### Checks with no finding

- **No key caching:** `keyBootstrapProvider` and friends are plain `Provider`s that hold only collaborators. `KeyBootstrap` has no mutable state. `db_key_providers_test` "the bootstrap is stateless" proves that every `obtain()` reads the store.
- **Zeroization:** the candidate, the read buffer and the stored copy are wiped in every branch, including exceptions (`finally` / catch-rethrow). Pigeon codec buffers are copied before wiping (accepted limit §5).
- **Kotlin `KeyErrorClassifier`:** AEAD and `KeyPermanentlyInvalidatedException` → UNUSABLE; API 33 `KeyStoreException` is UNUSABLE only when it is not transient and the code is DOES_NOT_EXIST/CORRUPTED; IOException and anything else → UNAVAILABLE; the cause chain is bounded and self-cycle-safe. Alias-null → UNUSABLE matches the note. The host maps read throwables to UNAVAILABLE, and every other error to code-only `KEY_STORE_FAILED`/`LEASE_TIMEOUT` with no message.
- **Swift status mapping:** success+32 bytes → found; success with another length → unusable; success+nil → unavailable; −25300 → notFound; everything else → unavailable. Queries always name service+account and `synchronizable=false`. Add uses `AfterFirstUnlockThisDeviceOnly`. `errSecDuplicateItem` returns the winner.
- **Cross-engine lease:** one process-wide manager per platform; ids are unique and never 0; a stale release is ignored; writes check `isValid` natively (stale lease → `LEASE_TIMEOUT`). `@Synchronized` / `NSLock` on the slot store serialise reads and writes across engines. `BootstrapLease.release` is idempotent, and `_withLease` releases on unexpected throws.
- **Tests:** meaningful assertions (call recording proves zero writes; file snapshots; buffers zeroed; redaction of every `toString`). Native JVM + XCTest cover the mapping, retries, winner semantics, refusal, read-back failure and lease timing. CI asserts that the named XCTests passed and that the Kotlin tests actually ran. Keys are synthetic, and none appear in test names or reasons.
- **Scope:** changes stay inside the task and its declared doc amendments. No backend calls, no UI, no strings.
