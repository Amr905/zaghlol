Other checks:
- Money: income target stored as `<minor>:<CODE>` via `Money.tryFromStorage`; strict `'$minor' == parts[0]` check; no double.
- Invalid writes: `format` requires a round trip, else `SettingsException('SETTING_INVALID_VALUE')` is thrown before `_dao.write`, so nothing is written. Errors are code-only.
- Corrupt values: `parse` falls back to the default and never throws. Only an explicit `reset` deletes. A bad stored value is left in place until overwritten.
- Null on `set` unsets the key via `reset`. This is documented.
- Concurrency: single upsert per write; two-repository test present.
