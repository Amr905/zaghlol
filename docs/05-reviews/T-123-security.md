## Summary

The design note's main promise holds: no API, log, exception, metric or span exposes private, HMAC or data-key material. Signatures are verified before they are returned. Purpose separation is enforced in two places, the key ring and the `Signer` methods. The process fails closed on a bad ring or on the Local provider outside Development/Testing. The time nonce is validated strictly, kept only in an `HttpContext` feature, and stays out of logs and spans in the capture test. The T-122 follow-ups FU-019, FU-022, FU-023, FU-025 and FU-026 are addressed correctly. The findings below are defence-in-depth gaps and items for later owner tasks, mostly T-140 (cloud adapter / IaC), T-132 (live nonce contract) and T-141 (app key embedding).

| Verify-before-return | PASS | `Signer.SignDigestAsync` checks every KMS signature against the configured JWK (`VerifiesDigest`, 64-byte length check) and fails closed as `KmsUnavailableException` → 503. A wrong `KeyRef` can never yield a header the app accepts. |
| Key ring rotation / kid & purpose separation | PASS | `SigningKeyRing` requires unique kids, unique key refs, the kid regex `^[se][0-9]{4}[a-z]\z`, a prefix matching the purpose, an on-curve P-256 JWK, and exactly one Active key per purpose. `Signer.SignAsync` accepts only `Sync` and `CreateJwsAsync` only `Entitlement`. Next/Retired keys can't sign by construction (`Active()` uses `Single`). The JWS header is built from the regex-validated kid, so JSON injection is impossible. |

The CI step "Production image refuses to start without a KMS" checks a non-zero, non-timeout exit with `KmsConfigurationException` in the log. |
| Time nonce (R4-2) | PASS | `TimeNonceFilter.TryRead`: absent → `null`; otherwise exactly one value of 22 chars, `[A-Za-z0-9_-]{21}[AQgw]`. Empty, duplicate, comma-joined, padded and `+`/`/` values give 400 with a fixed body that has no `detail` and no echo. The value lives only in `TimeNonceFeature`, whose `ToString()` is redacted. It is not added to Activity tags, LogContext or ProblemDetails (`ProblemDetailsCustomizer` adds only `code` and `correlationId`). `TheNonceAppearsInNoLogSpanOrExceptionOutput` covers the echo, throw and malformed paths against logs and spans. The echo-mismatch check throws a constant-message exception → 500, unsigned. |
| Response signing middleware | PASS | Body buffered via `StreamResponseBodyFeature`. The original feature is restored in `finally`. A handler-supplied `Zaghlol-Signature` is always removed (L65). A KMS failure surfaces as 503 + `Retry-After: 5` via `GlobalExceptionHandler`, before any byte is written. Compression (none yet) is documented to stay outside. |
| Envelope v1 | PASS | AES-256-GCM, fresh DEK per record from the KMS, random 96-bit nonce per record (with a fresh key, collision is not a concern). AAD = `"zaghlol-env-v1" ‖ 0x00 ‖ UTF-8(context)`; an empty context is refused. The parser bounds-checks every length. The key ref from the blob is checked against `EnvelopeDecryptKeyRefs` **before** any KMS call (L224–228; `AfterKeyRotation…` asserts the call count is unchanged). Every failure maps to a constant `EnvelopeDecryptionException`. `LocalKms` binds the key ref into the DEK-wrap AAD. Tamper and truncation tests run over every byte. |
| Local key refs | PASS | `local:` prefix plus `^[a-z0-9][a-z0-9-]{0,62}\z`; path traversal is rejected (`LocalKeyReferencesCannotLeaveTheKeyDirectory`). |
| DB role guard (FU-019, FU-023) | PASS | Rejects when `session_user <> current_user` (catches `-c role=` and `SET ROLE` at check time). Migrator membership is rejected. The group set must be exactly `{expected}`, so `pg_write_all_data`, provider admin groups and intermediates are all rejected.
