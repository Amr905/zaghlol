## Focus points
- **Tier order / never overwrite.** `Categorizer._decide` matches the note: rule A (counterparty over merchant_norm), own_account, P2P, exact, prefix/token, fuzzy, rule B, keywords, none; archived/missing rule category ignored. `Recategorizer.apply` is one `UPDATE` with deleted/internal/verified/source/old-category/old-merchant/archived-target guards and a no-op check; `user` and `user_rule` rows are excluded; `none` returns 0. Correct.
- **FU-095 harness.** `db_interleave.dart` is a genuine sequencing: blocker connection holds an uncommitted write lock, the action starts, `expect(done, isFalse)` proves it is blocked in the busy handler, then the blocker commits and the action runs with stale reads. It is deterministic up to a 300 ms settle (a slow machine only makes the "pending" proof weaker, never flaky-red). Limit (two already-running statements) is stated honestly. Accepted.
- **Integer Jaro-Winkler.** Derivation re-checked: window floor(max/2)-1, half-transposition count with t = half/2 kept exact, common denominator 6·la·lb·m, boost only when J > 7/10, prefix cap min(len, 4), rounding to nearest millionth. Overflow is not a concern for 64-char keys on 64-bit ints. Test compares to a float reference on golden vectors and a word grid; `ezaby/ezabi` is exactly 920000 and the 919999/920000/920001 edges are tested.
- **FTS safety.** `aliasCandidates` (T-018) is reached only after `isMerchantKey` (`[a-z0-9]` words) and rebuilds the MATCH string from quoted 3-grams of that alphabet; bound as a parameter. No quote/operator can reach MATCH. `aliasesByKeys` drops non-canonical keys, caps at 512, uses `IN`, no `LIKE`.
- **Performance.** Host p95 4.6 ms on the seed (target 5 ms, met) and 11.3 ms on the adversarial 3600-alias catalog where every alias shares a suffix. The real catalog is curated and far from that case; acceptable. The device figure (target 25 ms) is unmeasured, tracked below.
- **Seed.** Two Arabic aliases added to curated and seed CSV, regenerated; signature verification green. Native-speaker review stays with T-059 (PO-4).
- **Deviations 1 to 6.** All accepted. Integer scores are the right answer to the `no_double_money` lint. `merchantsByIds` replacing `merchantCategory` is sound. Deviation 4 (runner-up below threshold still counts for ambiguity) is stricter and safe. Deviation 6 (COALESCE of merchant; heuristic never replaces catalog) is consistent with "never downgrade".
- **Public API for T-046.** Clear: `categorizeInputFor` + `categorizerProvider` / `backfillCategorizerProvider`, `CategoryDecision` with `source.code`, and `Recategorizer.apply/run`. Header example in the providers file helps.
