## Re-review (delta)
Scope: `git diff f156cf8 d862950` (code at 1ecc8be, script/docs after). Reviewer: code-reviewer (Sonnet). JVM spool + capture run locally: OK (67 tests). app-ci 43010925676 is success, but on 1ecc8be. Later commits only touch `sms-spike-device.sh` and task docs, which app-ci does not run.

### Major #1: resolved
- **Key.** `SpoolStore.canonicalKey` uses `File.canonicalPath` (symlinks, `.`, `..`, relative paths). It falls back to an absolute, normalized path only on `IOException`. The new test uses `dir + "/./"` as an alias. Spool dir and status file are different keys, so the lock order store then status is unchanged.
- **Growth.** One map entry per distinct path. The app uses one spool dir and one status file, so growth is bounded. Only tests add entries, and they are tiny. Nothing is removed; that is acceptable here.
- **Lock coverage.** `put`, `write` and `sweepTmp` all use `synchronized(lock)`, and `lock` now comes from the shared per-path object. Tmp, fsync and rename sit inside one lock hold, and a sweep on any instance waits for them.
- **Status.** `lock` and `pending` both live in the shared object. `read`, `clear` and `record` all go through `lock`, so a delta is merged once. Test 3 asserts counts of 2 / 1 and `seq` 2 from three different instances.
- **Rate window.** `genericWrites` is in the shared object, under the shared lock. Test 2 covers it.
- **Tests fail without the fix.** I checked test 1 by reasoning. With per-instance locks, B's `sweepTmp` runs while A is parked between fsync and rename. It deletes A's tmp, A's move throws, and the `assertNull(error)` assertion fails. With the shared lock, B blocks until the 500 ms park expires, A finishes, and the sweep then sees 0 tmp. Tests 2 and 3 fail the same way. I did not run them against the unfixed code.

### Script
- `-r` parsing is correct. `OK (n tests)` is still printed on its own line in raw mode. `skipped_names` uses `substr($0,30)`, which is the right offset for `INSTRUMENTATION_STATUS: test=`, and it prints only for code -4. The allow-list is exactly `bundledBaseLoads`. The guard step is fatal on failure, on zero tests, on a disallowed skip, and on a missing `guard.timing`.
- The current sms-spike red on the guard step is the T-038 ICU regex defect (FU-101). It is not a T-039 finding.

### Findings
- nit: `SharedPathLockTest` uses a fixed 500 ms park. With the fix it passes deterministically. It could only pass falsely if B ran more than 500 ms late without the fix. No change required.
- nit: the `canonicalKey` IOException fallback can produce a different key from `canonicalPath`. This is only a theoretical edge, and it needs a comment at most.

No blocker or major.
