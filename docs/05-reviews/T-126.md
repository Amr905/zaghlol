## Acceptance criteria
- Rollout stable per install: `Bucket` = SHA-256 of `zaghlol.flag.v1:<key>:<installId>`, first 4 bytes BE, mod 100; no state or clock; per-flag; monotone. Documented in backend-api.md §4.8. Met.

- FU-011 live spec test for both operations: `FlagsLiveContractTests`. Met.

## Declared deviations
1. **Operator auth seam, fail closed: accepted.** `RejectAllOperatorTokenValidator` is registered with `TryAddSingleton` and returns null. No header, malformed header or refused token gives 401 through one challenge body. The handler never returns Success without the validator. The policy pins `AddAuthenticationSchemes(OperatorOidc)` plus `RequireAuthenticatedUser` and the role claim, so an install token cannot authenticate `/admin` (tested: `AnInstallTokenIsNotAnOperatorToken`, `EveryAdminCallIs401WithTheDefaultValidator`). Making the install scheme the explicit default does not weaken install auth: the policy still names it, and its handler ignores endpoints without `InstallTokenRequiredMetadata`. Tokens are not logged.
2. Closed key set with 404: accepted, documented in §4.8. Unknown key is 404 before the body is read, so no side effects.
3. Explicit default scheme: accepted (see 1).
4. Per-operator bucket: accepted. The `PerToken` limiter runs after `UseAuthorization`, which sets `context.User` from the policy scheme, so the operator claim is visible. Tested (429 for one operator, not another). Partition key is prefixed `op:`, so it cannot collide with install token hashes.
5. `FlagEvaluator.Snapshot` / `IFlagReader` plus the hash contract in §4.8: accepted. App login is SELECT only, admin login writes.
6. Metric and webhook: accepted. The metric tag is the closed key set, so cardinality is bounded. Webhook is https-only, redirects off, 3 s timeout, URL and exception text never logged, malformed value fails at startup without echoing it, a failed post never fails the committed change.

Other checks: audit row and upsert share one connection and transaction (`FlagAdminStore.UpsertAsync`), version incremented atomically in SQL; no idempotency key on either route (tested); Cache-Control no-store; no new user-facing strings; no money.
