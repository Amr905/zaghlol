## Design-note conformance (focus items)
- Triggers: start (unconditional), 300 ms trailing watch, `flush()` immediate, resume only when dirty / not `full` / key invalidated, `userUnreadable`/key invalidated rewrite then re-read: all present. `onPermissionChanged` does not write. Retry table 2/10/60 s then `parked`; `CONFIG_INVALID` and `NOT_AVAILABLE` never retried; no rule rollback.
- Over-count bound: an alert racing the clear fails the compare-and-clear, next read has a new seq and adds old+new to the informational count only; catch-up is a `min`, flags idempotent. Matches the note.
- Status read/clear only in the coordinator (UI engine). Worker/headless untouched.
- `foreground_ingestion.dart` removal: its behaviour (register `CaptureEventsApi`, drain at start and on `onSpoolChanged`) is covered by the coordinator; with `kIsSpikeBuild` the default loader is `loadSpikeRegistry`, so devSms keeps the foreground drain (test moved to `capture_providers_test`). Extra effect in devSms: a Guard write is attempted; with no native writer it ends in `unavailable`, harmless.
- Deviation 1 (no coordinator off Android / without a registry / on failed DB open): **safe** (no retry storm, nothing deleted, drain-time re-check in T-046 still enforces BR-CAP-01, native spool is bounded) but **not visible**: see F-1.
