| M-1 | **major** | `app/lib/core/db/app_database_opener.dart:547-564` (`_afterFailure`, line 551) | `_afterFailure` restores **any** `.migrate.tmp` it finds, whoever made it. ### Deviations (judged)
- **Standalone `tools/drift_codegen` + hand-written `schema_shape`:** accepted. The cause is a real resolver conflict (analyzer for drift_dev vs Pigeon 26/tools/lints). The script cleans up its scratch copies, its lock is enforced, CI fails on stale output, and tests cover the dump-equality and versions 1..N. The removal condition is documented in the pubspec. Gaps are m-3 and m-4.
- **`busy_timeout` before the key:** accepted. It is a connection setting that reads no page, so the T-007 invariant ("nothing reads the file before the key") still holds.
- **Lease re-check before `recreateAfterWipe`:** accepted. It is correct and tested (`lease lapses after the wipe: no key is written`).
- **Background engine never rolls back (`DB_MIGRATION_PENDING`):** accepted for step 1, but the failure path breaks it (M-1).
- **Lapsed lease → `DB_UNAVAILABLE` + `leaseLapsed`:** accepted. It maps to `retry` and nothing is touched.
- **Riverpod auto-retry off:** correct for Riverpod 3. An open may wipe or migrate, so a retry must be the gate's choice.
- **Accepted gap (notice lost if the app dies between wipe and create):** acceptable, but widen it per m-2.
- **T-017.md "Input from T-016" and CI grep extension:** in scope. The design note §8(b) asks for the T-017 hand-off, and §7 asks for the grep.

### Tests
The tests are strong: they use real sqlite3mc on host and device, cover every file, record the wipe order, include lapse-at-step-N, the two-opener race, transient-error no-wipe with snapshot equality, the closed failure enum → gate mapping, code-only `DbOpenFailure`, and the Riverpod wiring. The XCTest renew cases are registered in the CI grep. Missing: the two-engine migration overlap (M-1) and the leftover-path race (m-1).

## Security & privacy review

| # | Rating | Area | Finding |
|---|--------|------|---------|
| S-1 | **High** (before merge) | Data integrity / no wipe on transient errors | Same issue as M-1. A non-migrating engine's ordinary failure path performs a destructive replace of the live database. It is not a key wipe, but the effect is the same class: user data is lost without user action. It has to be fixed before T-008 brings the headless engine; the API (`allowMigrationProvider`) already invites it. |
| S-2 | Low (follow-up) | Data integrity | m-1: the leftover deletion includes the main file and runs without the lease. |
| S-3 | Info | D-70 notice | m-2. |

Checked and passing:
- **No wipe on transient errors:** only `isKeyRejected` (SQLITE_NOTADB) reaches `reportRejected`. A rejected retry, `DB_OPEN_FAILED`, BUSY, IOERR, unexpected exceptions and `KeyUnavailable` all map to `DB_UNAVAILABLE`. `KeyCreated` from `reportRejected` is refused, so no file is ever created over an existing one. The negative proof (c) is recorded.
- **Wipe order and crash safety:** `dbWipeOrder` deletes every companion, then `.migrate.part`, the copies, and the main file last. `ensureValid` runs before each step and before the key rewrite. `anyExists()` runs before `recreateAfterWipe`, giving `DB_WIPE_INCOMPLETE` on leftovers. Wipe steps name no secrets, and the iOS seat-key survival is covered by an XCTest.
- **Key handling:** the key is zeroized in `finally` on every path, including the retry key and refused `KeyCreated`. The key is not cached, and only the T-015 isolate copy exists, which T-015 already accepted. `PRAGMA key` exists only in `_execKey`, and its exception text is dropped. `driftLogStatements` is false, with a test and a CI grep that now also covers `stdout`/`stderr`/`dump` and `core/db/schema`.
- **Pre-migration copy:** a byte copy after `wal_checkpoint(TRUNCATE)`, and the copy is refused if the checkpoint is busy. A test shows it opens with the same key and has no plaintext header. `.part` is deleted on failure and at startup, and `.migrate.tmp` is deleted after confirmation. Both names are in `dbFileNames`, so they count as "a database exists" and are wiped.
- **Locations:** `<applicationSupport>/db` and the temp directory (`cacheDir` / `Library/Caches`) are covered by the T-165 rules. A host test pins the path and both platforms' exclusion rules.
- **Errors and logs:** every code is constant. `DbOpenResult.toString`, `diagFields` and `DbOpenFailure` carry no path, SQL or key. Nothing is logged.
- **Native `renew`:** it never takes a lease, rejects lease 0, stale and expired leases, and is synchronised. It has JVM and XCTest coverage.
