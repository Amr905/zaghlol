## Checks requested
- **No `double`:** none in prices code. `decimal`, `numeric(20,6)`, DecimalString on the wire. The only `double` is the existing metric gauge (age in seconds).
- **Rounding:** derived gold only, 2 dp away from zero, documented on `PriceNormalizer.GoldDecimals`, in the design note and tested. Provider-supplied gold is stored unrounded (to column scale). FX is 8 dp, which fits `numeric(24,12)`. Appropriate.
- **Digit-run CHECK vs `ContributionPrivacy`:** the SQL `([digits][[:space:].,/_،-]{0,3}){6,}` and the hand-written scanner agree: gap reset on a non-separator, run broken by a 4th separator, same four digit scripts, folding before the scan, `@` and 64 chars. The migration `Up` and `Down` restore the old regex exactly and match the model snapshot and docs. Only gap: whitespace (see #3).
- **Grants:** no GRANT change is needed. `GrantMatrix` already gives `worker_rw` and `ops_rw` SELECT/INSERT/UPDATE on `price_quotes` (enough for `ON CONFLICT DO UPDATE ... RETURNING`), `app_rw` SELECT, `ops_rw` INSERT on `audit_log`; `ops_rw` has no DELETE, which is why Clear expires the row. A grant test exists.
- **Metrics:** tags come from `PriceProviderNames` (startup rejects unknown names) and `PriceFetchOutcomes`; the age gauge is keyed by the closed symbol set. No free text.
- **Declared deviations:** all accepted. `ClearAsync` without a route matches the signed-off contract. The 12-digit and no-`@` limits are stricter than OpenAPI but safe and rejected before the INSERT, so the CHECK never fires. Not echoing `expiresAt` is fine. Failing startup on an unknown provider and refusing `fake` in Production are good.
