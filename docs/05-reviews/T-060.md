## Judgement on the specific questions
1. **Pigeon contract.** Sound and consistent with existing contracts: separate file so `AndroidCaptureHostApi` is untouched, same output layout and `ErrorClassName` convention as `capture_api`/`ocr_api`, reuses the documented error codes `IO_ERROR` and `SPOOL_DECRYPT_FAILED` with the same meaning (entry deleted), metadata-only descriptor, content only on `readShare`, `@TaskQueue` on blocking calls, idempotent discard. The generated Swift file lands in `ios/Runner/Platform` like the others (unused on iOS; harmless, matches convention). Two requests: F7 (poll on warm start) and sign-off recorded (F10). No change to shapes needed.
2. **ShareActivity.** Good: only `ACTION_SEND`, `content://` only, own-provider refusal (F4 caveat), limits enforced on bytes read (not declared size, tested at and over the boundary), magic-byte sniff of PNG/JPEG/WEBP/HEIF/PDF, strict UTF-8 plus NUL check for text, CSV not binary, ids validated by a 28-hex regex before any path use (tested), no logging (no `Log` in the package), malformed extras tolerated. Launch flags: `taskAffinity=""` on the share activity and `NEW_TASK|CLEAR_TOP|SINGLE_TOP` into `MainActivity` (singleTop, default affinity) puts the user in the app's own task; the intent carries no content, so StrandHogg-style hijack exposure is low. Open items: F3 (timeouts, recreation), F4, F7.
3. **KeystoreShareCipher.** Parameters match the contract. Not yet safe for T-039 reuse until F5 (single synchronized key owner) and F8 (directory/purge semantics).
4. **At-rest store.** `noBackupFilesDir`, `nonce||GCM`, tmp+fsync+rename, meta last, tamper tests and wrong-key test, 24 h purge on list/newWriter, discard idempotent. Gaps: F2, F6. Note purge only runs when the intake or host API runs (documented).
5. **Capture Guard skip for shared text.** Acceptable: user-initiated and always shown for confirmation; consistent with FR-ING-A-04. Keep the confirmation mandatory (no auto-save) when the UI lands.
6. **androidTest pins.** Acceptable given the stated Gradle consistent-resolution constraint; old versions (`junit 4.12`, `runner 1.3.0`, `ext:junit 1.1.2`) are test-only and not shipped. Revisit when `integration_test` updates.
7. **T-103 app lock.** Not integrated and not required here, but when the app is locked the share is already decrypted-capable: Dart must gate `readShare` behind unlock, and the activity should not surface content above the lock. File as follow-up on T-103 (owner) with the confirmation-route task.
