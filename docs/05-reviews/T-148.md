## Design-note conformance (checked by tracing the code)
- **Prefix and header.** Magic → `notABackup`; version > 1 → `newerFormat`; version 0, `headerLen` 0 or > 4096, or a short header → `corruptHeader` (`backup_format.dart:448-463`, `backup_stream.dart:123-135`). The strict CBOR (`strict_cbor.dart`) accepts only uint, bstr, tstr and map heads in shortest form. It refuses indefinite lengths, reserved additional info and uint64 ≥ 2^63, requires exact keys in order and exact bstr lengths, refuses trailing bytes, and never allocates more than the bytes present. Shape errors are reported ahead of KDF-bounds errors.
- **KDF bounds before the KDF.** `BackupHeader.decode` raises `unsupportedKdf` after parsing (`:433`). `_unlockSlot` and `Argon2idKdf.derive` check the bounds again. The order is cheap refusals (`newerSchema`, `newerFormat`) → normalize → KDF → unwrap → `kbkId` check, as §7 specifies.
- **Keys, nonces, AAD.** `K_chunk = HKDF(K_bk, fileId, "ZGLB v1 chunk")`. `nonce_i = noncePrefix ‖ u32be(i)`. `AAD_i = headerBlock ‖ u32be(i) ‖ u8(isLast)`, where `headerBlock` is the exact bytes read. The wrap AAD is `"ZGLB v1 wrap" ‖ CBOR(kdf) ‖ kbkId`. The chunk cap is 65 536 on both sides, so the u32 counter can't wrap.
- **Final chunk.** A short read is always the last chunk. A full chunk is last only when `atEnd`. A tag-only chunk is valid only at index 0 (empty payload). The writer holds one buffer back, so it seals with `isLast` correctly for 0, exact-multiple and partial payloads. Tests cover the edges (0, 1, c-1, c, c+1, 2c).
- **HKDF empty salt.** RFC 5869 §2.2 defines an absent salt as HashLen zero bytes. HMAC pads any key shorter than the block size with zeros up to 64 bytes, so an empty key and 32 zero bytes give the same K0. The change is equivalent, and two independent checks confirm it: RFC 5869 case 3 (empty salt) and the Python generator (`salt=None`).
- **Streaming and memory.** The writer reuses one `chunkSize` buffer; the reader allocates `chunkSize + 16` per read. No output is ever assembled in memory. Deviation 1 (weak references plus an RSS bound under 80 MiB instead of < 16 MiB on the host) is acceptable: the host growth comes from garbage produced by the pure-Dart GCM fallback, and nothing is retained (0/48 chunks alive).
- **Error mapping on device.** I read `cryptography_flutter` 2.3.4. Android `AEADBadTagException` and iOS `CryptoKitError.authenticationFailure` both map to `INCORRECT_MAC`, which becomes `SecretBoxAuthenticationError`, which becomes `corruptData` / `wrongPassphrase`. The mapping is correct; see finding 1 on the device test.

## Shared key-store code (T-015 backward compatibility)
- **Android.** `DbKeyStore` gets `blobName`/`aad` parameters whose defaults are `BLOB_NAME`/`AAD`. `dbKeyStore()` still uses the defaults and `AndroidKeystoreKek()` still defaults to `zaghlol_db_kek_v1`. The existing K_db blob path, AAD and alias are byte-identical. New tests cover both slots coexisting, deleting the backup slot without touching K_db or its KEK, and a blob moved between slots being `UNUSABLE` (the AAD differs). Slot routing is tested in `SecretStoreHostTest`.
- **iOS.** `DbKeyKeychain(account:)` defaults to `db_key_v1`. Every instance path (`readOnce`, add, the delete after a failed verify, `delete`) passes `account`. `SecretStoreRegistration.dbKey` is unchanged. See finding 3.
- **Dart.** No app code iterates or switches on `SecretSlot` except `PigeonSecretStore._slot` (updated). `key_bootstrap.dart` touches only `dbKey`, and the opener test now asserts that (`slotsTouched == {dbKey}`).

## Deviations
- **Deviation 5 ("negative proofs don't hold"; numbered 4 in the brief).** The analysis is right. `headerBlock` (which holds `fileId` and `noncePrefix`) is in every AAD, and `i` is in the nonce. So dropping `fileId` from the HKDF, or `i` from the AAD alone, leaves the substitution and swap tests green. The replacement test (`tamper_test.dart:171-191`) forces an equal `noncePrefix` and equal plaintext under one `K_bk`, so identical ciphertext means identical keystream. That is the property the per-file key exists for. I confirmed that it fails, alone, when `fileId` is removed.
- **Deviation 3 (`BackupKeySlotStore` port; the provider throws).** Acceptable for this branch, which is based on a `main` without `secure_state`. On `batch/2026-11-11-4`, T-019's table and `SecureStateDao` exist. The key `backup.key_slot.v1` passes the `[a-z0-9_.]` check and the slot (about 150 bytes) is within the 65 536-byte value limit, so the adapter is small. Follow-up: finding 2.
- **Deviations 2, 4, 6, 7, 8** (the `passphraseTooShort` code, the vector fixture with hashes instead of full hex, strictness choices, the NFC fast path, the slot write under the lease) are sound. The fast-path claim holds: no code point below U+0300 has a canonical decomposition with a starter that composes, and Hangul jamo are above U+0300.
