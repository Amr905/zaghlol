### Deviations (judged)
- **`categories` created here:** accepted. It is the FK parent of `transactions.category_id`, adding the FK later would mean rebuilding `transactions` and its FTS triggers, and T-018 has been told (`T-018.md`).
- **Constraints stricter than the spec DDL:** accepted. All are CHECKs or indexes the spec implies (FR-ACC-03 "exactly one", T-012 money bounds), and `database-schema.md` §2 lists them.
- **`transactions_fts_src` as a real table with `INTEGER PRIMARY KEY`:** accepted. It is the correct fix for the rowid instability of a TEXT-PK content table under `VACUUM`. The tests cover id changes and integrity-check.
- **Frozen v2 statements instead of `Schema2`:** accepted. The list is checked against the dump (`migration_v2_test.dart:87`), it has no `IF NOT EXISTS` (a stray object fails the step and the copy is restored, `:195`), and the migrated shape equals the fresh shape and the dump. Rule 2a in `database-schema.md` §5 makes this the pattern from now on.
- **Codegen fails on drift_dev warnings:** accepted. It prevents the silent drop that hit the view.
- **Plain DAO classes with `guardWrite`:** accepted. Every write path maps `SqliteException` to a code-only `DbWriteException`, unknown trigger messages collapse to `DB_CONSTRAINT_TRIGGER`, and the body-sentinel test proves it. Reads are the gap (F-1).
- **`2.0` accepted as 2:** not a money-safety issue. Affinity converts only REALs and texts that are **exactly** integral, the CHECK sees the converted value, and what is stored is an exact integer in ±(2^53−1). Values like `1.5`, `'1.5'`, blobs and out-of-range values are refused. The typed Dart path (`int` columns, `Money.toStorage`) can't bind a double anyway. Only the wording needs fixing (m-3).
- **1–2 digit searches find nothing:** accepted, as documented in `database-schema.md` §2.2 ("Search as built"). The Search screen task must send digit-only short queries to amount filters. Make sure the T-149 / search UI brief says so.
